# 🗂️ Jira — доски, Scrum и Kanban, workflow

Часть серии — [карта серии](00%20%E2%80%94%20Jira%20%E2%80%94%20%D1%87%D1%82%D0%BE%20%D1%8D%D1%82%D0%BE%2C%20Cloud%20%D0%B8%D0%BB%D0%B8%20Data%20Center%2C%20%D0%BE%D1%81%D0%BD%D0%BE%D0%B2%D0%BD%D1%8B%D0%B5%20%D0%BF%D0%BE%D0%BD%D1%8F%D1%82%D0%B8%D1%8F%20%D0%B8%20%D0%BA%D0%B0%D1%80%D1%82%D0%B0%20%D1%81%D0%B5%D1%80%D0%B8%D0%B8.md).

## 1. Kanban или Scrum

| | **Kanban** | **Scrum** |
| :--- | :--- | :--- |
| Ритм | непрерывный поток: взял → сделал → следующий | **спринты** фиксированной длины (1–2 недели) |
| Планирование | постоянно, по приоритету | в начале спринта: что успеем |
| Ограничение | **WIP-лимиты** — сколько задач одновременно в колонке | объём спринта |
| Метрики | **время цикла**, поток задач | **velocity** (скорость), burndown |
| Подходит | один человек или маленькая команда, поддержка, инфраструктура, свои проекты | команда, продукт с релизами |

Для изучения и личных проектов начните с **Kanban**: меньше ритуалов, сразу видно поток. Scrum попробуйте вторым проектом — его отчёты понятнее, когда работаешь спринтами.

## 2. Kanban-доска

```
 Backlog │ To Do (≤5) │ In Progress (≤2) │ Review (≤3) │ Done
─────────┼────────────┼──────────────────┼─────────────┼──────
 WEB-12  │ WEB-7      │ WEB-3            │ WEB-5       │ WEB-1
 WEB-13  │ WEB-9      │                  │             │ WEB-2
```

- **Колонки** = один или несколько статусов: **Board → ⋯ → Configure board → Columns**. Можно сделать колонку «Review», в которую попадают статусы «Code review» и «Testing».
- **WIP-лимит** (минимум/максимум задач в колонке) — там же. Превышение подсветит колонку красным: главный инструмент Kanban — **меньше начатого, больше законченного**.
- **Swimlanes** (дорожки): по эпикам, исполнителям, приоритету или по JQL-запросу — например, отдельная дорожка «Срочное» для `priority = Highest`.
- **Quick filters** — кнопки фильтров над доской по JQL: «Мои», «Баги», «Без оценки».
- **Kanban backlog** (включается в настройках доски): бэклог отдельно от доски, чтобы колонка To Do не превращалась в свалку.
- Done-задачи пропадают с доски через 2 недели (настраивается), но остаются в поиске.

## 3. Scrum: бэклог и спринты

### Бэклог

**Backlog** — список задач по приоритету (сверху — важнее). Перетаскиванием меняют порядок, ПКМ → Move to sprint. Хороший бэклог:

- сверху — задачи **готовы к работе**: понятное описание, критерии готовности, оценка;
- эпики видны слева (панель Epics) — удобно фильтровать;
- раз в неделю — «груминг»: уточнить, оценить, выкинуть неактуальное.

### Спринт

1. **Create sprint** в бэклоге → перетащить задачи.
2. **Start sprint**: длительность (1–4 недели) и **цель спринта** одной фразой.
3. Работа на доске спринта (**Active sprint**).
4. **Complete sprint**: незавершённые задачи уходят в следующий спринт или бэклог.

### Оценки

| Способ | Как |
| :--- | :--- |
| **Story points** | относительная сложность: 1, 2, 3, 5, 8, 13 (Фибоначчи). Не часы — «насколько сложнее эталонной задачи» |
| **Время** (Original estimate) | часы/дни: `4h`, `2d` |
| **Количество задач** | просто считать задачи (для Kanban) |

Способ оценки задаётся в **Board settings → Estimation**. Для одного человека хватит количества задач или грубых story points.

## 4. Workflow — статусы и переходы

**Workflow** — граф статусов задачи и разрешённых переходов между ними.

```
            ┌──────────────── Reopen ─────────────────┐
            ▼                                          │
  To Do ──Start──▶ In Progress ──Review──▶ In Review ──Approve──▶ Done
            ▲            │                     │
            └──Stop──────┘◀──── Changes ───────┘
```

Каждый статус относится к одной из трёх **категорий**: **To Do** (серый), **In Progress** (синий), **Done** (зелёный). Категории важны: по ним считаются отчёты, а JQL `statusCategory = Done` работает для любых названий статусов.

### Где редактировать

- **Team-managed**: Project settings → Work types → тип → **Edit workflow** — визуальный редактор, статусы и переходы мышью.
- **Company-managed**: Settings → Work items → **Workflows** (общие схемы) → редактор. Схема workflow привязывается к проекту через **workflow scheme**.

### Что можно повесить на переход

| Элемент | Пример |
| :--- | :--- |
| **Условие** (condition) | переводить в Done может только исполнитель |
| **Валидатор** (validator) | при переходе в Review обязательно поле «Ссылка на PR» |
| **Пост-функция** (post function) | при переходе в In Progress назначить задачу на того, кто перевёл |
| **Экран** (screen) | при закрытии спросить Resolution и комментарий |
| **Resolution** | в company-managed — признак завершённости (Done, Won't Do, Duplicate); у незакрытых пустой (`resolution = Unresolved` в JQL) |

### Рекомендуемый workflow для разработки с CI

```
To Do → In Progress → In Review → Done
```

- **In Progress** — создана ветка (`WEB-42-login-form`);
- **In Review** — открыт PR;
- **Done** — PR смёржен и сборка в main прошла.

Эти переходы можно делать **автоматически** по событиям из GitHub/GitLab/Bitbucket — заметки 04 и 05. Названия переходов делайте без лишних слов: их пишут в smart commits (`#in-review`).

## 5. Релизы и версии

**Releases** (в боковом меню проекта, company-managed): создать версию `1.4.0` с датой → указывать её в поле **Fix versions** задач → на странице релиза видно, что готово, что нет, и связанные сборки/деплои → **Release** — отметить выпущенной. Удобно сочетать с тегами git и релизами CI.

## 6. Отчёты и дашборды

| Отчёт | Где | Что показывает |
| :--- | :--- | :--- |
| **Burndown chart** | Scrum → Reports | сколько осталось работы в спринте по дням |
| **Velocity** | Scrum → Reports | сколько команда закрывает за спринт — для планирования следующих |
| **Sprint report** | Scrum → Reports | сделано / не сделано / добавлено в спринт |
| **Cumulative flow** | Kanban → Reports | ширина полос = очереди; расширяется «In Progress» — затор |
| **Control chart / Cycle time** | Kanban → Reports | сколько дней задача идёт от начала до конца |
| **Deployment frequency**, **Cycle time** (DevOps) | Reports, при подключённом CI | частота деплоев и время от коммита до продакшена (DORA-метрики) |

**Дашборд** (Dashboards → Create): набор гаджетов — «Задачи на мне», «Созданные vs решённые», круговая диаграмма по статусам, результаты фильтра. Источник каждого гаджета — сохранённый **JQL-фильтр** (заметка 03).
