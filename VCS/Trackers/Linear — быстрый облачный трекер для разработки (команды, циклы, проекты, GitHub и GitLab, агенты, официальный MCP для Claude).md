# ⚡ Linear — быстрый облачный трекер для разработки

**Linear** — облачный трекер задач для продуктовых команд. За что его выбирают:

- **скорость** — интерфейс работает почти мгновенно;
- **клавиатура** — почти всё делается без мыши;
- **продуманный процесс из коробки**: команды, циклы, проекты, триаж;
- **плотная связка с GitHub и GitLab**: статус задачи двигается сам по событиям PR;
- **платформа агентов**: задачу можно назначить ИИ-агенту.

Своей установки **нет** — только облако. Сравнение с другими трекерами — в [общей заметке](%D0%A2%D1%80%D0%B5%D0%BA%D0%B5%D1%80%D1%8B%20%D0%B7%D0%B0%D0%B4%D0%B0%D1%87%20%E2%80%94%20%D1%81%D1%80%D0%B0%D0%B2%D0%BD%D0%B5%D0%BD%D0%B8%D0%B5%20%28%D1%82%D0%B0%D1%80%D0%B8%D1%84%D1%8B%20%D0%BE%D0%BA%D1%82%D1%8F%D0%B1%D1%80%D1%8C%202026%2C%20MCP%20%D0%B4%D0%BB%D1%8F%20Claude%2C%20self-hosted%20%D0%BD%D0%B0%20Gentoo%2C%20Debian%2C%20Arch%29.md); open-source аналог в том же духе, который можно поставить у себя, — [Plane](Plane%20%E2%80%94%20open-source%20%D1%82%D1%80%D0%B5%D0%BA%D0%B5%D1%80%20%D0%B2%20%D1%81%D1%82%D0%B8%D0%BB%D0%B5%20Linear%20%D0%B8%20Jira%20%28%D1%86%D0%B8%D0%BA%D0%BB%D1%8B%2C%20%D0%BC%D0%BE%D0%B4%D1%83%D0%BB%D0%B8%2C%20Intake%3B%20CE%20%D0%BD%D0%B0%20Docker%20%D0%B4%D0%BB%D1%8F%20Gentoo%2C%20Debian%2C%20Arch%3B%20MCP%20%D0%B4%D0%BB%D1%8F%20Claude%29.md).

## 2. Понятия

| Понятие | Что это |
| :--- | :--- |
| **Workspace** | организация, адрес `linear.app/<workspace>` |
| **Team** | команда со своим ключом (`ENG`) → задачи `ENG-123`. У каждой команды свой workflow, циклы, метки и шаблоны |
| **Issue** | задача: статус, приоритет (Urgent, High, Medium, Low), исполнитель, оценка, метки, подзадачи, связи (blocks, related, duplicate) |
| **Cycle** | автоматический спринт команды: длина 1–8 недель. Незакрытые задачи сами переезжают в следующий цикл |
| **Project** | работа с целью и сроком, может включать задачи нескольких команд; есть обновления статуса (on track / at risk) и вехи |
| **Initiative** | группа проектов под одну цель компании — дорожная карта |
| **Triage** | входящие задачи (из интеграций, от других команд, из Asks): их принимают, отклоняют или помечают как дубль |
| **View** | сохранённый фильтр: список или доска |
| **Inbox** | уведомления: упоминания, назначения, изменения подписанных задач |

### Статусы

У каждой команды свой набор статусов, но все они делятся на категории:

| Категория | По умолчанию |
| :--- | :--- |
| Triage | Triage (если включён) |
| Backlog | Backlog |
| Unstarted | Todo |
| Started | In Progress, In Review |
| Completed | Done |
| Canceled | Canceled, Duplicate |

## 3. Клавиатура — основное

| Клавиша | Действие |
| :--- | :--- |
| `C` | новая задача |
| `Ctrl/Cmd + K` | палитра команд — найти любое действие |
| `S` | сменить статус |
| `A` | назначить |
| `P` | приоритет |
| `L` | метки |
| `Ctrl/Cmd + Shift + .` | **скопировать имя ветки** для задачи (с ключом `ENG-123`) |
| `?` | все сочетания |

## 4. Связь с GitHub и GitLab

### Как задача связывается с PR

1. **По имени ветки.** Скопируйте его из задачи (`Ctrl/Cmd + Shift + .`) — PR из этой ветки привяжется автоматически.
2. **По ключу в заголовке или описании PR** вместе с «волшебным словом». В коммите тоже работает.

| Слова | Что происходит |
| :--- | :--- |
| `Fixes`, `Closes`, `Resolves` + `ENG-123` | задача идёт по автоматизации, после влития PR — в статус «On PR or commit merge» (обычно Done) |
| `Ref`, `Part of`, `Contributes to` | задача двигается по статусам, но при влитии **не** закрывается |
| `Relates to`, `Related to` | только ссылка, статус не меняется |
| `Ignore ENG-123`, `skip ENG-123` | не связывать |
| `ENG-NEW` в описании PR | создать новую задачу в команде ENG и связать |

Одну задачу могут закрывать несколько PR: статус сменится, когда **последний** из них дойдёт до нужного состояния.

### Автоматическая смена статусов

Настраивается **для каждой команды**: **Settings → Team → Workflows & automations → Pull request and commit automations**.

| Событие PR | По умолчанию |
| :--- | :--- |
| черновик открыт | — (можно задать) |
| PR открыт | **In Progress** |
| запрошено ревью | — (например, In Review) |
| готов к влитию | — |
| влит | **Done** |

- **Правила по веткам** (с regex): влили в `staging` — статус «On Staging», влили в `main` — Done.
- **«Готов к влитию»** срабатывает только при стабильном зелёном статусе PR. Любая упавшая проверка, даже необязательная, его блокирует.
- Если задачу отменили, связанные PR со связью Closes или Contributes **закрываются**.

### Синхронизация с GitHub Issues

Репозиторий связывается с командой — в одну сторону (GitHub → Linear) или в обе стороны. Синхронизируются заголовок, описание, статус, исполнитель, метки, подзадачи, комментарии и приоритет.

Ограничения:
- переносятся только **новые** задачи, старые — через импорт;
- двусторонне можно связать только один репозиторий на команду.

### GitLab

Работают и gitlab.com, и свой GitLab **от 15.6**, если он **доступен из интернета**. Нужен токен со scope `api` — с `read_api` пропадут комментарии-ссылки в MR. Подключить можно один инстанс GitLab на workspace. Автоматизация статусов — та же: черновик, MR открыт, ревью, готов к влитию, влит.

## 5. Агенты в Linear

Задачу можно **назначить агенту**, как человеку, или упомянуть его в комментарии. Агент откроет PR, напишет документ, обновит задачу — в пределах выданных прав.

- **Linear Agent** включён в каждом workspace.
- Сторонних агентов администратор ставит из **Integrations Directory** и выбирает, к каким командам у них доступ.
- Агенты **не занимают платные места**, но у их поставщика может быть своя цена.
- В **Settings → AI & Agents** можно написать указания на уровне workspace и команды: какие репозитории, как называть ветки и коммиты, как проходит ревью.

## 6. Linear и Claude — официальный MCP

```bash
claude mcp add --transport http linear-server https://mcp.linear.app/mcp
# затем в сессии: /mcp → вход через браузер (OAuth 2.1)
```

| Вариант | Адрес |
| :--- | :--- |
| Чтение и запись | `https://mcp.linear.app/mcp` |
| **Только чтение** | `https://mcp.linear.app/mcp/readonly` — или ключ API только с правом Read |
| Без браузера | заголовок `Authorization: Bearer <OAuth-токен или API-ключ>` |
| SSE (устарел) | `https://mcp.linear.app/sse` |

Инструменты ищут, создают и обновляют задачи, проекты и комментарии. Что можно попросить:
- «составь сводку текущего цикла ENG»;
- «разбери баг ENG-412 и предложи план»;
- «создай задачи по этому списку в проекте „Релиз 2.0“».

Для нескольких workspace заведите отдельные подключения.

### Задача → агент → PR

1. Claude Code берёт задачу через MCP и создаёт ветку с именем из Linear (`eng-123-…`).
2. Делает правки и открывает PR с `Fixes ENG-123`.
3. Linear сам переводит задачу: In Progress → In Review → Done.

То же можно делать в CI через `claude-code-action`. Схема подробно разобрана на примере Jira в [заметке 06 серии](Jira/06%20%E2%80%94%20Claude%20%2B%20Jira%20%E2%80%94%20MCP-%D1%81%D0%B5%D1%80%D0%B2%D0%B5%D1%80%20Atlassian%2C%20acli%2C%20Claude%20Code%20%D0%B2%20CI%20%28%D0%B7%D0%B0%D0%B4%D0%B0%D1%87%D0%B0%20%E2%86%92%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%20%E2%86%92%20PR%29.md).

### API без MCP

GraphQL на `https://api.linear.app/graphql`. Личный ключ: **Settings → Security & access → Personal API keys**. Он передаётся в `Authorization` **без** слова `Bearer`.

```bash
curl -s https://api.linear.app/graphql \
  -H "Authorization: $LINEAR_API_KEY" -H "Content-Type: application/json" \
  -d '{"query":"{ issue(id: \"ENG-123\") { identifier title state { name } assignee { name } } }"}' | jq
```

## 7. На Gentoo, Debian, Arch

Официальные приложения есть для macOS, Windows, iOS и Android. **Под Linux — только веб-версия** в браузере. Её можно установить как приложение (PWA) через «Установить приложение» в Chromium или Chrome.

В AUR есть неофициальные клиенты: `linear-bin`, `linear-desktop-bin` (Tauri), `linear-electron-bin`, а также консольные `linear-cli*` от разных авторов. Это не продукты Linear — читайте PKGBUILD перед установкой, а ключ API давайте только с нужными правами.
