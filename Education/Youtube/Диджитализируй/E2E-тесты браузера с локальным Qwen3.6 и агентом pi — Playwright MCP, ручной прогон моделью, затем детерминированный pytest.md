# 🧪 E2E-тесты браузера с локальным Qwen3.6 и агентом pi (Диджитализируй)

Конспект ролика [«Пишем браузерные e2e-тесты с локальным qwen3.6 и агентом разработки pi»](https://www.youtube.com/watch?v=xShGjTBJbjE) канала [**«Диджитализируй!»**](https://www.youtube.com/@t0digital) Алексея Голобурдина (15.05.2026, ~26 минут). Видео расшифровано whisper, команды сверены с [файлом автора](https://github.com/alexey-goloburdin/knowledge-base) и текущей документацией инструментов. Логины, пароли, ключи и IP из ролика заменены заглушками.

**Главная мысль:** E2E-тест теперь пишется в два шага. Сначала **своими словами описываете тест-кейс**, и LLM сама «протыкивает» его в реальном браузере через MCP-сервер Playwright. Затем просите ту же модель превратить пройденный путь в **детерминированный тест на pytest**, который гоняется в CI без всякой LLM. Всё работает на **локальной Qwen3.6-27B на одной RTX 3090**: без лимитов, без передачи секретов провайдеру.

## Зачем E2E-тесты

- **Что это:** тест проверяет всё приложение в сборке так, как это делает пользователь: открывает браузер, кликает, вводит данные. Задействованы все слои: фронтенд, бэкенд, база, очереди.
- **Где гонять:** на тестовом стенде, идентичном продакшну, или даже на живой системе.
- **Почему они полезны:** с точки зрения поиска багов это **самые полезные тесты** — защищают от регрессии («вчера работало, сегодня после правок — нет»).
- **Сравнение с unit-тестами:** хорошие unit-тесты писать трудно, они должны ловить регрессии и не быть хрупкими (не переписываться при смене реализации). E2E проще сделать полезными и нехрупкими, хотя они медленнее и запускаются реже: при каждом билде в CI/CD, раз в неделю или как удобно.

## Стек из ролика

| Роль | Что использовано | Альтернативы |
| :--- | :--- | :--- |
| Модель | **Qwen3.6-27B Q4_K_M** (dense) в LM Studio на Windows, RTX 3090 (~70 тыс. ₽ на Авито) | **Qwen3.6-35B-A3B** (MoE) быстрее и тоже справляется, но dense 27B умнее; вместо LM Studio — Ollama или llama.cpp |
| Агент | **[pi](https://pi.dev/)** — минималистичный open-source агент, в WSL | свой код или Claude Code (умеет работать с локальными моделями) |
| Браузер | **MCP-сервер [Playwright](https://github.com/microsoft/playwright-mcp)** на Windows, где есть Chrome | — |
| Тесты | Python 3.14 + **uv** + **pytest** + Playwright | — |

**Почему pi:** «из коробки» у него **четыре инструмента**: чтение файла, запись файла целиком, правка части файла и bash. Короткий системный промпт экономит контекст. По словам автора, у Claude Code и OpenCode только системный промпт занимает ~10 тыс. токенов, а для локальной модели с маленьким окном это ощутимо. Всё остальное подключается расширениями.

## Шаг 1. pi и локальная модель

```bash
# установка (нужен Node.js ≥ 22.19; инсталлятор умеет поставить его сам)
curl -fsSL https://pi.dev/install.sh | sh
# или напрямую из npm
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
```

Модель описывается в `~/.pi/agent/models.json`. Подойдёт любой OpenAI-совместимый сервер: LM Studio, Ollama, llama.cpp.

```json
{
  "providers": {
    "lmstudio": {
      "baseUrl": "http://<IP-машины-с-LM-Studio>:<порт>/v1",
      "api": "openai-completions",
      "apiKey": "$LMSTUDIO_API_KEY",
      "models": [
        { "id": "qwen/qwen3.6-27b", "contextWindow": 80000 }
      ]
    }
  }
}
```

- **`apiKey`:** токен из настроек сервера LM Studio. Ключ лучше не вписывать литералом: pi понимает `"$ИМЯ"` (переменная окружения) и `"!команда"` (вывод команды, например из менеджера паролей).
- **`contextWindow`:** выставлять **равным окну, с которым модель реально загружена** в LM Studio. У автора было 50 тыс., на записи он поднял до **80 тыс.**
- **Проверка:** `pi` → «что ты умеешь?» → выход по `Ctrl+D`.
- **Если LM Studio на Windows, а pi в WSL:** IP Windows в сети WSL показывает `ipconfig` в PowerShell (адаптер `vEthernet (WSL …)`). Сервер LM Studio при этом должен слушать не только `localhost`. Другой вариант — включить в WSL режим сети `mirrored`, тогда хост доступен как `localhost`.

## Шаг 2. MCP-сервер Playwright

На машине с браузером (у автора Windows):

```powershell
winget install OpenJS.NodeJS.LTS
npx @playwright/mcp@latest --port 3000 --host 0.0.0.0 --allowed-hosts '*'
```

- **`--port`:** включает HTTP-транспорт, эндпоинт — `http://<хост>:3000/mcp`.
- **`--host 0.0.0.0`:** слушать все интерфейсы, чтобы до сервера достучался агент из WSL.
- **`--allowed-hosts '*'`:** отключает проверку заголовка Host.
- **Безопасность:** такой сервер даёт **управление вашим браузером любому в сети**, поэтому открывайте его только во внутреннюю сеть или WSL и закрывайте файрволом.
- **Если агент и браузер на одной машине**, проще stdio-запуск без сети: `npx @playwright/mcp@latest`.
- **Полезные флаги:**
  - `--headless` — для CI и серверов без экрана;
  - `--isolated` — профиль только в памяти;
  - `--browser chrome|firefox|webkit|msedge`;
  - `--executable-path` — указать системный Chromium.

### Подключение MCP к pi

**Как в ролике (май 2026):** через расширение `pi-mcp-adapter` и файл `.mcp.json` в каталоге проекта.

```bash
pi install npm:pi-mcp-adapter

cd ~/code/e2e-demo
cat > .mcp.json <<'EOF'
{
  "mcpServers": {
    "playwright": { "url": "http://<IP-машины-с-браузером>:3000/mcp" }
  }
}
EOF
```

**В актуальном pi MCP встроен**, и расширение не нужно. Пользовательские серверы хранятся в `~/.pi/agent/mcp.json`, проектные — в `.pi/mcp.json` (читаются только после того, как проекту выдано доверие). Формат тот же, что у Claude Code и Cursor.

```bash
pi mcp add -l playwright --url http://<IP-машины-с-браузером>:3000/mcp   # -l = в проект
pi mcp list        # подключится к серверам и покажет инструменты и ошибки
# внутри сессии: /mcp — состояние, переподключение, видимость инструментов
```

- **Конфликт с расширением:** если `pi-mcp-adapter` установлен, он **заменяет** встроенную поддержку MCP, и pi перестаёт читать `mcp.json`. Используйте что-то одно.
- **Транспорт:** встроенный клиент поддерживает stdio и streamable HTTP, **старый SSE — нет**. Playwright MCP с `--port` отдаёт streamable HTTP на `/mcp`, так что подходит.

**Проверка:** спросить агента «какие MCP-серверы тебе доступны и какие у них инструменты?». В ролике Playwright дал **23 инструмента**: переход по URL, назад, клик, ввод текста, выбор варианта, скриншот, загрузка файла, нажатие клавиш, выполнение JavaScript, сообщения консоли, сетевые запросы и их детали, размер окна, вкладки.

## Шаг 3. Модель проходит тест-кейс в браузере

Новая сессия (`/new`), задача обычными словами (сервис автора — SaaS для расчёта доставки):

```text
Открой сайт <URL приложения>, залогинься: логин <логин>, пароль <пароль>.
Затем перейди на вкладку «Расчёт стоимости и сроков» и посчитай стоимость доставки
до города Липецк груза весом 5 кг, стоимость к оплате 1500 ₽, объявленная стоимость 1000 ₽,
габариты не заполнены, считаем без учёта правил.
Выведи таблицу всех способов доставки со сроками и стоимостью.
```

Что сделала модель, **ничего не зная о сервисе заранее**:

1. **Вход и навигация:** открыла сайт, распознала форму входа, ввела логин и пароль, нажала «Войти», осмотрелась и сама нашла нужную вкладку калькулятора.
2. **Город:** открыла выпадающий список, ввела «Липецк» и выбрала его из подсказок.
3. **Поля формы:**
   - поставила галочку «Считать без учёта правил»;
   - заменила значение по умолчанию на 1500 и 1000;
   - **сама перевела 5 кг в 5000 г**, увидев, что поле в граммах;
   - **очистила** габариты X/Y/Z, а не обнулила их.
4. **Проверка результата:** увидев в таблице только два способа доставки, **прокрутила страницу**, чтобы убедиться, что ниже ничего нет, и вывела итоговую таблицу (два варианта СДЭК — пункт выдачи и курьер, оба по 2 дня).
5. **Контекст:** на всё ушло **~30 % окна в 80 тыс.** токенов. По мнению автора, это ответ тем, кто считает, что с маленьким окном локальной модели ничего не сделать.

Модель **рассуждает по-английски**, даже когда с ней говорят по-русски: английский экономнее по токенам.

## Шаг 4. Из пройденного пути — детерминированный тест

Есть два варианта:

- **В той же сессии** — так сделал автор, рассчитывая, что остатка окна хватит.
- **Через план и чистую сессию** — в файле автора это рекомендуемый вариант. Сначала попросить модель написать промпт для разработки тестов и сохранить его в `PLAN.md`, затем `/new` → `реализуй @PLAN.md`. Это **экономит контекстное окно**, что особенно важно для локальной модели.

Промпт из ролика (вариант в той же сессии):

```text
Создай теперь детерминированный тест или набор тестов, которые будут проверять
работоспособность этой функциональности веб-сайта, которую ты сейчас проверил.
Используй Python и uv для работы с Python-проектом. Используй Python 3.14, для тестов — pytest.
Тесты должны быть нехрупкими: например, не полагайся на порядок полей в форме, который может меняться.
Реализовав тесты, убедись, что они работают и проходят.
```

Как шла работа:

- **Цикл отладки:** модель создала uv-проект и написала тесты, запустила их, прочитала ошибку (`get_by_role("textbox")` находил оба поля формы входа), исправила page object и запустила снова. Потом так же разобралась с тестами калькулятора: падения, таймауты по 193 секунды, исправления, пока **все 9 не прошли**.
- **Время и контекст:** ~15–20 минут на написание, отладку и прогон; израсходовано **~64 % окна** (около 50 тыс. токенов) на весь путь — и браузер, и тесты.
- **Ручная проверка:** контрольный `uv run pytest` — **9 passed за ~30 с**.

**Что получилось (структуру модель выбрала сама, её не просили):**

```text
tests/
├── conftest.py            # фикстуры: browser, page, authenticated_page
├── test_login.py          # 2 теста авторизации
├── test_calculator.py     # 7 тестов калькулятора
└── page_objects/
    ├── login.py           # LoginPage — вход в систему
    └── calculator.py      # CalculatorPage + dataclass DeliveryOption
```

- **Авторизация:** страница входа загружается; успешный вход перенаправляет на дашборд.
- **Калькулятор:**
  - навигация через сайдбар;
  - форма для Липецка возвращает результаты;
  - в результатах есть варианты СДЭК;
  - у всех строк корректные данные (стоимость > 0, дней ≥ 0);
  - самовывоз дешевле курьера (автор считает это утверждение спорным);
  - пустые габариты не ломают расчёт;
  - значения формы сохраняются после смены города.
- **Где проверки ослаблены намеренно:** **конкретные цены и сроки тест не проверяет**, потому что они динамические. Как раз о таких «нехрупких» тестах автор и просил.

**Приёмы нехрупкости, которые модель применила сама:**

- **Поиск полей:** по тексту `<label>` (`locator("label").filter(has_text=…)`), а не по порядку в DOM.
- **Город:** через `get_by_role("combobox")` и `get_by_role("option")` с текстовым фильтром.
- **Навигация по SPA:** кликом по сайдбару, а не прямым URL — при hash-роутинге прямой переход не срабатывал.
- **Ожидание результатов:** опрос (polling), пока в таблице не появятся данные, потому что SPA рендерит с задержкой.

**Что доработать руками:** модель вписала логин и пароль прямо в код теста, потому что так они были даны в промпте. В реальном проекте **вынесите их в переменные окружения** (`os.environ["E2E_LOGIN"]`, секреты CI) и попросите модель следовать вашей структуре фикстур и хелперов, если она у вас есть.

## Выводы автора

- **Отговорок не остаётся:** покрываете основные пользовательские сценарии, фиксируете поведение тестом, гоняете в CI/CD — и регрессии ловятся автоматически.
- **Всё локально:** нет лимитов, блокировок по региону и передачи секретов провайдеру, и модель «не тупеет перед релизом новой версии».
- **Контекст расходуется экономно:** с минималистичным агентом даже окна в 80 тыс. токенов хватило на весь путь — от браузера до 9 зелёных тестов.

## 🐧 Повторить на своих системах

Агенту pi нужен **Node.js ≥ 22.19**, а `npx @playwright/mcp` работает на актуальном LTS. Для тестов на Python нужны `uv` и браузер Playwright (`uv run playwright install chromium`).

| Система | Node.js | uv | Браузер для Playwright |
| :--- | :--- | :--- | :--- |
| **Gentoo** (OpenRC) | `emerge -av net-libs/nodejs` (в дереве есть 22.x, 24.x, 26.x) | `emerge -av dev-python/uv` или `curl -LsSf https://astral.sh/uv/install.sh \| sh` | Gentoo официально не поддерживается: `playwright install chromium` обычно работает; иначе `www-client/chromium` и `--executable-path` |
| **Debian 13** | в репозитории **20.x — мало для pi** → инсталлятор pi поставит свой Node, либо NodeSource/`nvm` | инсталлятор astral | `uv run playwright install --with-deps chromium` |
| **Ubuntu** | NodeSource или `nvm` (системная версия зависит от релиза) | инсталлятор astral | `uv run playwright install --with-deps chromium` (Ubuntu — основная платформа Playwright) |
| **Arch** | `pacman -S nodejs npm` (26.x) | `pacman -S uv` | `playwright install chromium` или `pacman -S chromium` + `--executable-path` |
| **Entware** (RT-AX56U) | в репозитории `node` 18 — для pi слишком старый | — | браузер на роутере не запустить; роутер здесь не нужен |

**Сервер без экрана (VPS, CI):** запускайте MCP с `--headless`, тесты — по умолчанию (pytest-playwright и так headless). Если нужно видеть браузер глазами, есть Xvfb и VNC.

**Вместо pi — Claude Code на той же локальной модели:** LM Studio начиная с 0.4.1 отдаёт Anthropic-совместимый `/v1/messages`.

```bash
export ANTHROPIC_BASE_URL=http://<хост>:1234     # корень сервера, без /v1
export ANTHROPIC_AUTH_TOKEN=<токен LM Studio>
claude --model qwen/qwen3.6-27b
claude mcp add --transport http playwright http://<хост>:3000/mcp
```
