# 💾 Kali Linux на флешке с постоянным хранилищем (persistence)

Живой (Live) Kali грузится с флешки в оперативку и после перезагрузки **всё забывает**. **Persistence** добавляет на ту же флешку отдельный раздел, куда сохраняются изменения (файлы, настройки, установленные пакеты) между загрузками. Метод — стандартный механизм `live-boot` Debian, который Kali наследует; работает одинаково на всех сборках — бери **актуальную версию** (Kali нумеруется по схеме `ГОД.N`, сейчас это **2026.x**), старые вроде 2021.x тоже поддерживаются, но смысла ставить их нет.

> [!warning] Команды из видео — только часть процесса
> В [ролике](https://www.youtube.com/watch?v=Fgra3XYmrSc) показаны шаги настройки уже **существующего** раздела `sdb3`. Но чтобы флешка реально сохраняла данные, до них нужно: **записать ISO**, **создать раздел** и — ключевое, чего в показанных командах нет — **отформатировать его с меткой `persistence`**. Без метки `persistence` система хранилище не подхватит. Ниже — полный рабочий процесс; шаги из видео помечены 🎬.

---

## ⚠️ Перед началом: не сотрите не тот диск

Все операции идут по **имени устройства** (`/dev/sdb`). Если ошибиться буквой — можно затереть системный диск. Поэтому:

- 🎬 сначала смотрим список дисков и **находим свою флешку по размеру**:
  ```bash
  sudo fdisk -l
  ```
- дальше по тексту `/dev/sdb` — это **флешка** (в видео так). У тебя буква может быть другой (`/dev/sdc` и т.п.). Внутренний диск обычно `/dev/sda` или `/dev/nvme0n1` — его **не трогаем**.

---

## 1. Записать образ Kali на флешку

Скачать live-ISO с [kali.org/get-kali](https://www.kali.org/get-kali/) и записать **посекторно** (это создаст загрузочные разделы Kali, обычно `sdb1`/`sdb2`):

```bash
# ВНИМАНИЕ: of= это вся флешка целиком, не раздел. Проверь букву!
sudo dd if=kali-linux-2026.x-live-amd64.iso of=/dev/sdb bs=4M status=progress conv=fsync
```

- Windows/без CLI — тот же результат даёт **Rufus** (режим *DD Image*) или **balenaEtcher**. Но следующий шаг (метка `persistence`, ext4) всё равно требует Linux — его удобно сделать уже из загруженного Live-Kali.

## 2. Создать раздел под хранилище в свободном месте

ISO занимает лишь начало флешки; в оставшемся месте создаём **третий** раздел:

```bash
sudo fdisk /dev/sdb
# n  → новый раздел (primary), номер 3, весь оставшийся объём (Enter на границах)
# w  → записать таблицу и выйти
```

Появится `/dev/sdb3`. Если раздел не виден сразу — `sudo partprobe /dev/sdb`.

## 3. Отформатировать раздел с меткой `persistence` ⬅ ключевой шаг

```bash
sudo mkfs.ext4 -L persistence /dev/sdb3
```

**Метка `persistence` обязательна** — по ней `live-boot` находит хранилище. Именно этого шага нет в командах из видео. Если раздел уже создан без метки — поправить можно без переформатирования: `sudo e2label /dev/sdb3 persistence`.

## 4. Прописать конфиг persistence 🎬

```bash
sudo mkdir -p /mnt/my_usb                 # 🎬
sudo mount /dev/sdb3 /mnt/my_usb          # 🎬
sudo nano /mnt/my_usb/persistence.conf    # 🎬
```

В открывшийся файл вписать **одну строку** и сохранить (в nano: `Ctrl+O`, `Enter`, `Ctrl+X`):

```
/ union
```

🎬 `/ union` означает «сохранять изменения по всей файловой системе». Затем отмонтировать:

```bash
sudo umount /dev/sdb3                      # 🎬 (в видео: umount /dev/sdb3)
```

> [!note] Мелочь про umount
> Монтировали в `/mnt/my_usb`, отмонтировать можно и по точке (`sudo umount /mnt/my_usb`), и по устройству (`sudo umount /dev/sdb3`) — в видео используют второе. Оба варианта верны.

## 5. Загрузиться с нужным пунктом меню

Воткнуть флешку в целевую машину, зайти в Boot Menu (обычно `F12`/`F11`/`Esc`), выбрать загрузку с USB. В загрузчике Kali выбрать пункт:

- **«Live USB Persistence»** — обычное сохранение;
- **«Live USB Encrypted Persistence»** — если хранилище делалось зашифрованным (см. ниже).

Если выбрать обычный **«Live»** — сохранение работать не будет, даже когда раздел настроен правильно. Проверка: создать файл на рабочем столе, перезагрузиться в том же режиме — файл должен остаться.

## 🔐 Опция: зашифрованное хранилище (LUKS)

Persistence по умолчанию — **открытый ext4**: вынувший флешку прочитает все твои данные. Для пентестерской флешки это важно. Зашифрованный вариант вместо шага 3:

```bash
sudo cryptsetup --verbose --verify-passphrase luksFormat /dev/sdb3
sudo cryptsetup luksOpen /dev/sdb3 my_usb
sudo mkfs.ext4 -L persistence /dev/mapper/my_usb
sudo mount /dev/mapper/my_usb /mnt/my_usb
echo "/ union" | sudo tee /mnt/my_usb/persistence.conf
sudo umount /dev/mapper/my_usb
sudo cryptsetup luksClose /dev/mapper/my_usb
```

Загружаться потом пунктом **«Live USB Encrypted Persistence»** (спросит пароль LUKS).

## 🧯 Если не сохраняется — чек-лист

| Симптом | Причина / что проверить |
| :--- | :--- |
| после перезагрузки всё чисто | загрузился в режиме **«Live»**, а не **«…Persistence»** |
| пункт Persistence есть, но не пишет | у раздела **нет метки `persistence`** → `sudo e2label /dev/sdb3 persistence` |
| не пишет | в `persistence.conf` не та строка — должно быть ровно `/ union` |
| раздел не создаётся/не виден | не осталось свободного места после ISO, либо нужно `partprobe`/переткнуть флешку |
| затёрся не тот диск | перепутана буква устройства — всегда сверять по `fdisk -l` |

## 🖥️ С какой системы готовить флешку (хосты владельца)

Подготовка (`dd`, `fdisk`, `mkfs.ext4 -L`) — универсальные Linux-команды, работают с любого из дистрибутивов; отдельного пакета не требуют (`util-linux` + `e2fsprogs` есть везде).

| Система | Нюанс |
| :--- | :--- |
| **Gentoo** (основная) | всё из коробки; `cryptsetup` для LUKS — `emerge sys-fs/cryptsetup` |
| **Debian / Ubuntu** | из коробки; `sudo apt install cryptsetup` для шифрования |
| **Arch** | из коробки; `sudo pacman -S cryptsetup` |
| **Entware / RT-AX56U** | ➖ готовить загрузочную флешку для ПК с роутера смысла нет; `dd`-образ пишется с рабочего ПК |

> [!tip] Альтернатива для мультизагрузки
> Если хочется держать на одной флешке несколько ISO и при этом иметь persistence — смотри в сторону **Ventoy** (пункт «persistence» через отдельный `.dat`-образ). Для одной Kali описанный ручной способ проще и надёжнее.

Задача чисто установочная и легальна: это загрузка **своей** ОС с носителя. Юридические ограничения появляются только когда с этой Kali начинаешь работать по чужим системам — тогда нужна авторизация (ст. 272 УК РФ).
