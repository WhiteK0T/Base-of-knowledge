### Что такое rsync

**rsync** (remote sync) — утилита для **синхронизации и копирования файлов** локально и между машинами (обычно поверх SSH). Главная фишка — **дельта-передача**: при повторном запуске rsync шлёт не файлы целиком, а только изменившиеся куски, поэтому идеален для бэкапов и зеркал. Для передачи по сети rsync должен стоять **на обоих концах**.

### Основной синтаксис

```
rsync [опции] источник... назначение
```

**Форматы путей:**

- Локальный: `/path/to/dir`
- Удалённый по SSH: `user@host:/path` (push — отправить) или наоборот (pull — скачать)

```bash
rsync -a /local/dir/  user@host:/remote/dir/     # отправить (push)
rsync -a user@host:/remote/dir/  /local/dir/     # скачать (pull)
```

### ⚠️ Слэш в конце источника — главная ловушка

Косая черта **у источника** меняет смысл команды (у назначения — нет):

```bash
rsync -a src/  dst/      # копируются СОДЕРЖИМОЕ src  -> dst/f1, dst/sub/...
rsync -a src   dst/      # копируется САМА папка src   -> dst/src/f1, dst/src/sub/...
```

Правило: `src/` = «положи то, что внутри», `src` = «положи саму папку». Перед реальным запуском всегда прогоняйте с `-n` (см. ниже).

### Ключевые опции

| Опция | Что делает |
| :--- | :--- |
| `-a` | архивный режим = `-rlptgoD` (рекурсия, симлинки, права, время, владелец/группа, спецфайлы). **Основа для бэкапа** |
| `-v`, `-vv` | подробный вывод (повтор — больше деталей) |
| `-z` | сжатие при передаче (полезно по сети, не нужно локально) |
| `-h` | размеры в человекочитаемом виде |
| `-n`, `--dry-run` | **прогон вхолостую** — показать, что было бы сделано, ничего не меняя |
| `-P` | `--partial --progress`: прогресс по файлам + докачка прерванного |
| `--info=progress2` | общий прогресс по всей передаче (а не по каждому файлу) |
| `--delete` | удалить в назначении то, чего нет в источнике (**зеркало**) |
| `--exclude=ШАБЛОН` | не трогать подходящее (`--exclude-from=файл` — список из файла) |
| `-e 'ssh ...'` | задать транспорт: порт, ключ, jump-host |
| `--bwlimit=СКОР` | лимит скорости (напр. `--bwlimit=5m`) |
| `--link-dest=КАТ` | неизменные файлы брать жёсткой ссылкой из каталога — для инкрементальных снапшотов |
| `-AXH` | добавить к `-a` ACL, xattrs и жёсткие ссылки (их `-a` сам **не** переносит) |

### Примеры

#### Локально и бэкап

```bash
# Синхронизировать содержимое каталога
rsync -ah --info=progress2 /src/  /dst/

# Бэкап с зеркалированием (в dst станет ровно как в src)
rsync -a --delete /src/  /backup/src/

# Сначала безопасно посмотреть, что изменится
rsync -a --delete -n /src/  /backup/src/
```

#### По SSH (push / pull)

```bash
# Отправить папку на сервер со сжатием и прогрессом
rsync -azP /site/  user@server:/var/www/site/

# Скачать логи с сервера
rsync -azP user@server:/var/log/app/  ./logs/

# Нестандартный порт и ключ
rsync -azP -e 'ssh -p 2222 -i ~/.ssh/id_ed25519' /src/  user@server:/dst/

# Через jump-host
rsync -azP -e 'ssh -J jump@gw' /src/  user@internal:/dst/
```

#### Исключения

```bash
# Пропустить кэш/логи/вендор
rsync -a --delete \
  --exclude='node_modules/' --exclude='*.log' --exclude='.cache/' \
  /project/  user@server:/srv/project/
```

### Инкрементальные снапшоты (`--link-dest`)

Экономный «машина времени»: неизменённые файлы не копируются заново, а становятся жёсткими ссылками на вчерашний снапшот — на диске место занимает только то, что реально поменялось.

```bash
rsync -a --delete \
  --link-dest=/backup/2026-11-08 \
  /data/  /backup/2026-11-09/
```

### Коды возврата (частые)

| Код | Значение |
| :--- | :--- |
| `0` | успех |
| `1` | ошибка синтаксиса/опций |
| `3` | ошибка выбора файлов/каталогов |
| `11` | ошибка ввода-вывода (часто: нет места/прав в назначении) |
| `23` | частичная передача из-за ошибки (часть файлов не скопирована) |
| `24` | частичная передача: исходные файлы исчезли во время работы |
| `30` | таймаут приёма/передачи |

`23`/`24` особенно важны в скриптах: `rsync` вернул «успешно, но не всё» — проверяйте код выхода, а не только отсутствие явной ошибки.

### rsync vs scp vs cp

- **cp** — только локально, без дельты и докачки.
- **scp** — простая разовая передача по SSH; при обрыве начинает заново, дельты нет.
- **rsync** — дельта-передача, докачка (`-P`), зеркалирование (`--delete`), исключения, снапшоты. Для бэкапов и повторных синхронизаций — выбор по умолчанию.

### Установка по платформам

Обычно уже стоит; если нет:

| Система | Установка |
| :--- | :--- |
| **Gentoo** | `emerge --ask net-misc/rsync` |
| **Debian/Ubuntu** | `sudo apt install rsync` |
| **Arch** | `sudo pacman -S rsync` |
| **Entware** | `opkg install rsync` (3.5.1; есть `rsyncd` — демон, `rrsync` — ограниченный доступ по SSH) |

На роутере с Entware rsync удобен для бэкапа с USB-диска на сетевое хранилище или наоборот.

### Подводные камни и советы

- **Слэш у источника** решает всё (см. выше) — при сомнении `-n`.
- `--delete` **удаляет** лишнее в назначении: сначала всегда `--dry-run`.
- `-a` не переносит ACL, xattrs и жёсткие ссылки — для полного переноса добавьте `-AXH`.
- rsync нужен **на обоих концах** SSH-передачи, иначе `command not found`.
- `-z` имеет смысл только по сети; локально он лишь грузит CPU.
- Для возобновляемой заливки больших файлов — `-P` (докачает с места обрыва).
- Права/владельца удалённо сохранит только привилегированный приёмник (часто нужен root на той стороне).
