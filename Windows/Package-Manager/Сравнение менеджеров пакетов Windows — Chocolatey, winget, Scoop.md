# Менеджеры пакетов Windows: Chocolatey, winget, Scoop

Обзор и сравнение трёх основных менеджеров пакетов для Windows. Данные проверены **09.09.2026** по первоисточникам: официальный индекс winget (`source.msix` от Microsoft), исходники `chocolatey/choco` и `ScoopInstaller/Scoop`, GitHub API, документация Microsoft Learn.

Три менеджера **не конфликтуют** друг с другом: у каждого свой каталог, свой реестр установленного и своя папка. Нормальная практика — держать все три и брать каждый под свою задачу.

## Коротко: что выбирать

| Задача | Чем делать |
| :--- | :--- |
| Быстро поднять рабочую станцию, массовый софт | **winget** — встроен в систему, самый большой каталог |
| Dev-окружение, параллельные версии языков и утилит | **Scoop** — без прав администратора, всё в одной папке |
| Корпоративная среда, внутренний репозиторий, GPO | **Chocolatey** — единственный с полноценным enterprise-обвесом |
| Декларативное состояние машины «как в Ansible» | **winget configure** (DSC) |
| Нужен пакет, которого больше нигде нет | смотреть по каталогам, чаще всего выручает Chocolatey |

## Каталоги: сколько на самом деле пакетов

Цифры по каталогам гуляют по статьям годами, поэтому вот замеры по первоисточникам на 09.09.2026.

### winget — 14 756 пакетов

Microsoft публикует индекс источника как MSIX-архив с базой SQLite внутри. Это ровно тот файл, который скачивает клиент:

```bash
curl -sL "https://cdn.winget.microsoft.com/cache/source.msix" -o src.msix
unzip -o src.msix            # внутри Public/index.db
sqlite3 Public/index.db "SELECT COUNT(*) FROM ids;"
```

| Показатель | Значение |
| :--- | ---: |
| Уникальных идентификаторов пакетов | **14 756** |
| Записей «пакет + версия» | 170 037 |
| Различных строк версий | 63 898 |
| Пакетов `Microsoft.*` | 463 |

Самый большой каталог из трёх, и он же самый проверяемый: индекс пересобирается ежедневно и лежит открытым файлом.

### Scoop — 6 641 манифест в 10 бакетах

Scoop раскладывает пакеты по «бакетам» — отдельным git-репозиториям с манифестами. Список официальных лежит в [`buckets.json`](https://github.com/ScoopInstaller/Scoop/blob/master/buckets.json), их **десять**:

| Бакет | Репозиторий | Манифестов | Зачем |
| :--- | :--- | ---: | :--- |
| `extras` | ScoopInstaller/Extras | 2 383 | всё, что не проходит в `main` (GUI-программы) |
| `main` | ScoopInstaller/Main | 1 643 | консольные утилиты, подключён сразу |
| `versions` | ScoopInstaller/Versions | 604 | старые и preview-версии |
| `games` | **Calinou/scoop-games** | 419 | игры и игровые движки |
| `php` | ScoopInstaller/PHP | 391 | сборки PHP |
| `nerd-fonts` | matthewjberger/scoop-nerd-fonts | 367 | шрифты для терминала |
| `java` | ScoopInstaller/Java | 336 | JDK разных вендоров и версий |
| `nirsoft` | ScoopInstaller/Nirsoft | 291 | утилиты NirSoft |
| `nonportable` | ScoopInstaller/Nonportable | 132 | софт, который иначе не ставится |
| `sysinternals` | niheaven/scoop-sysinternals | 75 | Sysinternals Suite |
| **Итого** | | **6 641** | |

Два бакета из десяти (`games`, `nerd-fonts`, `sysinternals`) живут не в организации ScoopInstaller, а у сторонних мейнтейнеров — при этом считаются официальными.

По умолчанию подключён только `main`. Бакеты `java`, `php` и `nerd-fonts` добавляют вручную, и это как раз то, ради чего Scoop чаще всего и ставят.

### Chocolatey — точное число публично не отдаётся

Здесь честный ответ: **посчитать нельзя**, и это не лень, а ограничение самого API.

```bash
# $count возвращает 10000 на любой фильтр, включая заведомо пустые
curl -s "https://community.chocolatey.org/api/v2/Packages/\$count?\$filter=IsLatestVersion"
# 10000  — и ровно столько же для startswith(Id,'zz')

# постраничный обход упирается в тот же потолок
# $skip=10000 → HTTP 406 Not Acceptable
```

Дополнительно: фильтр `startswith(Id,'a')` на этом сервере возвращает пустой результат, хотя идентификаторы в нижнем регистре (`0ad`, `010editor`), — то есть разбить выборку на части и обойти потолок тоже не выходит. Сайт `community.chocolatey.org` общее число на странице не показывает.

Так что защищаемая формулировка — **не менее 10 000 пакетов**. Распространённое утверждение, что у Chocolatey самый большой каталог, при этом **сомнительно**: у winget подтверждённых 14 756.

## Модель пакета — главное архитектурное различие

Это важнее размера каталога, потому что определяет модель угроз.

**Chocolatey: пакет — это PowerShell-скрипт.** Внутри `.nupkg` лежит `chocolateyInstall.ps1`, который выполняется **с правами администратора**. Скрипт может делать что угодно. Модерация в публичном репозитории есть (VirusTotal + ручная проверка), но это произвольный код от произвольного участника.

**winget: пакет — это декларативный YAML.** Манифест содержит ссылку, SHA256 и тип инсталлятора. Из README `winget-pkgs`:

> At this time installers must be MSIX, MSI, APPX, MSIXBundle, APPXBundle, or .exe application installers. Font files … are also supported. **Script-based installers are not currently supported.**

Исполняемого кода в манифесте нет вообще — только описание. Это принципиально меньшая поверхность атаки.

**Scoop: JSON-манифест + отсутствие прав администратора.** Установщик прямо **отказывается** запускаться от админа (`Deny-Install 'Running the installer as administrator is disabled by default'`). Всё живёт в пользовательской папке, удаление — снос каталога.

> [!warning] Чего не делает ни один из трёх
> **Подписи репозитория нет нигде.** Проверяется только SHA256 из манифеста — то есть «файл тот, что ожидал автор манифеста», а не «файл от доверенного издателя». Это слабее, чем GPG-подпись репозитория в [APT](../../Linux/Package-Manager/APT.md).
>
> У winget есть флаг `--ignore-security-hash`, отключающий и эту проверку.

### Статусы модерации Chocolatey — контринтуитивно

- **approved** — модератор посмотрел пакет и не нашёл замечаний;
- **trusted** — пакет **пропускает** ручную модерацию, статус выдаётся мейнтейнеру, а не релизу;
- **exempted** — исключён из автоматической проверки, причина указана на странице пакета.

То есть `trusted` означает, что **живой человек этот конкретный релиз не смотрел**. Автоматика (VirusTotal, 50+ антивирусов) отрабатывает в любом случае. Совет «ставьте только approved или trusted» встречается часто и вводит в заблуждение: по строгости это разные вещи.

> [!caution] Публичный репозиторий сообщества — это supply-chain-поверхность
> Механика та же, что в [атаке на AUR](../../Security/Vulns/Linux/Atomic%20Arch%20%E2%80%94%20supply-chain%20%D0%B0%D1%82%D0%B0%D0%BA%D0%B0%20%D0%BD%D0%B0%20AUR%20%28infostealer%20%2B%20eBPF-%D1%80%D1%83%D1%82%D0%BA%D0%B8%D1%82%29.md): пакет с произвольным скриптом от произвольного участника. Для организаций единственная реально работающая защита — внутренний репозиторий (в Chocolatey это Package Internalizer в платной редакции).

## Требования и поддерживаемые системы

Взято из кода установочных скриптов и README, а не из пересказов.

| | winget | Chocolatey | Scoop |
| :--- | :--- | :--- | :--- |
| Windows | 10 build 17763 (1809)+, 11 | 7+ | 7 SP1+ |
| Windows Server | **2025 поддерживается** | да | да |
| PowerShell | — | **v3+** | **v5+** |
| .NET Framework | — | 4.8 | **4.5+** (нужен TLS 1.2) |
| Права админа | для машинных пакетов | требуются | **запрещены** |
| Прочее | не работает на **Server Core** | — | `Robocopy.exe` в `PATH`, политика выполнения не `Restricted` |

Про Windows Server стоит отдельно, потому что утверждение «winget не поддерживает Server» очень живучее. README `winget-cli`:

> The client requires Windows 10 1809 (build 17763), Windows 11, **Windows Server 2025**, or later at this time. **Windows Server 2019 and 2022 can run it experimentally (not supported)** by extracting the .msixbundle … it cannot be run on Windows Server Core.

То есть: Server 2025 — штатно, 2019/2022 — экспериментально через распаковку бандла, Server Core — нельзя.

## Что появилось в winget за последнее время

Список команд в winget вырос до 32, и часть из них закрывает сценарии, ради которых раньше брали Chocolatey:

| Команда | Что делает |
| :--- | :--- |
| `configure` | применить декларативное состояние машины (DSC) из YAML |
| `dsc` | ресурсы DSC v3 |
| `download` | скачать инсталлятор, не устанавливая |
| `pin` | закрепить версию пакета от обновления |

`winget configure` — прямой ответ на главный корпоративный аргумент в пользу Chocolatey: декларативное описание машины одним файлом.

## Совместное использование

Три менеджера можно и нужно комбинировать, но с одним правилом: **один пакет — один менеджер**. Если поставить VLC и через `choco`, и через `winget`, обновлять его будут оба, каждый по своему реестру, и рано или поздно они подерутся за версии.

Разумное разделение:

```powershell
winget install --id Mozilla.Firefox -e      # обычный десктопный софт
scoop install python nodejs go              # dev-инструменты, параллельные версии
choco install some-enterprise-thing -y      # то, чего нет в первых двух
```

Проверить, кто что поставил:

```powershell
winget list          # включая программы, поставленные не через winget
choco list           # только пакеты Chocolatey
scoop list           # только пакеты Scoop
```

Отдельно: `winget list` показывает **вообще все** установленные программы из «Установка и удаление программ», включая поставленные вручную и через другие менеджеры. Остальные два показывают только своё.

## Для сравнения — как это устроено в Linux

Аналогия «Chocolatey — это apt для Windows» верна лишь отчасти. Ключевое отличие всех трёх Windows-менеджеров: они **скачивают и запускают чужие инсталляторы**, а не распаковывают собственные архивы с зависимостями.

| | [APT](../../Linux/Package-Manager/APT.md) / [dpkg](../../Linux/Package-Manager/DPKG.md) | [OPKG](../../Linux/Package-Manager/OPKG.md) | Chocolatey | winget | Scoop |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Что в пакете | сам софт | сам софт | **скрипт**, качающий инсталлятор | **манифест** со ссылкой и хешем | манифест со ссылкой и хешем |
| Зависимости | полноценные | полноценные | есть | ограниченно | минимально |
| Подпись репозитория | **GPG** | подписи Entware | нет (хеш + VirusTotal) | нет (хеш) | нет (хеш) |
| Удаление начисто | да | да | зависит от инсталлятора | зависит от инсталлятора | да (папка) |
| Работа без root | нет | нет | нет | частично | **да** |

Сводная таблица команд по Linux-менеджерам — в заметке [Сравнение команд менеджеров пакетов](../../Linux/Package-Manager/%D0%A1%D1%80%D0%B0%D0%B2%D0%BD%D0%B5%D0%BD%D0%B8%D0%B5%20%D0%BA%D0%BE%D0%BC%D0%B0%D0%BD%D0%B4%20%D0%BC%D0%B5%D0%BD%D0%B5%D0%B4%D0%B6%D0%B5%D1%80%D0%BE%D0%B2%20%D0%BF%D0%B0%D0%BA%D0%B5%D1%82%D0%BE%D0%B2.md).

## Практический вывод

1. **winget как основной.** Встроен, каталог крупнейший (14 756 против ≥10 000 у Chocolatey), манифесты декларативные — без произвольного кода в пакете, есть `configure` для декларативного состояния машины. Развивается активнее всех.
2. **Scoop для dev-окружения.** Без админа, параллельные версии через `scoop reset`, `scoop cat` для инспекции манифеста до установки. Помнить про заморозку ядра и не забыть бакеты `java`, `php`, `nerd-fonts`.
3. **Chocolatey — когда нужен именно он:** пакета нет в первых двух, либо нужны внутренний репозиторий и групповые политики. Помнить, что пакет = PowerShell-скрипт с правами админа, а статус `trusted` означает отсутствие ручной проверки релиза.
