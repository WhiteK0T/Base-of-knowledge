# 🔑 Impersonate (SensePost) — олицетворение токенов Windows (эскалация до domain admin без LSASS)

**Impersonate** ([github.com/sensepost/impersonate](https://github.com/sensepost/impersonate)) — пентестерский PoC-инструментарий от **SensePost** для **манипуляции токенами доступа Windows**: перечислить доступные токены на скомпрометированном хосте, **олицетворить** (impersonate) залогиненного пользователя и выполнить действия от его имени — вплоть до **добавления себя в Domain Admins** — **не читая память LSASS**. GPL-3.0. ⚠️ **PoC к блог-посту 2022 года**, ~326★, последний коммит — **апрель 2023** (не поддерживается).

> [!warning] Правки к посту: это не «уязвимости», не «Python», и это ПОСТ-эксплуатация
> - **Это не эксплуатация уязвимостей.** Пост пишет «использует уязвимости в механизмах токенов». На деле это **злоупотребление штатной by-design функциональностью** Windows — олицетворением токенов (`SeImpersonatePrivilege`, `DuplicateTokenEx`, `ImpersonateLoggedOnUser`). Нет CVE/бага — есть легитимный механизм, которым злоупотребляют. Так же работают классические Potato-атаки и `incognito`/Meterpreter.
> - **Нужны уже повышенные права.** Чтобы перечислять и красть токены **других** пользователей, обычно требуется **локальный админ / `SeImpersonatePrivilege` / `SeDebugPrivilege`** на хосте. Это инструмент **бокового перемещения и эскалации** (из админа хоста → к токену domain admin, который там залогинен), а **не** «получить админа из ничего». Формулировку поста «получаем админский доступ» читай как «из уже привилегированного контекста».
> - **Не «Python-тулза».** GitHub метит язык как Python из-за обёртки CrackMapExec (`impersonate.py`), но сам **Impersonate.exe — это C/C++ бинарник** (компилируется в Visual Studio, `/MTd`).

> [!info] Что внутри репозитория (по README) — четыре компонента
> 1. **Impersonate (standalone binary)** — работа с токенами удалённо (**PsExec/WmiExec**) или интерактивно.
> 2. **CrackMapExec-модуль** (`impersonate.py`) со встроенным бинарём — доставка и запуск с оператора (в т.ч. с Linux через CME).
> 3. **Встроенный CME-бинарь** (`CME_module/`) — тот же Impersonate без `printf`.
> 4. **`list_tokens.c`** — C++ PoC-код из блог-поста (для понимания механизма).

> [!info] Три модуля Impersonate.exe (пост оборвался на «Три модуля:»)
> - **`Impersonate list`** — перечислить доступные токены на машине.
> - **`Impersonate exec`** — выполнить команду, **олицетворяя** выбранного пользователя.
> - **`Impersonate adduser`** — **поднять привилегии до domain admin** (добавить пользователя, действуя токеном админа).

## 🧬 Как это работает (суть)

Когда привилегированный пользователь (напр. **domain admin**) логинится/оставляет сессию/службу на машине, его **токен доступа** живёт в памяти процессов. Имея достаточные права на этом хосте, инструмент **находит** такой токен, **дублирует** его и **олицетворяет** — и дальше действует **от имени** этого пользователя (запуск команд, добавление в группы AD). Секреты при этом **не вытаскиваются из LSASS** — используется сам токен.

## 🧪 Факты против хайпа

> [!caution] «Обходит LSASS и многие EDR» — только отчасти
> - **LSASS не трогается** — да, поэтому детекты на **чтение памяти LSASS** (как у Mimikatz) не срабатывают. Это реальный плюс метода.
> - **Но токен-операции EDR тоже мониторят**: `DuplicateToken*`, `ImpersonateLoggedOnUser`, аномальные вызовы из инжектированных процессов, создание процессов с чужим токеном — всё это ловится современными EDR. «Обходит **многие**» ≠ «невидим».
> - **Инструменту ~3 года** (2022–2023, не обновляется): **готовый бинарь давно в сигнатурах** AV/EDR. «Из коробки» его часто ловят по хешу/сигнатуре — на реальном тесте нужна перекомпиляция/обфускация, а не «скачал и запустил».

> [!note] Требования и ограничения
> - Работает по **Windows/Active Directory**; нужен уже **привилегированный доступ** к целевому хосту и наличие на нём **полезного токена** (залогиненный админ). Нет админского токена в памяти — нечего олицетворять.
> - Это **техника, а не магия**: тот же класс, что `incognito`, `Rubeus`/Potato-семейство. Понимать механизм (см. блог SensePost) важнее, чем запускать бинарь.

## ⚖️ Право (РФ)

Наступательный инструмент компрометации учётных записей и AD. Применение к **чужой** инфраструктуре без письменного разрешения — **ст. 272 УК РФ** (неправомерный доступ) и **ст. 273 УК РФ** (использование ВПО: манипуляция токенами для эскалации). Легально — **только** свои лабораторные стенды (тестовый домен) и **авторизованный пентест по договору** с явным scope.

## 🖥️ Применимость на системах владельца

| Роль | Как ложится |
| :--- | :--- |
| **Цель** | **только Windows / Active Directory** — к Linux/Gentoo/роутеру неприменимо |
| **Оператор** | атаку можно вести и **с Linux** через CrackMapExec-модуль (доставка бинаря на Windows-цель по PsExec/WmiExec) |
| **Сборка** | бинарь собирается в **Visual Studio** (Runtime `/MtD`) на Windows; готовый из репо — засвечен в AV |

> [!tip] Легально тренироваться
> Только в **своей** лаборатории: подними тестовый AD-домен (несколько Windows-VM), где ты сам админ. Для защиты/детекта полезно смотреть токены процессов в [System Informer](../Windows/System%20Informer%20%E2%80%94%20%D0%BC%D0%BE%D0%BD%D0%B8%D1%82%D0%BE%D1%80%D0%B8%D0%BD%D0%B3%20%D0%BF%D1%80%D0%BE%D1%86%D0%B5%D1%81%D1%81%D0%BE%D0%B2%20%D0%B8%20%D0%BE%D1%85%D0%BE%D1%82%D0%B0%20%D0%BD%D0%B0%20%D0%BC%D0%B0%D0%BB%D0%B2%D0%B0%D1%80%D1%8C%20%28%D0%BF%D1%80%D0%B5%D0%B5%D0%BC%D0%BD%D0%B8%D0%BA%20Process%20Hacker%29.md) (вкладка Token у процесса) — так видно, что именно олицетворяется.
