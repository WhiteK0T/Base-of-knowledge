## 1. 🖥️ Januscape — побег из гостевой VM на хост через KVM

**CVE-2026-53359**, use-after-free в shadow MMU гипервизора **KVM/x86**. Дремал в ядре Linux **около 16 лет** (с 2010 года). Первый публичный guest→host эксплойт KVM, воспроизводимый **и на Intel (VMX), и на AMD (SVM)**; применён как 0-day в Google kvmCTF. **Исправлено** — нужно обновление ядра хоста.

📄 Подробный разбор: **[Januscape (CVE-2026-53359)](Linux/CVE/CVE-2026-53359%20%E2%80%94%20Januscape%20%28KVM%20shadow-MMU%20UAF%2C%20%D0%BF%D0%BE%D0%B1%D0%B5%D0%B3%20%D0%B8%D0%B7%20%D0%B3%D0%BE%D1%81%D1%82%D0%B5%D0%B2%D0%BE%D0%B9%20VM%20%D0%BD%D0%B0%20%D1%85%D0%BE%D1%81%D1%82%2C%20Intel%20%D0%B8%20AMD%29.md)**

> [!tip] Актуальность для владельца
> Прямо касается любой машины, где поднят KVM/QEMU (Gentoo, Debian/Ubuntu, Arch). Если виртуалки крутятся — обновление ядра обязательно; на роутере нерелевантно.

## 2. 📦 AsyncAPI — вредонос опубликовал собственный CI/CD проекта

**14 июля** атакующий получил право пуша в два репозитория AsyncAPI, закоммитил дроппер — и **штатные GitHub Actions сами собрали, подписали и выложили** пять заражённых версий npm-пакетов с валидными OIDC-аттестациями provenance. Украденных токенов в истории нет.

Ключевое: **provenance подтверждает происхождение, а не содержимое**. Аттестация честно говорит «собрано воркфлоу проекта из его ветки» — и это правда; она ничего не говорит о легитимности коммита.

Вредонос — RAT **Miasma v3**, срабатывает **не при `npm install`, а при `require()`** поражённого модуля, так что `--ignore-scripts` не помогает. Окно доступности — **от 2 ч 48 мин до 4 ч 03 мин**; все пять версий сняты с npm (проверил 10.09.2026 — их там действительно нет).

📄 Подробный разбор: **[AsyncAPI — supply-chain атака через собственный CI/CD](Apps/AsyncAPI%20%E2%80%94%20supply-chain%20%D0%B0%D1%82%D0%B0%D0%BA%D0%B0%20%D1%87%D0%B5%D1%80%D0%B5%D0%B7%20%D1%81%D0%BE%D0%B1%D1%81%D1%82%D0%B2%D0%B5%D0%BD%D0%BD%D1%8B%D0%B9%20CI-CD%20%285%20%D0%BF%D0%B0%D0%BA%D0%B5%D1%82%D0%BE%D0%B2%20npm%20%D1%81%20%D0%B2%D0%B0%D0%BB%D0%B8%D0%B4%D0%BD%D1%8B%D0%BC%20provenance%2C%20Miasma%20v3%2C%20%D1%81%D1%80%D0%B0%D0%B1%D0%B0%D1%82%D1%8B%D0%B2%D0%B0%D0%B5%D1%82%20%D0%BF%D1%80%D0%B8%20require%29.md)**

> [!caution] Уточнение к посту
> Пост описывает возможности вредоноса в общем. По разбору JFrog — **в этой кампании кража учёток, распространение и отравление ИИ-инструментов были выключены** в конфигурации; активны были персистентность, C2 и произвольное выполнение команд. Это не делает историю менее опасной, но точность тут важна.

## 3. 🌑 Nightmare Eclipse — RoguePlanet, GreatXML, LegacyHive

Продолжение конфликта исследователя с MSRC. За июнь–июль: отмена обещанного массового раскрытия с извинениями, **RoguePlanet** (TOCTOU-гонка в Microsoft Defender → SYSTEM на полностью пропатченных Windows 10/11), **GreatXML** (обход BitLocker через Defender Offline Scan + WinRE) и **LegacyHive** (LPE в Windows User Profile Service, PoC намеренно урезан).

📄 Подробный разбор: **[Nightmare Eclipse против Microsoft](Windows/Nightmare%20Eclipse%20%D0%BF%D1%80%D0%BE%D1%82%D0%B8%D0%B2%20Microsoft%20%E2%80%94%20RoguePlanet%2C%20GreatXML%2C%20LegacyHive%20%28%D0%B8%D1%8E%D0%BD%D1%8C-%D0%B8%D1%8E%D0%BB%D1%8C%202026%3B%20%D1%87%D1%82%D0%BE%20%D0%B7%D0%B0%D0%BA%D1%80%D1%8B%D1%82%D0%BE%20%D0%BA%20%D1%81%D0%B5%D0%BD%D1%82%D1%8F%D0%B1%D1%80%D1%8E%29.md)**

> [!note] Чего в июльском дайджесте быть не могло
> Пост верно писал, что на момент публикации LegacyHive исправления не было. Прошёл по бюллетеням MSRC за июль–сентябрь: **в июле закрыт CVE-2026-50661 (обход BitLocker), в августе — CVE-2026-62832 (LPE в User Profile Service) и CVE-2026-69414 (LPE в Defender)**, все с благодарностью «Anonymous». Совпадение по компоненту и классу полное, хотя Microsoft эксплойты по именам не называет.

> [!warning] Это не безобидные исследования
> Huntress фиксировала более ранний инструментарий NE (BlueHammer, RedSun, UnDefend) **в реальной цепочке атаки**, а BlueHammer (CVE-2026-33825, CVSS 7.8) числится активно эксплуатируемым.

## 4. 🐚 wp2shell — pre-auth RCE в ядре WordPress

Цепочка из **двух уязвимостей в самом ядре** WordPress (не в плагине), дающая **неаутентифицированное RCE** на голой установке: **CVE-2026-63030** (рассинхрон маршрутизации в batch-REST + SQLi) и **CVE-2026-60137** (SQL-инъекция в `author__not_in` у `WP_Query`).

📄 Подробный разбор: **[wp2shell](Apps/wp2shell%20%E2%80%94%20pre-auth%20RCE%20%D0%B2%20%D1%8F%D0%B4%D1%80%D0%B5%20WordPress%20%28batch%20REST%20route-confusion%20%2B%20SQLi%2C%20CVE-2026-63030%20%D0%B8%2060137%29.md)**

> [!tip] Актуальность для владельца
> Касается только если где-то поднят WordPress. Если да — обновление критично: pre-auth RCE без плагинов означает, что «у меня ничего лишнего не установлено» защитой не является.

## 5. 📓 GitLab Diff RCE — две ошибки памяти в Ruby-геме Oj

Исследователи depthfirst аудировали не GitLab, а его зависимость — JSON-парсер **Oj** с большой сишной частью. Из 18 находок (7 — memory safety) сложили **запись за границей буфера** + **раскрытие указателя кучи** в **RCE от пользователя `git`**. Триггер — открытие страницы diff коммита с `.ipynb`-ноутбуком в собственном проекте: ни админских прав, ни CI, ни чужого проекта не требуется.

Исправлено 10.06.2026 в GitLab **19.0.2 / 18.11.5 / 18.10.8** (поднят Oj до **3.17.3**).

📄 Подробный разбор: **[GitLab — RCE через diff Jupyter-ноутбука](Apps/GitLab%20%E2%80%94%20RCE%20%D1%87%D0%B5%D1%80%D0%B5%D0%B7%20diff%20Jupyter-%D0%BD%D0%BE%D1%83%D1%82%D0%B1%D1%83%D0%BA%D0%B0%20%28%D0%B4%D0%B2%D0%B5%20%D0%BE%D1%88%D0%B8%D0%B1%D0%BA%D0%B8%20%D0%BF%D0%B0%D0%BC%D1%8F%D1%82%D0%B8%20%D0%B2%20%D0%B3%D0%B5%D0%BC-%D0%B5%20Oj%3B%201753%20%D0%B4%D0%BD%D1%8F%20%D0%B2%20%D0%BA%D0%BE%D0%B4%D0%B5%2C%20%D0%B0%20%D0%BD%D0%B5%20%C2%AB%D1%88%D0%B5%D1%81%D1%82%D1%8C%20%D0%BB%D0%B5%D1%82%C2%BB%29.md)**

> [!caution] Поправка к посту
> Пост пишет «более шести лет». По первоисточнику — **1753 дня**, то есть 4 года 10 месяцев (08.08.2021 → 27.05.2026). Проверил по rubygems: Oj 3.13.0 вышел 09.08.2021, исправленный 3.17.3 — 04.06.2026.
