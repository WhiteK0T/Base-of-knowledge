# 🔍 GoReSym (Mandiant) — восстановление символов Go-бинарников для реверса

[**GoReSym**](https://github.com/mandiant/GoReSym) (Mandiant / Google) — кроссплатформенная CLI на **Go**, которая вытаскивает из скомпилированного Go-бинарника метаданные, зашитые самим компилятором для рантайма и рефлексии: **функции, файлы, номера строк, типы, строки, инфу о сборке и модулях**. Основной приём — прямой парсинг рантайм-структур **`pclntab`** (таблица функций/строк) и **`moduledata`**, минуя стандартную секцию символов, которую часто вырезают. Лицензия **MIT**, ~**1.1k★**.

> [!note] Зачем это нужно (проблема Go-бинарей для реверсера)
> Go статически линкует рантайм и тащит в бинарь **сотни функций стандартной библиотеки**. В стриппнутом бинаре обычные символы вырезаны — в дизассемблере видишь `sub_401230` вместо `main.encryptFile`. Но Go **дублирует** имена функций/файлов/строк в `pclntab` (нужна рантайму для стектрейсов и GC). GoReSym читает именно её → возвращает имена там, где `strip` их «убрал». Для аналитика малвари это разница между «голый граф» и «читаемый код с именами пакетов».

## 🧰 Что извлекает

| Категория | Что именно |
| :--- | :--- |
| **Метаданные бинаря** | версия компилятора Go, архитектура (x86/x64/ARM64), ОС, порядок байт (endianness) |
| **Функции** | адреса начала/конца, имена, исходный файл и номер строки |
| **Типы** | имена структур/интерфейсов из `moduledata` (флаг `-t`), дамп RTYPE по адресу (`-m <addr>`) |
| **Строки** | встроенные Go-строки из таблицы интернирования (`-strings`) |
| **Сборка** | `buildid`, флаги сборки, информация о модулях (go.mod) |

Вывод по умолчанию — **JSON** (машиночитаемый, под скрипты дизассемблеров); `-human` даёт человекочитаемый текст.

**Основные флаги:** `-t` (типы) · `-p` (встроенные пути к файлам) · `-d` (включать пакеты стандартной библиотеки, а не только `main`/сторонние) · `-strings` (строки) · `-m <addr>` (дамп RTYPE-структуры) · `-v <version>` (переопределить автодетект версии) · `-human` (текст вместо JSON).

## 🔌 Интеграция с дизассемблерами

JSON от GoReSym скармливается скрипту/плагину, который расставляет имена/метки в базе:

- **IDA Pro** — [`IDAPython/goresym_rename.py`](https://github.com/mandiant/GoReSym/tree/master/IDAPython) (читает JSON, ставит символы и лейблы).
- **Ghidra** — версия того же скрипта в каталоге `GhidraPython/`.
- **Binary Ninja** — в репозитории подмодуль `BinjaPython`; есть и отдельный community-плагин **binja-GoReSym**.

## 🧪 Факты против упрощений поста (сверено с README)

> [!warning] «Поддерживает все версии Go» — с оговорками
> - Парсинг **`pclntab`** — c **Go 1.2** и новее (частично тянет и legacy-раскладку pre-1.2).
> - Парсинг **`moduledata`** (типы, инфа о модулях) — только с **Go 1.5**.
> - Раскладки менялись (1.2 → 1.16 → 1.18/1.19/1.20 → 1.24); авторы дописывают поддержку под каждую новую версию. То есть «все» ≈ «широкий диапазон, регулярно догоняющий свежий Go», а не буквально любой релиз с одинаковой полнотой.

> [!caution] UPX/упакованные — «работает», но не напрямую
> GoReSym **не распаковывает** UPX сам. Он умеет переваривать **битый, уже распакованный** бинарь (UPX часто оставляет некорректные заголовки/секции) и данные, «разъехавшиеся» по секциям. Порядок такой: сначала `upx -d` (или ручная распаковка), потом GoReSym по результату. На всё ещё запакованном образе валидной `pclntab` он не найдёт.

> [!danger] Garble ≠ дешифровка — это главное ограничение
> GoReSym возвращает **то, что реально лежит в `pclntab`**. Обфускатор **[garble](https://github.com/burrowers/garble)** переименовывает символы в **хеши** и может вычищать build-info (тогда версия детектится как `unknown`). GoReSym в таком случае:
> - вернёт **хешированные** имена функций, а не оригинальные `main.encryptFile` — восстановления смысла **нет**;
> - если `pclntab`/`moduledata` намеренно **уничтожены** — упадёт с `no valid pclntab found`.
>
> Свежие правки улучшили разбор garble-бинарей (Go 1.24/1.26 парсятся без ручного `-v`), но это про «не падать и достать адреса», а **не** про деобфускацию имён. Для настоящего снятия garble нужен отдельный инструмент вроде **[GoResolver](https://www.volexity.com/blog/2025/04/01/goresolver-using-control-flow-graph-similarity-to-deobfuscate-golang-binaries-automatically/)** (Volexity, сравнение CFG). GoReSym — **статический парсер символов, а не деобфускатор и не декомпилятор.**

## 🚀 Установка

Это Go-тулза — ставится/собирается одинаково на всех десктоп-системах, нужен лишь установленный Go (либо готовый бинарь из релизов GitHub).

```bash
# Вариант 1: go install (нужен Go в PATH)
go install github.com/mandiant/GoReSym@latest   # бинарь в $(go env GOPATH)/bin

# Вариант 2: сборка из исходников
git clone https://github.com/mandiant/GoReSym
cd GoReSym && go build          # получится ./GoReSym

# Использование
GoReSym -t -d -p ./malware.bin > out.json       # полный дамп в JSON
GoReSym -human ./malware.bin                     # быстрый обзор в текст
```

| Система | Установка Go | Примечание |
| :--- | :--- | :--- |
| **Gentoo** (основная) | `emerge dev-lang/go`, затем `go install …` | либо готовый бинарь из Releases |
| **Debian / Ubuntu** | `apt install golang-go` (или свежий Go с go.dev) → `go install` | |
| **Arch** (план с июня 2026) | `pacman -S go` → `go install` | |
| **Entware / RT-AX56U** | практически **N/A** | Go для armv7 существует, GoReSym кросс-компилируется (`GOOS=linux GOARCH=arm go build`), но реверс-воркфлоу с IDA/Ghidra — десктопный; на роутере с 256 МБ flash смысла нет. При нужде — собери на десктопе и скопируй бинарь |

> [!tip] Только авторизованный анализ (право)
> Реверс и работа с малварью легальны **для исследования/защиты на своих или авторизованных сэмплах**. В РФ — ст. 273 УК (не публикуй рабочие сэмплы; анализ ≠ распространение), реверс чужого проприетарного ПО может нарушать лицензию/ст. 1280 ГК. Сэмплы держи в **изолированной ВМ/контейнере без сети**, не на рабочей машине. GoReSym только **читает** файл (не исполняет его) — это безопаснее динамики, но сам образец всё равно опасен при случайном запуске.

## 💡 Кому полезно

- **RE / malware-аналитикам, DFIR, threat-intel:** быстро вернуть имена в стриппнутом Go-стилере/бэкдоре и загрузить их в IDA/Ghidra одним скриптом.
- **CTF / обучение реверсу Go:** увидеть структуру пакетов и строки без ручного парсинга `pclntab`.
- **Не** заменяет декомпилятор и не снимает обфускацию — это шаг **обогащения символами** перед основным анализом.
