# 🔬 leanrea — скилл реверс-инжиниринга на 8 КБ вместо MCP-сервера REA

**leanrea** ([aicodeking/leanrea](https://github.com/aicodeking/leanrea), MIT, опубликован 17.10.2026, ~1,2 тыс. звёзд) — это **один файл `SKILL.md` на 8 КБ**. Он учит ИИ-агента (Claude Code, Codex, Cursor, Gemini CLI, OpenCode и др.) разбирать готовые программы **обычными консольными утилитами**: `file`, `strings`, `nm`, `otool`, `rg`, `asar`, `go version -m`, `jadx`, `tshark`, `binwalk` и другими.

Это облегчённая альтернатива **[REA — Reverse Engineer Anything](https://github.com/morluto/rea)**: npm-пакет `rea-agents` на ~25 МБ с MCP-сервером на **207 инструментов**. leanrea убирает эту MCP-прослойку и просто подсказывает агенту, **какая команда быстрее всего для каждого типа файла** и где ловушки. Автор прямо благодарит команду REA: большую часть подводных камней он взял из её кода и документации.

> [!note] Что проверено (репозиторий и сырые результаты бенчмарка)
> - **Время.** В бенчмарке автора задачи заняли **12–45 с** (медиана). Но это **точечные вопросы** — через какие IPC-каналы идёт функция, какие версии зависимостей у Go-бинарника, какой формат у сокета по дизассемблеру. Полный разбор приложения не измерялся.
> - **Токены.** Экономия есть **по сравнению с REA**: на 60 % меньше токенов и на 35 % дешевле. **По сравнению с голой моделью цена та же** — $2,17 против $2,21 за 12 прогонов. Выигрыш здесь в скорости (−19 %) и числе ходов (−32 %). Одна задача — около 90–280 тыс. токенов на Sonnet 5.5 (≈ $0,11–0,24), в основном это чтение из кэша.
> - **Назначение.** Скилл про **анализ**: как устроена функция, какие версии и зависимости, чем отличаются сборки. Про «пересборку» в нём одна строка: написать минимальную реализацию и сверить её с оригиналом на тех же входах. Повторить целиком большой продукт вроде офисного пакета или графического редактора — задача совсем другого масштаба.
> - **Инструменты.** Правило скилла — ставить пакеты **только с разрешения пользователя** (`brew install …` «if the user allows it»). Если утилиты нет, агент берёт запасной вариант из той же строки таблицы.
> - **Платформа.** Скилл и бенчмарк **рассчитаны на macOS**: `otool`, `lipo`, `codesign`, `cp -c` на APFS, `brew`. На Linux часть строк работает как есть (ELF, Go, Rust, APK, WASM, SQLite, pcap). Для команд под Mach-O нужны аналоги — они в таблице ниже.

## Бенчмарк автора

Условия: Claude Code в неинтерактивном режиме (`claude -p`), **Sonnet 5.5**, macOS arm64. 4 задачи × 3 повтора × 3 варианта = 36 прогонов. Ответы проверялись регулярными выражениями по ключам, составленным вручную. Сырые данные в `bench/results/final.jsonl` сходятся с итоговой таблицей.

| Вариант | Время (сумма) | Цена | Ходы | Токены | Баллы |
| :--- | ---: | ---: | ---: | ---: | :--- |
| **leanrea** | **388 с** | **$2,17** | **55** | **2,40 M** | 74/75 |
| без скилла | 479 с | $2,21 | 81 | 3,11 M | 67/75 (один отказ) |
| REA (MCP + её скилл) | 627 с | $3,36 | 124 | 5,93 M | 75/75 |

**Четыре задачи:**
1. **Electron-приложение (Notion):** проследить функцию от нативного кода до IPC-каналов.
2. **Его нативный аддон `.node`:** экспорты, проверка разрешений TCC и защита от запуска второго экземпляра.
3. **Стриппнутый `gh` на Go:** версии компилятора и зависимостей.
4. **«Глубокая» задача:** формат сокета, протокол и аутентификация собеседника **только по дизассемблеру**.

**Расход контекста на пустой запрос** («ответь OK»):

| Вариант | Добавка к контексту |
| :--- | :--- |
| leanrea | +3,1 тыс. токенов |
| REA с отложенной загрузкой инструментов (по умолчанию в Claude Code) | +3,5 тыс. |
| REA, если агент грузит все инструменты сразу | **+369 тыс. токенов и $1,60** — 207 инструментов это 3,35 МБ JSON-схем |

**Одна операция напрямую и через REA:**

| Операция | Напрямую | Через REA |
| :--- | :--- | :--- |
| `go version -m` | 0,06 с | 0,56 с |
| Обзор Mach-O | 0,04 с | 3,32 с |
| Анализ Electron-приложения | 4,8 с, 24 КБ | **47,9 с, 140 МБ JSON** (и сначала падает на проверке целостности asar) |

**Оговорки самого автора:**
- по 3 повтора, одна модель, одна машина;
- Ghidra, Hopper и jadx не были установлены, поэтому нативные задачи у обоих вариантов шли на инструментах Xcode;
- **голая модель и так неплохо справляется** — выигрыш leanrea над ней меньше, чем над REA.

## Что внутри скилла

**Правила:**
- **Работать на копии.** Каждую распаковку класть в свою папку `$TMPDIR/re/<имя>` и переиспользовать готовую.
- **Порядок разбора:** сначала тип файла по `file -b` и магическим байтам, затем самая дешёвая инвентаризация, и только потом декомпиляция.
- **Искать в распакованном через `rg -uu`.** Бандлеры прячут код в скрытых папках (`.webpack/`, `.vite/`), а обычный `rg` их пропускает.
- **Никогда не выводить `cat` целиком большой или минифицированный файл.** Брать срез вокруг нужного места: `rg -o '.{0,200}NEEDLE.{0,200}' F | head`. Дизассемблированный листинг сохранить в файл один раз и искать уже по нему.
- **Объединять независимые проверки в один вызов шелла** через `;` с маркерами `echo '--- name'`. Каждый вывод ограничивать через `head`.
- **Отвечать по уликам.** Каждое утверждение помечать как **seen** (файл:смещение, символ или строка) или **inferred**. Ненайденное — **unknown**, а не «отсутствует». Статическое чтение кода — не то же самое, что наблюдение за его выполнением.
- **«Ходы дороже байтов».** Цель — 2–4 вызова инструментов: одна общая разведка, один-два точечных среза, ответ.

**Таблица «тип файла → самая быстрая команда»** покрывает:
- **JavaScript и Electron:** приложения Electron/asar (IPC, preload, `contextBridge`, fuses), минифицированные бандлы и source maps, Hermes и bytenode.
- **Нативный код:** Mach-O, дизассемблер, ELF и PE.
- **Языки и платформы:** Go (buildinfo), Rust (`cargo audit bin`), .NET (`ilspycmd`), Android APK (`jadx`, `apktool`, приложения на Flutter и React Native), хэш снапшота Flutter, WASM (WABT).
- **Данные и трафик:** SQLite (только чтение, вместе с `-wal`), plist, pcap и HAR (`tshark`, `jq`), прошивки (`binwalk`, `unblob`).
- **Сайты и живые процессы:** сайты, отладка запущенного процесса (`lldb`, `frida`).

**Приёмы для скорости:**
- начинать со строк и импортов: `nm -u` показывает, что программа умеет;
- функцию, которая использует нужную строку, искать по комментариям `literal pool` в выводе `otool -tV`;
- читать последовательность вызовов, а не каждую инструкцию;
- при сравнении версий **сначала сравнивать инвентарь** (`nm`, список модулей, `go version -m`), а уже потом код.

## Установка

```sh
npx skills add aicodeking/leanrea                    # спросит, для каких агентов ставить
npx skills add aicodeking/leanrea -a claude-code -y  # только Claude Code
npx skills add aicodeking/leanrea -g -a '*' -y       # для всех агентов, на уровне пользователя

# вручную
git clone https://github.com/aicodeking/leanrea
mkdir -p ~/.claude/skills && cp -R leanrea/leanrea ~/.claude/skills/
```

**Цена в контексте** (o200k_base): в фоне висит только описание — **~76 токенов**; при вызове загружается весь `SKILL.md` — **~2,7 тыс. токенов**.

Вызов: `/leanrea Как работает поиск в Foo.app? Покажи улики.` Если агент не поддерживает скиллы, текст `SKILL.md` можно вставить в его правила или системный промпт.

## 🐧 На Linux: аналоги macOS-команд и пакеты

| В скилле (macOS) | На Linux |
| :--- | :--- |
| `otool -L` (библиотеки) | `readelf -dW T \| grep NEEDED`; `ldd T` — только для доверенных файлов, см. ниже |
| `nm -gU` / `nm -u` | `nm -D --defined-only T` / `nm -D --undefined-only T` |
| `otool -tV` (дизассемблер) | `objdump -d --no-show-raw-insn -C T` (или `-M intel`) |
| `xcrun dyld_info -exports -imports` | `readelf -sW --dyn-syms T` |
| `lipo`, `codesign`, `plutil` | для ELF не нужны |
| `cp -c` | `cp --reflink=auto` (мгновенно на Btrfs и XFS) |
| `lldb -p PID`, `dtrace`, `fs_usage` | `gdb -p PID`, `strace -f -p PID`, `ltrace`, `perf trace` |

| Утилиты | Gentoo (Portage) | Debian / Ubuntu | Arch | Entware (RT-AX56U) |
| :--- | :--- | :--- | :--- | :--- |
| `file`, binutils (`strings`, `nm`, `objdump`, `readelf`), `rg`, `jq` | `sys-apps/file`, `sys-devel/binutils`, `sys-apps/ripgrep`, `app-misc/jq` | `file binutils ripgrep jq` | `file binutils ripgrep jq` | `file`, `binutils`/`objdump`, `ripgrep`, `jq` — есть |
| radare2 / rizin | `dev-util/radare2`, `dev-util/rizin` | в Debian 13 нет (только sid) — релиз с GitHub | `radare2` | `radare2` — есть |
| binwalk | `app-misc/binwalk` | `binwalk` | `binwalk` | — |
| WABT (`wasm-objdump`, `wasm2wat`) | в дереве нет — релиз с GitHub | `wabt` | `wabt` | — |
| `tshark` | `net-analyzer/wireshark` (с USE `-gui` — только консольная часть) | `tshark` | `wireshark-cli` | — |
| jadx / apktool | в дереве нет — релизы с GitHub (нужна JDK) | `apktool`; jadx — релиз с GitHub | `jadx`; apktool — релиз с GitHub | — |
| Ghidra | в дереве нет — архив с GitHub (JDK 21) | архив с GitHub | `ghidra` | — |
| `@electron/asar`, `@electron/fuses` | через `npx -y` (нужен `net-libs/nodejs`) | через `npx -y` | через `npx -y` | — |

На роутере с Entware можно разве что быстро посмотреть прошивки и бинарники самого роутера через `file`, `strings`, `objdump` и `radare2`. Тяжёлые инструменты (JDK, Ghidra, jadx) туда не встанут.

## Право и безопасность

- **Реверс чужих программ ограничен лицензией и законом.**
  - Декомпиляция ради совместимости в узких рамках разрешена, например, ст. 1280 ГК РФ и ст. 6 Директивы ЕС 2009/24/EC.
  - Копировать код, интерфейс, название и ресурсы коммерческого продукта ради «клона» — нарушение авторских прав и товарных знаков.
  - Без риска можно разбирать своё ПО, open source, собственные сборки и то, что разрешено лицензией или программой bug bounty.
- **Недоверенные файлы разбирайте в изоляции.** Скилл и сам требует работать на копии. Для подозрительных файлов используйте ВМ или контейнер без сети. Ничего не запускайте и не применяйте `ldd`: он может выполнить код из файла. Агента держите в режиме, где каждую команду вы подтверждаете.
