# 🛡️ SkillSpector (NVIDIA) — сканер скиллов ИИ-агентов до установки

[**SkillSpector**](https://github.com/NVIDIA/skillspector) — открытый сканер безопасности от NVIDIA для скиллов ИИ-агентов (Claude Code, Codex CLI, Gemini CLI) и MCP-серверов. Он отвечает на вопрос «безопасно ли ставить этот скилл?» до установки: ищет вредные инструкции, утечку данных, опасный код и риски цепочки поставки. Заметка по посту [«Не баг, а фича»](https://t.me/bugnotfeature/28684) от 28 октября 2026 года, сверена с репозиторием.

| | |
| :--- | :--- |
| Разработчик | организация NVIDIA на GitHub; часть конвейера NVIDIA Verified Skills — проверенные скиллы публикуются в каталоге [NVIDIA/skills](https://github.com/NVIDIA/skills) |
| Лицензия | Apache-2.0 |
| Состояние | с 21 марта 2026 года — пост подаёт как новинку то, чему уже семь месяцев; версия 2.12.0, больше 2 000 коммитов, ~25 тыс. звёзд, активная разработка |
| Требования | Python 3.12–3.15, либо Docker |

## 1. Что умеет

- **Что сканирует:** Git-репозиторий по ссылке, URL, ZIP, каталог или отдельный `SKILL.md`. Можно рекурсивно обойти папку с десятками скиллов.
- **71 шаблон уязвимостей в 17 категориях:** prompt injection, обход отказов (джейлбрейк-формулировки), утечка данных, повышение привилегий, цепочка поставки, избыточная самостоятельность агента, обработка вывода, утечка системного промпта, отравление памяти, злоупотребление инструментами, «агент-изгой», злоупотребление триггерами, опасный код (анализ AST Python и JavaScript), taint-трекинг, сигнатуры YARA, а для MCP — минимальные привилегии и отравление описаний инструментов. В таблицах README 73 строки: категория «цепочка поставки» помечена «10+» и растёт.
- **Два этапа анализа:**
  - быстрый статический — регулярные выражения, AST, YARA;
  - необязательный смысловой — LLM читает содержимое файлов и оценивает, что скилл на самом деле велит агенту.
- **Зависимости:** имена и версии пакетов, которые объявил скилл, сверяются с базой уязвимостей [OSV.dev](https://osv.dev). Без сети — с небольшим встроенным списком.
- **Отчёты:** в терминале, JSON, Markdown и SARIF — последний для CI и code scanning на GitHub.
- **Базовая линия** для ложных срабатываний: принятые находки фиксируются, при следующих проверках показываются только новые.
- **MCP-сервер:** `skillspector mcp` даёт агенту инструмент `scan_skill`. Тогда Claude Code может сам проверить скилл или MCP-сервер перед установкой.

### Как считается оценка 0–100

Каждая находка добавляет баллы по серьёзности: CRITICAL — 50, HIGH — 25, MEDIUM — 10, LOW — 5. Баллы умножаются на уверенность находки, а повторы одного правила идут с убывающим весом (1; 0,5; 0,25). Итог ограничен сотней.

| Оценка | Уровень | Рекомендация |
| :--- | :--- | :--- |
| 0–20 | LOW | `SAFE` |
| 21–50 | MEDIUM | `CAUTION` |
| 51–80 | HIGH | `DO_NOT_INSTALL` |
| 81–100 | CRITICAL | `DO_NOT_INSTALL` |

Некоторые находки сами поднимают оценку до 51. Например, вложенные исполняемые артефакты, которые сканер не смог разобрать: не проверенное содержимое не должно пройти как безопасное.

## 2. Что за словами поста

- **«NVIDIA выкатили»** — инструмент официальный, но вышел в марте 2026 года, а не к моменту поста.
- **«Проверит 71 шаблон, даст оценку от 0 до 100»** — да, это прямо из README. Плюс к шаблонам — проверка зависимостей по OSV.dev и, по желанию, смысловой разбор через LLM.
- **«Просто даёте ссылку на репозиторий, ZIP или папку»** — да. Без настроенного LLM-провайдера лучше сразу запускать с `--no-llm` (раздел 3).

## 3. Важно знать до запуска

- **LLM-анализ включён по умолчанию** и требует провайдера: OpenAI, Anthropic, AWS Bedrock, NVIDIA build.nvidia.com, Gemini или локальный OpenAI-совместимый сервер (Ollama, vLLM, llama.cpp). Можно использовать и локальные CLI — `claude`, `gemini`, `opencode` — с их авторизацией. Провайдер `codex_cli` намеренно отключён: его песочница разрешает читать файлы хоста.
- **При LLM-анализе содержимое файлов уходит провайдеру.** Для приватного кода — `--no-llm` (только локальный статический анализ) или локальная модель через Ollama.
- **Имена зависимостей уходят на OSV.dev** даже с `--no-llm`: имена и версии пакетов, не содержимое, без ключа.
- **Сканер ничего не запускает и ничего не изолирует.** Анализ только статический плюс LLM по тексту: код скилла не выполняется. Но если вы поставите скилл вопреки отчёту, SkillSpector его не сдержит. Это дополнительный слой защиты, а не песочница.
- **Низкая оценка без LLM — не «чисто».** В JSON-ответе есть `llm_used` и `scan_mode`, чтобы статическую проверку не путали с полной.
- **Ограничения из README:**
  - может пропустить шаблоны **не на английском** — для русскоязычных скиллов это важно;
  - не читает текст на картинках;
  - не анализирует бинарный и зашифрованный код;
  - не видит поведение во время выполнения.

## 4. Установка

| Система | Python 3.12+ и установщик |
| :--- | :--- |
| Gentoo | Python есть; `emerge --ask dev-python/uv` (0.13.7) |
| Arch | `sudo pacman -S uv` |
| Debian 13 / Ubuntu 24.04+ | Python 3.13 / 3.12 есть, `uv` в репозиториях нет: `sudo apt install pipx` и ставить через `pipx` |
| Любая, без Python | Docker: образ собирается из `Dockerfile` в репозитории |

```bash
# через uv (Gentoo, Arch)
uv tool install git+https://github.com/NVIDIA/skillspector.git
# с MCP-сервером
uv tool install 'skillspector[mcp] @ git+https://github.com/NVIDIA/skillspector.git'

# через pipx (Debian, Ubuntu)
pipx install git+https://github.com/NVIDIA/skillspector.git
```

```bash
skillspector scan https://github.com/user/some-skill --no-llm      # только статика, ничего не уходит провайдеру
skillspector scan ./some-skill/                                    # с LLM, если провайдер настроен
skillspector scan ./skills/ --recursive --no-llm --format json --output report.json

# LLM через локальную Ollama — содержимое не покидает машину
SKILLSPECTOR_PROVIDER=ollama SKILLSPECTOR_MODEL=<модель> skillspector scan ./some-skill/

# как инструмент для Claude Code
claude mcp add skillspector -- skillspector mcp
```

- В режиме HTTP (`skillspector mcp --transport http`) сервер работает без аутентификации и слушает только loopback. Локальные пути по HTTP он отклоняет — только удалённые Git и ZIP по `https://`.
- Ограничения на входные данные: до 100 МиБ на загрузку и до 10 000 файлов в ZIP — защита от zip-бомб.

## 5. Откуда цифры про опасные скиллы

В основе — исследование «Agent Skills in the Wild» (Liu et al., 2026). Из 42 447 скиллов с крупных маркетплейсов проанализировали 31 132:
- в **26,1 %** нашлась хотя бы одна уязвимость;
- **5,2 %** показывают вероятный злой умысел;
- скиллы с исполняемыми скриптами уязвимы в 2,12 раза чаще.
