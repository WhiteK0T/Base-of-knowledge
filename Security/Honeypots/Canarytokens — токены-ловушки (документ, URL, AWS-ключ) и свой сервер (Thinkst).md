# 🍯 Canarytokens — токены-ловушки

[**Canarytokens**](https://github.com/thinkst/canarytokens) — приманка не в виде сервиса, а в виде **ловушки-предмета**: вы генерируете безобидный на вид файл, ссылку или ключ, кладёте его туда, где его может найти только злоумышленник, и получаете оповещение в момент, когда кто-то его открыл или использовал. Любое срабатывание — сигнал, что кто-то забрался туда, где его быть не должно. Делает Thinkst; попробовать можно бесплатно на [canarytokens.org](https://canarytokens.org/), не ставя ничего у себя.

| Хостинг | бесплатный публичный или свой сервер (Docker) |

## Виды токенов

- **Документ** Word/PDF/Excel — срабатывает при открытии (пингует домен токена).
- **Веб-ссылка / «быстрый редирект»** и **уникальный email** — обращение к ним = тревога.
- **AWS/Azure-ключ API** — выглядит как настоящий секрет; попытка им воспользоваться сразу видна (для AWS Thinkst держит инфраструктуру проверки).
- **Папка Windows** (срабатывает при просмотре в Explorer), **QR-код**, **MySQL-дамп**, **образ Docker**, **токен в коде/конфиге** и др.

Идея: разбросать такие «канарейки» по файловым шарам, бэкапам, репозиториям, почте. Легитимный пользователь их не трогает, а вор — да.

## Как пользоваться

- **Проще всего:** сгенерировать токен на [canarytokens.org](https://canarytokens.org/), указать e-mail или вебхук для оповещений. Установка не нужна — подходит в том числе с роутера на **Entware** (просто создать токен в браузере).
- **Свой сервер** (если не хотите слать данные наружу) — через Docker:

```bash
git clone https://github.com/thinkst/canarytokens-docker
# заполнить frontend.env и switchboard.env (домен, SMTP/вебхук)
docker compose up -d
```

Self-hosted вариант одинаково ставится там, где есть Docker — на Gentoo, Debian/Ubuntu, Arch; для роутера практичнее публичный хостинг.

## Чтобы не подставиться

- Токен не атакует и почти не несёт риска — но хостинг оповещений должен быть надёжным.
- Не раскладывать токены так, чтобы их случайно задел свой же сотрудник, иначе будут ложные тревоги.
- Для чувствительных сетей — поднимать свой сервер, чтобы факты срабатываний не уходили на сторонний хост.
