# ⚡ FreeToken — большие MoE-модели на домашнем железе

## ✅ Проверка утверждений поста

| Утверждение | Вердикт | Что на самом деле |
| :--- | :---: | :--- |
| «Гигантские модели на **ЛЮБОМ** железе» | ❌ Требования жёсткие | **Linux x86_64, NVIDIA, драйвер r580+, CUDA 13**. В README заявлена поддержка **RTX 30, 40 и 50** серий |
| «Распределяет вычисления между GPU, CPU и RAM» | ✅ Верно, и это суть | Экспертов держат в RAM, на GPU — LRU-кэш слотов; промахи либо тянутся по PCIe, либо считаются на CPU |
| «Qwen3.6 **35B** на RTX 4060 8 ГБ → 39 т/с» | ⚠️ Цифры в документации нет | Модель называется **Qwen3.6-35B-A3B**: 35 млрд всего, но **3 млрд активных**. Пост опустил `A3B`, а в нём вся суть |
| «DeepSeek-V4-Flash 284B на RTX 5090 → 25 т/с» | ⚠️ Не проверил | Модель в списке поддерживаемых есть, конкретных замеров в репозитории нет |

| Про **MoE-специфичность** | ❌ Умолчание | Весь выигрыш — только на MoE. Для плотных моделей движок переключается в режим, требующий VRAM целиком |

## 🧠 Почему это работает — и когда не работает

Идея не в «магической оптимизации», а в устройстве **Mixture-of-Experts**. В такой модели на каждый токен активна лишь малая часть весов: у `Qwen3.6-35B-A3B` из 35 миллиардов параметров работают **3 миллиарда**. Остальные эксперты в этот момент лежат мёртвым грузом — и их можно держать в обычной оперативной памяти, подтягивая по мере надобности.

FreeToken на этом и построен. Стратегии выбираются флагом `--moe-strategy`:

| Стратегия | Что делает |
| :--- | :--- |
| `fused` | эксперты целиком на GPU — нужна VRAM под всё; автоматически никогда не выбирается |
| `offload` | эксперты в оперативной памяти, на GPU — LRU-кэш слотов, промахи едут по PCIe |
| `cpu` | промахи не тянутся, а считаются на процессоре |
| `hybrid` | часть промахов по PCIe, часть на CPU, с перекрытием. Калибруется командой `ft bench bw` |
| `auto` | по умолчанию |

> [!danger] Вот здесь главное умолчание поста
> В документации про режим `auto` сказано прямо: **плотные модели всегда сводятся к `fused`**, а MoE — к `offload` с повышением до `hybrid`.
>
> То есть на **плотной** модели никакой выгрузки не происходит: нужна VRAM под все веса, как и в любом другом движке. Твой опыт с **Qwen3.6-27B** — это как раз плотная модель, и FreeToken там не дал бы ничего.

Плотные чекпоинты в списке поддерживаемых есть (`Qwen3.8-27B`, `Qwen3.6-27B`), но поддержка ≠ ускорение. Выигрыш — только у MoE.

## 🖥️ Железо: твой 1080 Ti не подойдёт

Требования из `docs/install.md` предельно конкретные:

```
Linux x86_64, NVIDIA GPU, driver r580+ (CUDA 13)
Python >= 3.10
```

Плюс: CUDA-ядра компилируются JIT при первом запуске, нужен **toolkit CUDA 13 с `nvcc` в PATH**.

В README список нативной поддержки — **RTX 30, RTX 40, RTX 50**, то есть Ampere и новее. **Pascal (GTX 10xx) там не значится**, а CUDA 13 старые архитектуры уже не обслуживает.

| Твоё железо | Вердикт |
| :--- | :--- |
| **GTX 1080 Ti, 11 ГБ** | ❌ Pascal вне списка, CUDA 13 не поддержит |
| **VPS: 7950X3D, 16 ГБ, без GPU** | ❌ Нужен NVIDIA GPU |

Печально, потому что сценарий «MoE на слабой карте» — ровно то, что решило бы твою проблему с 3 токенами в секунду. Но входной билет начинается с RTX 30-й серии.

## 🔬 Что говорит статья

Аннотация формулирует задачу честно: серверные системы инференса предполагают датацентр, а FreeToken рассматривает персональную машину как **единую эластичную платформу** из разнородных ресурсов — GPU, CPU, память, шины. Вместо фиксированной стратегии выгрузки система непрерывно раскладывает вычисления и состояние модели по тому, что реально доступно.

Заявлено: **более 20 MoE-моделей** и работа реальных кодинг-агентов на железе «от ноутбучной видеокарты на 8 ГБ до одной рабочей станции».

Отдельно полезное для агентов — **семантическое кэширование**: якорные контрольные точки для KV-кэша, чтобы правки контекста (вызовы инструментов, блоки размышлений) не заставляли пересчитывать всё заново. Плюс API, совместимые с Anthropic и OpenAI, с прицелом на Codex, [Claude Code](../Agents/Claude%20Code%20%E2%80%94%20%D1%88%D0%BF%D0%B0%D1%80%D0%B3%D0%B0%D0%BB%D0%BA%D0%B0%20%D0%BA%D0%BE%D0%BC%D0%B0%D0%BD%D0%B4.md), OpenCode и DeepSeek Harness.

Проект честно перечисляет, у кого заимствовал: SGLang, vLLM, FlashInfer, LightLLM, llama.cpp и mini-sglang.

## 📦 Установка (если появится подходящая карта)

```bash
# требуется Linux x86_64, NVIDIA RTX 30+, драйвер r580+, CUDA 13 с nvcc
uv venv && source .venv/bin/activate
uv pip install "freetoken[accel]"

ft --version
ft serve --model ~/path/to/Qwen3.6-35B-A3B
ft bench bw          # калибровка разделения PCIe/CPU под конкретную машину
```

Есть и десктопное приложение для Windows и Linux с [flashml.ai](https://www.flashml.ai/) — оно ставит движок само и даёт интерфейс. Но CLI-документация говорит только про **Linux x86_64**.

| Система | Пригодность |
| :--- | :--- |
| **Gentoo** (основная) | Технически подходит (Linux x86_64), но нужна карта RTX 30+ и `dev-util/nvidia-cuda-toolkit` версии 13 |
| **Debian / Ubuntu** | То же плюс десктопное приложение |
| **Arch** | То же |
| **Entware / RT-AX56U** | ❌ Неприменимо |

## 💡 Итог

- Проект **серьёзный**: Apache-2.0, статья на arXiv, среди авторов Keutzer, Han, Zaharia и Stoica. Не однодневка.
- **«На любом железе» — неправда**: Linux x86_64, NVIDIA, CUDA 13, RTX 30-й серии и новее.
- Главное умолчание: ускорение **только для MoE**. На плотных моделях движок сводится к обычному режиму с полной загрузкой в VRAM.
- Пост опустил суффикс **A3B** у Qwen3.6-35B — а именно 3 миллиарда активных параметров из 35 и делают возможными заявленные 39 токенов в секунду.
- Конкретных замеров из поста в репозитории и документации нет.
- **Для твоего 1080 Ti не подойдёт.** Если когда-нибудь появится карта RTX 30+, стоит вернуться: связка «MoE плюс выгрузка экспертов в RAM» действительно меняет расклад по сравнению с попытками запускать плотные модели.
