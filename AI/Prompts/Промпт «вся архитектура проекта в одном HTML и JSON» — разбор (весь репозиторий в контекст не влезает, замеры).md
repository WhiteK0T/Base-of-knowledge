# 🧭 Промпт «вся архитектура проекта в одном HTML и JSON» — разбор

Разбор [поста «Не баг, а фича» от 16.08.2026](https://t.me/bugnotfeature/27106) с «ультимативным промптом», который обещает сгенерировать всю архитектуру проекта в двух файлах.

Идея здравая, но обещания завышены, а сам промпт написан так, что на реальном проекте споткнётся. Ниже — замеры и переписанная версия.

## 📋 Что предлагает пост

Промпт короткий и просит две вещи: самодостаточный HTML с интерактивной диаграммой, панелью потоков и подсветкой пути по клику, плюс JSON вида `{nodes, edges, flows: [{steps}]}` «для других агентов». Начинается он с указания «проанализируй весь мой репозиторий целиком».

Обещания поста: «сгенерите **ВСЮ** архитектуру своего проекта», «просто кидаем запрос **Claude** и **через секунду** код будет чётко структурирован», «JSON даст **любому иному агенту мгновенно понять** ваш код».

## ✅ Проверка утверждений

| Утверждение | Вердикт | Что на самом деле |
| :--- | :---: | :--- |
| «Проанализируй **весь** репозиторий» | ❌ Физически не выйдет | Даже небольшие проекты не влезают в контекст — замеры ниже |
| «**Через секунду**» | ❌ Нет | Обход репозитория, чтение файлов и генерация большого HTML — это минуты и десятки тысяч токенов |
| «Просто кидаем запрос **Claude**» | ❌ Не сработает в чате | Обычный веб-чат не видит твои файлы. Нужен агент с доступом к ФС — Claude Code, Codex, Cursor |
| «JSON даст любому агенту **мгновенно понять** код» | ⚠️ Сильное преувеличение | Граф узлов и связей — это карта, а не понимание. И схема в промпте недоопределена, см. ниже |
| Идея «диаграмма + машиночитаемый JSON» | ✅ Здравая | Разделение на «для человека» и «для агента» — правильный подход |
| Промпт рабочий как есть | ⚠️ На маленьком проекте | На среднем и большом нужны ограничения, которых в нём нет |

## 📏 Главное: «весь репозиторий» в контекст не влезает

Замерил `tiktoken` (`o200k_base`) на трёх реальных проектах — считал только исходники и тексты, без `.git` и бинарников:

| Проект | Файлов | Объём | Токенов |
| :--- | ---: | ---: | ---: |
| **requests** (HTTP-библиотека) | 68 | 0,5 МБ | **120 567** |
| **flask** (веб-фреймворк) | 137 | 0,6 МБ | **146 640** |
| **yt-dlp** | 1 201 | 11,3 МБ | **3 203 335** |

Сопоставь с окном контекста в 200 000 токенов:

- **requests** — 68 файлов, одна библиотека для HTTP — съедает **60 %** окна. На рассуждения и генерацию HTML остаётся 40 %.
- **flask** — **73 %** окна. Технически влезает, практически места на работу почти нет.
- **yt-dlp** — превышает окно в **16 раз**. Даже в миллионное окно не помещается втрое.

> [!danger] Что произойдёт на практике
> Агент не скажет «не влезло». Он прочитает часть файлов, построит диаграмму по ним и выдаст уверенный результат — с виду полный. Проверить, что попало в анализ, а что нет, по готовому HTML **невозможно**. Это худший вид ошибки: тихая и правдоподобная.
>
> Формулировка «Analyze my entire code repository thoroughly» этому прямо способствует, потому что не даёт агенту ни лимитов, ни правил отбора, ни указания сообщить о пропущенном.

## 🔧 Три дыры в самом промпте

### 1. Нет исключений

Не сказано игнорировать `node_modules`, `vendor`, `.venv`, `dist`, `build`, `.git`, минифицированные бандлы, лок-файлы и тесты. На JS-проекте `node_modules` в одиночку способен превысить любой контекст, а к архитектуре отношения не имеет.

### 2. Схема JSON недоопределена

`{nodes, edges, flows: [{steps}]}` не описывает **ни одного поля внутри** узла или связи. Нет `id`, `type`, `label`, `file`, нет направления связи, нет словаря допустимых типов. Следствие: два запуска на одном и том же проекте дадут **разные** структуры, а обещание «любой агент мгновенно поймёт» ломается ровно об это — агенту нужна стабильная схема, а не «что модель придумала в этот раз».

### 3. Оба артефакта просятся одним ответом

Самодостаточный HTML с интерактивом плюс JSON — это большой объём **вывода**, а лимит на вывод существенно меньше контекста. Скорее всего HTML окажется урезанным или JSON — неполным.

## ✍️ Переписанный промпт

Что изменено: этап разведки до чтения кода, явные исключения, жёсткая схема JSON, отчёт о непрочитанном и разделение на два вызова.

**Шаг 1 — карта и JSON:**

```text
Составь карту архитектуры этого репозитория. Работай поэтапно.

ЭТАП 1. Разведка, без чтения содержимого файлов:
- построй дерево файлов, исключив: .git, node_modules, vendor, .venv,
  dist, build, target, *.min.*, lock-файлы, ассеты и снапшоты тестов;
- оцени объём оставшегося и назови мне цифру;
- определи точки входа, конфиги сборки, границы модулей.

ЭТАП 2. Чтение — только то, что нужно для архитектуры:
точки входа, определения публичных интерфейсов, конфигурация,
маршруты/обработчики, схемы данных. Реализацию функций не читай.
Если файл пришлось пропустить — запомни его.

ЭТАП 3. Выдай ТОЛЬКО JSON по схеме:
{
  "nodes": [{"id","label","type","files":[],"summary"}],
  "edges": [{"from","to","kind","why"}],
  "flows": [{"id","name","steps":[{"node","action"}]}],
  "coverage": {"files_total","files_read","skipped":[],"confidence"}
}
type ∈ entrypoint|service|module|store|external|ui
kind ∈ calls|imports|reads|writes|publishes|subscribes

Ничего не выдумывай: если связь не подтверждается кодом — не добавляй.
Поле skipped обязано перечислить всё, что не попало в анализ.
```

**Шаг 2 — визуализация, отдельным запросом:**

```text
Возьми architecture.json и собери один самодостаточный HTML:
интерактивная диаграмма узлов и связей, панель потоков справа,
подсветка полного пути при клике на поток, тултипы с полем summary.
Без внешних CDN, всё inline. Тёмная и светлая темы.
```

> [!tip] Ключевое отличие
> Поле **`coverage`** с обязательным `skipped` превращает молчаливый пропуск в явный. Ты сразу видишь, что из 1 201 файла прочитано 180 — и понимаешь, чего диаграмма не знает.

Последний вариант прямо перекрывает вторую половину промпта: там есть готовый тип `architecture`, и качество вывода несопоставимо с тем, что модель нарисует с нуля по трём строчкам требований.

## 💡 Итог

- Идея правильная: **диаграмма для человека + структурированный JSON для агентов** — хорошее разделение.
- Обещания завышены: «весь репозиторий» и «через секунду» не выполняются ни на одном проекте сложнее учебного. Даже `requests` на 68 файлов забирает 60 % контекстного окна.
- В обычном чате Claude промпт вообще не сработает — нужен агент с доступом к файлам.
- Как есть годится для **небольшого проекта** (десятки файлов). Для остального добавляй исключения, жёсткую схему JSON и обязательный отчёт о пропущенном.
- Если нужен именно красивый интерактивный HTML — быстрее и надёжнее взять [Diagram Design](../Skills/Diagram%20Design%20%28cathrynlavery%29%20%E2%80%94%2039%20%D1%82%D0%B8%D0%BF%D0%BE%D0%B2%20%D0%B4%D0%B8%D0%B0%D0%B3%D1%80%D0%B0%D0%BC%D0%BC%20%D0%B4%D0%BB%D1%8F%20%D0%98%D0%98-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BE%D0%B2%20%28206%20%D1%82%D0%BE%D0%BA%D0%B5%D0%BD%D0%BE%D0%B2%20%D0%B2%20%D1%84%D0%BE%D0%BD%D0%B5%2C%20%D1%88%D1%80%D0%B8%D1%84%D1%82%D1%8B%20%D0%B8%D0%B7%20Google%2C%20%D0%BD%D0%B5%20%D1%82%D0%BE%D0%BB%D1%8C%D0%BA%D0%BE%20Claude%20Code%29.md), чем изобретать вёрстку промптом.
