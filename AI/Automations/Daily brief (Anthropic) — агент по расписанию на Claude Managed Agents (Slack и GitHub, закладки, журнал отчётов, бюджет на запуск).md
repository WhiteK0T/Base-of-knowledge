# ⏰ Daily brief (Anthropic) — агент по расписанию на Claude Managed Agents

> [!info] Коротко
> 8 октября 2026 Anthropic опубликовала гайд [«Building effective agent automations»](https://claude.dev/blog/building-effective-agent-automations/) (Lance Martin, CJ Avilla, 9 минут чтения) и эталонную реализацию **daily-brief** в [`anthropics/claude-quickstarts`](https://github.com/anthropics/claude-quickstarts/tree/main/managed-agents/daily-brief). Агент каждое утро по будням читает каналы Slack и pull request'ы GitHub, отбирает то, по чему вам нужно что-то сделать сегодня, и публикует короткую сводку в канал Slack. Работает он в облаке Anthropic (**Claude Managed Agents**, бета), так что держать включённым свой сервер не нужно.
>
> Гайд и код бесплатны. Сами запуски оплачиваются: нужен аккаунт **Claude API** (подписка Pro/Max не подходит), по замерам авторов один запуск стоит около **$1**.

Главная ценность гайда — не сам дайджест, а **шесть правил для агента, который работает без присмотра**. Они пригодятся для любой фоновой автоматизации, не только на платформе Anthropic (раздел 6).

---

## 1. Что такое Claude Managed Agents

Это готовая агентская обвязка от Anthropic: цикл агента, песочница, инструменты и хранение истории живут на стороне Anthropic, а вы описываете только конфигурацию. Бета, заголовок `managed-agents-2026-04-01` (SDK ставит его сам), по умолчанию включена для всех API-аккаунтов.

| Сущность | Что это | Файл в daily-brief |
| :--- | :--- | :--- |
| **Agent** | модель, системный промпт, инструменты, MCP-серверы; версионируется | `agent.md` |
| **Environment** | песочница: облачная или своя (self-hosted), сетевой allowlist | `environment.yaml` |
| **Session** | один запуск агента в окружении | — |
| **Deployment** | запуск по cron: агент, окружение, первое сообщение, память, хранилище секретов, бюджет | `deployment.md` |
| **Memory store** | папка текстовых файлов, переживающая запуски; монтируется в `/mnt/memory/<имя>/` | `memory_store_*.yaml` |
| **Vault** | хранилище секретов; агент видит только заглушку | `vault.yaml` |

Всё описывается файлами и создаётся одной командой `ant apply` из CLI `ant`. Идентификаторы созданных ресурсов записываются в `claude-lock.json`, так что конфигурацию удобно держать в git.

## 2. Как устроен daily-brief

```
daily-brief/
├── agents/daily-brief/
│   ├── agent.md                       модель и инструменты во frontmatter, шаги запуска в теле
│   ├── deployment.md                  расписание, часовой пояс, бюджет, память; тело — первое сообщение
│   ├── environment.yaml               сетевой allowlist песочницы
│   ├── memory_store_preferences.yaml  ваши правила (агенту только для чтения)
│   ├── memory_store_state.yaml        память агента (закладки, журнал, записи запусков)
│   └── vault.yaml                     контейнер для токенов Slack и GitHub
├── agents/setup.sh                    создаёт всё, кладёт токены в vault, ставит расписание на паузу
├── scripts/run.sh                     запустить сейчас и показать результат и стоимость
├── scripts/seed-preferences.sh        залить preferences.md в хранилище настроек
├── scripts/reset-state.sh             очистить память после тестов
├── scripts/teardown.sh                удалить всё созданное
├── preferences.example.md             шаблон ваших правил
└── slack/manifest.yaml                Slack-приложение с двумя правами: channels:history, chat:write
```

### Источники и куда пишет

- **GitHub** — через официальный MCP-сервер `https://api.githubcopilot.com/mcp/`. Токен лежит в vault как `static_bearer` и подставляется по совпадению URL сервера.
- **Slack** — агент сам вызывает API через `curl` в песочнице. В переменной `$SLACK_BOT_TOKEN` у него лежит заглушка, настоящий токен подставляется **на выходе** из песочницы и только для `slack.com`.
- **Куда пишет** — один канал Slack, один пост в день с заголовком «Daily brief, <день недели> <месяц> <число>».

### Восемь шагов запуска (тело `agent.md`)

1. Заново прочитать `preferences.md`. Если не читается — остановиться, ничего не публиковать. Если там написано `STOP` — остановиться.
2. Прочитать состояние: `bookmarks.json`, `ledger.md`, `notes.md`, последнюю запись в `runs/`.
3. Прочитать каждый источник **с закладки минус 10 минут**. Упавший источник пропустить, закладку не двигать.
4. Отобрать: строка в сводке — только то, по чему читатель **сегодня** что-то сделает. Счётчик («12 открытых ревью») — не пункт.
5. **Перепроверить** каждый пункт прямо перед публикацией: решённое — убрать, изменившееся — поправить, неподтверждённое — выкинуть.
6. Написать сводку в пределах лимита длины; пробелы в данных — одной строкой в конце.
7. Проверить, нет ли уже сегодняшнего поста; записать статус `posting`; опубликовать; считать отправленным только при `"ok": true` и `ts` в ответе Slack.
8. Только после подтверждения: статус `posted`, строки в журнал, новые закладки, запись запуска.

### Память агента

| Хранилище | Доступ агента | Что внутри |
| :--- | :--- | :--- |
| `preferences` | **только чтение** (на уровне файловой системы) | чьи PR смотреть, какие каналы, куда писать, лимит длины, кого можно упоминать, закрытые темы, временные правила с датой окончания, условие остановки |
| `state` | чтение и запись | `bookmarks.json`, `ledger.md`, `notes.md` (особенности источников), `proposals.md` (предложения правок ваших правил), `runs/<дата>.md` |

Строка журнала (`ledger.md`): дата, источник, неизменный ID (timestamp сообщения Slack или номер PR) и последний известный статус:

```text
2026-09-11 github 481 review blocked, day 2 (still waiting)
```

Каждое изменение в хранилище сохраняется как версия: можно посмотреть, что агент записал, и откатить. Версии хранятся 30 дней.

## 3. Установка и запуск

### Что нужно

- аккаунт [Claude API](https://platform.claude.com/) с балансом;
- CLI **`ant` версии 1.34 или новее** (с этой версии `ant apply` умеет создавать vault), `jq`, `bash`, `perl`;
- Slack-приложение из манифеста и **fine-grained** токен GitHub только на чтение (Contents: read, Pull requests: read).

### Установка `ant` (последняя версия на 13.10.2026 — 1.40.0)

Релизы — готовые статические бинарники Go и пакеты для Linux: amd64, arm64, 386, armv6.

| Система | Как поставить |
| :--- | :--- |
| **Gentoo** | бинарник из релиза (ниже) или из исходников: `emerge --ask dev-lang/go app-misc/jq`, затем `go install github.com/anthropics/anthropic-cli/cmd/ant@latest` (нужен Go 1.25+) |
| **Debian / Ubuntu** | `sudo apt install jq` и пакет из релиза: `sudo apt install ./ant_1.40.0_linux_amd64.deb` |
| **Arch** | `sudo pacman -S jq` и пакет из релиза: `sudo pacman -U ant_1.40.0_linux_amd64.pkg.tar.zst`. Пакет `anthropic-cli-bin` в AUR застрял на 1.21.0 — для `ant apply` с vault он слишком старый |
| **Entware** | `opkg install jq bash perl` и бинарник `linux_armv6` (подходит для armv7 роутера) в `/opt/bin`. Роутер здесь только «пульт»: сам агент работает в облаке, `ant` лишь создаёт ресурсы и запускает прогоны |

Бинарник из релиза для любой системы:

```bash
VERSION=1.40.0
case $(uname -m) in
  x86_64) ARCH=amd64 ;; aarch64) ARCH=arm64 ;; armv7l|armv6l) ARCH=armv6 ;;
esac
curl -fsSL "https://github.com/anthropics/anthropic-cli/releases/download/v${VERSION}/ant_${VERSION}_linux_${ARCH}.tar.gz" \
  | sudo tar -xz -C /usr/local/bin ant      # на Entware: -C /opt/bin, без sudo
ant --version
ant auth login                               # OAuth через браузер; на сервере без браузера — ANTHROPIC_API_KEY
```

### Пошагово

```bash
git clone --depth 1 https://github.com/anthropics/claude-quickstarts.git
cd claude-quickstarts/managed-agents/daily-brief

cp .env.example .env          # вписать SLACK_BOT_TOKEN (xoxb-…) и GITHUB_TOKEN
agents/setup.sh               # создать всё; токены уходят в vault, расписание на паузе

cp preferences.example.md preferences.md   # ваши ID каналов, репозитории, канал назначения, лимит
scripts/seed-preferences.sh preferences.md

scripts/run.sh                # пробный запуск: сводка, ошибки источников, стоимость
ant beta:deployments unpause --deployment-id depl_…   # включить расписание
```

`setup.sh` передаёт токены в `ant` через here-string, а не аргументами, поэтому их не видно в `ps`. В Slack бота нужно пригласить (`/invite @Daily brief`) в каждый читаемый канал и в канал назначения: эти приглашения — его единственный доступ.

Вариант через Claude Code: `claude update`, затем `/claude-api managed-agents-onboard https://claude.dev/blog/building-effective-agent-automations/`. Скилл прочитает гайд, предложит конфигурацию под ваши источники, сложит файлы в `agents/` проекта и выполнит `ant apply`.

### Полезные режимы

- **Пробный прогон без публикации** — в `deployment.md` поставить хранилищу `state` `access: read_only` и сделать `ant apply`. Агент ничего не публикует, выводит сводку в последнем сообщении и не двигает закладки.
- **Остановить агента без удаления** — `ant beta:deployments pause --deployment-id …` или строка `STOP` в `preferences.md`.
- **История запусков и ошибок** — `ant beta:deployment-runs list --deployment-id … --has-error`.
- **Удалить всё** — `scripts/teardown.sh`. Slack-приложение и токен GitHub после этого отзовите сами.

## 4. Расписание и деньги

```yaml
schedule:
  type: cron
  expression: "32 7 * * 1-5"     # по будням в 07:32
  timezone: America/New_York     # для себя — Europe/Moscow и т.п.
budget:
  type: limit
  max_list_cost:
    amount: "500"                # строка, в центах: "500" = $5 на ОДИН запуск
    currency: USD
```

- Cron стандартный POSIX, точность — минута. К фактическому времени платформа добавляет случайный сдвиг до 15% интервала, но не больше 9 минут.
- При переходе на летнее время несуществующие часы (около 2:00) пропускаются, а повторяющиеся срабатывают дважды. Не ставьте запуск на 1:00–3:00 местного времени.
- Пропущенные во время паузы запуски потом не выполняются.
- Часовой пояс нужно указать **дважды**: в `timezone` (когда запускать) и в тексте первого сообщения (в каком поясе агенту считать даты). Иначе агент назовёт сегодняшнее утро «вчера».
- Бюджет действует **на каждый запуск отдельно**, а не на месяц. Упёршийся в него запуск не падает, а встаёт на паузу (`budget_reached`). В канале это выглядит как тишина, поэтому пропавшую сводку ищите в консоли.

### Сколько стоит

| Статья | Цена |
| :--- | :--- |
| Токены | по обычному прайсу модели; Sonnet 5.5 — $2 вход / $10 выход за 1 млн, чтение кэша ×0,05 |
| Рантайм сессии | **$0,08 за час**, считается только пока сессия в статусе `running` (ожидание не тарифицируется) |
| Веб-поиск внутри сессии | $10 за 1000 запросов (в daily-brief выключен) |

Замеры авторов: в загруженный день (2 канала и 2 репозитория, около 140 сообщений и 25 PR) запуск стоил **около $1,50 на Opus 5 и $1,00 на Sonnet 5**. Если все источники недоступны — $0,15–0,30. Вдвое больше источников добавили примерно треть, а не удвоили цену. Замеры делали до перехода на Sonnet 5.5, поэтому свою цену смотрите в выводе `scripts/run.sh`. Ориентир: **22 рабочих дня × ~$1 ≈ $20–25 в месяц**. Бюджет авторы советуют ставить в 3–5 раз выше обычного запуска и ужимать после недели реальных прогонов.

> [!note] Доступ из России
> Claude API официально недоступен для российских аккаунтов и карт, поэтому для Managed Agents нужен аккаунт и оплата в поддерживаемой стране. Managed Agents хранит историю сессий на стороне Anthropic и не подпадает под Zero Data Retention.

## 5. Безопасность: агент читает чужой текст

Сообщения в Slack и описания PR пишут другие люди, и в них может оказаться инструкция для агента (prompt injection). Защита в daily-brief построена так, чтобы даже подчинившийся такой инструкции агент мало что мог сделать:

- **Токен GitHub только на чтение.** Все инструменты GitHub выполняются без подтверждения (`always_allow`), иначе агент вечно ждал бы одобрения, которое некому дать. Поэтому ограничивает его именно токен.
- **Ваши правила агент изменить не может.** Хранилище `preferences` подключено только для чтения на уровне файловой системы. Свои предложения агент пишет в `proposals.md` — читайте их как недоверенный текст.
- **Сеть закрыта по умолчанию.** Из песочницы доступны только `slack.com` и MCP-сервер GitHub. Встроенные `web_search` и `web_fetch` **выключены**: они работают на серверах Anthropic, вне песочницы, и allowlist окружения на них не действует.
- **Токен Slack подставляется только для `slack.com` и только в заголовки** (`injection_location: {header: true}`). Агенту прямо запрещено искать или подбирать токены.
- **Слабое место — Slack.** Тот же токен и читает, и пишет, поэтому бот может написать в любой канал, где состоит. Запрет писать куда-то, кроме канала назначения, — это лишь правило в промпте. Для чувствительных каналов авторы советуют **два Slack-приложения**: одно только читает источники, второе (`chat:write`) приглашено только в канал назначения.
- `run.sh` вычищает управляющие символы из вывода агента, чтобы текст из Slack не мог передать escape-последовательности в ваш терминал.

## 6. Шесть правил для любой фоновой автоматизации

Эти приёмы годятся и для своего cron-скрипта с LLM, и для `/schedule` в Claude Code, и для n8n.

| Правило | Что ломается без него |
| :--- | :--- |
| **Читать с закладки, а не «за последние 24 часа».** Хранить время последнего прочитанного элемента для каждого источника | опоздавший запуск оставляет дыру, ранний повторяет старое |
| **Упавший источник — «недоступен», а не «новостей нет».** Закладку не двигать, в конце сводки — строка о том, что не прочиталось | истёкший токен выглядит как спокойный день, и неделями никто не замечает |
| **Перепроверять каждый пункт прямо перед публикацией** | «всё ещё ждёт вас» про давно закрытый PR — одна такая ошибка стоит больше доверия, чем десять пропущенных пунктов |
| **Считать пост отправленным только по ответу сервиса**, и лишь потом двигать закладки и журнал. Перед публикацией проверять, нет ли уже сегодняшнего поста | закладка ушла вперёд, а пост не дошёл — пункты потеряны навсегда; или повторная отправка «на всякий случай» даёт дубль |
| **Перечитывать настройки каждый запуск из хранилища, которое агент не может менять** | копия настроек в промпте продолжает применять правила, которые вы уже отменили |
| **Права только на чтение там, где агент только читает, и лимит расходов на запуск** | подчинившийся prompt injection агент пишет в репозиторий; зациклившийся запуск сжигает баланс |

Ещё две мелочи из `agent.md`, которые легко забыть:
- в `notes.md` агент пишет только устойчивые особенности источника («отдаёт не больше 50 последних элементов»), а не временные сбои и обходные пути: заметка переживёт исправление и будет путать следующие запуски;
- ссылки берутся из полей самого источника (`html_url` у PR, permalink у Slack) и никогда не собираются вручную.

## 7. Что если не Slack

- **Другие источники** (Linear, Notion, Jira и т.п.) подключаются через их MCP-серверы: сервер в `mcp_servers` агента, токен — в vault как `static_bearer` или `mcp_oauth` с тем же URL. В vault до 20 секретов.
- **Telegram напрямую так не сработает.** Vault подставляет секрет только в **заголовки и тело** запроса, а токен Telegram Bot API стоит в **пути URL** (`/bot<токен>/sendMessage`). Заглушка уйдёт в Telegram как есть, и он вернёт ошибку авторизации. Варианты: MCP-сервер для Telegram с токеном в vault; или режим без публикации (`state` только для чтения) — тогда сводку забирает ваш cron-скрипт (`ant beta:sessions:events list …`) и сам отправляет её в Telegram.
- **Без облака Anthropic.** Те же шесть правил переносятся на локальный агент. Например, на сервере с Claude Code: cron или таймер OpenRC/systemd вызывает `claude -p` с промптом, где закладки и журнал лежат в обычных файлах, а токены — у процесса с минимальными правами.
