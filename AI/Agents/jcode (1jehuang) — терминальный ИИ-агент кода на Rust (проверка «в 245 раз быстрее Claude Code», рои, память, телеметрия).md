# jcode — терминальный ИИ-агент кода на Rust

Разбор поста [@bugnotfeature/26684](https://t.me/bugnotfeature/26684) («Нашли топового агента ДЛЯ КОДИНГА — JCode… запускается в 245 раз быстрее Claude Code, ест 28 МБ ОЗУ на сессию»).

> [!info] Вердикт
> **Проект серьёзный, цифры настоящие — но не про то, что кажется.**
>
> «245 раз» — это **время до первого отрисованного кадра** (14 мс против 3437 мс), а не скорость работы. До момента, когда можно печатать, разрыв **72×**. Это честные замеры автора, но «запускается в 245 раз быстрее» и «работает в 245 раз быстрее» — разные утверждения.
>
> **«28 МБ» — это конфигурация с выключенным локальным эмбеддингом.** С включённым (а именно он даёт ту самую «глобальную память», которую пост хвалит соседним пунктом) одна сессия занимает **167 МБ — в 6 раз больше**. Оба преимущества одновременно получить нельзя.
>
> Плюс два умолчания: в проекте есть **недокументированная телеметрия** с открытыми багами про opt-out, и у него есть **платный хостинг инференса** ($10/мес).
>
> *Проверено по GitHub API, README, сайту и открытым issue 11 августа 2026.*

## 2. Откуда взялись цифры

Автор публикует полные таблицы с диапазонами и версиями всех сравниваемых инструментов — за это большой плюс, потому что из них видно то, чего нет в заголовке.

### Время до первого кадра (10 запусков в PTY)

| Инструмент | Время | Против jcode |
| :--- | ---: | ---: |
| **jcode** | **14,0 мс** | базовая |
| Antigravity CLI | 383,5 мс | 27,4× |
| pi | 590,7 мс | 42,2× |
| Codex CLI | 882,8 мс | 63,1× |
| OpenCode | 1035,9 мс | 74,0× |
| GitHub Copilot CLI | 1518,6 мс | 108,5× |
| Cursor Agent | 1949,7 мс | 139,3× |
| **Claude Code** | **3436,9 мс** | **245,5×** ← число из поста |

### Время до готовности к вводу

| Инструмент | Время | Против jcode |
| :--- | ---: | ---: |
| **jcode** | **48,7 мс** | базовая |
| Codex CLI | 905,8 мс | 18,6× |
| OpenCode | 1047,9 мс | 21,5× |
| Cursor Agent | 1978,7 мс | 40,6× |
| **Claude Code** | **3512,8 мс** | **72,2×** |

> [!note] Почему разрыв разный
> jcode рисует первый кадр за 14 мс, но до готовности принимать ввод ему нужно ещё 35 мс. У Claude Code первый кадр и готовность почти совпадают (3437 и 3513 мс). Поэтому по «первому кадру» разрыв 245×, а по практически значимому «когда можно печатать» — 72×.
>
> **72× — это тоже очень много.** 3,5 секунды против 0,05 секунды при десятке запусков в день — заметная разница. Просто «245» звучит громче, и пост взял именно её.
>
> Отдельно стоит посмотреть на разброс у Claude Code: **2032–8927 мс**. То есть иногда он стартует почти 9 секунд.

### Память

| | 1 сессия (PSS) | 10 сессий (PSS) | Каждая доп. сессия |
| :--- | ---: | ---: | ---: |
| **jcode (эмбеддинг выключен)** | **27,8 МБ** | 117,0 МБ | ~9,9 МБ |
| **jcode (по умолчанию)** | **167,1 МБ** | 260,8 МБ | ~10,4 МБ |
| Codex CLI | 140,0 МБ | 334,8 МБ | ~21,6 МБ |
| pi | 144,4 МБ | 833,0 МБ | ~76,5 МБ |
| Cursor Agent | 214,9 МБ | 1632,4 МБ | ~157,5 МБ |
| Antigravity CLI | 243,7 МБ | 1021,2 МБ | ~86,4 МБ |
| GitHub Copilot CLI | 333,3 МБ | 1756,5 МБ | ~158,1 МБ |
| **Claude Code** | **386,6 МБ** | **2300,6 МБ** | ~212,7 МБ |
| OpenCode | 371,5 МБ | 3237,2 МБ | ~318,4 МБ |

> [!warning] Главная находка: 28 МБ и «глобальная память» — взаимоисключающие
> Строка на 27,8 МБ подписана **`jcode (local embedding off)`**. Локальная модель эмбеддингов — это и есть движок той самой памяти, которую пост хвалит отдельным пунктом. Включи память — получишь **167,1 МБ**, в шесть раз больше рекламной цифры.
>
> При этом **на масштабе разница почти исчезает**: каждая дополнительная сессия стоит 10,4 МБ против 9,9 МБ, потому что модель эмбеддингов загружается один раз на всех. То есть с памятью 10 сессий = 261 МБ вместо 117 МБ, но 100 сессий ≈ 1,2 ГБ против 1,1 ГБ.
>
> Вывод, которого нет в посте: **чем больше сессий, тем меньше смысла отключать эмбеддинг** — а именно ради множества сессий инструмент и брали.

> [!caution] Что стоит держать в голове про эти замеры
> - Это **бенчмарк вендора против конкурентов**, а не независимая проверка. Методика описана подробно и версии всех инструментов указаны, что сильно лучше среднего, но воспроизводить придётся самому.
> - PSS (proportional set size) — методологически правильная метрика для нескольких процессов, тут придраться не к чему.
> - Замеры сделаны на одной машине автора под Linux.
> - **Ни одна из этих метрик не про качество кода.** Быстрый старт и малый расход памяти не делают агента умнее — он всё равно работает той же моделью, что и Claude Code.

## 3. Что это на самом деле

| | |
| :--- | :--- |
| Репозиторий | [github.com/1jehuang/jcode](https://github.com/1jehuang/jcode) |
| Лицензия | **MIT**, без функциональных ограничений |
| Язык | **Rust** |
| Создан | 5 января 2026 |
| Популярность | **17,2k ★**, 1,9k форков, 88 наблюдателей |
| Версия | **v0.75.3** (11 августа 2026) |
| Темп | **три релиза за один день** проверки; коммиты ежечасно |
| Открытых issue | ~272 (при 5 открытых PR) |
| Компания | Solo Systems, на сайте указано «Backed by Combinator» |
| Платформы | Linux x86_64/aarch64, macOS x86_64/aarch64, Windows aarch64, FreeBSD |

Три тезиса из манифеста, которые объясняют дизайн: параллелизм — главный рычаг продуктивности (не ждать агента, а раздавать следующую задачу); **harness важен не меньше модели** (прогресс модели идёт своим графиком, прогресс обвязки — наш); инструменты разработчика обязаны быть открытыми, раз уж они читают код и запускают команды на твоей машине.

### Что действительно интересно

**Swarm.** Не просто «запусти несколько агентов». Сервер знает, кто какой файл читал: когда агент A меняет файл, который агент B держит в контексте, **B получает уведомление** и может посмотреть диф, чтобы не работать по устаревшему коду. Есть личные сообщения между агентами и броадкаст по репозиторию. Агент умеет **сам породить рой**, став координатором.

**Память.** Каждый ход разговора эмбеддится в вектор и укладывается в граф памяти; на каждом ходу идёт поиск по косинусной близости, найденное подмешивается в контекст. Извлечение и укладка делаются отдельным sideagent'ом по триггерам (семантический дрейф, N ходов, конец сессии). Есть и явные инструменты памяти, и поиск по прошлым сессиям. Это заметно сложнее, чем «файл с заметками», который называют памятью большинство агентов — сравни с [Obsidian Mind — постоянная память для ИИ-агентов](Tooling/Obsidian%20Mind%20%E2%80%94%20%D0%BF%D0%BE%D1%81%D1%82%D0%BE%D1%8F%D0%BD%D0%BD%D0%B0%D1%8F%20%D0%BF%D0%B0%D0%BC%D1%8F%D1%82%D1%8C%20%D0%B4%D0%BB%D1%8F%20%D0%98%D0%98-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BE%D0%B2%20%D0%B2%20Obsidian-%D1%85%D1%80%D0%B0%D0%BD%D0%B8%D0%BB%D0%B8%D1%89%D0%B5%20%28Claude%20Code-Codex-Gemini%29%2C%20%D1%84%D0%B0%D0%BA%D1%82%D1%8B%20%D0%BF%D1%80%D0%BE%D1%82%D0%B8%D0%B2%20%C2%AB%D0%B1%D0%B5%D1%81%D0%BA%D0%BE%D0%BD%D0%B5%D1%87%D0%BD%D0%BE%D0%B9%20%D0%BF%D0%B0%D0%BC%D1%8F%D1%82%D0%B8%C2%BB.md).

**Resume чужих сессий.** `codex`, `claude code`, `opencode`, `pi`. Полезно ровно в том сценарии, который описан в README: «Claude Code сломался — продолжи сессию из jcode».

**Self-Dev.** Агент правит собственный исходник, собирает, тестирует и перезагружает свой бинарник, не роняя твои сессии. Любопытная идея кастомизации «без плагинов», но требует фронтир-модели.

## 4. Телеметрия — то, о чём молчат и пост, и README

> [!danger] В README телеметрии нет ни слова. В трекере — есть
> Три открытых issue от 11 августа 2026:
> - **`jcode telemetry disable` на свежей машине успевает отправить install-событие до того, как отключение вступит в силу.** То есть на новой машине факт установки уходит наружу, даже если ты сразу выключаешь телеметрию.
> - **Нельзя посмотреть содержимое телеметрических пакетов, не отправив их в продакшн-эндпоинт.**
> - Тесты телеметрии (12 из 35) падают на машине разработчика, который сам от неё отказался.
>
> Отдельно есть issue «на macOS нет способа отказаться от бандлов Jcode.app и брокера уведомлений».
>
> Команда `jcode telemetry disable` существует — то есть отключение предусмотрено, — но **включено по умолчанию и не задокументировано в README**. Для инструмента, который читает весь твой код и запускает команды на машине, это стоит знать до установки, а не после.

## 5. Бизнес-модель

Сам jcode — **MIT, бесплатный, без урезанных функций**: свои ключи, свои OAuth-подписки, локальные модели. Зарабатывает компания на **хостинге инференса**:

- подписка **$10/мес** даёт **$20 кредита** на инференс (то есть первые $20 — фактически вдвое дешевле прайса провайдера);
- дальше — по факту использования со **скидкой 10 %** от цен API провайдера;
- жёсткий потолок по умолчанию **$100 за календарный месяц**, настраивается вплоть до $0;
- кредит не накапливается между месяцами.

Схема прозрачная и не влияет на функциональность бесплатной версии. Но помнить стоит: у проекта есть инвесторы и роутер, через который выгодно пропускать трафик.

## 6. Состояние проекта

**~272 открытых issue при 5 открытых PR и нескольких релизах в день.** Это профиль не заброшенного, а **очень быстро едущего** проекта: issue копятся, потому что поток пользователей больше, чем один мейнтейнер успевает закрывать, но фиксы выходят в тот же день (в списке коммитов видно `fix: … (fixes #885)` рядом с `chore(release): prepare v0.75.2`).

Свежие проблемы из трекера, чтобы понимать характер багов:

- `Bug: ui downright broken` — от 11 августа;
- TUI ломает `Shift+Space` в tmux (не сбрасывается стек протокола клавиатуры CSI u при выходе);
- строчная `i` в TUI декодируется как `Ctrl+Alt+I`;
- `AGENTS.md` перечитывается каждый ход и **инвалидирует кэш промпта провайдера** — это прямые деньги при оплате по токенам;
- stale tool results: новый вызов инструмента подставляет результат предыдущего;
- `CLAUDE_CONFIG_DIR` игнорируется при поиске конфига Claude Code;
- swarm-инструмент отказывает вне git-репозитория;
- ACP в Zed падает на MCP-серверах.

> [!tip] Практический вывод
> Версия **0.75.x**, до 1.0 далеко, ломающие мелочи в TUI — обычное дело. Ставить стоит **фиксированную версию**, а не «последнюю», и обновляться осознанно: при трёх релизах в день «просто обновиться» — это лотерея.

## 7. Установка на твоих системах

> [!warning] Штатный способ — `curl | bash`
> ```bash
> curl -fsSL https://jcode.sh/install | bash
> ```
> Это скачивание и исполнение чужого скрипта одной командой. Как минимум сначала посмотреть, что там: `curl -fsSL https://jcode.sh/install | less`. Удаление, кстати, устроено так же — `curl … uninstall.sh | bash`.

| Система | Как ставить | Нюансы |
| :--- | :--- | :--- |
| **Gentoo** (основная) | **Ebuild'а нет.** Твой путь — из исходников: `emerge dev-lang/rust`, затем `git clone` + `cargo build --release` (README документирует этот способ явно) | ⚠️ Не перепутай: `dev-perl/Jcode` в дереве — это **совершенно другой** пакет, старый перловый модуль для японских кодировок. Сборка Rust-проекта такого размера долгая; автор сам пишет, что инкрементальная отладочная сборка у него занимает около минуты |
| **Debian / Ubuntu** | Готовый бинарник `jcode-linux-x86_64.tar.gz` из релизов, либо сборка из исходников через `rustup` | В apt пакета нет и не предвидится |
| **Arch** (планируется) | AUR: **`jcode-bin`** (0.75.3, 2 голоса) — только бинарник, PKGBUILD из исходников нет | Пакет свежий и почти без голосов, PKGBUILD стоит прочитать |
| **macOS** | `brew install jcode` | Единственный «нормальный» пакетный путь |
| **Entware** (ASUS RT-AX56U) | ❌ **не применимо** | Релизов под armv7 нет (только aarch64), и агент кодинга на роутере с 512 МБ ОЗУ смысла не имеет |

## 8. Факты против хайпа

**«Топовый агент для кодинга»** — пост меряет *харнесс*, а не качество кода. jcode не улучшает модель: тот же Opus или GPT в jcode и в Claude Code думает одинаково. Выигрыш — в скорости старта, расходе памяти и оркестрации. Это много, но это другое.

**«В 245 раз быстрее»** — про первый кадр. Практическая метрика (готовность к вводу) даёт 72×, и это всё равно отличный результат.

**«28 МБ»** — про сборку без эмбеддингов. С памятью — 167 МБ на первую сессию.

**«Без лишней мишуры»** — в README есть браузерная автоматизация, iOS-приложение, десктоп-режим, боковые панели, диаграммы и info-виджеты. Это не аскетичный инструмент, это очень насыщенный.

**Малый расход памяти не бесплатен по токенам.** Сто параллельных агентов — это стократный расход контекста у провайдера. Ограничение переезжает с ОЗУ на счёт за API; смотри issue про инвалидацию кэша промпта. Следить за сессиями удобно через [abtop — мониторинг сессий ИИ-агентов](Tooling/abtop%20%E2%80%94%20htop%20%D0%B4%D0%BB%D1%8F%20AI-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BE%D0%B2%20%D0%BA%D0%BE%D0%B4%D0%B0%20%28%D0%BC%D0%BE%D0%BD%D0%B8%D1%82%D0%BE%D1%80%D0%B8%D0%BD%D0%B3%20%D1%81%D0%B5%D1%81%D1%81%D0%B8%D0%B9%20Claude%20Code-Codex-OpenCode%29.md).

**Rust не делает агента безопаснее в том смысле, который важен.** Память безопасна, а вот команды на твоей машине агент запускает те же самые. В трекере есть отдельный запрос сделать «bash risk gate» настраиваемым — то есть песочница пока не выглядит зрелой.

---

## 9. Когда брать, а когда нет

**Брать, если:**
- реально работаешь несколькими агентами параллельно — тут jcode вне конкуренции по ресурсам, и swarm с уведомлениями о правках чужих файлов решает настоящую проблему;
- раздражает трёхсекундный старт Claude Code при десятках запусков в день;
- гоняешь **локальные модели** — лёгкий харнесс освобождает ОЗУ под саму модель;
- нужен один инструмент поверх множества подписок и провайдеров;
- машина слабая, и каждые 200 МБ на счету.

**Не брать, если:**
- нужна стабильность: 0.75.x, ~272 открытых issue, релизы по три в день;
- телеметрия по умолчанию неприемлема, а разбираться с `telemetry disable` и открытыми багами вокруг него не хочется;
- работаешь одной сессией — тогда весь выигрыш сводится к экономии трёх секунд на старте;
- нужен зрелый Windows: бинарник только под aarch64;
- ждёшь, что агент станет «умнее» — качество даёт модель, а не харнесс.

Как это соотносится с остальными — в [Сводная таблица AI-агентов для программирования](%D0%A1%D0%B2%D0%BE%D0%B4%D0%BD%D0%B0%D1%8F%20%D1%82%D0%B0%D0%B1%D0%BB%D0%B8%D1%86%D0%B0%20AI-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BE%D0%B2%20%D0%B4%D0%BB%D1%8F%20%D0%BF%D1%80%D0%BE%D0%B3%D1%80%D0%B0%D0%BC%D0%BC%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F%20%28%D0%B0%D0%B2%D0%B3%D1%83%D1%81%D1%82%202026%29.md).
