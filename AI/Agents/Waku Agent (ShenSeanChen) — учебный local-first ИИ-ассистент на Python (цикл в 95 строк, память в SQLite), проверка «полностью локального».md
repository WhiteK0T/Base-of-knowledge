# Waku Agent — учебный ассистент, у которого видно все кишки

**Что это.** Персональный ИИ-ассистент на Python, написанный так, чтобы его можно было **прочитать целиком за вечер**. Автор — Sean Chen, ведущий YouTube-канала про системный дизайн ИИ; репозиторий сопровождает 20-минутный разбор на видео. Главный агентный цикл занимает 95 строк, память лежит в одном файле SQLite, разговаривать с ассистентом можно из терминала, из браузера или через Telegram.

Ключевая мысль проекта заявлена честно: это **не конкурент Claude Code, а учебное пособие**. Четыре опоры любого серьёзного агента — обвязка, цикл, память, оценка — показаны без фреймворков, которые обычно прячут самое интересное.

Пост-источник пересказал проект в целом верно, но допустил одну важную подмену и одно преувеличение по срокам.

> [!danger] Главное расхождение: «полностью ЛОКАЛЬНЫЙ» — нет
> Сам проект называет себя **local-first**, а не local, и это разные вещи. Локально работают обвязка, память, инструменты и веб-панель. **Мозг — облачный:** в файле цикла стоит `import anthropic`, а список провайдеров содержит **11 облачных API** — Anthropic, OpenAI, Gemini, DeepSeek, MiniMax, Kimi, GLM, xAI, OpenRouter, OpenCode Zen, OpenCode Go.
>
> Слов `ollama`, `llama.cpp`, `LM Studio`, `vllm` или `localhost` в модуле моделей **нет ни одного**. Без ключа к облачному провайдеру ассистент не заработает.

## 2. Что такое эти 95 строк

Цифра честная, но её стоит понимать правильно. 95 строк — это **файл цикла**, а не весь агент. Для масштаба: пакет `waku/` — это 80 файлов Python примерно на 567 КБ, плюс 64 файла тестов на 342 КБ. Крупнейшие: панель управления 52 КБ, интеграции 38 КБ, реестр моделей 23 КБ.

Но именно цикл и есть та деталь, ради которой репозиторий стоит открыть. Вот его суть дословно из `waku/loop/agent.py`:

```python
def run_loop(client, model, system, messages, tools,
             max_iterations=10, max_tokens=2048, observer=None, stream=False):
    for iteration in range(1, max_iterations + 1):
        # ---- reason: один вызов LLM с текущей рабочей памятью
        response = client.messages.create(
            model=model, system=system, messages=messages,
            tools=tools.schemas(), max_tokens=max_tokens)

        messages.append({"role": "assistant", "content": response.content})
        tool_uses = [b for b in response.content if b.type == "tool_use"]

        # ---- ограничитель 1: инструментов не просят → модель говорит с человеком
        if not tool_uses:
            result.reply = "".join(b.text for b in response.content if b.type == "text")
            return result

        # ---- act: выполнить инструменты; observe: вернуть результаты в контекст
        tool_results = []
        for call in tool_uses:
            output = tools.execute(call.name, call.input, notify=notify)
            tool_results.append({"type": "tool_result",
                                 "tool_use_id": call.id, "content": output})
        messages.append({"role": "user", "content": tool_results})

    # ---- ограничитель 2: кончились итерации
    result.reply = "(I hit my iteration limit before finishing — ...)"
```

Комментарий автора в шапке файла стоит того, чтобы его привести:

> *«Every agent framework is ultimately this while-loop with more indirection.»*

Это и есть учебная ценность. Два условия выхода: модель перестала просить инструменты (естественный конец хода) либо исчерпан лимит в 10 итераций (жёсткий стоп, чтобы не крутиться вечно). Всё остальное в любом агентном фреймворке — надстройки над этими двадцатью строками.

> [!tip] Что здесь полезно разобрать самому
> - `messages` **мутируется на месте** — после вызова список содержит всю рабочую память хода: мысли модели, вызовы инструментов, их результаты. Именно это и уходит в трассировку.
> - Стриминг сделан с откатом: любая ошибка потоковой выдачи → обычный одиночный вызов. Простой и правильный приём.
> - `observer` — единственная точка, через которую панель и трассировка видят происходящее, не вмешиваясь в логику цикла.
> - Ограничитель на итерации — то, чего часто не хватает самописным агентам, и то, что спасает от бесконечных петель и сожжённого бюджета.

## 3. Насколько он «локальный» на самом деле

Разберём по слоям, потому что ответ не «да» и не «нет».

| Слой | Где выполняется |
| :--- | :--- |
| Агентный цикл, реестр инструментов | ✅ локально |
| Память (`state.db`, SQLite + FTS5) | ✅ локально, по умолчанию |
| Веб-панель (порт 7777) | ✅ локально, на `127.0.0.1` |
| Инструменты календаря, заметок, workspace | ✅ локально |
| Голос через Kokoro | ✅ локально и офлайн (опция) |
| **Языковая модель — вся «мыслительная» часть** | ❌ **облако**, 11 провайдеров |
| Веб-поиск | ❌ облако: DuckDuckGo по умолчанию, Tavily по ключу |
| Альтернативные хранилища памяти | ❌ облако, если включить (Supabase, mem0, Zep, LangMem, Notion) |

Формулировка README — *«The dashboard is a tiny web server on your machine… Nothing leaves your laptop»* — относится **только к панели**: браузер не ходит наружу, ход обрабатывает тот же локальный процесс. Двумя абзацами ниже честно написано: *«Use the model you already pay for»* — и перечислены облачные провайдеры. Пост, судя по всему, взял первую фразу и выкинул вторую.

### Можно ли всё-таки подключить локальную модель

Готового пресета под Ollama или llama.cpp нет. Но лазейка есть: в `.env.example` задокументированы

```bash
# Advanced: point at any compatible endpoint / bring your own key var:
WAKU_BASE_URL=
WAKU_API_KEY=
```

Адаптер openai-совместимого формата уже написан, поэтому теоретически сюда можно направить локальный сервер:

```bash
# Ollama с openai-совместимым API
WAKU_PROVIDER=openai
WAKU_BASE_URL=http://localhost:11434/v1
WAKU_API_KEY=ollama
WAKU_MODEL=qwen3.6:27b
```

```bash
# llama.cpp в режиме сервера
llama-server -m model.gguf --host 127.0.0.1 --port 8080 &
WAKU_PROVIDER=openai
WAKU_BASE_URL=http://127.0.0.1:8080/v1
WAKU_API_KEY=none
```

> [!warning] Это непроверенный путь, и вот почему он может не поехать
> Цикл говорит на диалекте **Anthropic Messages** и опирается на структурированные вызовы инструментов (`tool_use` / `tool_result`). Адаптер переводит формат OpenAI в этот вид, но локальная модель должна **уверенно поддерживать function calling** — иначе агент будет молча отвечать текстом вместо вызова инструментов, и цикл выродится в обычный чат.
>
> Я такую связку не запускал и в документации проекта она не описана. Если пробовать — начинать стоит с модели, у которой tool calling заявлен явно, и сразу смотреть вкладку **Loop** в панели: если `iter` всегда равен 1 и вызовов инструментов нет, значит модель их не выдаёт.

## 4. Четыре опоры: что пост потерял

Автор формулирует так: **Harness · Loop · Memory · Eval/LLM-Ops**. Пост заменил четвёртую опору на «развитие навыков» — и зря, потому что именно **оценка** тут сделана необычно основательно для учебного проекта:

- **64 файла детерминированных тестов** в `evals/` — на календарь, память, консолидацию, шлюзы, провайдеров, граф выполнения.
- **LLM-as-judge** рядом с ними — `waku/ops/judge.py`, `scoring.py`.
- **Release gate** (`release_gate.py`) — порог качества, ниже которого версия не выпускается.
- **Memory Arena** (27 КБ) — сравнение конфигураций памяти между собой.

Показательно, какие issue автор заводит **сам на себя**:

> `#77` — *«The retrieval gate's accuracy has never been measured»*
> `#66` — *«list_events has no test coverage — and it once reported an empty calendar that wasn't»*

Для учебного репозитория это редкая и хорошая черта: слабые места названы вслух, а не заметены под ковёр. Именно поэтому странно, что пост выкинул из описания ровно эту опору.

## 5. Память: три вида и один файл

Память в проекте подана как главный герой, и устроена она по канонической схеме:

| Вид памяти | Что хранит | Где в коде |
| :--- | :--- | :--- |
| **Семантическая** | факты: «Алекс предпочитает утренние встречи» | таблица `facts` в `state.db` |
| **Эпизодическая** | эпизоды диалогов | `waku/memory/episodic/` |
| **Процедурная** | навыки — markdown «как действовать» | `.waku/skills/`, `waku/memory/procedural/` |

Плюс два механизма, которые и делают память осмысленной:

- **Retrieval gate** (`retrieval_gate.py`) — решает, **надо ли вообще** лезть в память на этот запрос. Экономит токены и снижает шум.
- **Consolidation** (`consolidation.py`) — фоновая перегонка истории чата в факты, без явной команды «запомни».

Инструмент `save_note` при этом делает ровно одну вещь — пишет строку в таблицу `facts` локальной базы:

```python
conn.execute("INSERT INTO facts (subject, content, source) VALUES (?,?,'user')",
             (subject.lower().strip(), content))
```

> [!caution] «Один файл SQLite» — правда только для настроек по умолчанию
> В репозитории лежат альтернативные бэкенды семантической памяти: **Supabase** (pgvector), **mem0**, **Zep**, **LangMem**, а для эпизодической — **Notion**. Включаются переменной вроде `WAKU_SEMANTIC_STORE=supabase`.
>
> Если их включить, память **перестаёт быть локальной** и уезжает на чужой сервер. По умолчанию этого не происходит, но при чтении поста «память в одном файле» стоит держать в голове, что это конфигурируемо.

Отдельная приятная деталь: во вкладке **Data** панели встроен браузер SQLite с таблицами, схемой и SQL-консолью только на чтение. Базу можно просто открыть и посмотреть — это и есть обещанное «Open it. Read it. It's yours».

## 6. «Развивает сама себя» — что это на самом деле

Формулировка поста наводит на мысль о самомодифицирующемся коде. Ничего подобного не происходит.

Есть инструмент **`create_skill`**: когда вы научили ассистента повторяемому порядку действий, он предлагает сохранить его как навык — **markdown-файл** в `.waku/skills/`, подхватываемый в той же сессии. Это процедурная память, ровно тот же механизм, что `SKILL.md` у Claude Code.

Есть также установка чужих навыков одной командой:

```bash
python -m waku skill install https://github.com/<user>/<repo>/blob/main/skills/<skill>/SKILL.md
```

> [!danger] Установка навыка по ссылке — это исполнение чужих инструкций
> Команда скачивает markdown с произвольного URL и кладёт его в каталог, откуда он попадает **прямо в системный промпт** вашего агента. Агент имеет доступ к календарю, файлам рабочего пространства, поиску и — на macOS — к почте и заметкам.
>
> Навык с недобрыми инструкциями — это классическая непрямая инъекция в промпт. Автор это понимает, в README прямо стоит: *«Skills are markdown — read what you install»*. Совет верный: **читайте файл перед установкой**, особенно если ставите из чужого репозитория, а не из `skills/community/`, куда PR проходят проверку CI.

Как проверять качество самих навыков — см. соседнюю заметку про [skillcheck — A/B-тест скиллов](../Skills/skillcheck%20%28sx4im%29%20%E2%80%94%20A-B-%D1%82%D0%B5%D1%81%D1%82%20%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%D0%BE%D0%B2%20%28SKILL.md%2C%20AGENTS.md%2C%20CLAUDE.md%29%20%D1%81%D0%BE%20%D1%81%D0%BB%D0%B5%D0%BF%D0%BE%D0%B9%20%D0%BE%D1%86%D0%B5%D0%BD%D0%BA%D0%BE%D0%B9%20%D0%B8%20bootstrap-CI%2C%20%D1%80%D0%B0%D0%B7%D0%B1%D0%BE%D1%80%20%D0%BC%D0%B5%D1%82%D0%BE%D0%B4%D0%B8%D0%BA%D0%B8%20%D0%B8%20%D0%B3%D0%B4%D0%B5%20%D0%BE%D0%BD%D0%B0%20%D0%B2%D1%80%D1%91%D1%82.md): там разбирается инструмент, который A/B-тестирует, помогает ли конкретный `SKILL.md` вообще хоть чему-нибудь.

## 7. Что работает на Linux, а что только на macOS

Это самый практичный раздел для вашей ситуации, и в посте он полностью выпал.

| Возможность | Linux (Gentoo/Debian/Arch) | macOS |
| :--- | :---: | :---: |
| Терминал, веб-панель, память, цикл | ✅ | ✅ |
| Telegram / Discord / WhatsApp шлюзы | ✅ | ✅ |
| Встроенный календарь (ICS + SQLite) | ✅ | ✅ |
| Google Calendar (опция `.[gcal]`) | ✅ | ✅ |
| Веб-поиск (DuckDuckGo / Tavily) | ✅ | ✅ |
| MCP-серверы (опция `.[mcp]`) | ✅ | ✅ |
| GitHub-инструменты, workspace | ✅ | ✅ |
| Notion как хранилище эпизодов | ✅ | ✅ |
| **Календарь Apple** | ❌ | ✅ |
| **Почта (Apple Mail)** | ❌ | ✅ |
| **Заметки и напоминания (Apple Notes/Reminders)** | ❌ | ✅ |
| Голос «из коробки» (`say`) | ❌ | ✅ |
| Голос через Kokoro (локально, офлайн) | ✅ | ✅ |

Проверено по коду: функции `read_apple_calendar`, `read_apple_mail`, `create_reminder`, `create_note` работают через AppleScript (`osascript`), а условие включения — буквально `sys.platform == "darwin"`. На других платформах интерфейс сообщает «macOS only».

> [!important] Вывод по почте и заметкам
> **Никакой почты на Linux нет вообще** — ни IMAP, ни Gmail API. Фраза поста «подключается к календарю, почте, заметкам» верна только для пользователя Mac. На Gentoo вы получите календарь (локальный или Google), поиск, MCP, GitHub и память — но не почту.

## 8. Установка на четырёх системах

Требуется **Python ≥ 3.11** и ключ хотя бы одного облачного провайдера.

### Gentoo (основная)

```bash
# Python 3.11+ обычно уже стоит; проверьте активный слот
eselect python list
python3 --version

# uv — рекомендованный проектом способ, ставится в домашний каталог
sudo emerge --ask dev-python/uv        # если нет в дереве:
#   curl -LsSf https://astral.sh/uv/install.sh | sh

git clone https://github.com/ShenSeanChen/waku-agent && cd waku-agent
uv venv && uv pip install -e .
cp .env.example .env                    # вписать провайдера и ключ
uv run waku                             # терминал
uv run waku dashboard                   # панель → http://localhost:7777
```

Опциональные наборы ставятся так же: `uv pip install -e '.[mcp]'`, `'.[gcal]'`, `'.[eval]'`.

> [!tip] Про MCP на Gentoo
> Большинство MCP-серверов из экосистемы — на Node. Если планируете ими пользоваться, понадобится `net-libs/nodejs` с USE-флагом `npm`. Демонстрационный сервер в репозитории при этом на чистом Python и Node не требует — начать можно с него:
> ```bash
> cp examples/mcp.demo.json .waku/mcp.json
> ```

### Debian / Ubuntu

На Debian 13 (trixie) и Ubuntu 24.04+ штатного Python 3.11+ достаточно:

```bash
sudo apt install -y python3 python3-venv python3-pip git
pip install waku-agent          # или клонировать репозиторий, как выше
waku
```

На Debian 12 (bookworm) системный Python — 3.11, тоже подходит. Ставить в системный Python не стоит, PEP 668 этого и не даст — используйте `venv` или `uv`.

### Arch

```bash
sudo pacman -S python python-pip git uv
git clone https://github.com/ShenSeanChen/waku-agent && cd waku-agent
uv venv && uv pip install -e .
```

Пакета в AUR под waku-agent нет.

### Entware (ASUS RT-AX56U)

> [!caution] Неприменимо
> Формально `opkg` даёт Python 3, и цикл — обычный HTTP-клиент, так что теоретически что-то запустится. Практически смысла нет: 512 МБ ОЗУ и 256 МБ flash, зависимости `anthropic` + `openai` + FTS5-база, а веб-панель и голосовой шлюз на роутере не нужны никому.
>
> Единственный осмысленный сценарий для роутера — **Telegram-шлюз** как всегда доступная точка входа. Но и его правильнее держать на десктопе или VPS: ассистенту всё равно нужен постоянный доступ к облачной модели, и роутер тут ничего не добавляет.

## 9. Итог

**Что действительно хорошо:**
- **Учебная ценность настоящая.** Цикл в 95 строк с комментариями — лучшее объяснение того, как работает агент, из виденного в открытом доступе. Обещание «прочитать за вечер» выполнимо.
- **Опора на оценку.** 64 файла детерминированных тестов, LLM-судья, релизный гейт и арена памяти — для учебного проекта это заметно выше среднего.
- **Память разобрана всерьёз:** три вида, гейт извлечения, консолидация. Не «положили всё в вектора и надеемся».
- **Автор честен.** «Local-first», а не «local»; issue на собственные непокрытые места; предупреждение читать устанавливаемые навыки.
- **Панель управления,** где видно каждый шаг хода — гейт, вызов инструмента, обновление памяти.
- MIT, 11 провайдеров, включая [OpenCode Zen](../ProxyLLM/OpenCode%20Zen%20%E2%80%94%20%D0%B1%D0%B5%D1%81%D0%BF%D0%BB%D0%B0%D1%82%D0%BD%D1%8B%D0%B5%20%D0%BC%D0%BE%D0%B4%D0%B5%D0%BB%D0%B8%20%D0%B4%D0%BB%D1%8F%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BE%D0%B2%20%D0%BA%D0%BE%D0%B4%D0%B0%20%28%D0%BF%D1%80%D0%BE%D0%B2%D0%B5%D1%80%D0%BA%D0%B0%20%C2%AB%D0%BC%D0%B8%D0%BB%D0%BB%D0%B8%D0%B0%D1%80%D0%B4%D0%B0%20%D1%82%D0%BE%D0%BA%D0%B5%D0%BD%D0%BE%D0%B2%C2%BB%3A%20%D1%80%D0%B5%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D0%B5%20%D0%BB%D0%B8%D0%BC%D0%B8%D1%82%D1%8B%20%D0%B8%20%D1%87%D0%B5%D0%BC%20%D0%BF%D0%BB%D0%B0%D1%82%D0%B8%D1%88%D1%8C%20%D0%B2%D0%BC%D0%B5%D1%81%D1%82%D0%BE%20%D0%B4%D0%B5%D0%BD%D0%B5%D0%B3%29.md) и OpenRouter с бесплатными моделями по умолчанию.

**Что нужно держать в голове:**
- **Не «полностью локальный».** Без облачного ключа не работает; локальную модель можно попробовать подключить через `WAKU_BASE_URL`, но это непроверенный путь и он требует уверенного function calling.
- Проекту месяц, версия **0.1.1**, статус Beta, автор фактически один.
- **95 строк — это цикл, а не агент.** Вся система — около 567 КБ Python.
- Почта и заметки — **только macOS**. На Linux этих интеграций нет.
- «Развивает сама себя» = сохраняет markdown-навыки, а не переписывает код.
- «Один файл SQLite» верно по умолчанию; включение Supabase/mem0/Zep/Notion уводит память в облако.
- Установка навыка по URL — поверхность для инъекции в промпт.

**Кому пригодится:** тому, кто хочет **понять**, как устроены агенты, а не просто пользоваться готовым. Как учебник — отличный: маленький цикл, честные комментарии, видео-разбор, живые тесты. Как повседневный ассистент на Linux — сыровато и без почты; для этого есть [Claude Code — гайд](Claude%20Code%20%E2%80%94%20%D0%B3%D0%B0%D0%B9%D0%B4.md) и другие зрелые инструменты.

**Отдельно ценно:** если вы пишете своего агента, `waku/loop/agent.py` стоит прочитать целиком до того, как тянуть LangGraph или подобное. Возможно, окажется, что фреймворк вам не нужен — а это, судя по всему, ровно то, что автор и хотел донести.
