# 🧠 Memora — постоянная память для ИИ-агентов через MCP

**[Memora](https://github.com/agentic-box/memora)** — MCP-сервер памяти для ИИ-агентов. Агент сохраняет в него факты, решения, задачи и документы между сессиями, а потом находит их семантическим поиском. Хранилище — SQLite (локально или в облаке), связи между записями видны в веб-интерфейсе в виде графа.

| :--- | :--- |
| Лицензия / язык | **MIT** · Python 3.10+ |
| Звёзды / форки | 738 · 80, проект с сентября 2025 |
| Версия | **0.4.6** в репозитории (23.09.2026); на PyPI пакет `memora-mcp` отстаёт — **0.3.3** |
| Разработка | практически один автор (`spokV`, 529 коммитов из ~535) |

> [!info] Уточнение к посту
> Memora — это **MCP-сервер**, а не библиотека для конкретных фреймворков. Упоминаний **LangChain и AutoGPT в репозитории нет**. Подключается к любому клиенту с поддержкой MCP: в README есть готовые настройки для **Claude Code** и **Codex CLI**, для Claude Code есть ещё и плагин с хуками.

## 1. Что умеет

**Хранение**
- SQLite локально или с синхронизацией в облако: S3, Cloudflare R2 (с шифрованием), Cloudflare D1;
- несколько хранилищ в одном процессе (`/mcp/<имя>`), разделы и подразделы, экспорт и импорт;
- **документы**: Markdown разбивается на фрагменты (утверждения, пункты плана, риски), каждый ищется отдельно, документ целиком тоже доступен.

**Absorb и история знаний**
- `absorb`: новые факты отдаются LLM, она сравнивает их с хранилищем и решает — дубль, обновление, противоречие, связанная запись или новая. Дубли пропускаются, связи проставляются. Есть пробный режим `dry_run`;
- **устаревшее не удаляется, а заменяется**: поиск по умолчанию идёт по цепочке к актуальной версии, но вся история остаётся;
- `memory_digest(тема)` за один вызов возвращает связанные записи, открытые задачи и ошибки, связи и источники.

**Поиск**
- гибридный: полнотекстовый + векторный, фильтры по датам и тегам (AND/OR/NOT);
- эмбеддинги: **OpenAI (по умолчанию)**, локальные `sentence-transformers` или простой TF-IDF;
- поиск и слияние дубликатов через LLM.

**Интерфейс**
- веб-граф знаний (по умолчанию `http://localhost:8765`) с кластерами;
- чат с памятью (RAG) прямо в веб-интерфейсе;
- статистика, поиск устаревших записей, история всех операций;
- уведомления для обмена между агентами, интеграция с Neovim.

## 2. Установка

Memora ставится через `pip`, поэтому способ одинаковый для всех дистрибутивов. Ставьте в отдельное окружение через `pipx`:

| Система | Подготовка |
| :--- | :--- |
| **Gentoo** | `emerge --ask dev-python/pipx` |
| **Debian / Ubuntu** | `sudo apt install pipx` |
| **Arch** | `sudo pacman -S python-pipx` |
| **Entware** | не подходит: нужны `openai`, `boto3`, а для локальных эмбеддингов — PyTorch |

```bash
# последняя версия из репозитория (на PyPI — устаревшая 0.3.3)
pipx install "git+https://github.com/agentic-box/memora.git"

# с локальными эмбеддингами без внешнего API (PyTorch, около 2 ГБ)
pipx install "memora-mcp[local] @ git+https://github.com/agentic-box/memora.git"

memora-server info
```

> [!warning] Не перепутайте пакет
> На PyPI пакет называется **`memora-mcp`**. Пакет `memora` без суффикса — посторонний проект. В README плагина для Claude Code всё ещё встречаются старые команды (`agentic-mcp-tools/memora.git`, `memora[local]`) — используйте команды из основного README.

Контейнерный вариант из README рассчитан **только на macOS 26 с Apple Silicon** (Apple `container` + LaunchAgent). На Linux используйте установку через pip.

### Подключение к Claude Code

`.mcp.json` в корне проекта (или через `claude mcp add`):

```json
{
  "mcpServers": {
    "memora": {
      "command": "memora-server",
      "env": {
        "MEMORA_DB_PATH": "~/.local/share/memora/memories.db",
        "MEMORA_ALLOW_ANY_TAG": "1",
        "MEMORA_GRAPH_PORT": "8765",
        "MEMORA_EMBEDDING_MODEL": "sentence-transformers",
        "MEMORA_LLM_ENABLED": "0"
      }
    }
  }
}
```

Две последние переменные включают **полностью локальный режим**: эмбеддинги считаются на своей машине, LLM для поиска дублей отключена. С ними данные никуда не уходят. Без них нужен `OPENAI_API_KEY`.

Учтите, что `absorb` и чат с памятью без LLM не работают: им нужна модель для классификации и ответов. Если они нужны без облака, можно попробовать указать локальную OpenAI-совместимую модель через `OPENAI_BASE_URL` (например, Ollama). В README такой вариант не описан, так что сначала проверьте его на тестовой базе.

### Подключение к Codex CLI

```toml
# ~/.codex/config.toml
[mcp_servers.memora]
command = "memora-server"
args = ["--no-graph"]
env = { MEMORA_DB_PATH = "~/.local/share/memora/memories.db", MEMORA_ALLOW_ANY_TAG = "1" }
```

### Плагин для Claude Code

В каталоге `claude-plugin/` — плагин с хуками:
- **SessionStart** ищет в памяти записи по текущему проекту и подставляет их в начало сессии;
- **PostToolUse** сам сохраняет значимые действия: git-коммиты, результаты тестов, веб-поиск, правки документации.

## 3. Нюансы

- **По умолчанию текст уходит в OpenAI.** Эмбеддинги по умолчанию считает OpenAI (`text-embedding-3-small`), а `absorb`, поиск дублей и чат используют `gpt-4o-mini`. С плагином туда автоматически попадают коммиты, результаты тестов и прочее. Для приватного кода включите локальный режим (см. выше).
- **Тихий откат на TF-IDF.** Если эндпоинт эмбеддингов сломан или не существует (например, `OPENAI_BASE_URL` указывает на OpenRouter, у которого нет эмбеддингов), Memora молча переходит на простой поиск по словам и выглядит исправной. Автор советует ставить **`MEMORA_EMBEDDING_STRICT=1`**, чтобы ошибка была видна.
- **Ключи эмбеддингов задаются парой**: `MEMORA_EMBEDDING_API_KEY` и `MEMORA_EMBEDDING_BASE_URL` — либо обе, либо ни одной. Иначе сервер откажется стартовать: так ключ одного провайдера не уйдёт на чужой хост.
- **Смена модели эмбеддингов** (или эндпоинта) требует ручной перестройки векторов.
- **Веб-граф** слушает порт 8765 — не открывайте его наружу; на сервере используйте `--no-graph` или доступ через SSH-туннель.
- **Один разработчик и быстрые изменения.** Версия ещё 0.x, зависимость `mcp` жёстко закреплена на 1.27, PyPI отстаёт от репозитория.
