# 🏗️ Code Modernization — плагин Claude Code для миграции легаси-кода

**Code Modernization** — официальный плагин Anthropic для Claude Code: ведёт старый проект через анализ, извлечение бизнес-правил, план, саму миграцию и **проверку, что новый код ведёт себя как старый**. Подходит для любого языка и трёх видов работ:

- **uplift** — новая версия той же технологии (Java 8 → 17, Spring Boot 2 → 3, .NET Framework → .NET 8, Python 2 → 3);
- **transform** — переписать на другой стек по одному модулю (COBOL → Java, PHP → Python/FastAPI, AngularJS → React);
- **reimagine** — пересобрать на новой архитектуре (монолит → REST-сервисы).

| | |
| :--- | :--- |
| Где лежит | официальный маркетплейс [`claude-plugins-official`](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/code-modernization) |
| Версия | **1.0.0** (25.09.2026); первые коммиты — апрель 2026, всего около 60 |
| Лицензия | Apache-2.0 — команды, агенты и сценарии можно форкнуть под свой стек |
| Состав | 13 команд, 8 агентов, 6 многоагентных сценариев (workflows), Python-скрипты проверки и отчёта, хуки |

Всё описанное в посте подтверждается: анализ архитектуры и зависимостей, план, помощь в переходе на новые технологии, тесты и сравнение поведения старой и новой версий, а финальное одобрение — за человеком.

---

## 1. Установка

```
/plugin install code-modernization@claude-plugins-official
```

Нужен Claude Code. Желательно (команда `preflight` проверит сама):

| | Gentoo | Debian / Ubuntu | Arch |
| :--- | :--- | :--- | :--- |
| Python 3.8+ (карта, план, отчёт, проверка) | `dev-lang/python` | `python3` | `python` |
| Подсчёт строк кода | `dev-util/cloc` | `cloc` | `cloc` |

Вместо `cloc` можно [`scc`](https://github.com/boyter/scc) — в репозиториях его нет, ставится через `go install github.com/boyter/scc/v3@latest`. Плюс сборочный инструментарий самого проекта (JDK, .NET SDK, компилятор COBOL и т.п.): с ним плагин может **запустить старый и новый код рядом** — это самая сильная проверка. Entware не подходит: Claude Code с плагином работает на рабочей машине.

## 2. Как работать

Откройте пустую папку для работы и наберите:

```
/code-modernization:modernize
```

Команда задаст пару вопросов (что хотите сделать с кодом), запишет ответы в `analysis/<имя>/INTENT.md` и выдаст точную первую команду. Если цель пока неясна — выберите **«Understand it first»**: получите оценку, карту, бизнес-правила и план без переписывания.

Код не копируется: `--source <путь>` делает ссылку `legacy/<имя>`. **Исходники плагин не меняет** — пишет только в `analysis/<имя>/` и `modernized/`.

### Шаги

| № | Команда (`/code-modernization:…`) | Что даёт |
| :---: | :--- | :--- |
| 0 | `modernize` | цель работы → `INTENT.md` |
| 1 | `modernize-preflight <имя> [стек] --source <путь>` | готово ли окружение: пять вопросов к человеку (вся ли это система, собирается ли здесь, есть ли своя сборка, пытались ли раньше, что трогать нельзя), пробная сборка |
| 2 | `modernize-assess <имя>` | инвентаризация, сложность, техдолг, безопасность, рекомендуемый путь. `--portfolio <каталог>` — сравнить много систем на одной странице |
| 3 | `modernize-map <имя>` | интерактивная карта: зависимости, потоки данных, точки входа |
| 4 | `modernize-extract-rules <имя>` | бизнес-правила карточками Given/When/Then со ссылкой `файл:строка`; каждое перепроверяет второй агент |
| 4b | `modernize-review <имя>` | человек подтверждает или правит сомнительные правила |
| 5 | `modernize-brief <имя> [стек]` | поэтапный план. **Пока его не одобрят, ничего не строится** |
| 6 | `modernize-uplift` / `modernize-transform` / `modernize-reimagine` | сама миграция |
| 7 | `modernize-verify <имя>` | **доказательство**: независимая перепроверка, вердикт по каждому модулю |
| 8 | `modernize-harden <имя>` | поиск уязвимостей в старом коде и патч, который вы применяете сами |
| — | `modernize-status <имя>` | где вы сейчас и какую команду запускать дальше |

Каждая команда обновляет `analysis/<имя>/REPORT.html` — одну страницу со всем найденным (работает без интернета). Для смены версии (uplift) достаточно `preflight → assess → uplift → verify`, правила и ревью можно пропустить.

**Человек решает в шести местах**, и плагин их за вас не решает: ответы preflight, неверные правила, одобрение плана, принятие найденных различий, подпись под доказательством, применение патча безопасности.

## 3. Как доказывается эквивалентность

Главное отличие от «попросить агента переписать». `modernize-verify` лучше запускать **в новой сессии** — он не верит заметкам сборки и всё перепроверяет:

- **Тесты с нуля** — результат сборки удаляется, весь набор запускается заново, числа берутся из файлов отчёта тест-раннера. Прогон, где не выполнилось ни одного теста, — провал.
- **Старое и новое на одних входах** — если старый код можно запустить, оба работают на одних данных, скрипт сравнивает вывод побайтно. Маскируются только поля, которые обязаны отличаться (время, ID); числа с плавающей точкой — в объявленном допуске.
- **Входы, которых никто не использовал** — не меньше десяти новых: границы, пустые, огромные, битые записи.
- **Тесты, способные упасть** — намеренная поломка в одну строку («канарейка») обязана сделать тесты красными.
- **Каждое критичное (P0) правило** должно быть покрыто тестом, который реально выполнился.
- **Исходники не тронуты** — проверка по времени изменения файлов.

Вердикт по модулю считает скрипт `scripts/proof_pack.py`, а не модель: **PROVEN**, **PARTLY PROVEN** (с перечнем, чего не хватает) или **NOT PROVEN**. Если старую систему здесь не запустить (мейнфрейм, только прод), лучший возможный вердикт — PARTLY PROVEN.

## 4. На чём пробовали (из README)

| Проект | Миграция | Итог |
| :--- | :--- | :--- |
| AWS CardDemo (COBOL, CICS) | → Java 21 | 35 правил, 213 тестов; пять проверок подряд нашли расхождения с настоящим COBOL, последняя — ещё 7 → **NOT PROVEN** |
| Eclipse Jetty (2 600 файлов) | Java 8 → 17 | 946 тестов одинаково на обеих версиях; сборка нашла 6 изменений, которых чтение кода не предсказало |
| osCommerce (PHP 5) | → Python + FastAPI | страница товара: 17 957 тестов, 17 727 сравнений с PHP идентичны → **PROVEN** |
| JPetStore | → REST API | 6 из 24 новых сравнений отличаются → **NOT PROVEN** |
| Spring PetClinic | Boot 2.6 → 3.3 | каталог изменений: 59 импортов `javax`, запрос, отвечавший 200 и теперь 400 |
| Код с ловушками | — | внедрённые инструкции в комментариях, README, `CLAUDE.md` и настройках не выполнены, исходники не изменены |

Честно описаны и неудачи: пилот, остановленный планом, прогоны, упёршиеся в ограничения тестовой машины. Повторный запуск может дать другие числа (правила извлекает модель).

## 5. Стоит знать

### Расход лимитов

Тяжёлые шаги запускают **много агентов параллельно**: `extract-rules` в тестах — от 50 до 200 агентов (перед большим запуском спрашивает). Ориентиры на системе в десятки тысяч строк: preflight 3–4 мин, assess 5–8, map и extract-rules по 5–15, один модуль — 15–30 мин. **Начинайте с одного модуля**, а не со всей системы.

### Защита исходников

Плагин не меняет исходники по соглашению, а README советует закрепить это правилом в `.claude/settings.json` рабочей папки:

```json
{
  "permissions": {
    "allow": ["Read(**)", "Edit(analysis/**)", "Edit(modernized/**)"],
    "deny": ["Edit(/legacy/**)"]
  }
}
```

Так как `legacy/<имя>` — ссылка, запрет надо продублировать на настоящий путь (`"Edit(//path/to/code/**)"`) и добавить его в `additionalDirectories`. Правило не действует на скрипты, которые открывают файлы сами, поэтому для шагов с массовой записью (`uplift` и `reimagine`) держите Bash в режиме с подтверждением.

Анализируемый код считается **недоверенным**: внедрённые в него инструкции агенты перечисляют в отчёте, но не выполняют. Найденные секреты маскируются (`AKIA****`) и складываются в отдельный файл, исключённый из git.

### Телеметрия (включена по умолчанию)

Плагин отправляет **только целые числа** — какая команда запущена, сколько найдено правил, ОС и версия Python, коды ошибок; не код, не пути и не тексты. Сам плагин в сеть не ходит: числа уходят через телеметрию Claude Code, поэтому при выключенной телеметрии Claude Code не отправляется ничего. Один раз на версию плагина при старте сессии счётчик отправляется даже без использования команд. Посмотреть, что уйдёт: `python3 scripts/telemetry.py show <папка>` из каталога плагина. Выключить — любым из способов:

```bash
export CODE_MODERNIZATION_TELEMETRY=0          # только этот плагин
export DISABLE_TELEMETRY=1                     # вся телеметрия Claude Code
```

или опция **Usage counts** в настройках плагина.

### Прочее

- **Живая панель прогресса** (карта, колода ревью правил, подпись плана) — ранний доступ, нужен запуск `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude`.
- Состояние хранится в файлах (`INTENT.md`, `PREFLIGHT.md`, план), а не в чате — работу может продолжить коллега или новая сессия. Коммитить `analysis/` и `modernized/` плагин не будет, это делаете вы.
- В режиме `claude -p` фоновые шаги обрываются через 10 минут — нужен `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0`.
- Рядом есть отдельный набор [code-migration-kit-with-claude-code](https://github.com/anthropics/code-migration-kit-with-claude-code) — промпты, шаблоны и скрипты для больших миграций между языками без пошаговых команд.
