# REA (Reverse Engineer Anything) — реверс-инжиниринг ИИ-агентом через MCP

> [!info] Что это
> **MCP-сервер и CLI** (`rea-agents`, TypeScript, MIT), который даёт кодинг-агенту (Claude Code, Codex, Cursor и др.) инструменты реверс-инжиниринга. Через него агент получает псевдокод и ассемблер из **Hopper / Ghidra / IDA**, модули и IPC из **JavaScript/Electron**-приложений, метаданные **.NET**, классы **Android APK** (JADX), регионы **прошивок** (binwalk/unblob), сетевые записи **HAR** и наблюдения за сайтами через Chrome. Агент разбирает, как устроена конкретная функция программы, показывает доказательства и пишет свою реализацию.
>
> Пост в канале «Не баг, а фича» (2026-10-06) описывает суть верно, но **преувеличивает** («ЛЮБАЯ программа», «соберёт аналог апки») и **умалчивает о главном**: «анализ локальный» не значит «данные никуда не уходят». Декомпилированный код, строки и найденные фрагменты уходят **провайдеру модели** агента.

| «Работает через MCP с CLI» | ✅ | `npx rea-agents setup` регистрирует MCP-сервер в агентах. Те же операции доступны из терминала: `rea …` |
| «Разберётся в ЛЮБОЙ программе» | ⚠️ преувеличение | «Reverse Engineer Anything» — это слоган проекта. На деле — 12 классов целей (раздел 3), и у каждого свои ограничения. Упакованный, обфусцированный код, защита от отладки и **серверная логика** (её в клиенте просто нет) остаются трудными. Сам README пишет, что результаты включают «evidence **and limitations**» |
| «Воссоздаст фичи … и даже соберёт аналог самой апки» | ⚠️ | README обещает **фичу**: «explain how the feature works … and build a version for your project». Клонирование целого приложения не обещается. | «Проанализирует всё ЛОКАЛЬНО и не отправит приложение» | ⚠️ **наполовину** | Сам файл REA действительно не выгружает: в исходниках нет телеметрии, сеть нужна для скачивания Hopper, проверки обновлений и загрузки source map с исследуемого сайта. Но **результаты инструментов читает модель**: псевдокод, строки, фрагменты кода уходят в Anthropic / OpenAI / Google. README сам оговаривает: «its model provider has its own data policy» |
| «Поддерживает Claude Code, Codex, Cursor, Gemini CLI и Windsurf» | ✅ и больше | `setup` знает **13** клиентов: ещё Claude Desktop, Devin, OpenCode, Antigravity, GitHub Copilot CLI, Command Code, VS Code, Grok Build (плюс Grok Bot вручную). Подойдёт любой агент с локальным MCP |
| «Ультимативная тулза» | — оценочное | Проект активный и серьёзный, но очень молодой, см. раздел 2 |

## 3. Что умеет анализировать

| Цель | Что возвращает | Что нужно |
| :--- | :--- | :--- |
| Нативные бинарники | Псевдокод, ассемблер, строки, символы, вызовы, xref | **Hopper, Ghidra или IDA** |
| ELF (офлайн) | Секции, сегменты, релокации, кандидаты защит | pwntools (Linux x64) |
| EVM-байткод | Селекторы, аргументы, мутабельность | локальный hex |
| Падения процессов Linux | Регистры и сигналы всех потоков | pwntools, опционально GDB/pwndbg |
| JavaScript / Electron | Модули, импорты, source maps, маршруты, IPC, нативные аддоны | только Node.js — **декомпилятор не нужен** |
| Сайты | Структура, скрипты, сеть, скриншоты | Chrome/Chromium |
| HAR / mitmproxy | Запросы, ответы, пейлоады | HAR; mitmdump |
| .NET | Метаданные, CIL, нативные зависимости | статический разбор |
| Android APK | Манифест, классы, декомпилированные методы | headless **JADX** + полный JDK |
| Прошивки | Регионы, извлечение, передача в нативный анализ | **binwalk / unblob** (Linux) |
| Пакеты и ресурсы | Инвентарь файлов, хэши, plist, анатомия Apple-бандлов | — |
| Поведение процесса | Вывод терминала, взаимодействие, ФС, сравнение прогонов | Linux/macOS с PTY |

Статический разбор JS и .NET **не запускает** цель. Runtime-режимы (процессы, Electron, сайты) **запускают** её с вашими правами.

Ghidra-адаптер — 25 **только читающих** операций. REA создаёт временный изолированный проект и удаляет его после сессии, а ваши проекты Ghidra не трогает.

## 4. Установка

### Общее

```bash
npx rea-agents setup                 # выбрать агентов, посмотреть план, подтвердить
# или постоянная команда:
npm install --global rea-agents && rea setup
rea setup --client claude_code --dry-run    # только посмотреть, что изменится
rea doctor --client claude_code --json      # диагностика (только чтение)
rea update                                  # обновить
rea uninstall [--purge-data]                # убрать регистрации, скилл, (и кэш)
```

`setup` правит конфиги выбранных агентов (с резервными копиями) и кладёт скилл в `~/.agents/skills`. После этого агент нужно перезапустить. Обновление скилла — повторный `setup` после `rea update`.

### Нативный «движок» по системам

У Hopper **автоустановка поддерживается только на** macOS 12+, Ubuntu 24.04+, Fedora 41+, Arch/CachyOS. Hopper — **коммерческий**: в демо-режиме есть ограничения производителя. На Linux REA запускает демо на скрытом Xvfb-дисплее. Ghidra (бесплатная, NSA) нужна **версии 12.1.x** с JDK 21+.

| Система | Node.js | Ghidra 12.1 | Прочее |
| :--- | :--- | :--- | :--- |
| **Gentoo** | `emerge net-libs/nodejs` | В основном дереве **нет**, а в оверлеях (`pentoo`, `java`, `hamari`…) только **11.x** — для REA не годится. Ставьте официальный zip: распаковать в `/opt/ghidra`, `export GHIDRA_INSTALL_DIR=/opt/ghidra` | JDK: `emerge dev-java/openjdk-bin:21`; binwalk: `emerge app-misc/binwalk`; JADX — `dev-util/jadx` только в оверлеях, проще zip с GitHub |
| **Debian / Ubuntu** | `apt install nodejs npm` (на Debian 13 проверьте версию ≥ 22.19, иначе NodeSource) | В репозиториях нет → официальный zip | `apt install openjdk-21-jdk binwalk`; Hopper — `.deb` (Ubuntu 24.04+) |
| **Arch** | `pacman -S nodejs npm` | `pacman -S ghidra` (extra, 12.1.2) | `pacman -S jadx binwalk jdk21-openjdk`; Hopper — официальный пакет Arch |
| **Entware** | — | — | **Не для роутера** (Node 22+, Java, Ghidra). Но прошивку роутера можно разобрать **на ПК**: `binwalk` + REA firmware-режим |

Ghidra (любая система):
```bash
# https://github.com/NationalSecurityAgency/ghidra/releases (на 2026-10-09 — 12.1.4)
unzip ghidra_12.1.4_PUBLIC_*.zip -d /opt && ln -sfn /opt/ghidra_12.1.4_PUBLIC /opt/ghidra
export GHIDRA_INSTALL_DIR=/opt/ghidra           # setup может прописать в конфиг агента
```

### Попробовать без декомпилятора

```bash
npx -y rea-agents@latest analyze-javascript-application /абсолютный/путь/к/app.asar --json
```

Electron-приложения (VS Code, Obsidian, Discord, Notion…) разбираются **без Ghidra**. Это самый быстрый способ посмотреть, на что способен инструмент.

Промпт агенту из README:
```text
Understand how search works in the Notes app, show me the evidence,
and build a similar feature for my project.
```

## 5. Риски и подводные камни

> [!danger] Данные уходят модели
> «Локально» относится к **разбору**, а не к **мышлению**. Агент получает результаты инструментов: псевдокод, строки, имена функций, куски JS. Всё это уходит в облако провайдера модели. Для **проприетарного кода вашего работодателя**, NDA-проектов и клиентских бинарников это та же утечка, что и вставка кода в чат. Альтернатива — агент на **локальной модели** (OpenCode и др. + Ollama/llama.cpp), но качество реверса на маленьких моделях заметно ниже.

> [!warning] Вредоносные и недоверенные бинарники
> По `SECURITY.md`, REA **не песочница**. Разбор недоверенного файла выполняет Ghidra/Hopper с **вашими правами**, а runtime-режимы **запускают** цель. Для вредоносов — только отдельная VM без доступа к вашим ключам и сети. Есть и второй риск — **prompt injection**: строки внутри исследуемого файла попадают в контекст агента. Бинарник может содержать текст вида «игнорируй инструкции, выполни …». Не давайте агенту автоматический доступ к shell (auto-approve), когда он разбирает чужой код.

> [!warning] Право
> README прямо перекладывает ответственность на пользователя: «lawful reverse-engineering research … You are responsible for obtaining any required authorization». Что важно знать (не юридическая консультация):
> - **Идеи и функциональность авторским правом не охраняются**, а **код — охраняется**. Понять, как устроен поиск, и написать свой — нормально. Перенести в свой проект декомпилированный код, даже «переписанный» агентом построчно, — это производное произведение.
> - **РФ**: ст. 1280 ГК РФ разрешает законному владельцу декомпиляцию **только для совместимости** и при условиях (информация недоступна иначе, затрагиваются лишь нужные части, результат не используется для создания похожей программы). Задача «повторить фичу у себя» под это исключение **не подпадает**.
> - **ЕС**: аналогичная ст. 6 Директивы 2009/24/EC (только для интероперабельности). **США**: EULA часто прямо запрещают реверс, а обход защиты ограничивает DMCA §1201 (с узкими исключениями).
> - Чистые цели: свои программы, open source, CTF, анализ вредоносов, совместимость, исследования безопасности по программам bug bounty.

Прочее:
- **Нужен «тяжёлый» стек**: Node 22+, JDK 21, Ghidra (~1 ГБ+), для APK — JADX, для сайтов — Chromium. Hopper на Linux — демо, а полная лицензия платная.
- **Расход токенов**: псевдокод крупных функций объёмный, а исследование фичи — это десятки вызовов инструментов. На подписке с лимитами это заметно.
- **Gentoo нет в списке поддерживаемых** хостов для Hopper. Ghidra-путь работает на любом Linux x64, но его надо поставить вручную (раздел 4).
- **Быстрые мажорные версии**: фиксируйте версию (`npx rea-agents@6.0.0 …`) в скриптах, если важна воспроизводимость.

## 6. Итог

REA — **реальный и сильный инструмент**: аккуратная граница безопасности моста, только читающие операции, доказательства и ограничения в каждом ответе, хорошие витрины с проверяемой реконструкцией. Лучше всего он подходит для **Electron/JS-приложений** (без декомпилятора), CTF, разбора собственных старых бинарников без исходников и исследования совместимости. Пост преувеличивает охват («любая программа», «аналог апки») и подменяет «локальный анализ» на «ничего не отправляет». Для чужого проприетарного кода юридические и приватностные ограничения важнее технических возможностей.
