## Что обещает пост

Пост «Не баг, а фича» ([26873](https://t.me/bugnotfeature/26873)):

1. «Экономим **96% токенов** на кодинге»;
2. «Claude Code, который тратил на сложную задачу **8 минут**, с инструментом тратит **2 минуты**»;
3. Индексирует структуру репозитория вместо простого чтения файлов;
4. Автоматически создаёт документацию для каждого файла и модуля;
5. Строит граф зависимостей;
6. Анализирует историю git и показывает проблемные участки;
7. Находит неиспользуемый код и устаревшие зависимости;
8. Извлекает архитектурные решения из коммитов и комментариев;
9. «Разрабы говорят, что можно снизить стоимость вайбкодинга **аж до 36%**».

## Что это на самом деле

Идея одной фразой: **любой вопрос агента про репозиторий имеет ответ, который можно посчитать заранее**. Кто вызывает эту функцию? Что сломается, если её изменить? Почему код написан именно так? Без индекса агент каждый раз переоткрывает ответ: grep, read, re-read, забыл.

repowise строит пять слоёв индекса и отдаёт их агенту через **10 MCP-инструментов**:

| Слой | Что даёт | Нужна ли модель |
| :--- | :--- | :---: |
| **Граф** | зависимости файлов и символов, разрешение вызовов, сообщества, центральность, циклы | нет |
| **Git** | горячие точки, владельцы, совместные изменения, bus factor, история багфиксов | нет |
| **Документация** | вики по каждому модулю и файлу с оценкой свежести, гибридный поиск | нет (проза — опция) |
| **Решения** | архитектурные обоснования из 5 источников, каждое утверждение со ссылкой на доказательство | 6 из 7 источников — нет |
| **Здоровье кода** | 49 детекторов: риск дефектов, поддерживаемость, производительность, план рефакторинга | нет |

Ключевое: **граф, git, здоровье, оценка риска, тесты, мёртвый код и разбор PR не делают ни одного вызова LLM**. Это статический анализ, а не «ещё одна обёртка над моделью».

Десять MCP-инструментов сделаны «под задачу», а не «под сущность»: можно передать несколько целей в один вызов и получить полный контекст. README приводит пример — *«добавь rate limiting ко всем API-эндпоинтам»* за 5 вызовов вместо ~30 grep-ов и чтений.

Отдельная фича, которую пост не упомянул вообще, а она едва ли не самая полезная: **`repowise distill`** — сжатие вывода shell-команд **до того**, как агент их прочитает. Ошибки вперёд, код возврата сохранён, каждое сокращение оставляет маркер `[repowise#<ref>]`, обратимый через `repowise expand`.

Ставил в чистый venv на Python 3.14.6, телеметрию отключал через `DO_NOT_TRACK=1`.

Тянутся они безусловно, даже если вы собираетесь работать полностью офлайн через `--no-prose`. Это не блокер, но знать про гигабайт до установки полезно.

### Экономия токенов — считал сам, `tiktoken` (`o200k_base`)

**Карточка контекста против чтения файла целиком:**

| Файл | `Read` целиком | `repowise context` | Экономия |
| :--- | ---: | ---: | ---: |
| `requests/sessions.py` | 7 372 ток. | 2 068 ток. | **−71,9%** |
| `requests/models.py` | 9 117 ток. | 2 299 ток. | **−74,8%** |
| `requests/adapters.py` | 5 961 ток. | 1 657 ток. | **−72,2%** |

**`repowise distill` на реальных командах:**

| Команда | Сырой вывод | После distill | Экономия |
| :--- | ---: | ---: | ---: |
| `git log -50` | 16 110 ток. | 755 ток. | **−95,3%** |
| `git log -20 --stat` | 10 166 ток. | 755 ток. | **−92,6%** |
| `ls -laR` (каталог с кодом) | 1 778 ток. | 396 ток. | **−77,7%** |
| `git diff HEAD~5 --stat` | 97 ток. | 97 ток. | 0% (мелкое проходит нетронутым) |

README обещает на `git log -50` 89% — у меня вышло 95,3%, то есть **лучше заявленного**. Обратимость проверил: маркер `[repowise#a535ecb50a0d: 777 lines omitted (~11606 tokens)]`, команда `repowise expand a535ecb50a0d` вернула все 799 строк.

> [!important] Почему это всё равно не «−96% за сессию»
> Мои −72% на карточке контекста и −95% на distill — это экономия **на конкретном чтении**. Но агент не только читает: он рассуждает, пишет код, вызывает инструменты. И `CLAUDE.md`, который repowise сам себе генерирует, содержит честную оговорку: *«Pre-edit, not instead-of-edit… Claude Code requires a raw Read of any file you will Edit, and that Read is correct and expected»*.
>
> То есть карточка решает, **какие** файлы читать, а не заменяет чтение. Поэтому 70–95% на отдельных вызовах превращаются в 15–32% по сессии — и это не обман, а нормальная арифметика.

## Редкий случай: документация честнее рекламы

Обычно в этих разборах я ловлю проект на завышении. Здесь наоборот — **проект сам себя занижает**, и это стоит отметить.

Что я нашёл в `docs/BENCHMARKS.md`:

- **Отдельный раздел про «лёгкое число»**: *«This is the measurement almost every tool in this category publishes, and we are labelling it as such»* — про те самые 35,6×. И тут же: *«It says our representation of a commit is smaller than the commit, not that an agent finishes faster»*.
- **Объяснение, как из 35× делают 209×**: пулинг против среднего по отношениям. *«A one-line commit where get_context returns 40 tokens contributes a huge ratio… That is how a 35x becomes a 209x in a press release»*.
- **Публикуют строки, где проигрывают**: CodeGraph строит полный индекс в 22 раза быстрее. Дословно: *«If a call graph is all you need, that is the right trade and you should take it»*.
- **Называют конкурента вторым местом**: *«CodeGraph is a genuine second at −24.4%, and the honest reading is that we lead a field in which more than one tool works»*.
- **Дисквалифицируют собственный результат**: один прогон на Opus провалил свой же контроль (−9,3% когда инструмент вызывался против −10,7% когда не вызывался), и токены из него **не цитируются ни для кого, включая себя**.
- **Признают нестабильность**: колонка «агент вообще вызвал инструмент» на Claude Code дала 15/15, а повторные прогоны в другие дни — 4/15 и 3/15. Комментарий: *«Treat that column as unstable, including our own 15 of 15»*.

Статистика приводится с n, p-значениями, знаковыми тестами и **запечатанной** выборкой (42 инстанса, отложенные от всех раундов улучшений). Для инструмента из этой категории — редкость.

## Что важно знать до установки

### Claude Code — самый слабый из измеренных харнессов

Пост ставит Claude Code первым в списке. По собственным замерам проекта это как раз **худший случай**:

| Харнесс | Экономия выходных токенов |
| :--- | ---: |
| Codex (n=43, django) | **−31,6%** |
| `qwen3:8b` под Ollama, локальные инструменты | −47,9% (и −41,5% по времени) |
| **Claude Code, `claude-sonnet-5` (n=15)** | **−15,9%** |

Причина объяснена в бенчмарках: Claude Code подгружает схемы MCP-инструментов по требованию, поэтому агент должен сначала *пойти их искать* — и часто не идёт. В том же прогоне `code-review-graph` не был вызван **ни разу за 15 вопросов**, Graphify — трижды.

Практический вывод: в Claude Code стоит **явно просить** агента пользоваться инструментами repowise, иначе он может о них просто не вспомнить. Хуки (`repowise hook install`) частично решают это, проталкивая контекст в сессию сами.

### `init` пишет в ваш репозиторий

После `repowise init` в проекте появилось:

```console
$ git status --short
?? .claude/          # CLAUDE.md с описанием инструментов, 5 091 байт
?? .mcp.json
?? .repowise/        # сам индекс, 3,6 МБ
?? .vscode/          # mcp.json + extensions.json
```

Инструмент об этом честно сообщает («Written to your repo (not gitignored)»), но **в `.gitignore` ничего не добавляет**. Если не хотите — `repowise init --no-editor-setup`, а `.repowise/` добавьте в `.gitignore` руками. Иначе рискуете закоммитить индекс.

Мелочь, которую заметил: `repowise update` всё равно перезаписал `.vscode/mcp.json`, хотя при `init` я передавал `--no-editor-setup`.

### Телеметрия включена по умолчанию

```console
$ repowise telemetry status
Telemetry: enabled
```

Собираются, по заявлению README, «имена команд и грубое окружение». Отключается тремя способами: `repowise telemetry disable`, переменная `DO_NOT_TRACK=1` или полностью офлайновый режим. Я работал с `DO_NOT_TRACK=1`.

### Лицензия AGPL-3.0

Не MIT. Для личного и внутрикорпоративного использования бесплатно и без обязательств. Но AGPL — **сетевой копилефт**: если вы поднимете repowise как сервис для внешних пользователей, придётся открывать производные. Для этого случая продаётся коммерческая лицензия. Тарифы на сайте: Pro $15/мес, Teams $20 за место (минимум 3), Enterprise по запросу. Сам инструмент при self-host бесплатен, и **ни один язык за коммерческую лицензию не спрятан**.

### Что работает без ключей, а что нет

Без единого API-ключа работает: граф, git-аналитика, здоровье кода, мёртвый код, оценка риска, структурная вики, полнотекстовый поиск, distill. Проверил `repowise ask` без ключей — выдал ответ со ссылками на файлы и списком «читать дальше».

Ключ (или Ollama) нужен для: прозы в вики, семантического поиска (нужен эмбеддер), археологии комментариев, `get_answer` в MCP-режиме. Полностью офлайн — Ollama плюс локальная модель эмбеддингов.

## Установка по системам

Требуется Python ≥ 3.11 и git. Компиляция не нужна — все зависимости идут колёсами.

> [!tip] Всегда в venv или через pipx
> 130+ пакетов на гигабайт в системный Python тащить нельзя. Правильный способ — `pipx`, он сам изолирует и кладёт `repowise` в `PATH`.

### Gentoo (основная)

```bash
sudo emerge --ask dev-python/pipx
pipx install repowise

cd /path/to/repo
export DO_NOT_TRACK=1          # телеметрия по умолчанию включена
repowise init --no-prose -y --no-editor-setup
echo ".repowise/" >> .gitignore
repowise serve                 # дашборд на http://localhost:3000
```

Всё ставится колёсами `manylinux`, так что многочасовой сборки, как с `dev-lang/rust` или chromium, здесь нет — установка заняла у меня 42 секунды. Если хотите полностью офлайн, добавьте [Ollama](../../Local-LLM/Ollama%20%E2%80%94%20%D0%BC%D0%B5%D0%BD%D0%B5%D0%B4%D0%B6%D0%B5%D1%80%20%D0%B8%20%D1%81%D0%B5%D1%80%D0%B2%D0%B5%D1%80%20%D0%BB%D0%BE%D0%BA%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D1%85%20LLM.md) — он же закроет семантический поиск.

### Debian / Ubuntu

```bash
sudo apt install pipx git
pipx ensurepath
pipx install repowise
```

В стабильных ветках Python 3.11–3.12 — подходит. На старых LTS с Python 3.10 не поставится (`requires_python >=3.11`), понадобится deadsnakes PPA.

### Arch (планируется с июня 2026)

```bash
sudo pacman -S python-pipx git
pipx install repowise
```

Пакета в AUR нет. Python в Arch 3.13+ — совместим, я проверял даже на 3.14.6.

### Entware (ASUS RT-AX56U)

> [!danger] Не встанет и не нужно
> Три независимых блокера:
> 1. **1 ГБ зависимостей** против 256 МБ флеша на роутере;
> 2. `pyarrow`, `lancedb`, `scipy`, `numpy` — нативные расширения, колёс под `armv7` у них нет, а собирать из исходников на 512 МБ ОЗУ бессмысленно;
> 3. индексация — это `tree-sitter` по всем файлам плюс NetworkX-графы, нагрузка не для роутерного CPU.
>
> Правильная схема, если очень нужно: **индексировать на десктопе, а на роутер класть только результат**. Каталог `.repowise/` — это SQLite (`wiki.db`) плюс JSON-граф, 3,6–7,6 МБ на средний репозиторий. Читать его на роутере можно обычным `sqlite3` из `opkg`, но MCP-сервер там поднимать всё равно незачем: агент живёт на десктопе.
