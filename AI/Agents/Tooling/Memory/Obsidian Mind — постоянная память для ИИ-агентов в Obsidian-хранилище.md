# 🧠 Obsidian Mind — постоянная память для ИИ-агентов в Obsidian-хранилище

**Obsidian Mind** ([github.com/breferrari/obsidian-mind](https://github.com/breferrari/obsidian-mind)) — **шаблон Obsidian-хранилища**, который даёт кодинг-агентам память между сессиями. Полная поддержка — у [Claude Code](../../Claude%20Code%20%E2%80%94%20%D0%B3%D0%B0%D0%B9%D0%B4.md), для Codex CLI и Gemini CLI работают те же хуки и команды.

Как это работает:
- в начале сессии агент получает контекст: цели, активные проекты, свежие изменения, открытые задачи;
- по ходу работы он сам ведёт структурированные заметки — решения, профили людей, инциденты, достижения;
- всё это — обычные Markdown-файлы в отдельном Obsidian-хранилище, их можно читать и править вручную.

## 🧩 Как устроено

**Память живёт в хранилище, а не в модели.** Долговременные знания лежат в тематических заметках `brain/` (под git, со ссылками). Авто-память Claude Code (`~/.claude/.../MEMORY.md`) служит только индексом, который указывает на нужные места в хранилище. Поэтому память переживает смену машины и видна в графе Obsidian.

**В контекст попадает не всё хранилище, а выжимка.** Контекст модели конечен, и проект это учитывает:
- в начале сессии подгружаются выдержки из ключевых файлов, сводка git и список файлов — в пределах заданного бюджета;
- каждую инъекцию сопровождает строка с её размером;
- остальное агент находит по запросу — через QMD или `grep` и Obsidian CLI.

Целиком кодовую базу в память не грузят: хранятся решения, задачи, люди, инциденты.

**Жизненный цикл сессии держат хуки:**

| Хук | Когда | Что делает |
| :--- | :--- | :--- |
| SessionStart | старт и возобновление | переиндексирует QMD, подставляет цели (North Star), активную работу, свежие изменения, задачи и список файлов |
| UserPromptSubmit | каждое сообщение | определяет тип записи (решение, инцидент, достижение, 1:1, архитектура, человек, проект) и подсказывает, куда её положить |
| PostToolUse | после записи `.md` | проверяет frontmatter и wikilinks, не даёт класть файлы памяти не туда, отмечает слишком большие заметки |
| PreCompact | перед сжатием контекста | сохраняет стенограмму сессии в `thinking/session-logs/` |
| Stop | после каждого ответа | проверяет «гигиену» хранилища и отдаёт отчёт агенту со следующим сообщением |

### Мод для Claude Code (с v9.0)

На Claude Code **2.1.287+** хранилище ставит мод — плагин в `.claude/skills/obsidian-mind/`, который запускает те же скрипты хуков, но меняет доставку их вывода:
- контекст сессии приходит как **файл инструкций** (как `CLAUDE.md`): переживает `/compact` и `/clear` целиком, доходит до субагентов и не обрезается на лимите вывода хуков в 10 000 символов;
- отчёт Stop превращается в одну строку под ответом, а полный отчёт агент получает со следующим сообщением.

Где мод не загружается, хуки работают как раньше: в Codex, Gemini, старых версиях Claude Code, при запуске из подкаталога хранилища.

> [!warning] Мод — это код без песочницы
> Он выполняется с вашими правами и загружается только после того, как вы подтвердите доверие к папке. Перед этим стоит посмотреть, что он делает: `claude plugin validate .claude/skills/obsidian-mind` выводит все события и вызовы. Выключить мод можно так — в `.claude/settings.local.json`: `"enabledPlugins": { "obsidian-mind@skills-dir": false }`.

## 🗂️ Команды

Всего 20 команд с префиксом `/om-`. Основные:

| Команда | Что делает |
| :--- | :--- |
| `/om-standup` | утренний старт: цели, активные проекты, открытые задачи, свежие изменения в git, приоритеты |
| `/om-dump <текст>` | свободный «брейн-дамп» — раскладывает сказанное по нужным заметкам |
| `/om-wrap-up` (или «wrap up») | итог сессии: проверка заметок, индексов и ссылок, поиск незафиксированных достижений |
| `/om-weekly` | недельная сводка: закономерности между сессиями, сверка с целями |
| `/om-capture-1on1`, `/om-prep-1on1`, `/om-meeting`, `/om-intake` | встречи: запись, подготовка, разбор входящих заметок |
| `/om-incident-capture <ссылка>` | разбор инцидента из Slack: таймлайн, причина, участники |
| `/om-self-review`, `/om-review-peer`, `/om-review-brief` | подготовка к ревью — своему и коллег |
| `/om-tidy`, `/om-vault-audit`, `/om-correct` | обслуживание: архивация, разбиение, поиск сирот и устаревшего, исправление факта во всех местах |
| `/om-vault-upgrade` | обновление хранилища через ShardMind с сохранением ваших правок |

> [!info] Это память про работу в целом, не только про код
> Судя по командам и примерам, основной упор — на рабочий контекст: 1:1 с руководителем, профили коллег (`org/people/`), записи решений, **Brag Doc** (лог достижений для ревью), разбор инцидентов. Получается «второй мозг» рабочей жизни с агентом-секретарём; для памяти по коду он тоже годится.

## 🔍 QMD — семантический поиск

[QMD](https://github.com/tobi/qmd) формально необязателен: без него агент ищет через `grep` и Obsidian CLI. Но на нём держится большая часть «умного» поиска, и субагенты тоже ходят в него первым делом. Он подключается как MCP-сервер (`mcp__qmd__query` и др.) и работает **локально, без ключей**, на трёх небольших моделях:

| Модель | Размер | Задача |
| :--- | ---: | :--- |
| `embeddinggemma-300M` | ~328 МБ | векторы заметок и запросов |
| `qmd-query-expansion-1.7B` | ~1,28 ГБ | переписывает запрос в удачные поисковые термины |
| `Qwen3-Reranker-0.6B` | ~640 МБ | пересортировывает найденное по релевантности |

Итого около 2,2 ГБ, скачиваются при первом использовании. Есть GPU — QMD использует CUDA или Metal, нет — работает на CPU. Нужна версия **2.5.1+**. Если тяжёлые модели не нужны, `qmd search` (обычный BM25) работает вообще без моделей.

## 🛠️ Установка

```bash
npm install -g shardmind          # для обновлений нужен ShardMind 0.1.7+
mkdir my-vault && cd my-vault
shardmind install github:breferrari/obsidian-mind

# опционально — семантический поиск
npm install -g @tobilu/qmd
node --experimental-strip-types .scripts/qmd-bootstrap.ts
```

Дальше:
1. открыть папку как хранилище в Obsidian;
2. включить Obsidian CLI (Settings → General);
3. запустить агента в корне хранилища: `claude`, `codex` или `gemini`.

Вместо мастера ShardMind можно просто сделать `git clone` — содержимое будет тем же. [ShardMind](https://github.com/breferrari/shardmind) — «пакетный менеджер» шаблонов хранилищ того же автора. Он спрашивает имя, цели и нужные модули, а при обновлении делает трёхстороннее слияние с вашими правками. Если удалить `.shardmind/`, хранилище продолжит работать как обычный клон.

Скрипты хуков — это TypeScript, который Node запускает напрямую с флагом `--experimental-strip-types`, поэтому нужен Node 22.6+.

> [!tip] Тебе это особенно близко — ты и так живёшь в Obsidian
> У тебя уже есть Obsidian-хранилище (эта база знаний). Obsidian Mind — **отдельное** хранилище под память агента; не смешивай его с личной базой сразу, а поставь отдельно и посмотри протокол заметок. Часть идей — записи решений, индексы, бюджет инъекции с замером размера — можно перенять и без установки.

## 🖥️ Применимость на системах владельца

| Система | Как поставить |
| :--- | :--- |
| **Gentoo** (основная) | `emerge --ask net-libs/nodejs` (стабильные 24.x и 26.x подходят). Obsidian в основном дереве нет: есть в оверлее `gentoo-zh` (`app-office/obsidian`, `~amd64`), либо Flatpak или AppImage |
| **Debian / Ubuntu** | Node 22+ из NodeSource или `nvm` (штатный `nodejs` в Debian 13 — 20.x); Obsidian — `.deb` с obsidian.md или Flatpak |
| **Arch** | `sudo pacman -S nodejs npm obsidian` |
| **Entware / RT-AX56U** | ➖ не для запуска: Node в Entware — 18.x, десктопа нет. Роутер может разве что хранить файлы хранилища по сети |
