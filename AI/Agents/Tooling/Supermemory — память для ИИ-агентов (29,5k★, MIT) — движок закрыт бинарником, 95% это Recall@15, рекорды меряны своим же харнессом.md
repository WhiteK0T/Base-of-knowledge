# 🧠 Supermemory — память для ИИ-агентов: что забирается, а что остаётся у вендора

**Supermemory** ([github.com/supermemoryai/supermemory](https://github.com/supermemoryai/supermemory)) — движок памяти и контекста для ИИ: извлекает факты из диалогов, строит профиль пользователя, разрешает противоречия и «забывает» протухшее. **29 568★, 2583 форка, MIT**, живёт с 27.02.2024, разработка активная (пуш сегодня). Компания из Сан-Франциско, продукт коммерческий: есть API, тарифы и «Talk to sales».

> [!warning] Коротко
> Проект серьёзный, цифры не выдуманы — но три уточнения меняют картину.
> **Первое:** «забираем» — забираются **SDK, MCP-прокси, документация и UI-компоненты**. Самого движка памяти в репозитории **нет**: `supermemory-server` поставляется только готовым бинарником в релизах (**298 МБ** под linux-x64), исходников и сборочного workflow в репозитории не существует.
> **Второе:** «95 % восстановления» — это **Recall@15** на LongMemEval, то есть нужный факт попал в топ-15 найденного. Не точность ответов и не «95 % памяти».
> **Третье:** «первое место на всех основных бенчмарках» — **самозаявленный результат**. Ни у LongMemEval, ни у LoCoMo, ни у ConvoMem нет публичного лидерборда, и ни в одном из трёх репозиториев Supermemory не упоминается. Замеры сделаны их собственным харнессом MemoryBench.

## 📦 Что реально лежит в репозитории

772 файла, 146 МБ. Разложил по каталогам:

| Каталог | Размер | Что это |
| :--- | ---: | :--- |
| `apps/docs` | **66 МБ** | документация (больше половины репозитория) |
| `apps/mcp` | 812 КБ | MCP-сервер — ходит в `https://api.supermemory.ai` |
| `apps/web` | 2,9 МБ | последний коммит: *«reduce the app to a redirect shell, drop the browser extension»* |
| `apps/raycast-extension`, `*-playground` | 6,3 МБ | расширение и песочницы |
| `packages/*-sdk-*`, `ai-sdk`, `tools` | ~1,8 МБ | SDK под TypeScript/Python, обёртки под Vercel AI SDK, Mastra, LangChain и т.д. |
| `packages/memory-graph` | 392 КБ | *«Interactive graph visualization component»* — виджет визуализации, не движок |
| `packages/ui`, `hooks`, `lib`, `validation` | ~600 КБ | компоненты и утилиты |

**Чего нет:** ни каталога с сервером или движком, ни Rust, ни Go, ни единого `Dockerfile`. Из 12 GitHub-workflow ни один не собирает `supermemory-server` — они публикуют только npm/PyPI-пакеты SDK.

### Как поставляется движок

```bash
curl -fsSL https://supermemory.ai/install | bash
```

Скрипт (прочитал, не запуская) тянет ассет из релизов **того же репозитория**, тег `server-v<версия>`. Последний — `server-v0.0.8` от 17.08.2026:

| Платформа | Размер | Скачиваний |
| :--- | ---: | ---: |
| linux-x64 | **297,8 МБ** | 1583 |
| windows-x64.exe | 277,8 МБ | 324 |
| linux-arm64 | 269,4 МБ | 259 |
| darwin-x64 | 272,7 МБ | 26 |
| darwin-arm64 | 258,2 МБ | 589 |

> [!tip] Гигиена установщика — на уровне
> В отличие от многих «портативных» поделок, тут всё сделано правильно: скачивается `manifest.json` с **sha256 для каждой платформы**, контрольная сумма проверяется, версию можно закрепить (`bash -s -- 0.0.3`), есть предупреждение делать бэкап данных перед откатом. Локальный сервер защищён автогенерируемым API-ключом, а не открыт всем подряд.

Формально документация называет этот бинарник *«free, open source»*. Бесплатный — да. Открытых исходников у него в репозитории нет.

## 📈 Что означают цифры

### 95 % — это Recall@15, а не точность ответов

**LongMemEval** ([xiaowu0162/LongMemEval](https://github.com/xiaowu0162/LongMemEval), MIT, 1077★) — 500 вопросов на пять способностей долговременной памяти. В варианте `longmemeval_s` вся история диалогов на один вопрос — **~115k токенов (~40 сессий)**, в `longmemeval_m` — около 500 сессий.

Supermemory отчитывается по **Recall@15**: нужное воспоминание оказалось среди пятнадцати выданных. Это метрика **поиска**, а не ответа — модель ещё должна из этих пятнадцати кусков собрать правильный ответ. Разбивка из их README: Knowledge Updates 99 %, Assistant recall 100 %, User recall 97 %, Multi-session 93 %, Temporal Reasoning 91 %, Preference 90 %.

### 99,4 % — честная арифметика

720 токенов вместо 115 000 — это ровно 99,37 %. Тут придраться не к чему, цифра сходится с первоисточником бенчмарка. Заявлены также 99,6 % при @10 и 99,8 % при @5 — логично, меньше выдач, меньше токенов, ниже recall.

### «Первое место» проверить нельзя

| Бенчмарк | Статус | Лидерборд | Упоминает Supermemory |
| :--- | :--- | :--- | :--- |
| **LongMemEval** | жив, MIT, пуш 11.05.2026 | нет | нет |
| **LoCoMo** (snap-research) | пуш **13.08.2024** — два года тишины | нет | нет |
| **ConvoMem** | ссылка в README **битая** (`Salesforce/ConvoMem` → 404), настоящий репозиторий — `SalesforceAIResearch/ConvoMem`, 25★ | нет | нет |

Ни один из трёх не ведёт таблицу результатов. Значит «#1 on every major AI memory benchmark» — утверждение вендора о самом себе, полученное собственным инструментом.

Справедливости ради: **MemoryBench** ([supermemoryai/memorybench](https://github.com/supermemoryai/memorybench), MIT, 314★) действительно открыт и умеет гонять `supermemory`, `mem0` и `zep` на одних и тех же данных, с метрикой из трёх частей (качество, задержка, стоимость) — авторы прямо пишут, что схлопывать их в одно число неправильно. То есть проверить их заявление **можно самому**, что уже лучше, чем ничего. Но чужой независимой проверки на данный момент нет.

## ⚠️ Бенчмарки меряны не тем, что вы скачаете

Это ключевой момент, и он написан в их же документации **дважды**:

> In production, Supermemory runs **proprietary models tuned for long-horizon data understanding**. Self-hosted, you bring any model.

И в сравнении Local с Enterprise:

> Local runs the extraction pipeline on whatever model you bring. Enterprise runs it on Supermemory's **proprietary models** … **higher-quality memories** at a lower effective cost than any bring-your-own-key setup.

То есть рекордные 95 % получены на облачной конфигурации с закрытыми моделями вендора. Локальный бинарник использует **твою** модель (OpenAI, Anthropic, Gemini, Groq, Ollama) — и по признанию самих авторов качество памяти там ниже. Насколько — не опубликовано.

## 🖥️ Локальный запуск: чего он стоит по железу

Из их же `configuration.mdx`:

```
[ingest] memory limit 1.0 GB above baseline (1.6 GB) · 2 concurrent
```

- **Базовое потребление после загрузки — ~1,6 ГБ RAM**, плюс до **+1 ГБ** на индексацию (`SUPERMEMORY_EMBEDDING_RAM_LIMIT`, по умолчанию 1 ГБ). Итого рабочий набор около **2,6 ГБ**.
- Порт **6767**, данные в `./.supermemory` (одна папка — легко бэкапить и переносить).
- Эмбеддинги по умолчанию локальные — `Xenova/bge-base-en-v1.5`, 768 измерений, без ключа. Можно переключить на OpenAI, Gemini или Ollama.
- LLM обязателен хотя бы один. Полностью офлайн — через Ollama.
- Картинки, видео и «высокоточные» PDF требуют ключа **Gemini или Vertex AI**; текст работает с любым провайдером.

> [!warning] Версия 0.0.x — и это заметно
> Читая примечания к релизу `server-v0.0.8`: *«Upgrading an rc store to 0.0.7 **silently wiped search vectors**… документы оставались в списке, но поиск по ним ничего не возвращал»*. Починили автолечением при загрузке, но осадок показательный: движку меньше года, схема данных ещё едет, и документация сама просит делать бэкап каталога перед откатом версии.

## 💻 По системам

Пакета нет ни в одном дистрибутиве — только установщик или npm/PyPI-SDK. Бинарник — **готовый, не собирается из исходников** (их нет).

### Gentoo (основная)

```bash
# SDK и MCP — из исходников, тут всё честно
emerge -av net-libs/nodejs        # для npx/SDK
# движок — только готовый бинарь:
curl -fsSL https://supermemory.ai/install | bash   # linux-x64, 298 МБ
```

Собрать движок портежем нельзя — исходников нет. Если принципиально не ставить чужие бинарники, остаётся облачный API либо связка «MCP + свой бэкенд». `sys-apps/bubblewrap` (0.12.0) или контейнер — разумная мера, если бинарник всё же запускать.

### Debian / Ubuntu

```bash
sudo apt install curl nodejs npm
curl -fsSL https://supermemory.ai/install | bash
npm install supermemory        # или: pip install supermemory
```

### Arch (с июня 2026)

```bash
sudo pacman -S curl nodejs npm
curl -fsSL https://supermemory.ai/install | bash
```

В AUR пакета нет.

### Entware / ASUS RT-AX56U (armv7, 512 МБ RAM, 256 МБ flash)

❌ **Исключено по трём причинам сразу:** сборок под **armv7 нет** (только linux-x64 и linux-arm64), бинарник весит **298 МБ** при 256 МБ flash, а базовое потребление в **1,6 ГБ RAM** втрое больше всей памяти роутера.

Единственный применимый на роутере сценарий — облачный MCP-эндпоинт (`https://mcp.supermemory.ai/mcp`) из клиента на нормальной машине; роутер тут не участвует вообще.
