# 🔬 OpenResearch (alphaXiv) — кодинг-агенты как исследователи

## 🌳 Главное: параллельные агенты в изолированных worktree

Ради чего вообще стоит смотреть на проект — таблица возможностей из README, по-русски:

| Что даёт | Как устроено |
| :--- | :--- |
| **Параллельное исследование** | Каждому направлению — отдельная сессия агента и **свой git worktree**. Агенты не топчутся в одной рабочей копии |
| **Воспроизводимые эксперименты** | Варианты отслеживаются в **git-native дереве экспериментов**; каждый прогон получает неизменяемый архив своего коммита |
| **Доказательства в контексте** | Логи, диффы, файлы, результаты и артефакты привязаны к породившей их работе |
| **Выбор агента** | Claude Code, Codex, OpenCode или Cursor — харнесс и модель выбираются **на сессию** |
| **Выбор вычислителя** | Локально, на своей инфраструктуре или на managed-компьюте OpenResearch |
| **Локальное владение** | Проекты, переписки, эксперименты, прогоны, логи, код и артефакты остаются на машине |

Тот же зафиксированный снапшот исходников можно запустить локально, **по SSH**, или на Slurm, Kubernetes, Ray, Hugging Face Jobs, Modal, Tinker. Публиковать репозиторий не требуется.

> [!tip] Идея не уникальна — но здесь она доведена до исследовательского цикла
> Параллельные агенты в git-worktree уже разобраны в заметке про [Orca](Orca%20%28stablyai%29%20%E2%80%94%20%D0%BF%D0%B0%D1%80%D0%B0%D0%BB%D0%BB%D0%B5%D0%BB%D1%8C%D0%BD%D1%8B%D0%B5%20%D0%BA%D0%BE%D0%B4%D0%B8%D0%BD%D0%B3-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D1%8B%20%D0%B2%20git-worktree%20%28MIT%2C%20Linux%20%D0%B5%D1%81%D1%82%D1%8C%3B%202713%20issue%20%D0%B8%202912%20PR%3B%20%D0%B2%20Arch%20orca%20%E2%80%94%20%D1%8D%D1%82%D0%BE%20%D1%81%D0%BA%D1%80%D0%B8%D0%BD%D1%80%D0%B8%D0%B4%D0%B5%D1%80%29.md). Разница в надстройке: Orca — про параллельный **кодинг**, OpenResearch — про цикл «гипотеза → эксперимент → доказательства → следующая гипотеза» с деревом экспериментов и архивом прогонов.

### 🔄 Autoresearch — что это за «автономность»

Формулировка README: система может крутить полный цикл сама — **предложить идею, изменить код, запустить эксперимент, изучить результаты и решить, что пробовать дальше**. Несколько агентов при этом исследуют разные направления параллельно, а дерево экспериментов хранит их родословную.

Ключевое слово здесь — **эксперимент над кодом**. Это инструмент для ML/науки о данных, где «эксперимент» = прогон обучения или замера с изменёнными параметрами. Для условного веб-проекта «автономный исследователь» выродится в обычного кодинг-агента с красивым деревом веток.

## 📚 «Вся литература» — это arXiv

Из полезного в CLI:

```sh
orx discover keyword <query>     # поиск по ключевому слову
orx paper <arxiv-id-or-doi>      # разбор конкретной статьи
```

Отсюда и потолок: **arXiv — это препринты без рецензирования**. Всё, что лежит за пейволлами Elsevier, Springer и IEEE, а также медицинский корпус PubMed, в охват не попадает. Для CS/ML это терпимо — там arXiv действительно основная площадка. Для любой другой области «изучит ВСЮ литературу» — рекламная фраза.

## 🏠 «Локально» — разберём по слоям

Пост говорит «обрабатывается локально», и это правда ровно на треть. Три разных слоя:

| Слой | Где выполняется | Комментарий |
| :--- | :--- | :--- |
| **Оркестрация** (дашборд, проекты, SQLite, worktree, логи) | ✅ Локально, `127.0.0.1` | *«Creating a project or launching a run does not publish your code»* |
| **Сам агент** (Claude Code, Codex, Cursor) | ❌ **Облако** | Код и промпты уходят в Anthropic / OpenAI по обычным API-ключам |
| **Телеметрия** официальных сборок | ⚠️ Облако, **opt-out** | Случайный ID установки + грубые события |

> [!important] Полностью локальный режим существует, но он один
> Единственный по-настоящему офлайновый путь — **харнесс OpenCode + локальная модель** (LM Studio, oMLX, Ollama или свой OpenAI-совместимый эндпоинт). Все остальные комбинации отправляют твой код наружу. Это не упрёк проекту — авторы честно пишут «local ownership» про **данные workspace**, а не про инференс. Упрёк — посту, который сворачивает это в «обрабатывается локально».

## ⚠️ Три вещи, о которых пост молчит

> [!caution] 1. Удалённый режим — без аутентификации
> Про `orx up --remote user@host` README говорит прямым текстом:
>
> > *«The remote service binds to loopback and has no application-level authentication, so other users on that host can reach it.»*
>
> То есть на **многопользовательском** сервере (университетский кластер, общая GPU-машина) любой локальный пользователь достучится до твоего workspace: проекты, логи, код, артефакты. Loopback тут не защита — он отсекает сеть, но не соседей по хосту. Если хост общий — либо не поднимай `--remote`, либо изолируй контейнером/своим пользователем.

> [!warning] 2. Телеметрия включена по умолчанию
> Официальные релизные сборки шлют **opt-out** аналитику: случайный ID установки и грубые события. Авторы перечисляют, чего в ней **нет** — кода, промптов, содержимого и путей файлов, имён репозиториев, токенов, почт, идентификаторов проектов и экспериментов. Сборки из исходников аналитику не шлют вовсе. Выключается так:
>
> ```sh
> orx telemetry off        # отключить насовсем
> orx telemetry status     # проверить состояние
> orx <command> --no-telemetry   # разово
> ```

> [!note] 3. `curl | sh` — что именно делает установщик
> Проверил скрипт из релиза. Сгенерирован **cargo-dist 0.32.0**, и ведёт себя прилично, но пару вещей стоит знать:
>
> - ставит в **`$CARGO_HOME/bin`**, по умолчанию `~/.cargo/bin` — странное место, если Rust тебе не нужен. Переопределяется `OPENRESEARCH_CLI_INSTALL_DIR`;
> - **правит шелл-конфиги** (`.profile`, `.bashrc`, `.zshrc`, fish), дописывая PATH. Отключается `OPENRESEARCH_CLI_NO_MODIFY_PATH=1`;
> - **sudo не требует** — всё в домашний каталог;
> - **проверяет SHA256** скачанных архивов (контрольные суммы зашиты в скрипт), но **цифровых подписей нет**. Если `sha256sum` в системе отсутствует, проверка молча пропускается.

## 💻 Установка на твоих системах

Бинарники под Linux собраны **статически против musl** — значит работают одинаково на Gentoo, Debian и Arch, независимо от версии glibc.

```sh
# как предлагают авторы
curl -LsSf https://openresearch.sh/install.sh | sh
orx up          # дашборд на http://127.0.0.1:4791

# аккуратнее: скачать, прочитать, потом ставить, и не в ~/.cargo/bin
curl -LsSf https://openresearch.sh/install.sh -o orx-install.sh
less orx-install.sh
OPENRESEARCH_CLI_INSTALL_DIR="$HOME/.local/bin" \
OPENRESEARCH_CLI_NO_MODIFY_PATH=1 sh orx-install.sh

orx telemetry off
orx install-skills    # поставить скилл OpenResearch в поддерживаемых агентов
```

| Система | Что делать |
| :--- | :--- |
| **Gentoo** (основная) | В Portage пакета нет. Либо установщик выше (musl-бинарь x86_64), либо сборка из исходников: `git clone` + `cargo build --release` (`dev-lang/rust` и так стоит). Второй путь ещё и отключает телеметрию — сборки из исходников её не шлют |
| **Debian / Ubuntu** | Тот же установщик; в репозиториях пакета нет |
| **Arch** | Аналогично; в официальных репо и AUR на момент заметки пакета нет — ставь установщиком или собирай `cargo` |
| **Entware / RT-AX56U** | ❌ Неприменимо. Готовых бинарников под **armv7** нет вовсе (только `aarch64-unknown-linux-musl` и `x86_64`), а 512 МБ ОЗУ не потянут ни агента, ни эксперименты |
| **VPS (7950X3D, без GPU)** | ⚠️ Оркестрация поедет, но «эксперименты» для ML без GPU бессмысленны. И помни про `--remote` без аутентификации, если на VPS есть другие пользователи |

Команды на каждый день:

```sh
orx projects                 # список проектов
orx project view <id>        # обзор проекта
orx runs <project-id>        # прогоны
orx logs <run-id>            # логи прогона
orx exp run <experiment-id>  # запустить эксперимент
```

## 🧠 Локальные модели: требования жёстче, чем кажется

Подключение локальной модели идёт **только через харнесс OpenCode** (Настройки → Harnesses → OpenCode → Add Local Model). Адреса по умолчанию:

| Приложение | Эндпоинт |
| :--- | :--- |
| [LM Studio](../../Local-LLM/LM%20Studio%20%E2%80%94%20%D0%B4%D0%B5%D1%81%D0%BA%D1%82%D0%BE%D0%BF-GUI%20%D0%B4%D0%BB%D1%8F%20%D0%BB%D0%BE%D0%BA%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D1%85%20LLM.md) | `http://127.0.0.1:1234/v1` |
| [Ollama](../../Local-LLM/Ollama%20%E2%80%94%20%D0%BC%D0%B5%D0%BD%D0%B5%D0%B4%D0%B6%D0%B5%D1%80%20%D0%B8%20%D1%81%D0%B5%D1%80%D0%B2%D0%B5%D1%80%20%D0%BB%D0%BE%D0%BA%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D1%85%20LLM.md) | `http://127.0.0.1:11434/v1` |
| oMLX (Apple Silicon) | `http://127.0.0.1:8000/v1` |
| Свой OpenAI-совместимый | нужен `GET /v1/models` и поддержка tool-calling |

> [!caution] Два ограничения, которые убивают затею на слабом железе
> - Модель **обязана уметь tool calling**, и документация честно предупреждает: *«A small model or short context may not reliably handle coding tools»*. Рекомендованный контекст — **32K**, и он должен совпадать с тем, что реально загружено в LM Studio/Ollama.
> - **Автоматического отката в облако нет**: упал локальный сервер — упала сессия.
>
> Практический вывод для железа владельца базы (1080 Ti 11 ГБ + 16 ГБ ОЗУ): одна 27B-модель в Q4 выдаёт около **3 токенов/с** при выгрузке слоёв в ОЗУ — см. замеры в заметке [про кибер-расцензуренную Qwen](../../Model/Qwen3.8-27B-Uncensored-Cyber%20%28IQ4_XS%2C%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BD%D1%8B%D0%B9%20imatrix%29%20%E2%80%94%20%D1%80%D0%B0%D1%81%D1%86%D0%B5%D0%BD%D0%B7%D1%83%D1%80%D0%B5%D0%BD%D0%BD%D1%8B%D0%B9%20Qwen%20%D0%BF%D0%BE%D0%B4%20%D0%BA%D0%B8%D0%B1%D0%B5%D1%80%D0%B1%D0%B5%D0%B7%20%2815%20%D0%93%D0%91%20%E2%80%94%20%D1%82%D0%BE%D0%BB%D1%8C%D0%BA%D0%BE%20%D0%B2%D0%B5%D1%81%D0%B0%2C%20262K%20%D0%BD%D0%B5%20%D1%82%D0%B5%D1%81%D1%82%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D0%BB%D0%B8%2C%20%D0%B7%D1%80%D0%B5%D0%BD%D0%B8%D1%8F%20%D0%BD%D0%B5%D1%82%29.md). А ключевая фича OpenResearch — **несколько агентов параллельно**. Локально это не масштабируется: либо облачные ключи, либо модель поменьше и по одному направлению за раз.

## 💡 Итог

- Инструмент настоящий, **MIT, на Rust**, с живой разработкой и внятной архитектурой: параллельные сессии агентов в изолированных **git worktree** плюс git-native дерево экспериментов с неизменяемым архивом каждого прогона. Это действительно полезная идея.
- **«Из ЛЮБОГО агента»** — из четырёх: Claude Code, Codex, OpenCode, Cursor (пост забыл Cursor).
- **«ВСЮ литературу»** — препринты arXiv и DOI. Рецензируемая периодика и PubMed мимо.
- **«Локально»** — локальна оркестрация и хранилище. Агент по умолчанию облачный, телеметрия в релизных сборках включена по умолчанию.
- **Не для роутера и не для слабой машины**: armv7-сборок нет, а параллельные агенты на локальной модели упираются в скорость инференса.
- **Главное на что смотреть перед запуском** — `--remote` без аутентификации на общем хосте. Авторы об этом пишут, пост — нет.
- Полезнее всего **ML-исследователям с GPU и облачными ключами**.
