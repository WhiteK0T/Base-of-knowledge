# 🧊 Claude Code — кэш промптов: TTL 5 минут и 1 час, `subagentPromptCacheTtl`

> [!info] Коротко
> Настройка **`"subagentPromptCacheTtl": "1h"`** продлевает кэш промптов для **субагентов** и других фоновых запросов Claude Code с 5 минут до часа. Она есть в официальной документации (Claude Code **v2.1.242+**). Экономит она тогда, когда субагент **простаивает дольше 5 минут** между своими запросами, — иначе запись в часовой кэш стоит дороже и выгоды нет. Ниже — как это устроено, что сбрасывает кэш и как проверить, помогает ли настройка именно вам.

Связанные заметки: [Claude Code — гайд](Claude%20Code%20%E2%80%94%20%D0%B3%D0%B0%D0%B9%D0%B4.md), [Claude Code — шпаргалка команд](Claude%20Code%20%E2%80%94%20%D1%88%D0%BF%D0%B0%D1%80%D0%B3%D0%B0%D0%BB%D0%BA%D0%B0%20%D0%BA%D0%BE%D0%BC%D0%B0%D0%BD%D0%B4.md).

## 1. Как работает кэш промптов

Модель ничего не помнит между запросами, поэтому Claude Code на **каждом** шаге заново отправляет весь контекст: системный промпт, `CLAUDE.md`, всю историю и результаты инструментов. Новое дописывается в конец, так что почти весь запрос совпадает с предыдущим. API кэширует **начало запроса (префикс)**: совпавшую часть он не пересчитывает, а читает из кэша по низкой цене.

Порядок слоёв в запросе — от редко меняющегося к частому:

| Слой | Что внутри | Когда меняется |
| :--- | :--- | :--- |
| Системный промпт | инструкции, описания инструментов | изменился набор инструментов |
| Контекст проекта | `CLAUDE.md`, авто-память, правила | старт сессии, `/clear`, `/compact` |
| Диалог | сообщения, ответы, результаты инструментов | каждый ход |

Совпадение должно быть точным: изменение в префиксе пересчитывает всё, что после него.

### Цены (API Anthropic, относительно обычной цены входных токенов)

| Операция | Множитель |
| :--- | ---: |
| Запись в кэш на **5 минут** | **×1,25** |
| Запись в кэш на **1 час** | **×2** |
| Чтение из кэша | ×0,1 (у Opus 5.5 и Sonnet 5.5 — ×0,05, у Fable 5.1 — ×0,025) |

Каждое попадание в кэш **продлевает** его срок. Пока вы работаете без пауз, кэш не истекает. После паузы дольше срока жизни следующий запрос пересчитывает и **заново записывает** весь префикс — это и есть та «перезапись контекста», о которой говорит пост.

## 2. Какой срок у каких запросов

Claude Code делит запросы на две группы:

- **основной диалог** — ваши ходы в интерактивном режиме, `-p`, Agent SDK и вспомогательные запросы внутри них;
- **всё остальное** — **субагенты**, workflow, участники agent teams, форки, сжатие (`/compact`), генерация заголовков сессий.

| Группа | Подписка Claude, в пределах лимита плана | Usage credits сверх плана, API-ключ, Bedrock/Vertex/Foundry |
| :--- | :--- | :--- |
| Основной диалог | **1 час** | 5 минут |
| Всё остальное | **5 минут** (кроме нескольких служебных запросов, которые Anthropic держит на часе) | 5 минут |

Отсюда следует главное:
- **На подписке основной диалог уже кэшируется на час.** Настройка из поста его не касается.
- **Субагенты по умолчанию живут на 5 минутах даже на подписке.** Именно это и меняет `subagentPromptCacheTtl`.
- **На API-ключе и в облаках** по умолчанию всё на 5 минутах. Там есть смысл и в `promptCacheTtl` для основного диалога.
- Если на подписке вы ушли **сверх лимита на usage credits**, основной диалог автоматически переходит на 5 минут, потому что запись на 5 минут дешевле.

## 3. Настройка

Два параметра в `settings.json` (оба с v2.1.242), значения — только `"5m"` или `"1h"`, остальные игнорируются:

```json
{
  "promptCacheTtl": "1h",
  "subagentPromptCacheTtl": "1h"
}
```

| Параметр | Что регулирует | Переменная окружения |
| :--- | :--- | :--- |
| `promptCacheTtl` | основной диалог | `CLAUDE_CODE_PROMPT_CACHE_TTL` |
| `subagentPromptCacheTtl` | субагенты, workflow, сжатие, фоновые запросы | `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` |

Где задавать:
- `~/.claude/settings.json` — для всех ваших проектов;
- `.claude/settings.json` — для проекта (попадёт в git, увидит команда);
- `.claude/settings.local.json` — для проекта, только у вас.

Можно попросить и сам Claude Code: `/update-config поставь subagentPromptCacheTtl 1h в пользовательские настройки`.

Пути одинаковы на **Gentoo, Debian/Ubuntu и Arch** — это настройки Claude Code, а не системы. На **Entware** Claude Code не ставится, вопрос неактуален.

### Тонкая настройка для одного субагента

Срок можно задать отдельному субагенту в его frontmatter (`.claude/agents/<имя>.md`, с v2.1.248), внутри `experimental`:

```yaml
---
name: long-researcher
description: Долгое исследование с паузами на тяжёлые команды
experimental:
  cacheTtl: 1h
---
```

На подписке, пока вы расходуете usage credits, `1h` во frontmatter игнорируется.

### Порядок приоритета

1. `FORCE_PROMPT_CACHING_5M=1` — принудительно 5 минут для всех (удобно для сравнения и отладки);
2. переменная окружения группы (`CLAUDE_CODE_…_CACHE_TTL`);
3. параметр в `settings.json`;
4. `experimental.cacheTtl` у конкретного субагента;
5. `ENABLE_PROMPT_CACHING_1H=1` — час для обеих групп (старый способ для API-ключа и облаков);
6. значения по умолчанию из таблицы раздела 2.

## 4. Когда это экономит, а когда нет

Пусть префикс субагента — **P** токенов.

| Сценарий | Кэш 5 минут | Кэш 1 час | Итог |
| :--- | :--- | :--- | :--- |
| Субагент работает без пауз дольше 5 минут | запись 1,25P, дальше дешёвые чтения | запись **2P**, дальше дешёвые чтения | 1 час **дороже** на 0,75P |
| Одна пауза от 5 минут до часа (ждёт долгий билд, тесты, фоновую задачу; его возобновили позже) | 1,25P + **1,25P** (перезапись после истечения) = 2,5P | 2P + чтение ~0,1P = **2,1P** | 1 час **дешевле** |
| Несколько таких пауз | +1,25P за каждую | только чтения | 1 час **заметно дешевле** |
| Пауза дольше часа | перезапись | тоже перезапись | разницы нет |

Документация API формулирует то же правило: **часовой кэш выгоден, когда к одному префиксу возвращаются реже раза в 5 минут, но чаще раза в час**. Если запросы идут чаще, 5-минутный кэш и так продлевается бесплатно.

Типичные случаи, когда `subagentPromptCacheTtl: "1h"` помогает:
- субагенты гоняют долгие сборки и тесты (`Ctrl+B` в фон, ожидание результата);
- вы **возобновляете** субагента или форк позже (первый запрос возобновлённого запуска может прочитать кэш, нагретый в прошлый раз);
- workflow и agent teams, где участники ждут друг друга;
- сжатие диалога после паузы.

Когда не поможет: короткие одноразовые субагенты, которые отрабатывают за пару минут и больше не нужны, — для них часовая запись просто дороже.

> [!note] Про «экономию до 25%»
> Точной цифры экономии из документации не вывести: она зависит от того, сколько пауз дольше 5 минут бывает у ваших субагентов. На API выгода считается по таблице выше. На подписке Anthropic не публикует, как именно часовая запись кэша учитывается в лимитах плана, поэтому проверяйте эффект замером (раздел 6).

## 5. Что сбрасывает кэш (и как этого избежать)

Пересчёт с нуля обходится дороже любой разницы в TTL, поэтому полезно знать, что его вызывает:

| Действие | Что происходит | Как избежать |
| :--- | :--- | :--- |
| Смена модели (`/model`, `opusplan`, скилл с другой `model`) | у каждой модели свой кэш — весь диалог пересчитывается | выбирать модель в начале сессии |
| Смена effort | на большинстве моделей — пересчёт; на **Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.1** с API-ключом или подпиской кэш сохраняется | менять effort между задачами |
| Включение fast mode | один пересчёт на диалог (дальше вкл/выкл кэш не ломает) | включать в начале |
| Подключение MCP-сервера или удаление инструмента | при включённом tool search (по умолчанию) — без пересчёта; без него — пересчёт | не менять набор серверов посреди задачи |
| `/compact` | диалог заменяется сводкой — новый префикс | сжимать на естественных паузах; чтобы отменить ветку, лучше `/rewind` (он возвращается к уже закэшированному префиксу) |
| Много картинок | старые изображения выбрасываются пачкой, история с этого места пересчитывается | не копить скриншоты |
| Обновление Claude Code | меняется системный промпт — первый запрос после перезапуска без кэша | `DISABLE_AUTOUPDATER=1`, если важен контроль |

**Кэш не ломают:** правка файлов проекта, правка `CLAUDE.md` посреди сессии (но она и не применится до `/clear`, `/compact` или перезапуска), смена режима прав, смена output style, вызов скиллов и команд, `/recap`, `/rewind`, запуск субагента (кэш родителя не трогается).

Ещё одна деталь: кэш фактически привязан к **машине и каталогу**. Параллельные сессии в одной папке читают кэш друг друга, сессии в разных папках — нет.

## 6. Как проверить, работает ли кэш

- **`/usage`** — строка `Prompt cache (main)`: доля попаданий, число промахов, тёплый ли кэш сейчас и, с v2.1.260, вероятная причина последнего промаха (например, `tool definitions changed`).
- **Статус-строка** — поля `cache_creation_input_tokens` (записано) и `cache_read_input_tokens` (прочитано) из `current_usage`. Хорошо, когда чтений много больше, чем записей; если запись высокая ход за ходом — что-то меняет префикс.
- **Какой TTL реально применился** к основному диалогу:
  ```bash
  claude -p "hello" --output-format json | jq '.usage.cache_creation'
  # ephemeral_1h_input_tokens — запись на час, ephemeral_5m_input_tokens — на 5 минут
  ```
- **Сравнить на своей работе:** день поработать как обычно, день — с `subagentPromptCacheTtl: "1h"`, сравнить расход в `/usage`. Для контрольного прогона на 5 минутах без правки настроек — `FORCE_PROMPT_CACHING_5M=1 claude`.

> [!warning] Через шлюзы
> Через собственный `ANTHROPIC_BASE_URL` часовой кэш работает, только если шлюз пробрасывает заголовок `anthropic-beta` без изменений. Через **Claude apps gateway** часовой TTL недоступен вовсе. На Bedrock поддержка часового кэша зависит от модели и региона.
