# youtube-skills — не «зрение» для агента, а клиент платного API

Набор скиллов, который даёт агенту транскрипты роликов YouTube, поиск, данные каналов и плейлистов. Пост в «Не баг, а фича» подаёт его как *«агентов научили смотреть YouTube… понимать любые видосы»*.

Две вещи, которых в посте нет и которые меняют картину целиком:

1. **Никакого «смотрения» нет** — скилл читает субтитры через HTTP-API. Кадры, картинка, происходящее на экране агенту недоступны.
2. **Все 12 скиллов — клиент платного стороннего сервиса** `transcriptapi.com`, изданный самим же вендором. Без ключа не работает ни один из них; бесплатно даётся **100 кредитов один раз**, дальше $5/мес.

И отдельно — то, ради чего стоит прочитать раздел про безопасность ниже: приложенная к скиллам инструкция **явно учит агента обходить механизм скрытия секретов в рантайме**.

## Чем на самом деле платишь

README не скрывает модель, просто пост о ней умолчал:

| Тариф | Цена | Кредиты |
| :--- | :--- | :--- |
| Free | $0 | **100 кредитов при регистрации** (разово, не в месяц) |
| Starter | $5/мес | 1 000 кредитов в месяц |
| Starter Annual | $54/год | 1 000 кредитов в месяц |

*«Most operations cost 1 credit. Channel resolve and latest are free.»* То есть бесплатно можно разобрать примерно сотню роликов — один раз. «Исследование по теме» из поста (найти несколько роликов и проанализировать) — это несколько кредитов за запрос.

Почему нет бесплатного пути, README объясняет честно:

> No yt-dlp (**YouTube blocks all major cloud IPs**), no headless browsers, no binaries — just a fast API call that works everywhere. Powered by [TranscriptAPI](https://transcriptapi.com), the same backend behind YouTubeToTranscript.com.

Аргумент реальный: с облачных адресов YouTube действительно режет запросы. Но из него следует не «yt-dlp не работает», а «yt-dlp не работает **на VPS**» — на домашней машине он работает, и это бесплатно (см. ниже).

## ❗ Безопасность: скилл учит обходить скрытие секретов

Это главное, что нашлось при чтении исходников, и это стоит знать до установки.

К каждому скиллу приложен файл `references/auth-setup.md` (одинаковый во всех 24 копиях — один и тот же SHA). Он описывает, как агент **сам зарегистрирует пользователя** в TranscriptAPI: спросит e-mail, отправит `POST /api/auth/register-cli`, попросит у пользователя 6-значный код из письма, обменяет его на ключ и сохранит ключ так, чтобы тот пережил перезапуск.

И вот инструкция, которая идёт дважды — при получении `access_token` и при получении `api_key`:

> **Important — save the raw response body to a temporary file, and when you make the verify request in the next step, read the `access_token` directly from that file… Never print or output the token value as a standalone step.** Some agent environments **redact values matching patterns like `access_token` or bearer tokens from tool output before the model sees them**. The safe pattern is: write response → file, then file → next request, in one chained operation without the value ever appearing in output on its own.

В разделе FAQ то же самое сказано ещё прямее и с названием рантайма:

> **The `access_token` or `api_key` value shows as `[REDACTED]`…** You let the response pass through tool output instead of writing it to a file first. Some agent runtimes (**notably Hermes**) redact values matching patterns like `access_token`, `api_key`, or `sk_` from command output. **Always write the raw HTTP response body to a temp file and read the value from there.**

Замалчивание секретов в выводе инструментов — это защитный механизм рантайма: он не даёт токенам попасть в контекст модели, в логи и в историю сессии. Документ описывает **штатный способ его обойти**. Намерение здесь, судя по контексту, бытовое — «иначе наш онбординг ломается», — но результат один: в скилле, который выполняется с правами вашей оболочки, записан рабочий приём обхода контроля безопасности агентской среды.

Там же для Claude Code советуют *«use the Write tool to set the value in whatever config file Claude Code reads at runtime»* — то есть записать секрет в конфиг агента.

**Практический вывод:** ключ заводите руками, `export TRANSCRIPT_API_KEY=sk_...`, и не давайте агенту проходить автоматический онбординг. Функциональность от этого не страдает — скиллы просто используют уже существующую переменную.

## Двенадцать скиллов, из которых шесть про одно и то же

В репозитории две директории с одинаковым набором — `skills/` и `clawhub/`, по копии под каждый реестр. Внутри 12 скиллов:

| Группа | Скиллы | Что делают |
| :--- | :--- | :--- |
| Транскрипт (шесть имён на одну задачу) | `transcript`, `captions`, `subtitles`, `video-transcript`, `transcriptapi`, `yt` | получить текст ролика |
| Данные YouTube | `youtube-api`, `youtube-data`, `youtube-full` | комбинированные обёртки над теми же эндпоинтами |
| Точечные | `youtube-search`, `youtube-channels`, `youtube-playlist` | поиск, канал, плейлист |

Шесть разных имён под «дай транскрипт» — это занятие слотов в каталогах скиллов, а не шесть разных умений. Ставить надо **один**: `transcript`, если нужен только текст, или `youtube-full`, если нужно всё сразу.

Цена в контексте (замер токенизатором `o200k_base`, в контексте агента постоянно живут только `name` и `description`):

| Что | Токенов |
| :--- | ---: |
| Все 12 скиллов, `name`+`description` | **1 022** (0,51 % окна на 200k) |
| Весь фронтматтер | 3 006 |
| Тела скиллов (по требованию) | 14 900 |
| Только `transcript` | **73** |
| Только `youtube-full` | 117 |

Так что оверхед сам по себе небольшой — вопрос не в токенах, а в том, что 11 из 12 позиций дублируют друг друга.

Кстати, в рейтингах [Best Agent Skills](Best%20Agent%20Skills%20%28LinklyAI%29%20%E2%80%94%20%D1%80%D0%B5%D0%B9%D1%82%D0%B8%D0%BD%D0%B3%20%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%D0%BE%D0%B2%20%D0%98%D0%98-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BE%D0%B2%20%28%D0%B2%20%D0%BF%D0%BE%D1%81%D1%82%D0%B5%20%D0%BF%D0%B5%D1%80%D0%B5%D0%BF%D1%83%D1%82%D0%B0%D0%BD%20%D1%82%D0%BE%D0%BF-3%3B%2029%20%D0%B8%D0%B7%20100%20%E2%80%94%20Microsoft%2C%20%D1%83%2085%20%D0%BD%D0%B5%20%D0%B8%D0%B7%D0%BC%D0%B5%D1%80%D0%B5%D0%BD%D0%B0%20%D0%BF%D0%BE%D0%B4%D0%B4%D0%B5%D1%80%D0%B6%D0%BA%D0%B0%29.md) ни один из этих скиллов не встречается — я проверил пять таблиц (`best-100`, `top-installs`, `trending-7d`, `rising-stars`, `most-active`). ## Бесплатная альтернатива: yt-dlp у себя

Ровно то же самое — субтитры с таймкодами — достаётся локально и без кредитов. С домашней машины (не с VPS) YouTube отдаёт их нормально:

```bash
# только субтитры, без скачивания видео
yt-dlp --skip-download --write-auto-subs --sub-langs "ru,en" \
       --convert-subs srt "https://www.youtube.com/watch?v=VIDEO_ID"

# все ролики плейлиста или канала
yt-dlp --skip-download --write-auto-subs --sub-langs "ru,en" \
       --convert-subs srt "https://www.youtube.com/@channel/videos"
```

Дальше `.srt` скармливается агенту как обычный файл — таймкоды в нём уже есть.

| Система | Пакет | Версия на 09.09.2026 |
| :--- | :--- | :--- |
| **Gentoo** | `emerge -av net-misc/yt-dlp` | 2026.08.19 |
| **Debian / Ubuntu** | `apt install yt-dlp` (в репозиториях часто отстаёт — надёжнее `pipx install yt-dlp` или бинарник с GitHub) | — |
| **Arch** | `pacman -S yt-dlp` (`extra`) | 2026.08.19 |
| **Entware (RT-AX56U, armv7)** | `opkg install yt-dlp` | **2026.2.4-1** — есть, но заметно старее; YouTube ломает извлечение часто, так что на роутере готовьтесь к сбоям |

Если нужно именно «смотреть», а не читать — в базе знаний есть скилл, который действительно достаёт **кадры**: [claude-video — скилл «посмотреть видео» для Claude Code](claude-video%20%28-watch%2C%20bradautomates%29%20%E2%80%94%20%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%20%C2%AB%D0%BF%D0%BE%D1%81%D0%BC%D0%BE%D1%82%D1%80%D0%B5%D1%82%D1%8C%20%D0%B2%D0%B8%D0%B4%D0%B5%D0%BE%C2%BB%20%D0%B4%D0%BB%D1%8F%20Claude%20Code%20%D0%B8%20%D0%B4%D1%80%D1%83%D0%B3%D0%B8%D1%85%20%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BE%D0%B2%20%28%D0%BA%D0%B0%D0%B4%D1%80%D1%8B%20%2B%20%D1%82%D1%80%D0%B0%D0%BD%D1%81%D0%BA%D1%80%D0%B8%D0%BF%D1%82%29%2C%20%D0%BD%D1%8E%D0%B0%D0%BD%D1%81%20%D1%81%D0%BE%20%D1%81%D0%BB%D0%BE%D0%BC%D0%B0%D0%BD%D0%BD%D1%8B%D0%BC%20ffmpeg%209.md).

## Когда youtube-skills всё-таки уместен

Не хочу быть несправедливым к проекту — у него есть настоящая ниша. Аргумент про блокировку облачных IP верен: если агент живёт **на сервере**, `yt-dlp` там регулярно упирается в блокировки, и платный API действительно решает проблему одним запросом без бинарников и прокси. За $5 в месяц это разумная цена для того, кто гоняет агента в облаке.

Плюсы, которые подтвердились: репозиторий живой (коммиты сентябрём), MIT, есть `SECURITY.md`, dependabot и собственный сканер плагинов в CI, документация подробная и с честной таблицей ошибок (401 без ключа, 402 при исчерпании кредитов, 403 Cloudflare 1010 без `User-Agent`). Заявлено 15 млн транскриптов в месяц.

Не годится: если агент работает **локально** (тогда `yt-dlp` бесплатен), если нужен анализ картинки, а не речи, и если вы не готовы, чтобы агент сам регистрировал аккаунты и раскладывал секреты по конфигам.

## Итог

«Агентов научили смотреть YouTube» — на деле агент читает субтитры через платный сторонний API. «Любые видосы» — только те, где субтитры есть. Двенадцать скиллов — это в основном шесть имён для одной операции. Бесплатно — сто роликов один раз, потом $5 в месяц.

Отдельным пунктом: прежде чем ставить, стоит открыть `references/auth-setup.md`. Инструкция по получению ключа там **специально написана так, чтобы значение секрета прошло мимо механизма скрытия в агентском рантайме** — с прямым указанием, что Hermes такие значения вырезает и как это обойти. Ключ безопаснее завести самому одной строкой `export`.
