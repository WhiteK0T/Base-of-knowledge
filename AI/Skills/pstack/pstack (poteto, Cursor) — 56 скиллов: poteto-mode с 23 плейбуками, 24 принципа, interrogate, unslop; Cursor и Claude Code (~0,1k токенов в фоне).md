# pstack (poteto) — один режим вместо набора команд

> [!info] Что это
> Плагин **Cursor** с набором скиллов **Lauren Tan (poteto)** — инженера Cursor, участницы команды React Compiler, ранее работавшей в Meta и Netflix. Лежит в официальном монорепозитории [`cursor/plugins`](https://github.com/cursor/plugins/tree/main/pstack), лицензия **MIT**. Девиз: *«if you want to go fast, go deep first»* — писать **меньше кода, но выше качеством**, а потом спокойно запускать много агентов параллельно.
>
> Главная идея: вы почти всегда вызываете **один** скилл — `/poteto-mode`. Он сам выбирает один из 23 плейбуков, ведёт список шагов и подключает остальные скиллы и принципы, когда шаг их требует.

Зато **запуск дорогой**: `poteto-mode` грузит своё тело, индекс принципов и нужный плейбук, а плейбуки массово раздают работу субагентам и нескольким моделям. Сама автор в гайде предупреждает: «a pstack run spends real tokens».

> **Как на самом деле подбираются принципы.** Агент не находит их сам — все они вызываются только вручную. Их подключает `poteto-mode`: у него внутри **индекс принципов**, который он читает в начале задачи, а отдельные файлы нужны, чтобы другие скиллы ссылались на принцип по имени.

## 2. poteto-mode и 23 плейбука

При вызове `/poteto-mode`:

1. сопоставляет задачу с плейбуком и открывает список задач, первые пункты которого — шаги плейбука **дословно**;
2. по мере шагов вызывает другие скиллы;
3. пишет ответы, уже прогнанные через `unslop`, — для того, кто будет пользоваться, и для того, кто будет сопровождать.

В Cursor режим можно «закрепить» на все ходы (выбрать в меню `/` и нажать Alt+Enter — custom mode). Хорошо сочетается с `/loop` Cursor: агент работает часами, не теряя строгости.

| Группа | Плейбуки |
| :--- | :--- |
| **Понять** | investigation (вопрос только на чтение) |
| **Чинить** | bug fix (воспроизвести → корень → фикс с доказательством), runtime forensics (живая утечка, холостой CPU), trace forensics (cpuprofile, trace, heap snapshot) |
| **Скорость** | perf (против базовой линии), hillclimb (научное улучшение одной метрики: гипотеза → замер до/после → коммит на каждую победу) |
| **Строить** | feature (от названной структуры данных), refactoring (без смены поведения), prototype, visual parity (пиксель в пиксель), multi-phase plan |
| **Скиллы и проверки** | authoring a skill, eval (вслепую проверить, как правка скилла меняет поведение агента) |
| **Довести до слияния** | babysit (конфликты, треды ревью, CI), shipping (проверить зелёный стек и влить снизу вверх), opening a pr (маленькие упорядоченные коммиты, Conventional Commits; **завершает каждый плейбук**) |
| **Долгие и автономные** | autonomous run, orchestrate (многодневный проект: стек PR, флоты субагентов), autopilot-full (независимые PR до merged, рой проверяет каждую версию), autopilot-stack (один линейный стек для ревью оператором) |
| **Сессии и уборка** | session pickup, pause safely, worktree cleanup |

Если ни один плейбук не подходит — скилл `figure-it-out` проектирует новый, строгий и проверяемый.

Примеры запросов из README:

```
/poteto-mode this pr has a subtle bug where the scroll drifts every 750ms even when idle. repro first, then fix and verify.
/poteto-mode a big list takes a second or two to load even though we virtualize. run a cpu trace and tell me why.
/poteto-mode i'm going to bed. land the stack even if ci flakes. i want everything merged by morning.
```

## 4. 24 принципа

Короткие правила (54–451 слово), по одному на скилл. Их имена — способ **рулить агентом посреди задачи**: «apply fix-root-causes», а не длинное объяснение (глава 8 гайда).

| Группа | Принципы |
| :--- | :--- |
| **Core (10)** | `laziness-protocol` — склонность к удалению и минимальной правке; `foundational-thinking` — сначала правильные типы и структуры данных; `redesign-from-first-principles` — перепроектировать, будто требование было с первого дня; `attack-the-premise` — после двух провалов с общей посылкой проверить саму посылку; `subtract-before-you-add`; `minimize-reader-load`; `outcome-oriented-execution` — не держать временную совместимость при плановой миграции; `experience-first`; `exhaust-the-design-space` — 2–3 конкурирующих прототипа; `build-the-lever` — сделать инструмент (codemod, скрипт, скилл), а не работать руками |
| **Architecture (6)** | `model-the-domain`; `boundary-discipline` — проверки на границах системы, внутри доверять типам; `type-system-discipline` — недопустимые состояния непредставимы; `make-operations-idempotent`; `migrate-callers-then-delete-legacy-apis`; `separate-before-serializing-shared-state` |
| **Verification (5)** | `prove-it-works` — проверять на реальном артефакте, а не «компилируется»; `fix-root-causes` — найти первое место, где всё пошло не так; `sequence-verifiable-units`; `test-behavior-not-implementation`; `explain-the-number` — прежде чем верить измерению, найти, что его ограничивает |
| **Delegation (2)** | `guard-the-context-window` — объёмную работу в субагентов, в основном треде только сводки; `never-block-on-the-human` — делать, показать результат, дать человеку поправить после; **подтверждение — только для необратимых действий** |
| **Meta (1)** | `encode-lessons-in-structure` — правило в линтер, флаг, проверку или скрипт, а не в ещё один текст |

> «Never block on the human» — не «никогда ничего не спрашивать»: необратимые действия по-прежнему требуют подтверждения.

## 5. Несколько моделей

- `/setup-pstack` определяет доступные модели и пишет правило с моделью для каждой роли (код, суждения, панели ревью) и бюджетом рассуждений.
- **По умолчанию:** код (фичи, рефакторинг, баг-фиксы, perf, hillclimb) делегируется **Grok**, а самые сложные изменения, тексты и суждения — **Opus 5.5**; панель ревью — Opus 5.5 + Grok.
- `interrogate`, `arena` и ревью-панели получают сигнал **от разнообразия моделей**, а не от назначенных «персон».
- После смены значений по умолчанию старое правило продолжает их перекрывать — удалить строки ролей (или файл) и перезапустить `/setup-pstack`.

## 6. Философия, которую стоит знать

- **Нет скиллов планирования.** «Лично я не верю в планирование. Лучшая спека — это код». Для плана хватает plan mode Cursor; `poteto-mode` умеет планировать, но не по умолчанию. Это прямая противоположность [Matt Pocock](../mattpocock/skills%20%28Matt%20Pocock%29%20%E2%80%94%2038%20%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%D0%BE%D0%B2%20%D0%B4%D0%BB%D1%8F%20%D0%BD%D0%B0%D1%81%D1%82%D0%BE%D1%8F%D1%89%D0%B8%D1%85%20%D0%B8%D0%BD%D0%B6%D0%B5%D0%BD%D0%B5%D1%80%D0%BE%D0%B2%3A%20grilling%2C%20%D0%B3%D0%BB%D0%BE%D1%81%D1%81%D0%B0%D1%80%D0%B8%D0%B9%20%D0%B8%20ADR%2C%20to-spec%20%D0%B8%20to-tickets%2C%20tdd%2C%20code-review%20%28~0%2C6k%20%D1%82%D0%BE%D0%BA%D0%B5%D0%BD%D0%BE%D0%B2%20%D0%B2%20%D1%84%D0%BE%D0%BD%D0%B5%29.md) с его интервью и тикетами.
- **Сначала глубина — потом параллельность.** Если одному агенту можно доверить проверяемый код, можно спокойно запускать много.
- **Главная привычка из гайда:** дайте агенту **цель и способ проверить её** своими словами — и перестаньте микроменеджить.
- **«Сделай своим»:** `/automate-me` собирает ваш собственный режим поверх pstack; форки и PR приветствуются.

## 7. Установка

**Cursor:**

```
/add-plugin pstack
```

Затем `/setup-pstack` (модели и бюджет) и `/poteto-mode` для любой задачи, где нужна строгость.

**Claude Code** — официально поддерживается через адаптер:

```
/plugin marketplace add cursor/plugins
/plugin install pstack@cursor-plugins
```

| В Cursor | В Claude Code |
| :--- | :--- |
| `/poteto-mode` | `/pstack:poteto-mode` (префикс плагина) |
| `Task` | `Agent`; `readonly: true` → `Explore`, `environment: "cloud"` → `isolation: "worktree"` |
| модели `grok-*`, `gpt-*` | не задаются — агент работает на модели сессии |
| правило `~/.cursor/rules/pstack-models.mdc` | `~/.claude/rules/pstack-models.md` (`/pstack:setup-pstack` пишет его сам) |
| Automations, Bugbot, облачные агенты | **пропускаются** с одной строкой «Skipped in Claude Code: …» |

Итог для Claude Code: работает, но **мультимодельность теряется** — Grok и GPT заменяются моделью сессии, так что `interrogate` и `arena` становятся «одна модель много раз». Не входят в pstack и ставятся отдельно из `cursor-team-kit`: `/deslop`, `control-cli`, `control-ui`.

> [!note] Платформы
> Cursor для Linux распространяется с [cursor.com](https://cursor.com) как AppImage, `.deb` (Debian/Ubuntu) и RPM для x64 и ARM64; в Arch — из AUR (`cursor-bin`), на Gentoo — AppImage. В Claude Code (Gentoo, Debian, Arch) — команды выше. Entware: не нужен — это текстовые скиллы для агента на рабочей машине.

## 9. Что учесть

- **Создан под Cursor**: максимум — с несколькими моделями и автоматизациями Cursor; в Claude Code работает урезанно (см. раздел 7).
- **Дорого в запуске**: режим, плейбуки и рои субагентов тратят много токенов, а автономные плейбуки (overnight, autopilot) рассчитаны на щедрые лимиты.
- **Много автономии**: «land the stack even if ci flakes» и автослияние стеков — давать только в отдельном репозитории или ветке, где это допустимо.
- **Меняется ежедневно** (0.15.x, десятки коммитов в неделю) — гайд и README сверять после обновления.
- Часть скиллов завязана на окружение автора: Grok Bot, Slack, iOS-симуляторы, TypeScript.

## 10. С чего начать

1. Поставить плагин и выполнить `/setup-pstack`.
2. Прочитать [гайд](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/README.md) — 10 коротких глав с реальными промптами.
3. Любую серьёзную задачу начинать с `/poteto-mode` и формулировать **цель + как проверить**.
4. Не знаете, что вызвать, — `/poteto-help`.
5. Даже без pstack полезно забрать себе `unslop` и выучить имена нескольких принципов.
