# Best Agent Skills — ежедневный рейтинг скиллов для ИИ-агентов

Проект, который каждый день собирает данные о скиллах агентов из нескольких реестров и соцсетей и публикует **девять рейтингов**. Данные выкладываются на GitHub в CSV под **CC BY 4.0**, пайплайн сбора открыт отдельным репозиторием.

Пост в «Не баг, а фича» рекламирует его как *«чарт умений для нейронок»* с топ-3: **agent-browser, frontend-design, find-skills**.

Проект хороший и на удивление добросовестный — его методология честнее, чем 90 % того, что попадает в такие подборки. А вот в посте перепутан топ-3, и не сказано главное: чем этот рейтинг **не** является.

## Что реально в этом «топ-100»

Скачал `data/latest/rankings/best-100.csv` и посчитал. Картина сильно отличается от «100 лучших умений».

**Издателей всего 14 на 100 позиций:**

| Издатель | Позиций в топ-100 |
| :--- | ---: |
| microsoft | **29** |
| mattpocock | **21** |
| steipete | 11 |
| prisma | 9 |
| heygen-com | 7 |
| vercel-labs | 6 |
| anthropics | 3 |
| open.feishu.cn | 3 |
| supabase / neondatabase | по 2 |
| remotion-dev / juliusbrussee / leonxlnx | по 1 |
| без указания | 4 |

**Два издателя занимают ровно половину чарта.** Двадцать девять позиций — это скиллы Microsoft вокруг Azure (`azure-ai`, `azure-kusto`, `azure-compute`, `azure-messaging`, `entra-app-registration`, `appinsights-instrumentation` и так далее).

Причина названа в самой методологии и вины проекта тут нет — так считает источник:

> Installs are **bundle-level**: installing a repo counts once for every skill in it. […] all skills of a popular multi-skill repo rank high together — the current lists do not fold same-repo skills.

То есть человек поставил один репозиторий `microsoft/azure-skills` — и все скиллы внутри получили по установке. Отсюда и кучность: у соседних азуровских позиций счётчики отличаются на сотни при значениях под 567 тысяч.

У проекта есть детектор аномалий, но он до этого случая не дотягивается — и авторы это признают:

> The current detector flags **identical** install counts shared by 3+ skills of one publisher… it does **not** yet catch near-identical clusters.

Проверил по CSV: **ни одна из 100 строк не помечена аномалией** (`anomaly` пуст у всех).

## Половина «оценок» — не измерена, а подставлена

Самое важное, что видно только в данных. WIS складывается из пяти измерений, а неизмеренные заполняются нейтральной константой 0,3. Сколько ячеек в `best-100.csv` пустые (то есть подставлена константа):

| Измерение | Вес | Не измерено |
| :--- | ---: | ---: |
| Популярность (установки) | 0,30 | 0 из 100 |
| Доверие к издателю | 0,20 | 0 из 100 |
| Импульс (trending) | 0,15 | 15 из 100 |
| **Репутация (соцсети)** | 0,20 | **58 из 100** |
| **Поддержка (свежесть обновлений)** | 0,15 | **85 из 100** |

Для большинства строк топ-100 «активность у общества» и «поддержка» — это не замер, а одно и то же число 0,3. Реально различают позиции только **установки и флаг официальности издателя**. Причина документирована: свежесть обновлений умеет отдавать только ClawHub, а в топ-100 из ClawHub всего 15 строк.

Туда же — покрытие источниками: **86 из 100 строк имеют оценку `C`** (данные об установках только из одного реестра) и `match=single`, остальные 14 — `B`. Оценки `A` нет ни у одной. По платформам: 85 строк из skills.sh, 15 из ClawHub, из Tencent SkillHub — **ни одной**, хотя он заявлен источником.

## «Лучших» ≠ «качественных»: живой пример

На **99-й позиции** стоит `design-taste-frontend` от `leonxlnx` (458 658 установок, WIS 55,2) — часть набора Taste Skill. В базе знаний он уже разобран: [Taste Skill — 13 скиллов против ИИ-шаблонности во фронтенде](Taste%20Skill%20%28Leonxlnx%29%20%E2%80%94%2013%20%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%D0%BE%D0%B2%20%D0%BF%D1%80%D0%BE%D1%82%D0%B8%D0%B2%20%D0%98%D0%98-%D1%88%D0%B0%D0%B1%D0%BB%D0%BE%D0%BD%D0%BD%D0%BE%D1%81%D1%82%D0%B8%20%D0%B2%D0%BE%20%D1%84%D1%80%D0%BE%D0%BD%D1%82%D0%B5%D0%BD%D0%B4%D0%B5%20%28%D0%BF%D1%80%D0%BE%D0%B2%D0%B5%D1%80%D0%BA%D0%B0%20%E2%80%94%2022k%20%D1%82%D0%BE%D0%BA%D0%B5%D0%BD%D0%BE%D0%B2%2C%20%D0%BA%D0%B8%D1%80%D0%B8%D0%BB%D0%BB%D0%B8%D1%86%D0%B0%2C%20%D0%B2%D1%8B%D0%B4%D1%83%D0%BC%D0%B0%D0%BD%D0%BD%D1%8B%D0%B5%20%D0%B8%D1%81%D1%81%D0%BB%D0%B5%D0%B4%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F%29.md) — там нашлись выдуманные ссылки на исследования и лишние 22k токенов.

Это не претензия к рейтингу: он честно считает установки и не притворяется, что оценивает содержание. Претензия к слову «лучших» в посте — популярность и качество здесь разные вещи, и авторы рейтинга прямо пишут, что оценочных рейтингов не публикуют принципиально.

## Что у проекта сделано хорошо

Редкий случай, когда методология заслуживает отдельной похвалы. Из `docs/methodology.md`:

- **Числа не суммируются между площадками.** Каждая считает своё, поэтому объединённые рейтинги строятся на перцентилях **внутри своей платформы** после лог-преобразования; сырые числа остаются в CSV рядом.
- **Звёзды репозитория не ранжируют отдельные скиллы.** *«A monorepo with 17 skills shares one star count; attributing it to each skill would be meaningless»* — под звёзды выделен отдельный рейтинг `top-repos`.
- **Склейки раскрыты.** Колонка `match` говорит, как объединялись строки между площадками, колонка `coverage` — из скольких реестров есть данные об установках.
- **Одноимённые скиллы — разные скиллы.** Ключ — полный идентификатор, а не короткое имя.
- **Скиллы с «обычными» именами** (github, weather, prototype) **исключены** из рейтинга обсуждаемости: упоминания таких слов нельзя приписать скиллу.
- **Кандидаты с HN и Bluesky проверяются LLM** на релевантность, а сырые дофильтровые числа публикуются рядом (`hn_raw_7d`, `bsky_raw_7d`).
- **Неизмеренное не завышает оценку** — нейтральная константа вместо выбрасывания измерения.
- Ограничения перечислены отдельным разделом, включая неудобные: телеметрию skills.sh можно отключить, установки из CI могут завышать счётчики, соцсигналы англоцентричны, X собирается только для топ-50.

Отдельно — это **лид-магнит**: Linkly AI продаёт десктопное приложение, расширение и CLI для индексации и поиска по своим файлам. Что не мешает данным быть открытыми и воспроизводимыми.

## Девять рейтингов, а не один

`data/latest/rankings/`: `best-100.csv`, `top-installs.csv`, `trending-7d.csv`, `social-buzz.csv`, `most-active.csv`, `official-100.csv`, `official-vendors.csv`, `rising-stars.csv`, `top-repos.csv`.

Практически: если нужно «что поставить» — смотреть `official-100` (только официальные издатели) и `top-repos`; если «что нового» — `rising-stars` и `trending-7d`. Именно `best-100`, где половину занимают два издателя из-за bundle-подсчёта, для выбора скиллов наименее полезен.

## Как пользоваться данными локально

Никакой установки не требуется — это CSV в публичном репозитории:

```bash
# последний срез
curl -sO https://raw.githubusercontent.com/LinklyAI/best-skills/main/data/latest/rankings/best-100.csv

# весь архив снимков (27 дней на 09.09.2026)
git clone --depth 1 https://github.com/LinklyAI/best-skills
```

Дальше обычными средствами: `csvkit`/`csvlook` или `python3 -c "import csv..."`. По системам — **Gentoo** `emerge -av dev-python/csvkit`, **Debian/Ubuntu** и **Arch** `apt/pacman -S csvkit` (в Arch — через AUR `python-csvkit`), на **Entware** есть `python3` и `git`, файл на 20 КБ роутер осилит, но смысла в этом мало. Лицензия CC BY 4.0 требует указывать источник при перепубликации данных.

## Итог

Проект честный и технически грамотный: открытые данные под CC BY 4.0, открытый пайплайн, подробная методология с признанием собственных слабых мест, 27 дней снимков без пропусков и полный русский перевод README.

К посту три поправки. Топ-3 назван неверно — первое место у **find-skills**, а не у agent-browser. «Тысячи ресурсов и систем» на деле 10 000+ скиллов из 7 источников. И главное: «топ-100 **лучших**» — это рейтинг по счётчикам, а не по качеству; **29 позиций из 100 занимает один Microsoft** из-за того, что установка одного репозитория засчитывается каждому скиллу внутри, у **85 строк не измерена поддержка**, у 58 — обсуждаемость, а безопасность скиллов не проверяется вообще («No security scanning yet»).

Как радар «что сейчас качают» — годится и удобен. Как список «что поставить себе» — нет; для этого лучше `official-100` и собственная проверка содержимого.
