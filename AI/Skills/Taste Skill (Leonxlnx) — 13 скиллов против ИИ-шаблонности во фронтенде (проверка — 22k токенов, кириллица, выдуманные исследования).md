# Taste Skill — скиллы против «ИИ-шаблонности» во фронтенде

> [!info] Короткий вывод
> Вещь **реальная и качественная** — редкий случай, когда за хайпом стоит содержательный артефакт. Это 1206 строк жёстких правил про то, чего агент делать не должен: без AI-фиолетовых градиентов, без трёх одинаковых карточек, без «Quietly in use at», без фейковых дашбордов из `div`-ов. Установил и проверил — ставится за одну команду, файл на месте, хэш сходится.
>
> Но пост умалчивает четыре вещи, и все четыре важны:
> **① Это не «скилл», а 13 скиллов**, и флагманский весит **21 912 токенов** при каждом срабатывании — я замерил. На сессии в 200k это ~11% контекста.
> **② Автор сам пометил флагман как «v2 (experimental)»**, а последняя правка его содержимого была **26 мая 2026** — с тех пор в репозиторий коммитят только логотипы спонсоров.
> **③ Область применения сужена самим скиллом:** «NOT for dashboards, data tables, multi-step forms». Пост же обещает «ЛУЧШИЕ сайты и интерфейсы».
> **④ Для русскоязычных сайтов есть прямой конфликт:** «непреложный» запрет на тире `—` ломает русскую пунктуацию, а половина рекомендуемых шрифтов без кириллицы. Проверил по API Google Fonts.
>
> Отдельно: раздел `research/`, на который ссылается README как на обоснование правил, содержит **выдуманные и переприписанные чужим лабораториям цифры**. Разобрал ниже.

## Что это на самом деле

Скилл в терминах Claude Code — это markdown-файл с YAML-заголовком. Агент постоянно держит в контексте только `name` и `description`, а тело подгружает, когда решит, что задача подходит. Кода в Taste Skill нет вообще: четыре `.mjs`-скрипта в репозитории занимаются исключительно нарезкой картинок для README (поэтому GitHub и подписывает язык репозитория как JavaScript — это обманчиво).

| :--- | :--- | :--- |
| **taste-skill** | `design-taste-frontend` | Флагман, **v2 (experimental)**. Три «ручки», карта дизайн-систем, запреты, чек-лист |

### Три «ручки» флагмана

Настраиваются числами 1–10 прямо в файле:

- **DESIGN_VARIANCE** — смелость композиции: ниже — центрированно и чисто, выше — асимметрия;
- **MOTION_INTENSITY** — глубина анимации: ниже — только hover, выше — scroll-триггеры и магнитные эффекты;
- **VISUAL_DENSITY** — плотность информации на экран.

Логика правильная: §0 «Brief Inference» требует от агента сначала одной строкой объявить, что он вообще понял («Reading this as: B2B SaaS landing for technical buyers…»), и только потом писать код. Это лечит главную болезнь — прыжок в дефолтную эстетику без чтения задачи.

## Установка (проверено вручную)

Ставится через CLI [`skills`](https://github.com/vercel-labs/skills) от Vercel Labs — это отдельный npm-пакет (MIT, v1.5.22), понимающий **76 агентов**: Claude Code, Codex, Cursor, Gemini CLI, OpenCode, Windsurf, Copilot, Qwen Code, Hermes Agent, Kimi и далее.

```bash
# только флагман (рекомендую начать с этого)
npx skills add https://github.com/Leonxlnx/taste-skill --skill "design-taste-frontend" -a claude-code

# все 13 сразу
npx skills add https://github.com/Leonxlnx/taste-skill --skill '*' -a claude-code
```

Что получилось у меня на самом деле:

```
◇  Installed 1 skill
│  ✓ design-taste-frontend (copied)
│    → ./.claude/skills/design-taste-frontend
```

Файл `SKILL.md` — 87 253 байта, побайтово идентичен репозиторию (сверил `diff`). Рядом появляется `skills-lock.json` с SHA-256 источника — приятно, что установщик фиксирует хэш. Установка всех тринадцати заняла 314 КБ на диске.

Ещё установщик прогоняет скилл через три сканера и печатает результат (`Gen: Safe · Socket: 0 alerts · Snyk: Low Risk`), а в конце честно предупреждает: **«Review skills before use; they run with full agent permissions»**. Совет не пустой — скилл это инструкции, которые ваш агент выполнит с вашими правами.

> [!tip] Node не нужен, если не хотите
> Скилл — это просто markdown. Можно вообще без CLI:
> ```bash
> mkdir -p ~/.claude/skills/design-taste-frontend
> curl -sL https://raw.githubusercontent.com/Leonxlnx/taste-skill/main/skills/taste-skill/SKILL.md \
>   -o ~/.claude/skills/design-taste-frontend/SKILL.md
> ```
> Или просто вставить содержимое в чат/`AGENTS.md`/`CLAUDE.md`.

## Что внутри флагмана

1206 строк, 14 разделов плюс три приложения. Самое ценное — не «делай красиво», а перечень **конкретных запретов**, выведенных из наблюдений за тем, что модели генерируют по умолчанию:

- **§9 AI Tells** — фиолетовые градиенты, центрированный герой над тёмным mesh-фоном, три одинаковые карточки фич, `Inter + slate-900`, «Quietly in use at», Jane Doe, Acme, декоративные точки, нумерация секций вида `001 · Capabilities`, плашки `BETA` в герое, надписи `Scroll ↓`, фейковые скриншоты из стилизованных `div`-ов;
- **§2 Brief → Design System Map** — если бриф читается как Material / Fluent / Carbon / Polaris / GOV.UK / USWDS, брать **официальный пакет**, а не изобретать; если бриф — это эстетика (глассморфизм, бенто, брутализм), делать на веб-стандартах и честно это называть;
- **§5 канонические скелеты GSAP** — готовый код sticky-stack и horizontal-pan с правильными `start: "top top"`, `pin: true`, `scrub`. Запрещены `window.addEventListener('scroll')` и `requestAnimationFrame`-циклы, дёргающие состояние React;
- **§6 гардрейлы** — анимировать только `transform`/`opacity`, обязательный `prefers-reduced-motion` при `MOTION_INTENSITY > 3`, WCAG AA на контрасте кнопок и форм, `min-h-[100dvh]` вместо `h-screen`;
- **§11 Redesign Protocol** — что при редизайне **никогда не меняется молча**: структура URL, подписи навигации, имена полей форм, вордмарк, юридические тексты. Это взрослое правило, его редко пишут;
- **§14 Pre-Flight Check** — около 60 чекбоксов перед выдачей кода.

> [!caution] Стек зашит сильнее, чем признаёт README
> FAQ обещает: «Does it work with React, Vue, Svelte? Yes. Rules target design intent, not a single framework API.»
>
> По факту значительная часть правил — это буквальные классы Tailwind и идиомы React/Next: `leading-[1.1]`, `pb-1`, `pt-24`, `max-w-7xl mx-auto`, `bg-zinc-950`, `'use client'`, `useEffect` с cleanup, `useReducedMotion()`, `motion/react`, тема, выставляемая в `layout.tsx`. CHANGELOG прямо фиксирует «Tailwind v4 default». На Vue или Svelte философия перенесётся, а половина конкретики — нет.
>
> То же самое независимо отметили в issue **#86** («Portability feedback: framework coupling in §3…»), открытом с 23 июля без ответа.

Хорошая новость про анимации: **GSAP с апреля 2025 бесплатен для коммерческого использования**, включая все ранее платные плагины Club GreenSock (ScrollTrigger, SplitText, MorphSVG) — после покупки GreenSock компанией Webflow. Оговорка: он **free-to-use, но не open source** — исходники нельзя декомпилировать и на их основе делать конкурирующие продукты.

## Русский язык: два конкретных конфликта

Ни слова «Cyrillic», «Russian», «i18n» или «localization» во флагманском скилле нет — проверил grep-ом. Он писался под латиницу, и для русскоязычного сайта это выстреливает дважды.

### ① Запрет тире ломает русскую пунктуацию

§9.G называется «EM-DASH BAN (the single most-violated Tell)» и сформулирован максимально жёстко:

> **ZERO em-dashes (`—`) anywhere on the page.** Headlines, eyebrows, pills, body, quotes, attribution, captions, buttons, alt text. Zero. Non-negotiable.

Для английского это осмысленно: злоупотребление `—` действительно выдаёт текст, написанный моделью. **В русском тире — обязательный знак препинания.** «Москва — столица России» без тире становится ошибкой, а не стилем. Замена на дефис, которую предписывает скилл (`Use a hyphen (-)`), даёт типографский брак в каждом предложении с опущенной связкой.

Что делать: при работе над русским интерфейсом явно отменяйте это правило в промпте, например «§9.G не применяется: язык страницы русский, тире — обязательная пунктуация, запрет касается только декоративного использования». Ту же проблему для китайского подняли в issue **#33** («Different "bad taste" patterns in Chinese AI writing») — ответа нет.

### ② Половина рекомендуемых шрифтов без кириллицы

## Раздел `research/`: здесь проект сам делает то, с чем борется

README ссылается на папку `research/` как на обоснование: «anti-repetition rules **informed by dedicated research**». Внутри — 12 markdown-файлов про «лень LLM». Проверил ссылки: **ни одного URL, DOI или arXiv-идентификатора во всём разделе нет**. Дальше — по пунктам.

| Что заявлено в `research/` | Проверка |
| :--- | :--- |
| «EmotionPrompt (Microsoft Research)» | ✅ **Реальная работа** — Microsoft + Институт ПО КАН, [arXiv:2307.11760](https://arxiv.org/abs/2307.11760), 45 задач, +10,9% на генеративных задачах по человеческой оценке |
| «LazyBench» | ⚠️ **Работа существует** — [arXiv:2410.11437](https://arxiv.org/abs/2410.11437), окт. 2024. Но она про **мультимодальные** модели и визуальные вопросы (VQA), а не про обрезание кода. Контекст в пересказе потерян полностью |
| «Финансовое обрамление ("$200 tip") → +45% качества и длины (Microsoft Research)» | ❌ **Ложная атрибуция и завышенная цифра.** Это не исследование Microsoft, а неформальный тред в X от **@voooooogel (thebes), декабрь 2023**, автор сам назвал его ненаучным. Измеренный эффект — **+11% к длине** ответа, не +45% к «качеству». Более аккуратная перепроверка Макса Вульфа (февраль 2024) устойчивого эффекта не нашла |
| «"Take a deep breath" → точность с 34% до 80% (Microsoft Research)» | ❌ **Чужая работа.** Это **Google DeepMind, OPRO** ([arXiv:2309.03409](https://arxiv.org/abs/2309.03409)), модель PaLM 2-L на GSM8K. Плюс подмена смысла: 34% — это база вообще без промптинга, а «Let's think step by step» давал уже 71,8%. То есть фразе про «глубокий вдох» приписан весь скачок, хотя её вклад — с 71,8% до 80,2% |
| «Winter Break Hypothesis — статистический анализ подтвердил» | ❌ Это **вирусная непроверенная гипотеза** из декабря 2023 о том, что модели «ленятся под Рождество». Ничем не подтверждена; «статистический анализ» не назван |
| «2025 Controlled Laziness Experiments — трёхчастное академическое исследование, декабрь 2025» | ❌ **Не находится.** Ни авторов, ни площадки, ни ссылки. Из этой несуществующей работы файл `empirical-results.md` выводит развёрнутые «Эксперимент A/B/C» с результатами |

Итог: две реальные работы (одна пересказана не про то), две чужие находки, приписанные Microsoft с искажёнными числами, одна интернет-легенда и одно ненаходимое исследование, из которого выведена целая страница «эмпирики». Для проекта под лозунгом «anti-slop» это неудобная ирония — и хороший повод не принимать раздел `research/` за доказательную базу. **На качество самих правил в `SKILL.md` это, впрочем, не влияет**: они выведены из практики («production testing showed the same Tells emerging across builds»), а не из этих ссылок.
