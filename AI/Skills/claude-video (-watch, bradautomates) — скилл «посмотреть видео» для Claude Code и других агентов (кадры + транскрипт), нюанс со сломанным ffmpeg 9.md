# claude-video (`/watch`) — скилл «посмотреть видео» для ИИ-агентов

Разбор поста [@bugnotfeature/26657](https://t.me/bugnotfeature/26657) («Claude Code сам посмотрит видос и выкатит саммари»). Речь про [`bradautomates/claude-video`](https://github.com/bradautomates/claude-video).

**Короткий вердикт: пост честный.** Все четыре заявленные фичи подтверждаются, README у проекта на редкость аккуратный — с измеренными цифрами и явным разделом «Limits», что для вирусного репозитория редкость. Но есть две вещи, о которых пост не говорит и которые прямо влияют на то, заработает ли скилл у тебя **сегодня**: он **ломается на ffmpeg 9**, а сам проект не принимал коммитов с **30 июня 2026** при 76 открытых PR.

> [!info] Что это
> Agent Skill (`/watch`), который даёт агенту «посмотреть» видео: скачивает через `yt-dlp`, нарезает кадры через `ffmpeg`, добывает транскрипт (родные субтитры → фолбэк на Whisper) и отдаёт агенту **кадры как изображения + текст с таймкодами**.
>
> - Лицензия: **MIT** · Язык: Python (чистая стандартная библиотека, без внешних пакетов)
> - **15,0k ★**, 1,4k форков · релиз **v0.2.0** (1 июля 2026)
> - Автор: Brad Bonanno (Solaris Automation)
> - Работает не только в Claude Code: Codex, Cursor, Copilot, Gemini CLI и ещё 50+ хостов через Agent Skills, плюс загрузка `.skill` в claude.ai
>
> *Проверено по GitHub API, README и исходникам на 11 августа 2026.*

| «Максимально экономит токены, не грузит десятки одинаковых кадров» | ✅ **верно** | Дедупликация кадров реально реализована (появилась в 0.2.0, 29 июня 2026), детали в §4 |

| «Всего один скилл» | ✅ | Один самодостаточный пакет `skills/watch/` — `SKILL.md` + 7 Python-скриптов |

> [!important] Важная рамка, которой нет ни в посте, ни в рекламе
> Агент **не смотрит видео**. Он получает **N стоп-кадров** (по умолчанию до 100) плюс текст. Отсюда следствия, которые надо держать в голове:
> - **Движение между кадрами не видно.** Посчитать повторы в упражнении, оценить плавность анимации, поймать однокадровую вспышку — нельзя.
> - **Звук не слышен**, есть только его текстовая расшифровка. Интонация, музыка, звуковые эффекты, «кто это сказал» — теряются.
> - На 49-минутном ролике 100 кадров — это **один кадр примерно каждые 30 секунд**. Скрипт сам печатает предупреждение «sparse scan».
>
> Это не претензия к проекту — README всё это честно пишет. Это про то, как формулировать ожидания: «посмотрел видео» здесь означает «пролистал слайд-шоу из кадров и прочитал стенограмму».

## 2. Как работает пайплайн

```
URL или локальный файл
        │
        ▼
 setup.py --check ──────► проверка yt-dlp / ffmpeg / ключа (<100 мс после первого раза)
        │
        ▼
 download.py (yt-dlp) ──► сначала пробует СУБТИТРЫ. В режиме `transcript`
        │                 видео вообще не качается
        ▼
 frames.py (ffmpeg) ────► нарезка кадров: keyframes или scene-change
        │                 JPEG 512 px по ширине (клампится до 1998 px по высоте)
        ▼
 дедупликация ──────────► выкидывает почти одинаковые кадры (§4)
        │
        ▼
 transcribe.py ─────────► разбор VTT-субтитров;
        │                 нет субтитров → mp3 mono 16 кГц 64 кбит/с → Whisper API
        ▼
 агент делает Read по каждому кадру → отвечает
        │
        ▼
 очистка временного каталога
```

Мелочи из исходников, которые полезно знать:

- Аудио для Whisper режется на куски по **24 МБ** (`MAX_UPLOAD_BYTES`) — это автоматический чанкинг под лимит API, добавленный в 0.2.0.
- Эндпоинты: `api.groq.com/openai/v1/audio/transcriptions` и `api.openai.com/v1/audio/transcriptions`.
- Весь Python — **на чистой стандартной библиотеке**, никаких `requests`/`Pillow`. Ставить в venv ничего не нужно.
- Очистку временного каталога делает **агент**, а не скрипт. Если сессия оборвалась — временные файлы (и скачанное видео!) останутся в `/tmp`.

## 3. Режимы детализации и цена в токенах

Цифры ниже — **замеры автора** на реальном 49-минутном ролике 1280×720 с автосубтитрами (долгая статичная запись экрана, худший случай для лимитов). Разовая загрузка видео — ~37 с / 76 МБ.

| Режим | Движок | Кадров | Время нарезки | Оценка image-токенов |
| :--- | :--- | :--- | :--- | :--- |
| `transcript` | без кадров, только субтитры | 0 | ~4,5 с (без скачивания) | **0** (но ≈26,6k текстовых) |
| `efficient` | только keyframes (`-skip_frame nokey`) | 50 | **~0,5 с** | ~9,8k |
| `balanced` (по умолчанию) | scene-change | 100 | ~20,9 с | ~19,7k |
| `token-burner` | scene-change, без лимита | 116 | ~21,0 с | ~22,8k |

**Как считаются токены картинки:** `(ширина × высота) / 750`. При дефолтных 512 px кадр 720p становится 512×288 ≈ **197 токенов**. Флаг `--resolution 1024` увеличивает это примерно вчетверо.

> [!warning] «Экономит токены» — относительно
> Дефолтный `balanced`-прогон 49-минутного видео = ~19,7k токенов кадрами **плюс** ~26,6k токенов транскриптом ≈ **46k токенов за один вопрос**. Это не «дёшево», это «дешевле, чем могло быть».
>
> Реальная экономия:
> - `--detail transcript` — **ноль** image-токенов, если визуал не нужен (лекция, подкаст, интервью);
> - `--start` / `--end` — сфокусированный отрезок вместо разреженного скана всего ролика (и бюджет кадров там плотнее);
> - `--detail efficient` — 50 кадров вместо 100 и в ~40 раз быстрее нарезка;
> - `--max-frames N` — жёстко ограничить.

Автоматический бюджет кадров по длительности: ≤30 с → ~30 кадров; 30 с–1 мин → ~40; 1–3 мин → ~60; 3–10 мин → ~80; >10 мин → 100 (потолок в режимах с лимитом).

## 4. Дедупликация кадров — как она устроена

Заявление поста «не грузит десятки одинаковых кадров» подтверждается, и механизм приятно простой:

1. Один вызов `ffmpeg` уменьшает каждый извлечённый JPEG до эскиза **16×16 в градациях серого**.
2. Считается **средняя абсолютная разница** (MAD) со **последним сохранённым** кадром — среднее изменение яркости на пиксель по шкале 0–255.
3. Разница ≤ **2.0** → кадр считается почти-дубликатом и выбрасывается. Иначе кадр сохраняется и становится новой точкой отсчёта.
4. Лимит бюджета применяется **после** дедупликации — то есть бюджет тратится на разные кадры.

Сравнение именно с *последним сохранённым*, а не с предыдущим — это ловит медленные затухания, которые покадровый порог никогда бы не перешагнул. Порог намеренно низкий и меряет яркость, а не структуру: правка одной строки кода, прокрутка терминала на строку или два разных однотонных слайда **переживут** фильтр.

Отключается флагом `--no-dedup`. В отчёте печатается строка вида `6 selected from 14 candidates (… 8 near-duplicates dropped …)`.

## 5. ⚠️ Главная проблема: скилл сломан на ffmpeg 9

> [!danger] `-vsync` удалён в ffmpeg 9.0 — нарезка кадров падает целиком
> В `skills/watch/scripts/frames.py` флаг `-vsync vfr` используется **в обоих путях извлечения кадров**: строка **256** (scene-change) и строка **615** (keyframes). В **ffmpeg 9.0** опция `-vsync`, депрекейтнутая ещё в ветке 5.x, **удалена окончательно**. Результат — `Unrecognized option 'vsync'` и **ноль извлечённых кадров**, независимо от режима.
>
> Об этом сообщали как минимум пять раз ([27 июля](https://github.com/bradautomates/claude-video/issues), 6, 8 и 9 августа 2026), есть готовые PR с однострочным фиксом — **ни один не влит**.

**Что это значит именно для тебя:**

| Система | Версия ffmpeg | Статус |
| :--- | :--- | :--- |
| **Gentoo stable** | `media-video/ffmpeg-8.1.2` (stable amd64) | ✅ работает — `-vsync` ещё есть (депрекейтнут, но принимается) |
| **Gentoo ~amd64** | `media-video/ffmpeg-9.0` (в testing) | ❌ **сломается**, если размаскируешь |
| **Arch** | обычно самый свежий | ⚠️ проверь: `ffmpeg -version` |
| **Debian/Ubuntu** | зависит от релиза, чаще 6.x/7.x | ✅ работает |

**Патч на две строки** (пока апстрим не проснулся) — `-fps_mode` существует с ffmpeg 5.x, так что правка безопасна на любой ffmpeg ≥ 5:

```bash
# найди, куда установился скилл
SKILL=~/.claude/skills/watch          # или ~/.codex/skills/watch, или каталог плагина

# сделай копию и замени флаг
cp "$SKILL/scripts/frames.py"{,.bak}
sed -i 's/"-vsync", "vfr"/"-fps_mode", "vfr"/g' "$SKILL/scripts/frames.py"

# проверь, что заменилось ровно два вхождения
grep -n 'fps_mode\|vsync' "$SKILL/scripts/frames.py"
```

> [!note] Проверить свою версию заранее
> ```bash
> ffmpeg -version | head -1
> ffmpeg -hide_banner -h 2>&1 | grep -c 'vsync'   # 0 → опции больше нет, патч обязателен
> ```

- **YouTube отдаёт 403 / пустоту** — нужен свежий `yt-dlp` с impersonation-таргетами (`curl_cffi`), иногда `deno`; отдельная issue про необходимость куки браузера.
- **HTTP 429** из-за запроса автопереведённых дорожек субтитров.
- **Дубли строк** из «скользящих окон» автосубтитров YouTube.

- **`watch.py` затирает исходный файл**, если он лежит внутри `--out-dir` — задокументированный сценарий, а файл пропадает. Это про потерю данных, держи `--out-dir` отдельно от исходников.
- Жёсткий потолок 2 fps не даёт разобрать сверхкороткие быстрые клипы.

**Практический вывод:** ставить можно, но фиксируй у себя рабочую копию и будь готов патчить сам. В issue упоминается форк `pheistman/claude-watch` (мультипровайдерная транскрипция, transcript-first) — если апстрим не оживёт, смотреть надо туда.

### Системные зависимости

Скилл сам зовёт `setup.py --check` и на macOS выполняет `brew install ffmpeg yt-dlp`, а на Linux/Windows печатает команды. Ставить лучше руками, штатным пакетным менеджером:

| Система | Команда |
| :--- | :--- |
| **Gentoo** (основная) | `emerge media-video/ffmpeg net-misc/yt-dlp` — оба собираются из исходников. Для ffmpeg проверь USE-флаги на нужные кодеки (`x264`, `x265`, `vpx`, `opus`, `mp3`); для скачивания с YouTube полезен `net-misc/curl` с HTTP/2 |
| **Debian / Ubuntu** | `apt install ffmpeg` + **yt-dlp из pipx/pip, а не из apt** — репозиторный отстаёт на месяцы, а YouTube ломает старые версии еженедельно: `pipx install yt-dlp` |
| **Arch** (планируется) | `pacman -S ffmpeg yt-dlp` — обе свежие. ⚠️ Здесь ffmpeg 9 приедет раньше всех → патч из §5 понадобится первым |
| **Entware** (ASUS RT-AX56U) | ❌ смысла нет: скилл — часть агента, который живёт на твоей рабочей машине. `opkg install ffmpeg` на роутере есть, но нарезать кадры на armv7 с 512 МБ ОЗУ и гонять их в API — не тот сценарий |

> [!tip] yt-dlp обновляй чаще всего остального
> Большая часть «не работает с YouTube» в трекере — это устаревший `yt-dlp`, а не баг скилла. На Gentoo: `emerge --sync && emerge -1 net-misc/yt-dlp`. Если тормозит выход в дерево — `pipx install yt-dlp` в домашний каталог рядом с системным пакетом, и подсунуть его в `PATH` первым.

## 8. Приватность, ключи и деньги

```bash
# скилл сам создаёт файл с правами 0600
~/.config/watch/.env
#   GROQ_API_KEY=...      (предпочтительно — дешевле и быстрее)
#   OPENAI_API_KEY=...    (альтернатива)
#   WATCH_DETAIL=transcript   (сменить режим по умолчанию)
```

| Что нужно | Стоимость |
| :--- | :--- |
| Скачивание + родные субтитры | **бесплатно**, ключи не нужны |
| Whisper-фолбэк (Groq `whisper-large-v3`) | дёшево и быстро |
| Whisper-фолбэк (OpenAI `whisper-1`) | по стандартному прайсу |
| Полностью без Whisper | `--no-whisper` — только кадры |

> [!warning] Куда уезжает твой звук
> Whisper-фолбэк **отправляет аудиодорожку на сторонний сервер** (Groq или OpenAI). Для публичного ролика с YouTube это никого не волнует. Для **локальной записи экрана с рабочим совещанием, внутренним дашбордом или чужими персональными данными** — это передача данных третьему лицу.
>
> Фолбэк срабатывает именно там, где риск выше всего: у локальных файлов субтитров обычно нет. Если разбираешь что-то чувствительное — ставь `--no-whisper` (или `WATCH_DETAIL` без Whisper) и работай по кадрам, либо расшифровывай локальной моделью отдельно.
>
> Отдельно: сами **кадры** уходят в контекст твоей LLM. Скриншот с открытым паролем, токеном в терминале или личной перепиской попадёт в облако провайдера модели ровно так же.

**Право.** Скачивание видео с YouTube нарушает его пользовательское соглашение (сам `yt-dlp` — легальный инструмент, вопрос в применении). Для чужого контента: анализ «для себя» — одно, публикация пересказа или кадров — уже вопрос авторского права и цитирования. Записи чужих созвонов и вебинаров часто отдельно запрещены к сохранению условиями сервиса.

## 9. Факты против хайпа

**«Claude сам посмотрит видео»** — Claude получит слайд-шоу из кадров и стенограмму. Для саммари, разбора структуры и поиска момента этого хватает с запасом. Для всего, что зависит от движения или звука, — нет.

**«Экономит токены»** — экономит **относительно наивного подхода**. Дефолтный прогон часового ролика — это всё равно десятки тысяч токенов. Настоящая экономия начинается, когда ты осознанно выбираешь `--detail transcript` или `--start/--end`.

**«Один скилл и всё работает»** — при условии, что у тебя стоят `yt-dlp` и `ffmpeg` **правильных версий**, есть ключ Groq для видео без субтитров, и твой ffmpeg ещё не 9.0.

**`efficient` — это не «меньше кадров»**, а «быстрее нарезка» (~0,5 с против ~21 с). На малоподвижном видео keyframes могут дать **больше** кадров, чем scene-change.

**Кадры не бесплатны даже при дедупликации.** Дедуп режет только почти-идентичные кадры; на подвижном видео не выбрасывается ничего, и платишь полную цену.

**Скилл ест место на диске.** Загрузка 49-минутного ролика — 76 МБ, плюс кадры. Уборку делает агент; при обрыве сессии `/tmp` остаётся забитым.

**Плюс, которого в посте нет:** это **не эксклюзив Claude Code**. Тот же пакет ставится в Codex, Cursor, Copilot, Gemini CLI и ещё полсотни хостов одной командой `npx skills add`.

## 10. Когда брать, а когда нет

**Брать:**
- разбор чужого контента: структура ролика, хук, что реально нового в «революционном» апдейте;
- диагностика бага по скринкасту — тот случай, где кадры работают идеально;
- превращение курса или плейлиста в набор заметок (сюда же — сразу писать саммари в этот же vault);
- быстрое «а что там в 2:30» без отсматривания часа.

**Не брать:**
- нужен анализ движения, тайминга, физики, спорта — кадры этого не покажут;
- нужна интонация, музыка, разделение говорящих — есть только текст;
- чувствительное локальное видео и нельзя гонять аудио в чужое API (тогда только `--no-whisper` + кадры);
- у тебя ffmpeg 9 и нет желания патчить;
- нужен инструмент с гарантией поддержки — проект без коммитов больше месяца и с 76 висящими PR.

## 11. Чек-лист перед установкой

- [ ] `ffmpeg -version` — если 9.x, сразу применить патч `-vsync` → `-fps_mode` (§5).
- [ ] `yt-dlp --version` — обновить, это причина большинства отказов на YouTube.
- [ ] Ставить симлинком из клона, если планируешь патчить.
- [ ] Ключ Groq — только если реально нужны видео без субтитров; иначе не заводить вовсе.
- [ ] Чувствительное видео → `--no-whisper`.
- [ ] `--out-dir` **никогда** не указывать на каталог с исходниками (известный баг с затиранием файла).
- [ ] По умолчанию пробовать `--detail transcript`, кадры включать осознанно.
- [ ] Длинное видео → сначала `transcript`, потом точечно `--start/--end` по найденному таймкоду. Это и дешевле, и точнее.
- [ ] Периодически чистить `/tmp` от брошенных рабочих каталогов.
