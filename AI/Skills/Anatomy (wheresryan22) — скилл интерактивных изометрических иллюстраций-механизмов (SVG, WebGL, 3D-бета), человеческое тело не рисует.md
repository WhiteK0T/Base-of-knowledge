# ⚙️ Anatomy — скилл интерактивных изометрических иллюстраций

**[Anatomy](https://github.com/wheresryan22/anatomy)** — скилл для Claude Code (и Antigravity, OpenCode, Codex, MiniMax Code), который объясняет идею, **придумывая и строя физический механизм, чья работа и есть эта идея**. Пример из README: кэш, который пропускает работу, если ничего не поменялось, превращается в цилиндровый замок — он поворачивается, только когда совпали все штифты. Агент собирает такой механизм из десятков мелких деталей с объёмной заливкой, оформляет карточкой с заголовком, подсказкой и «живым» показанием и анимирует под мышь и клавиатуру.

## 1. Что из поста подтверждается

| Пост | На деле |
| :--- | :--- |
| Генерирует интерактивные иллюстрации, «объясняющие что угодно изнутри» | ✅ для **механизмов, приборов, инструментов** и абстрактных идей через метафору-механизм (кэш → замок, пул соединений, CDN, rate limiter) |
| Работа двигателей | ✅ пример — ракетный двигатель Raptor 2 на стенде с пламенем на WebGL, разбирается на 11 узлов |
| **Человеческое тело** | ❌ README прямо пишет в ограничениях: **рисует машины, приборы, инструменты и мебель — не людей** и не точные карты. Название «Anatomy» — про «анатомию» механизма |
| Нейронки | ⚠️ напрямую — нет, только как метафора-механизм (как с кэшем или GPU-контекстом). Идеи без механизма, по словам автора, выходят слабее |
| «Анимированные модели с 3D-эффектами — крутить, приближать, разбирать на детали» | ⚠️ основа — **изометрический SVG с фиксированной камерой**: детали двигаются при наведении, перетаскивании и с клавиатуры, некоторые примеры разбираются на части. «Настоящее» 3D (детали вращаются) — **режим в бете**, проверен на одном примере. Свободного вращения сцены и масштабирования как в 3D-просмотрщике нет |
| «Редачить» | ✅ результат — исходник, который принадлежит вам: Node-скрипт сборки и страница, либо React-компоненты |
| Для статей, презентаций, видео, лендингов | ✅ вывод: отдельная HTML-страница, одиночный `.svg` со встроенными стилями или компоненты React/Next.js; светлая и тёмная тема |

## 2. Установка

| Способ | Команда |
| :--- | :--- |
| skills CLI, для пользователя (Claude Code) | `npx skills add wheresryan22/anatomy -g -a claude-code` → `~/.claude/skills/anatomy` |
| git | `git clone https://github.com/wheresryan22/anatomy.git ~/.claude/skills/anatomy` |
| без git | `mkdir -p ~/.claude/skills/anatomy && curl -L https://github.com/wheresryan22/anatomy/archive/refs/heads/main.tar.gz \| tar -xz --strip-components=1 -C ~/.claude/skills/anatomy` |

Для Codex — `-a codex` (папка `~/.agents/skills/anatomy`, вызов `$anatomy`), OpenCode — `-a opencode`. Копируется весь репозиторий с примерами (~10 МБ). Новый скилл Claude Code подхватывает в той же сессии; если папки `skills` не было при старте — `/reload-skills`.

Зависимости для сборки и самопроверки:

| Система | Node.js 20.10+ | Chrome/Chromium (для проверок) |
| :--- | :--- | :--- |
| **Gentoo** | `net-libs/nodejs` | `www-client/chromium` (долгая сборка) или `www-client/google-chrome` |
| **Debian / Ubuntu** | `nodejs` (в Debian 13 — 20.x) или NodeSource | `chromium` |
| **Arch** | `nodejs` | `chromium` |
| **Entware** | не подходит: агент и браузер работают на рабочей машине | — |

Браузер ищется в обычных местах и в кэше Playwright; иной путь — `CHROME_PATH=/путь/к/chrome`. Без браузера рисунок всё равно строится, не работают только автоматические проверки.

## 3. Как пользоваться

```text
/anatomy explain how a token bucket rate limiter works, interactive
/anatomy an isometric SVG explaining how a CDN edge cache works, cache hit vs miss, TTL of 60 s, dark theme. Just the SVG file and a PNG preview.
```

Скилл срабатывает и без команды — на просьбы об изометрической иллюстрации, объясняющем рисунке для документации, статьи или лендинга. Советы автора:

1. **Назовите идею, а не рисунок**, и дайте реальные числа (размеры, количества, пороги) — механизм агент придумает сам.
2. **Или назовите объект**, если знаете (кофемашина, горелка, замок), и что в нём должно двигаться.
3. **Скажите, куда пойдёт результат**: отдельная HTML-страница, `.svg` или React-компонент; светлая или тёмная тема.

Порядок работы по `SKILL.md`: собрать настоящие числа → придумать объект → список деталей → геометрия через `kit/` → отрисовка сзади вперёд → карточка → движение → **проверка как у критика**: `kit/audit.mjs` доказывает, что ничего ни через что не проходит и всё стоит на опорах, а скрипты в headless Chrome снимают скриншоты и крупные планы каждого стыка в обеих темах.

### Готовые примеры — посмотреть сразу

Собранные страницы лежат в `examples/` — их можно открыть в браузере без агента. Пересобрать: `node examples/dial-indicator/build.mjs --light`. Проверил на Gentoo с Node 26.3: страница собралась за 0,05 с и **совпала с закоммиченной байт в байт**; внешних ресурсов (CDN, шрифтов) в готовых страницах нет.

| Пример | Что показывает |
| :--- | :--- |
| `dial-indicator` | индикатор часового типа над набором мерных плиток, ~300 строк — самый простой |
| `desk-computer` | компьютер 1984 года: печатаете на клавиатуре — текст появляется на ЭЛТ |
| `arcade-cabinet` | игровой автомат со снятой панелью: монета катится по жёлобу, импульс бежит по кабелю, ЭЛТ прогревается (~240 деталей) |
| `raptor-engine` | ракетный двигатель на стенде, разбирается на 11 узлов, факел на WebGL |
| `ripple-tank` | волновая ванна с бликами и каустикой на WebGL по модели дисперсии |
| `turning-dial` | 3D-режим (бета): кодовый диск с маленькой рукой-роботом |
| `test-rig`, `spot-plate` | компоненты React/Next.js с реального сайта |

## 4. Стоит знать

- **Медленно — нарочно.** Рисунок делается долгой сессией: список деталей, геометрия, аудит, крупные планы в двух темах. Сборка Raptor — несколько минут, полный 3D-аудит — 15–20 минут на 30 деталей. Это расход лимитов подписки.
- **Цена в токенах.** В фоне висит только описание (~970 символов, порядка 200–250 токенов); при срабатывании подгружается `SKILL.md` ~31 КБ (порядка 8 тыс. токенов), плюс справочники по мере надобности. Описание широкое («explanatory diagram or figure for docs…»), так что скилл может подхватываться на любые просьбы о схемах — если нужна обычная блок-схема, скажите это явно или используйте [Diagram Design](Diagram%20Design%20%28cathrynlavery%29%20%E2%80%94%2039%20%D1%82%D0%B8%D0%BF%D0%BE%D0%B2%20%D0%B4%D0%B8%D0%B0%D0%B3%D1%80%D0%B0%D0%BC%D0%BC%20%D0%B4%D0%BB%D1%8F%20%D0%98%D0%98-%D0%B0%D0%B3%D0%B5%D0%BD%D1%82%D0%BE%D0%B2%20%28206%20%D1%82%D0%BE%D0%BA%D0%B5%D0%BD%D0%BE%D0%B2%20%D0%B2%20%D1%84%D0%BE%D0%BD%D0%B5%2C%20%D1%88%D1%80%D0%B8%D1%84%D1%82%D1%8B%20%D0%B8%D0%B7%20Google%2C%20%D0%BD%D0%B5%20%D1%82%D0%BE%D0%BB%D1%8C%D0%BA%D0%BE%20Claude%20Code%29.md).
- **Не библиотека графиков**: осей, рядов данных и диаграмм нет — числа появляются только как «живое» показание модели механизма.
- **Шейдеры требуют WebGL**; без него SVG всё равно читается, а при «уменьшении движения» в системе рисунок замирает.
- **Codex в песочнице** может не дать запустить Chrome — тогда рисунок строится, но без самопроверки; README описывает, как разрешить запуск.
- **Публикация в общую галерею** ([anatomy-community](https://github.com/wheresryan22/anatomy-community)) — только по вашей просьбе: агент покажет, что отправит, и после подтверждения откроет pull request через `gh`.
