# 🛠️ skill-creator (Anthropic) — создание и тестирование скиллов

**skill-creator** — официальный скилл Anthropic, который помогает писать другие скиллы: от интервью «что должен делать скилл» до тестов, сравнения с базовым вариантом и подбора описания, по которому Claude будет его вызывать. Лежит в репозитории [`anthropics/skills`](https://github.com/anthropics/skills/tree/main/skills/skill-creator) (180 тыс. звёзд), лицензия **Apache-2.0**, обновлялся 09.10.2026.

Поводом для заметки стал пост про сторонний **skill-forge** — он разобран в разделе 4. Почти всё, что умеет skill-forge, есть в официальном skill-creator, на который автор skill-forge и ссылается как на источник вдохновения.

---

## 1. Как поставить

| Где | Как |
| :--- | :--- |
| **Claude Code** | из официального маркетплейса (подключён по умолчанию): `/plugin install skill-creator@claude-plugins-official` |
| Claude Code, вместе с другими примерами | `/plugin marketplace add anthropics/skills`, затем `/plugin install example-skills@anthropic-agent-skills` |
| **claude.ai, Cowork** | уже встроен на платных планах (Customize → Skills) |
| Вручную | скопировать `skills/skill-creator/` в `~/.claude/skills/` |

Скрипты внутри — на Python 3 без внешних зависимостей. Для оптимизации описания нужен `claude` CLI (режим `claude -p`), то есть она работает только в Claude Code. Пути одинаковы на **Gentoo, Debian/Ubuntu и Arch**. На **Entware** Claude Code не ставится.

Вызов — обычной просьбой: «сделай скилл для …», «улучши мой скилл …», «проверь, срабатывает ли скилл …».

## 2. Как он работает

### Создание

1. **Понять задачу**: что скилл должен делать, когда срабатывать, какой результат нужен. Скилл задаёт вопросы и при необходимости изучает предметную область.
2. **Написать `SKILL.md`** по принципам из самого skill-creator:
   - **постепенная загрузка** (progressive disclosure): в фоне висят только имя и описание, тело `SKILL.md` загружается при вызове, справочники и скрипты — по мере надобности;
   - тело — до ~500 строк, детали — в `references/`, повторяемая работа — в `scripts/`;
   - **«без сюрпризов»**: содержимое скилла не должно расходиться с его описанием; никакого вредоносного кода, скрытой отправки данных или скиллов, вводящих в заблуждение.
3. **Составить тестовые задания** — реалистичные запросы, на которых будет проверяться скилл.

### Тестирование и бенчмарк

1. Для каждого задания **параллельно** запускаются два субагента: **со скиллом** и **без него** (для существующего скилла — со старой версией). Результаты складываются в `<имя>-workspace/iteration-N/`.
2. Пока прогоны идут, составляются проверки (assertions). Проверяемое скриптом проверяется скриптом.
3. Агент-оценщик (`agents/grader.md`) выставляет оценки, `aggregate_benchmark.py` собирает `benchmark.json`/`.md`: доля пройденных проверок, время и токены, среднее ± разброс и разница с базовым вариантом.
4. Агент-аналитик ищет то, что прячут средние цифры: проверки, которые проходят и без скилла, нестабильные задания, перерасход токенов.
5. **Просмотрщик в браузере** (`eval-viewer/generate_review.py`) показывает результаты и цифры рядом, вы оставляете отзыв — и начинается следующая итерация.

Дополнительно — **слепое сравнение** двух версий: независимый агент оценивает результаты, не зная, где какая версия.

### Оптимизация описания (description)

От описания во frontmatter зависит, вызовет ли Claude скилл. skill-creator подбирает его автоматически:

1. Составляет около **20 запросов**: 8–10, на которых скилл должен сработать, и 8–10 «почти похожих», на которых не должен. Набор можно поправить в HTML-форме.
2. `run_loop.py` делит набор на **60% для подбора и 40% для проверки**, прогоняет каждый запрос **3 раза** через `claude -p`, просит Claude улучшить описание по ошибкам и повторяет до **5 итераций**.
3. Лучшее описание выбирается **по отложенной части**, а не по той, на которой подбиралось — чтобы не подогнать его под тесты.

```bash
python -m scripts.run_loop \
  --eval-set trigger-eval.json \
  --skill-path ~/.claude/skills/my-skill \
  --model claude-opus-5-5 \
  --max-iterations 5 --verbose
```

Модель лучше указывать ту же, на которой вы работаете: срабатывание проверяется в тех же условиях.

> [!tip] Почему простые тесты бесполезны
> Claude обращается к скиллу только когда задача ему не по силам «с ходу». На запросе вроде «прочитай этот PDF» скилл может не сработать при идеальном описании. Тестовые запросы должны быть содержательными и многошаговыми.

### Упаковка

`package_skill.py` собирает папку в файл `.skill` для загрузки в claude.ai или передачи другим.

## 3. Что учесть

- **Тесты стоят токенов**: каждое задание прогоняется минимум дважды (со скиллом и без), оптимизация описания — 20 запросов × 3 прогона × до 5 итераций.
- README репозитория `anthropics/skills` предупреждает: скиллы там — **примеры для обучения**, перед серьёзным использованием их нужно проверять в своей среде.
- Скиллы для документов (`docx`, `pdf`, `pptx`, `xlsx`) в том же репозитории — **не open source**, а source-available. skill-creator к ним не относится: он под Apache-2.0.

## 4. skill-forge — сторонний вариант

**[skill-forge](https://github.com/AgriciDaniel/skill-forge)** (AgriciDaniel) — набор из 9 скиллов и 8 агентов для того же: планирование, создание, аудит, улучшение, тесты, бенчмарк, публикация скиллов. MIT, 180 звёзд.

| | **skill-creator** | **skill-forge** |
| :--- | :--- | :--- |
| Автор | Anthropic | один разработчик |
| Обновления | регулярно, последнее 09.10.2026 | функции не добавлялись с марта 2026; последние коммиты — шаблоны issue и ссылки на блог автора |
| Создание и улучшение | есть | есть (`plan`, `build`, `evolve`) |
| Тесты со скиллом и без, бенчмарк | есть, с просмотрщиком в браузере | есть (`eval`, `benchmark`) |
| Слепое сравнение версий | есть | есть |
| Подбор описания | есть, с отложенной выборкой | есть |
| **Своё** | — | **уровни сложности 1–4**, аудит с оценкой 0–100 по 6 категориям, **конвертация в Codex, Gemini CLI, Antigravity и Cursor** |
| Постоянная нагрузка на контекст | одно описание (~80 токенов) | 9 скиллов + 8 агентов, **~1,6 тыс. токенов** |

**Уровни 1–4** — это не уровни качества, а шаблоны структуры:

| Уровень | Структура |
| :--- | :--- |
| 1 | один `SKILL.md` |
| 2 | `SKILL.md` + скрипты |
| 3 | главный скилл + скиллы-помощники |
| 4 | целая система: скиллы, агенты, скрипты |

Установка — `git clone` и `bash install.sh` (есть и `install.ps1` для Windows). Удаление — `bash install.sh --uninstall`.

**Итог.** Для создания и проверки скиллов в Claude Code достаточно официального skill-creator. skill-forge имеет смысл, только если нужна именно **конвертация скилла под другие агенты** или аудит с баллами — и с поправкой на то, что проект не развивается.
