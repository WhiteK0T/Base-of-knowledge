# nodumbmode — скиллы против предсказуемых ошибок проектирования

> [!info] Что это
> Набор скиллов для ИИ-агентов кода (Claude Code, Codex, Cursor и ещё десятки), собранный русскоязычным дизайнером **Ильёй Хануматори**. Задача — заставить агента *сначала понять задачу, проверить масштаб и собрать факты*, и только потом писать код. Содержание сильное и написано по делу: это не очередной «awesome-список», а плотный свод правил, выведенных из конкретных провалов на реальном проекте.
>
> Но три вещи из поста стоит поправить: скиллов **шесть**, а не четыре; команда установки из поста ведёт на **ник, который автор уже освободил и который занят другим аккаунтом**; и «не даст сжигать токены» — это про дисциплину агента, а не про экономию контекста: сами скиллы стоят **798 токенов постоянно** и до **25 549** при полном чтении.

## 3. Главная находка — ник в команде установки

Это единственное место, где пост может реально навредить.

### Что произошло

| Аккаунт | id | Создан | Публичных репозиториев |
| :--- | :--- | :--- | ---: |
| **`hanumatori`** — автор | 252923723 | 4 января 2026 | 3 |
| **`hronicasync`** — старый ник | **314566573** | **8 августа 2026, 08:07 UTC** | **0** |

Это **разные аккаунты с разными id**. В репозитории есть коммит `d263abf` от 8 августа: `docs: команды установки на новый ник`. То есть автор в тот день переименовался — и освободившийся ник в тот же день был зарегистрирован кем-то ещё.

Принадлежит ли `hronicasync` самому автору как запасной аккаунт, из открытых данных установить нельзя. Важно другое — что бывает дальше.

### Что говорит документация GitHub

> *«After changing your username, your old username becomes available for anyone else to claim.»*

> *«If the new owner of your old username creates a repository with the same name as your repository, that will override the redirect entry and your redirect will stop working.»*

Сейчас редирект `hronicasync/nodumbmode` → `hanumatori/nodumbmode` работает. Он перестанет работать в ту секунду, когда владелец ника `hronicasync` создаст у себя репозиторий с именем `nodumbmode`.

### Почему это не безобидно: lock-файл запоминает ник

Поставил обеими командами и сравнил `skills-lock.json`:

```json
// после npx skills add hronicasync/nodumbmode  (команда из поста)
"nodumb": {
  "source": "hronicasync/nodumbmode",
  "sourceType": "github",
  "skillPath": "nodumb/SKILL.md",
  "computedHash": "9fead556728a5d633450501bf830f1643acf93c4c65ca5f95725f609026236f7"
}

// после npx skills add hanumatori/nodumbmode  (команда из README)
"source": "hanumatori/nodumbmode"
```

CLI записывает **ровно ту строку, которую ввели**, а не результат редиректа. Дальше `skills update` ходит по ней. То есть все, кто поставил по команде из поста, привязаны к чужому нику навсегда — и в момент, когда редирект сломается, `skills update` молча притянет содержимое из репозитория постороннего аккаунта прямо в каталог скиллов агента, который исполняется с полными правами.

`computedHash` фиксирует то, что скачали, но не удостоверяет источник — при обновлении он просто перезапишется.

> [!danger] Что делать
> Ставить и обновлять **только по нику из README**:
> ```bash
> npx skills@latest add hanumatori/nodumbmode
> ```
> Если уже поставили по команде из поста — проверить и починить:
> ```bash
> grep -o '"source": "[^"]*"' skills-lock.json | sort -u
> # если видно hronicasync — переустановить:
> npx skills@latest remove nodumb nodumb-loop edge-hunt ask-nodumb changelog-discipline system-feedback
> npx skills@latest add hanumatori/nodumbmode
> ```
> Это не паранойя про конкретный аккаунт, а общее правило: **ставить скиллы по каноническому адресу, а не по редиректу.** Скилл — это инструкции, исполняемые агентом с вашими правами.

## 4. Установка — проверено руками

Что делает `npx skills@latest add hanumatori/nodumbmode`. CLI — пакет **`skills`** из npm (`vercel-labs/skills`, MIT, версия 1.5.23 от 18.08.2026, 91 версия в реестре).

Неинтерактивный запуск в проект:

```bash
npx skills@latest add hanumatori/nodumbmode --skill '*' -a claude-code -y
```

Результат у меня (Node 26.3.0, npm 11.16.0):

```
◇  Installed 6 skills
  ✓ ask-nodumb (copied)            → ./.claude/skills/ask-nodumb
  ✓ changelog-discipline (copied)  → ./.claude/skills/changelog-discipline
  ✓ edge-hunt (copied)             → ./.claude/skills/edge-hunt
  ✓ nodumb (copied)                → ./.claude/skills/nodumb
  ✓ nodumb-loop (copied)           → ./.claude/skills/nodumb-loop
  ✓ system-feedback (copied)       → ./.claude/skills/system-feedback

└  Done!  Review skills before use; they run with full agent permissions.
```

**280 КБ, 24 markdown-файла.** Сверил `diff -rq` — все шесть каталогов **побайтово идентичны** репозиторию, ничего по дороге не подменяется и не дописывается.

Глобальная установка (из README):

```bash
npx skills@latest add hanumatori/nodumbmode -g -y -a claude-code -a codex --skill '*'
```

Полезные предупреждения, которые автор честно вынес в README:

- скиллы кладутся один раз в `~/.agents/skills/`, в каталоги агентов уходят **симлинки** — обновление доезжает до всех сразу;
- флаг `--all` брать не стоит: *«он берёт всех известных агентов, включая тех, кто не умеет глобальную установку, и валится с ошибкой на каждом таком»*;
- при согласии «поставить во всех найденных» CLI пишет и тем агентам, которыми вы не пользуетесь, — он смотрит на наличие каталога, а не на факт использования;
- `skills update` **без имён обновляет вообще все** установленные скиллы, включая чужие. Поэтому в README обновление расписано поимённо:

```bash
npx skills@latest update nodumb-loop nodumb edge-hunt ask-nodumb changelog-discipline system-feedback
```

### Без npx вообще

Скиллы — это markdown, никакой CLI для них не обязателен:

```bash
git clone https://github.com/hanumatori/nodumbmode.git
mkdir -p ~/.claude/skills
for s in nodumb nodumb-loop edge-hunt ask-nodumb changelog-discipline system-feedback; do
  cp -r nodumbmode/$s ~/.claude/skills/$s
done
```

Для Codex — `~/.codex/skills/`, для Cursor — `~/.cursor/skills/`. Такой путь заодно снимает вопрос с ником: клонируете по явному адресу и видите, что копируете.

## 5. Цена в токенах — честный расчёт

Пост обещает, что скиллы «не дадут сжигать токены». Разложим.

**Постоянные расходы.** Агент всегда держит в контексте фронтматтеры всех установленных скиллов, чтобы понимать, когда какой включать:

| Скилл | Токенов во фронтматтере |
| :--- | ---: |
| nodumb | 159 |
| edge-hunt | 159 |
| ask-nodumb | 159 |
| system-feedback | 117 |
| nodumb-loop | 108 |
| changelog-discipline | 96 |
| **Итого всегда в контексте** | **798** |

Описания намеренно длинные — в них перечислены и условия «использовать», и условия «не использовать». Для маршрутизации это правильно, но 798 токенов платятся в каждом запросе.

**Переменные расходы.** Дальше работает прогрессивное раскрытие: сначала читается `SKILL.md`, `references/` подтягиваются только по мере надобности. Худший случай — если `nodumb-loop` протащит задачу через несколько скиллов с чтением справочников: до **25 549 токенов**.

Автор это понимает и пишет прямо в `nodumb/SKILL.md`:

> *«Не проходить весь скилл каждый раз. Выбрать нужный режим по текущей ситуации. Перед запуском режима назвать, какой его результат способен изменить следующий шаг; если такого результата нет, пропустить режим.»*

**Вывод по существу:** экономия здесь не на контексте, а на **повторных заходах**. Одна несделанная итерация «переписал не то → откатил → переписал заново» окупает 798 токенов многократно. Но формулировка «не даст сжигать токены» вводит в заблуждение — прямой расход растёт.

## 6. Чем содержание действительно хорошо

Это редкий случай, когда за скиллами стоит собственный опыт, а не пересказ статей.

**Реальный постмортем как источник правил.** `nodumb/references/scaling-postmortem.md` начинается так:

> *«Реальный проект: нативное macOS-приложение, ~12 000 строк UI, один разработчик плюс агент. Продукт работал и использовался ежедневно.»*

И дальше — диагноз, записанный в коммите брошенной ветки редизайна: вёрстка шла угадыванием, токены в противоречивом состоянии, кегли подбирались на глаз, проверялось сборкой, а не живым приложением. Три причины провала, и *«ни одна не про качество макетов»*.

**Правила формулируются как отрицания, а не как благопожелания.** Из `nodumb/SKILL.md`:

> *«Не заводить дизайн-систему, библиотеку компонентов или другой слой просто "на будущее". Нормальный результат проверки — общий слой пока не нужен.»*

> *«Код — дешёвая часть ошибки. Дороже всего уверенно делать не то, не там или на основании факта, которого никто не проверял.»*

**Есть конкретные пороги вместо «делайте хорошо».** Из `AGENTS.md`:

> *«Заводить абстракцию на третьем повторении, не на втором. Два случая не показывают ось изменчивости.»*

> *«Собралось ≠ работает. Визуальные изменения проверять в живом приложении; зелёные тесты означают "не сломал остальное", а не "сделал правильно".»*

> *«Не объявлять победу по сигналу, который физически не может опровергнуть гипотезу.»*

**Проект ест собственную еду.** `CHANGELOG.md` репозитория ведётся ровно по формату, который предписывает `changelog-discipline`: 6 записей в формате **Что / Где / Почему / Было**, с датой и типом (`feat` / `docs`), с явной фиксацией отвергнутых вариантов. Пример из записи от 21 августа:

> *«…отдельное security-правило не добавлялось, потому что ошибка относится к любому переносу контекста»*

Это ровно то, чего почти никогда не бывает в чужих changelog'ах — запись о том, что решили **не** делать и почему.

**Полезное правило про внешний поиск** (добавлено 31 августа), которое стоит прочитать даже без установки скиллов:

> *«Внешний поиск формулировать через контракт, версию и точный симптом, а не через общий запрос "как исправить". Найденное утверждение остаётся гипотезой, пока локальный пробник или воспроизведение не подтвердят его применимость к этому проекту.»*

## 7. Слабые места

| Что | Насколько мешает |
| :--- | :--- |
| **Лицензии нет вообще** | Формально это «все права защищены»: без лицензии у вас нет прав на модификацию и распространение. Для личного использования не мешает, для форка или включения в корпоративный набор — блокер. Стоит завести issue с просьбой добавить MIT |
| **Один автор, ноль обратной связи** | 29 коммитов, все от одного человека; 0 issue, 0 PR, 0 релизов. При 9 форках никто ничего не прислал. Проект живёт ровно столько, сколько им занимается автор |
| **Версий нет** | Без релизов и тегов нельзя закрепиться на конкретной версии — `skills update` всегда тянет `main`. Если правила изменятся не в вашу сторону, откатываться придётся вручную через git |
| **Языки описаний смешаны** | Пять описаний по-русски, у `changelog-discipline` — по-английски. Описание это то, по чему агент решает, включать скилл; разнобой языков в одном наборе — лишний шум для маршрутизации |
| **Нет измерений эффекта** | Главная претензия. Ни одного замера, что с этими скиллами агент ошибается реже |
| **Прицел на дизайн и продукт** | Автор — дизайнер, и это видно: `ask-nodumb`, `system-feedback` и половина `nodumb` про UX, макеты и продуктовые развилки. Бэкендщику часть правил будет мимо |

Отдельно хорошее: имена во фронтматтерах (`name: nodumb` и т. д.) **совпадают с именами каталогов** у всех шести. Звучит мелочью, но именно на этом ломается флаг `--skill` у некоторых наборов — например у [Taste Skill](Taste%20Skill%20%28Leonxlnx%29%20%E2%80%94%2013%20%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%D0%BE%D0%B2%20%D0%BF%D1%80%D0%BE%D1%82%D0%B8%D0%B2%20%D0%98%D0%98-%D1%88%D0%B0%D0%B1%D0%BB%D0%BE%D0%BD%D0%BD%D0%BE%D1%81%D1%82%D0%B8%20%D0%B2%D0%BE%20%D1%84%D1%80%D0%BE%D0%BD%D1%82%D0%B5%D0%BD%D0%B4%D0%B5%20%28%D0%BF%D1%80%D0%BE%D0%B2%D0%B5%D1%80%D0%BA%D0%B0%20%E2%80%94%2022k%20%D1%82%D0%BE%D0%BA%D0%B5%D0%BD%D0%BE%D0%B2%2C%20%D0%BA%D0%B8%D1%80%D0%B8%D0%BB%D0%BB%D0%B8%D1%86%D0%B0%2C%20%D0%B2%D1%8B%D0%B4%D1%83%D0%BC%D0%B0%D0%BD%D0%BD%D1%8B%D0%B5%20%D0%B8%D1%81%D1%81%D0%BB%D0%B5%D0%B4%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F%29.md), где совпали только 4 имени из 13.

## 9. Как проверить, что от этого есть польза

Единственный честный ответ на «не даст совершать ошибки» — измерить. В хранилище для этого уже есть разбор методики: [skillcheck](skillcheck%20%28sx4im%29%20%E2%80%94%20A-B-%D1%82%D0%B5%D1%81%D1%82%20%D1%81%D0%BA%D0%B8%D0%BB%D0%BB%D0%BE%D0%B2%20%28SKILL.md%2C%20AGENTS.md%2C%20CLAUDE.md%29%20%D1%81%D0%BE%20%D1%81%D0%BB%D0%B5%D0%BF%D0%BE%D0%B9%20%D0%BE%D1%86%D0%B5%D0%BD%D0%BA%D0%BE%D0%B9%20%D0%B8%20bootstrap-CI%2C%20%D1%80%D0%B0%D0%B7%D0%B1%D0%BE%D1%80%20%D0%BC%D0%B5%D1%82%D0%BE%D0%B4%D0%B8%D0%BA%D0%B8%20%D0%B8%20%D0%B3%D0%B4%D0%B5%20%D0%BE%D0%BD%D0%B0%20%D0%B2%D1%80%D1%91%D1%82.md) — A/B-тест скиллов со слепой оценкой.

Минимальный домашний вариант без всякой методологии: взять три-четыре свои реальные задачи, прогнать каждую дважды (со скиллами и без), и сравнить не качество кода, а **число итераций до приемлемого результата**. Именно на этой метрике набор и должен окупаться.

Дёшево и полезно: прочитать `nodumb/SKILL.md` и `AGENTS.md` глазами, вытащить оттуда 5–10 правил, которые попадают в ваши грабли, и положить их в свой `CLAUDE.md`. Обойдётся в 200 токенов вместо 798 и не потребует ни CLI, ни доверия чужому репозиторию.

## 10. Установка по системам

Нужен только **Node.js** (или вообще ничего, если копировать вручную — см. раздел 4).

**Gentoo (основная).** Всё из исходников, как обычно:

```bash
emerge -av net-libs/nodejs        # USE="npm" для npm/npx
node --version && npx --version
npx skills@latest add hanumatori/nodumbmode
```

Если не хочется тянуть nodejs ради одной команды — ручной способ через `git clone` и `cp` работает ровно так же и вообще не требует Node.

**Debian / Ubuntu:**

```bash
apt install nodejs npm            # в старых релизах версия древняя — тогда NodeSource
npx skills@latest add hanumatori/nodumbmode
```

**Arch (планируется с июня 2026):**

```bash
pacman -S nodejs npm
npx skills@latest add hanumatori/nodumbmode
```

**Entware / ASUS RT-AX56U:** технически возможно — в репозитории `armv7sf-k3.2` есть `node` **v18.20.2-2** и `node-npm` v18.20.2-2, а также `git` 2.50.1-2. Но смысла нет: скиллы нужны агенту кода, а агент кода на роутере не живёт. Если вдруг понадобилось положить файлы на роутер — проще `git clone` через Entware-git, чем гонять npx на armv7 с 512 МБ ОЗУ.
