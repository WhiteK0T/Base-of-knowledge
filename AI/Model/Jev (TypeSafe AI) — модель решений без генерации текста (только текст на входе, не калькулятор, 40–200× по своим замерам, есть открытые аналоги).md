# 🎚️ Jev (TypeSafe AI) — модель решений без генерации текста

Разбор [поста «Робот сочинит симфонию?» от 20.09.2026](https://t.me/rssjournal/7939) про «новую нейросеть, которая не умеет писать текст, но переворачивает всю индустрию».

**Модель настоящая, класс задач действительно новый, и почти всё в посте — правда.** Это не очередной хайп вокруг обёртки: Jev сделал [Диогу Алмейда](https://techcrunch.com/2026/09/18/a-new-kind-of-ai-model-from-a-chatgpt-inventor-is-thrilling-developers/), бывший исследователь OpenAI и один из авторов ChatGPT и RLHF, компания два года сидела в стелсе. Претензии к посту три, и все — про умолчания:

1. **Jev принимает только текст.** Ни картинок, ни звука, ни видео — документация говорит это прямым текстом. Поэтому «в виртуальной примерочной он слушает человека и примеряет одежду» физически не про Jev: слушает распознавалка речи, одевает генератор картинок, а Jev в этой связке в лучшем случае выбирает *что* надеть.
2. **У вендора есть отдельная страница «где модель косячит»** — и там ровно тот сценарий, на котором разработчик слил $31 680. Jev официально **не калькулятор**, не умеет считать и ненадёжно сравнивает даты. Трейдинг-бот проиграл не вопреки документации, а по ней.
3. **Уже есть открытые аналоги**, которые крутятся локально на CPU — Laya, NanoJev, jev-local и ещё несколько. В посте про них ни слова, а для «второго мозга» это самая полезная часть истории.

Проверено 20.09.2026 по официальной документации и блогу TypeSafe, странице тарифов и лимитов, статье TechCrunch и каталогу сообщества awesome-jev.

## 🧩 Как это устроено

Идея в одной фразе: **LLM генерирует текст для человека, а Jev возвращает значение для кода.**

Обычный путь — попросить LLM выдать JSON, потом распарсить его и надеяться, что схема совпала. Jev убирает оба шага: ты заранее объявляешь пространство ответов, и модель возвращает точку в нём.

| Примитив | Вопрос | Возвращает |
| :--- | :--- | :--- |
| **`Choice`** | Какой отдел должен взять тикет? | `choice`, `probabilities` по каждому варианту, `confidence` |
| **`Score`** | Насколько раздражён клиент? | `score` (дробный), `probabilities` по уровням, `confidence` |
| **`Noul`** | Клиент просит возврат денег? | `noul` — вероятность «да» от 0 до 1 |

Все три типа смешиваются в одном вызове:

```bash
curl -X POST https://api.typesafe.ai/v1/systemone \
  -H "Authorization: Bearer $TYPESAFE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-latest",
    "state": "Третий день не могу подключить Stripe, интеграция падает. Теряю продажи, помогите срочно.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Какая команда должна это взять",
        "criteria": {
          "billing":   "Платежи и подписки",
          "technical": "Баги и проблемы интеграции",
          "sales":     "Цены и вопросы по аккаунту"
        }
      },
      "is_urgent": {
        "type": "noul",
        "instructions": "Сообщение передаёт срочность"
      }
    }
  }'
```

Ответ — сразу готовые к употреблению значения:

```json
{
  "model": "jev-1.13.0",
  "answers": {
    "department": {
      "type": "choice",
      "choice": "technical",
      "confidence": 0.78,
      "probabilities": { "technical": 0.85, "billing": 0.15, "sales": 0.0 }
    },
    "is_urgent": { "type": "noul", "noul": 0.95 }
  }
}
```

> [!note] Почему «System One»
> Отсылка к Канеману: Система 1 — быстрые интуитивные суждения, Система 2 — медленное обдумывание. Фронтирные LLM гонятся за Системой 2; Jev сознательно занял пустую нишу Системы 1. Правило из доков: **один вопрос = одно суждение**, которое знающий человек вынес бы за пару секунд. Сложное решение надо разложить на атомарные вопросы и собрать в коде — тогда при смене приоритетов правишь коэффициент, а не переписываешь промпт.

## 🎭 «Не галлюцинирует» — что за этим стоит

Формулировка гуляет по пересказам, и её стоит понимать буквально.

> [!warning] Гарантия типа, а не гарантия правды
> Jev **математически не может** вернуть значение вне объявленной схемы — вариантов ровно столько, сколько ты перечислил. Именно это и называют «нулём галлюцинаций».
>
> Но **ответ по-прежнему может быть неверным**. Вендор сам оговаривает, что цифры про галлюцинации и типобезопасность **не эмпирические**, а следуют из конструкции. И про калибровку: *«калибровка измеряется на группах предсказаний; она не гарантирует, что отдельный ответ верен»*.

Отдельная тонкость — `confidence` ≠ вероятность. Из примера в доках: топовый вариант набрал 0,84, но у второго было 0,159, и `confidence` вышел **0,596** — модель показывает не «насколько уверена в победителе», а насколько распределение похоже на решённое.

## 🪚 Где модель косячит — официальный список

Это самая ценная страница в документации и одновременно самое крупное умолчание поста. TypeSafe ведёт раздел **[jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13)** — «зазубрины», где `jev-1.13` работает плохо.

| Что ломается | Как правильно |
| :--- | :--- |
| **Буквальное чтение.** Модель отвечает на вопрос, который ты написал, а не на тот, что имел в виду; отрицания и подразумеваемые условия читаются в лоб | Прописывать точное условие в `instructions`, граничные случаи — в `criteria` |
| **Математика и счёт.** «Jev не калькулятор». Не считает надёжно ни символы, ни вхождения, ни элементы длинного списка — ошибка растёт с размером | Считать в коде: задать по одному `Noul` на элемент и просуммировать самому |
| **Числовые представления.** По hex-кодам цветов работает хуже, чем по названиям; по ассемблеру хуже, чем по высокоуровневому коду | Конвертировать в коде, модели оставлять именно суждение |
| **Даты и время.** Читает даты как текст, а не как упорядоченные величины. Что раньше, насколько далеко, попадает ли в окно — **ненадёжно** | Извлекать компоненты через `Choice` (12 месяцев, 31 день — закрытые множества), арифметику делать в коде |
| **Индирекция.** Двойные отрицания и «свойство свойства» стоят точности | Писать прямо, называть нужные части `state` по имени |
| **Большой `state` с лишним.** Точность падает, когда в состоянии много нерелевантного — **Jev страдает от context rot** | Фильтровать до отправки; если нельзя — отсеивать через `Noul` на релевантность |
| **Состязательный контент.** *«State — это данные, и `jev-1.13` не считает их враждебными по умолчанию»*. Инъекция инструкции или текст, аргументирующий сам за свою классификацию, **сдвигают ответ** | Явные критерии + тестирование граничных случаев до продакшена |
| **Структурные инварианты не гарантированы** | Не переносить порог с `Noul` на `Choice` и не ждать арифметических тождеств между вопросами |

> [!danger] Их собственный пример развала инвариантов
> Один и тот же вопрос «клиент просит возврат?» на тикете *«Мне не подошёл размер. Какие у меня варианты?»*:
>
> | `Noul` | `Choice` yes | `Choice` no | `Choice` confidence |
> | ---: | ---: | ---: | ---: |
> | 0,22 | 0,01 | 0,99 | 0,97 |
>
> А вопрос и его отрицание, заданные двумя `Noul` на тикете «списали дважды»: `refund` = 0,72, `not_refund` = 0,47, **сумма 1,19**. Вероятности не складываются в единицу, и так и задумано — это разные вопросы, а не две стороны одного.

Ещё два ограничения, которые легко проглядеть:

- **Язык.** Английский — основной язык обучения и там точность лучшая. Остальные, включая CJK, *«обрабатываются, но не одинаково хорошо»*. **Для русскоязычного контента надо тестировать самому** и внимательно смотреть на `confidence`.
- **Никакого дообучения.** Одни и те же веса на все аккаунты, ни файнтюна, ни LoRA. Домен задаётся только через `state`, `instructions` и `criteria`.

## 🔍 Разбор трёх демо из поста

### SEO-аудит за $0,21 — цифры сходятся, но работал не только Jev

586 страниц, 8 790 решений, 45 секунд, $0,21 — всё верно. Что пост опустил: **8 790 = 586 × 15**, то есть перед Jev стоял отдельный этап. Пайплайн был такой:

1. **эмбеддинги** отобрали по 15 ближайших страниц-кандидатов для каждой;
2. **Jev** отвечал «да/нет» по каждой паре — это и есть 8 790 вопросов;
3. **`Choice`** выбирал якорный текст **из уже существующего в тексте**, а не сочинял его.

Итог: 584 проставленные внутренние ссылки, 139 страниц модель отказалась линковать — ничего не подошло. Сравнение в том же прогоне: Claude Opus 5 за то же время успел 21 страницу за $1,43.

Это хорошая иллюстрация правильного применения — **Jev как быстрый фильтр внутри пайплайна**, а не как замена всему.

### Примерочная — единственное место, где пост ошибается

Jev не принимает ни аудио, ни изображения. Реалистичная схема такой демки: распознавание речи → текст → Jev выбирает предмет одежды из каталога → генератор картинок. Подпись «он слушает человека и примеряет одежду» приписывает Jev две способности, которых у него нет по документации.

### Торговый бот на −$31 680 — ровно то, от чего предупреждает вендор

Бот получал биржевые и ончейн-данные и решал, какие сделки совершать. Но биржевые данные — это **числа и временные ряды**, то есть пересечение сразу двух официальных слабых мест: «не калькулятор» и «даты читает как текст». Плюс рынок — состязательная среда, а Jev *«не считает state враждебным по умолчанию»*.

Правильная форма была бы другой: считать индикаторы в коде, а Jev спрашивать что-то семантическое — например, «похож ли этот новостной заголовок на объявление о делистинге». Потеря — не баг модели, а применение её там, где документация прямо говорит не применять.

## 🏠 Открытые аналоги — то, чего в посте нет

Класс оказался воспроизводимым, и за неделю появилось несколько открытых реализаций. Для локального запуска это важнее самого Jev.

| Проект | Что это |
| :--- | :--- |
| **[Laya](https://github.com/NandhaKishorM/laya)** | Apache-2.0, `pip install laya`. Три чекпоинта: `laya` (ModernBERT-large, 421M, контекст 512, английский), `laya-multilingual` (mmBERT-base, **322M, контекст 1024, 100+ языков**, вдвое быстрее), `laya-typed-decisions`. Те же `choice`/`score`/`noul`, обучение тем же RLCD, **один форвард-пасс ~33 мс** (7,2 мс на вопрос в батче, замер на T4). Есть роутер, который сам выбирает чекпоинт по языку |
| **[jev-local](https://github.com/us/jev-local)** | Локальный сервер с **тем же `POST /v1/systemone`** на открытых весах — проверен как drop-in замена под официальный SDK, с температурной калибровкой |
| **[NanoJev](https://github.com/TianyuCodings/NanoJev)** | 0.6B, параллельная модель решений с полными распределениями и без декодирования выходных токенов; выложены пайплайн обучения, веса и датасет |
| **[laya-mlx](https://github.com/mizorewww/laya-mlx)** | Порт Laya под Apple Silicon: 13,4 мс на решение, без PyTorch и облака |
| **minojev, openJev-verdict-2.0** | Совсем мелкие реплики — 547k и 151M параметров |

Каталог всего экосистемного — [awesome-jev](https://github.com/yibie/awesome-jev) (более 250 проектов по категориям). Там же видно, где класс реально прижился: **роутеры моделей** (`jev-router`, `pi-jev-router`, `jcm-router` — выбор дешёвой модели под каждый запрос), **гардрейлы** (`jev-git` — pre-commit, который за доли секунды ищет в диффе секреты и опасные команды) и **computer use**.

### По платформам

Сам Jev — обычный HTTPS API, поэтому «установка» сводится к SDK либо к `curl`.

| Система | Что нужно |
| :--- | :--- |
| **Gentoo** (основная) | Python в системе уже есть; SDK ставить **в venv**, а не в систему: `python -m venv ~/.venvs/jev && ~/.venvs/jev/bin/pip install typesafe-sdk`. Для локальной Laya — там же `pip install laya` (потянет torch; для CPU-сборки бери индекс `--index-url https://download.pytorch.org/whl/cpu`) |
| **Debian / Ubuntu** | `apt install python3-venv`, дальше venv и `pip install typesafe-sdk` / `laya`. Node-вариант: `npm i @typesafe-ai/sdk` |
| **Arch** | `pacman -S python python-virtualenv` (или `python-pipx` для изолированной установки CLI), дальше так же |
| **Entware / RT-AX56U** | ✅ **Работает — и это не шутка.** Jev живёт в облаке, роутеру нужен только HTTPS-клиент: `opkg install curl ca-certificates jq` (в репозитории `armv7sf-k3.2` есть `curl` 8.15.0 и `jq` 1.8.1), либо `opkg install python3 python3-pip` (Python **3.13.9**) и SDK в venv. Готовый сценарий — гонять логи или события роутера через `Noul` и решать, слать ли алерт.<br>❌ **А вот локальные аналоги — нет:** в репозитории Entware нет ни одного пакета с torch, а 322M параметров Laya в 512 МБ ОЗУ не поместятся |

## 💡 Итог

- **Класс задач действительно новый и полезный.** Там, где ответ выбирается из известного множества, решение принимается много раз подряд и есть куда деть `confidence`, — Jev объективно уместнее LLM. $0,042 за миллион входных токенов и бесплатный выход при задержке 70–500 мс делают возможными вещи, которые на фронтирной модели просто не окупались.
- **«Не галлюцинирует» = не нарушает схему.** Соответствие типу гарантировано конструкцией, правильность ответа — нет, и вендор это оговаривает сам.
- **Главное умолчание поста — страница jaggedness.** Не калькулятор, не сравнивает даты, читает буквально, страдает от лишнего в `state`, поддаётся инъекциям в данных, не гарантирует структурных инвариантов. Потерянные на боте $31 680 — прямое следствие первых двух пунктов.
- **Демка с примерочной приписана не тому.** Jev принимает только текст.
- **Замеры вендорские, и вендор честно это помечает:** воркфлоу для бенчмарков писала его же команда, «193,6× и 444,6×» названы верхней границей, цифры про галлюцинации — не эмпирические.
- **Для русского языка — обязателен свой тест.** Английский основной, остальные «не одинаково хорошо».
- **Весов нет, self-hosting невозможен, лимиты меняются без уведомления.** Если это критично — смотреть в сторону Laya и jev-local: те же три примитива, Apache-2.0, локально и на CPU.
- **Формула из поста «LLM ставит цели, Jev принимает тысячу мелких решений» — это ровно то, что рекомендует вендор** под именем confidence-gated routing. Тут пост угадал.
