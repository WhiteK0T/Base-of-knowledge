# Heretic — снятие safety-ограничений с открытых LLM (abliteration)

[**Heretic**](https://github.com/p-e-w/heretic) (автор — p-e-w, лицензия **AGPL-3.0-or-later**) — инструмент, который **автоматически** убирает «отказы» (safety-refusals) из открытых трансформерных языковых моделей методом **abliteration** (directional ablation), без дообучения. Цель — получить «расцензуренную» модель, минимально потеряв исходные способности.

Стал заметным: ~20k+ звёзд на GitHub, попал в тренды; сообщество выложило 3000+ обработанных вариантов моделей.

> [!warning] Юридический и этический контекст
> Снятие safety-ограничений **повышает риск** генерации вредоносного контента и может нарушать лицензии/условия использования конкретных моделей. Это инструмент **dual-use**: легитимные применения — исследования alignment и механизмов отказа, red-teaming, изучение устойчивости защит; нелегитимные — обход ограничений для вредоносных целей. Использовать только к моделям, чья лицензия это допускает, и в рамках закона. Заметка носит **справочно-образовательный** характер.

## 🧠 Как работает (принцип)

Abliteration основан на наблюдении, что «отказ» в модели соответствует определённому **направлению в пространстве скрытых состояний**:

1. Прогоняются **вредные** и **безвредные** промпты, вычисляется разница скрытых состояний → находится «направление отказа» (refusal direction).
2. Матрицы компонентов трансформера **ортогонализируются** относительно этого направления (послойными весовыми ядрами ablation).
3. Параметры **оптимизируются автоматически**, балансируя подавление отказов и качество модели.

Ключевое отличие от ранних ручных подходов — полная автоматизация + оптимизация параметров для минимальной деградации (в посте приводят пример Gemma 3 12B: отказы со 97/100 до 3/100 при KL-дивергенции ~0.16).

## 🖥️ Поддержка и требования

- **Модели:** большинство dense-моделей (включая мультимодальные), ряд MoE и гибридных архитектур (напр. Qwen3.5). Чистые state-space и некоторые исследовательские архитектуры — без встроенной поддержки.
- **PyTorch:** 2.2+ (некоторым моделям нужен 2.6+).
- **Железо:** на RTX 3090 модель ~4B обрабатывается за ~20–30 минут; **квантизация** через `bitsandbytes` (4-bit) заметно снижает требования к VRAM. Инструмент сам бенчмаркит систему для подбора batch size.

## ⚙️ Установка и базовый запуск

```bash
pip install -U heretic-llm
heretic Qwen/Qwen3-4B-Instruct-2507
```

После обработки модель можно сохранить локально, выгрузить на Hugging Face, пообщаться с ней интерактивно или прогнать стандартные бенчмарки (MMLU, GSM8K). Тонкая настройка — через конфиги и опции CLI.

## 🧪 Живой пример: Qwen3.8-27B-Uncensored-FP8 (OrcaRouter)

Разбор поста [t.me/bugnotfeature/27287](https://t.me/bugnotfeature/27287) — *«Qwen3.8 БЕЗ ЦЕНЗУРЫ и ограничений вышла»*. Полезен тем, что это **готовая абляционированная модель с опубликованными замерами** — можно посмотреть, что метод даёт на практике, а не в теории.

| «идеал для разраба изучить поведение LLM» | ✅ | Ровно то, что пишут авторы: research, интерпретируемость, red-teaming. Они же добавляют: *«Do not deploy it to end users or in production without adding your own safety, moderation, and abuse-prevention layers»* |
| не сказано в посте | ℹ️ | Это **мультимодальная** vision-language модель (изображения + видео), контекст **262 144** токена, сохранён MTP-хед спекулятивного декодирования |

### Как именно сделана абляция

Карточка модели описывает процедуру подробно — и это буквально метод из статьи, на которой стоит весь abliteration: [Arditi et al., «Refusal in Language Models Is Mediated by a Single Direction»](https://arxiv.org/abs/2406.11717) (arXiv:2406.11717, 17.06.2024, среди авторов Neel Nanda).

- Одно направление отказа `r` (k = 1) оценивается как разность средних последних остаточных состояний на **вредных (AdvBench)** и **безвредных (Alpaca)** промптах, на **слое 38** из 64 (`round(0.6 × 64)`), с маскированием massive-активаций.
- Дальше `r` ортогонализируется из каждой матрицы, пишущей в остаточный поток: `W' = W − r(rᵀW)`, вычисление во float32.

| Что правили | Матриц |
| :--- | ---: |
| `self_attn.o_proj` (16 слоёв полного внимания + MTP) | 17 |
| `linear_attn.out_proj` (48 слоёв Gated DeltaNet) | 48 |
| `mlp.down_proj` (64 слоя + MTP) | 65 |
| `embed_tokens` (пространство строк) | 1 |
| **Итого** | **131** |

Зрительная башня не тронута совсем (все 333 тензора `visual.*` скопированы как есть), MTP-хед абляционирован согласованно с основной моделью — поэтому спекулятивное декодирование продолжает работать. Остаточная «утечка» направления после правки — `1.8e-2`.

Только после этого веса переквантованы в **block-FP8 (E4M3)**, блок 128×128, активации динамические по токенам, без калибровочного набора: 407 весов квантованы, 792 скопированы, 1606 тензоров — ровно как в официальном `Qwen3.8-27B-FP8`, с совпадением FP8-кодов на 99,9 %.

### Что дают замеры

Это самая ценная часть: у метода наконец есть цифры на серьёзной модели, а не на 4B.

**Отказы на вредных промптах, режим размышления выключен** (меньше = «расцензуреннее»):

| Бенчмарк | n | База FP8 | Эта модель | Ответ с дисклеймером |
| :--- | ---: | ---: | ---: | ---: |
| AdvBench | 100 | 99,0 % | **0,0 %** | 44,0 % |
| JailbreakBench (harmful) | 100 | 94,0 % | **0,0 %** | 47,0 % |
| StrongREJECT | 150 | 97,3 % | **2,0 %** | 41,3 % |
| HarmBench (standard) | 150 | 98,7 % | **2,7 %** | 42,0 % |
| MaliciousInstruct | 100 | 99,0 % | **0,0 %** | 40,0 % |
| SimpleSafetyTests | 50 | 64,0 % | **6,0 %** | 56,0 % |
| ForbiddenQuestions | 150 | 73,3 % | **4,7 %** | 35,3 % |

С включённым размышлением отказы падают ещё ниже — не выше **1,7 %** ни на одном наборе.

**Ложные отказы на безобидных промптах** (XSTest-safe, n = 250): **5,6 % → 0,4 %**. Это отдельный аргумент в пользу метода: абляция снижает не только настоящие отказы, но и «перестраховочные».

**Сохранение способностей** — против официальной базы FP8, теми же скриптами:

| Бенчмарк | n | База FP8 | Эта модель | Δ |
| :--- | ---: | ---: | ---: | ---: |
| MMLU (0-shot) | 300 | 84,3 % | 84,7 % | **+0,4** |
| MMLU-Pro (CoT) | 250 | 77,6 % | 76,8 % | −0,8 |
| GSM8K (CoT) | 150 | 90,0 % | 88,7 % | −1,3 |
| CMMLU (китайский) | 500 | 81,4 % | 80,8 % | −0,6 |

Перплексия на WikiText-2-raw — 6,96. То есть заявление Heretic о «минимальной деградации» на этой модели подтверждается независимо: всё в пределах ±1,3 пункта.

> [!note] Насколько этим цифрам верить
> Авторы сами оговаривают методику: отказ определяется **правиловым классификатором по первой фразе ответа**, и это *«indicative, not an LLM-judge / publication-grade number»*. Цифры сравнимы между базой и переделкой (скрипты и настройки одни), но это не публикационного уровня оценка. Размеры выборок тоже скромные — 50–500 промптов.

### Чей это релиз и зачем

Публикует **OrcaRouter** — коммерческий шлюз к LLM («200+ Models. Programmable Routing. 0% Markup… **Agent Firewall. Guardrails.**»). В организации 22 модели: семейство `Qwen3.8-27B-Uncensored` в шести форматах (FP8, GGUF, MLX, NVFP4, INT8 и неквантованный), плюс `Qwen3.8-Flash-Next-Uncensored` и `GLM-5.3-Flash-Uncensored`. Эта же модель у них крутится на платном хостинге как API.

То есть «расцензуренные» веса здесь — заодно и витрина для платного шлюза, который в описании продаёт как раз файрвол и гардрейлы. На качество самой работы это не влияет, но понимать контекст полезно.

Популярность на 09.09.2026: 417 156 загрузок и 1 483 лайка у FP8-варианта, 299 670 у GGUF, 148 416 у MLX.

### Как запускать

Развёртывание — vLLM, из карточки модели:

```bash
docker run -d --name qwen38-uncensored --gpus all --ipc=host --shm-size=8g \
  -v /path/to/Qwen3.8-27B-Uncensored-FP8:/model:ro \
  -p 8000:8000 vllm/vllm-openai:v0.24.0 \
  --model /model --served-model-name Qwen3.8-27B-Uncensored \
  --language-model-only \
  --speculative-config '{"method":"mtp","num_speculative_tokens":3}' \
  --kv-cache-dtype fp8 \
  --gpu-memory-utilization 0.9 \
  --max-model-len 262144 --max-num-seqs 96 \
  --trust-remote-code \
  --reasoning-parser qwen3 \
  --enable-auto-tool-choice --tool-call-parser qwen3_coder
```

Важное из их же примечаний: `quantization_config` берётся из `config.json`, **`--quantization fp8` передавать не надо**; флаг `--language-model-only` отключает зрение — убрать, если нужна мультимодальность.

Практически это значит: **30,9 ГБ весов плюс KV-кэш на 262K контекста**, и FP8-путь vLLM требует GPU с аппаратным FP8 (Hopper/Ada/Blackwell). На одной потребительской карте с 24 ГБ не поместится — либо две карты, либо 48/80 ГБ, либо GGUF-вариант на CPU с большим ОЗУ. Для владельца этой базы знаний вывод простой: на Gentoo-десктопе без такой видеокарты запускать нечего, а на роутере с Entware — тем более.
