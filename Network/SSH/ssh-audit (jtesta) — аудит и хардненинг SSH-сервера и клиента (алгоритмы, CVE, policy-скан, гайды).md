# 🔐 ssh-audit (jtesta) — аудит и хардненинг SSH-сервера и клиента

[**ssh-audit**](https://github.com/jtesta/ssh-audit) (поддерживаемый форк v2.0+ от **Joe Testa / jtesta**) — инструмент на **Python** для аудита безопасности SSH. Подключается к SSH-сервису (или слушает подключение клиента), снимает баннер, разбирает обмен ключами и **все поддерживаемые алгоритмы** (key exchange, host-key, шифрование, MAC, сжатие) и ставит каждому оценку: `weak` / `legacy` / `unsafe` и т.п., плюс даёт исторический контекст по OpenSSH / Dropbear / libssh и рекомендации, что выключить. Лицензия **MIT**, ~**4.3k★**, Python **3.10–3.14**, **без внешних зависимостей**.

> [!note] Пост описал лишь верхушку
> В посте: «собирает баннеры, обмен ключами, алгоритмы». Это верно, но это **малая часть**. Реально ssh-audit ещё: аудитит **и сервер, и клиент**, делает **policy-скан** (проверка на соответствие эталонной хардненинг-конфигурации), находит **известные CVE** для версии, тестирует **длину DH-модуля и RSA-ключа**, определяет ОС/устройство и **выдаёт готовые команды/гайды по хардненингу**. Ниже — по пунктам.

## 🧰 Что умеет

| Возможность | Детали |
| :--- | :--- |
| **Аудит сервера** | коннект к SSH → баннер, KEX, host-key, шифры, MAC, сжатие; оценка каждого алгоритма и рекомендации |
| **Аудит клиента** | режим прослушки (`-c`, по умолчанию порт **2222**): запускаешь, клиент подключается — ssh-audit разбирает **его** набор алгоритмов |
| **Policy-скан** | `-P` — проверка на соответствие встроенной или своей политике (хардненинг/compliance), в т.ч. батчем по списку хостов `-T` |
| **CVE и история** | сопоставляет версию SSH-софта с известными уязвимостями и историей изменений алгоритмов |
| **Крипто-проверки** | длина DH-модуля (moduli), длина RSA host-key |
| **Хардненинг-гайды** | встроены: `--list-hardening-guides`, `--get-hardening-guide <os>`; полные гайды — на [sshaudit.com](https://www.sshaudit.com/hardening_guides.html) |
| **Форматы/поиск** | JSON-вывод (`-j`) для автоматизации; `--lookup alg1,alg2` — справка по конкретным алгоритмам |

```bash
ssh-audit example.com                 # базовый аудит сервера (порт 22)
ssh-audit -p 2222 host                # нестандартный порт
ssh-audit -c                          # аудит клиента (слушает :2222, жди подключения)
ssh-audit -T servers.txt -P policy.txt  # policy-скан по списку хостов
ssh-audit -j host                     # вывод в JSON
ssh-audit --get-hardening-guide openssh # готовый рецепт хардненинга
```

## 🧪 Нюансы (то, чего в посте нет)

> [!tip] Главная ценность — не «показать алгоритмы», а сказать что чинить
> ssh-audit не просто перечисляет алгоритмы — он помечает слабые (`arcfour`, `cbc`, `sha1`-KEX, короткие DH-moduli, `ssh-rsa`) и даёт **конкретный** хардненинг-рецепт под ОС. Практический сценарий: `ssh-audit localhost` → видишь `(fail)`-строки → берёшь `--get-hardening-guide` → правишь `sshd_config` → перепроверяешь. Отлично ложится на [SSH-Ключи](SSH-%D0%9A%D0%BB%D1%8E%D1%87%D0%B8.md) и настройку sshd.

> [!warning] Онлайн-скан = отправка цели третьей стороне
> Есть веб-версии ([ssh-audit.com](https://www.ssh-audit.com/), сторонний sshaudit.online) — удобно без установки, но ты **сообщаешь чужому сервису IP/хост своей цели**, и скан идёт **с их адресов**, а не с твоего. Для своей инфраструктуры/приватности запускай **локально** (pip/скрипт) — зависимостей нет, это одиночный Python-файл.

> [!danger] Скан чужого SSH — только с разрешения (право)
> ssh-audit делает полноценный SSH-хендшейк к цели. Аудит **своих** серверов/клиентов и авторизованных в scope — норма. Скан **чужого** SSH без разрешения в РФ подпадает под ст. 272 УК (неправомерный доступ/попытка), а с чужих IP (онлайн-сервис) — тем более. По своим хостам — сколько угодно.

## 🚀 Установка и запуск на твоих системах

Инструмент — один Python-скрипт без зависимостей, поэтому переносим куда угодно, где есть Python 3.10+. Универсальный путь — `pipx`/`pip`; где есть родной пакет — можно им.

| Система | Установка | Примечание |
| :--- | :--- | :--- |
| **Gentoo** (основная) | `pipx install ssh-audit` (в `dev-python/pipx`), либо `git clone` + `python ssh-audit.py` | зависимостей нет — venv не обязателен; проверяй свой `sshd` из OpenSSH |
| **Debian / Ubuntu** | `apt install ssh-audit` (есть в репозитории) или `pipx install ssh-audit` | пакет может отставать от upstream — для свежих CVE-баз бери pip |
| **Arch** (план с июня 2026) | `pipx install ssh-audit`, либо `ssh-audit` из AUR (`yay -S ssh-audit`) | |
| **Entware / RT-AX56U** | не ставить на роутер, а **аудитить его снаружи**: `ssh-audit <ip_роутера> -p 22` с десктопа | на Entware SSH — это **Dropbear**, у которого набор алгоритмов беднее OpenSSH; ssh-audit **знает Dropbear** и корректно оценит его. Ставить сам ssh-audit на armv7 нет смысла (Python-скрипт бы завёлся при наличии `python3`, но флеш жалко) |

> [!note] Docker/Snap/Homebrew/Windows
> Есть и готовые сборки: **Docker**, **Snap**, **Homebrew**, **exe под Windows** — на случай, если не хочется Python на хосте. Для Gentoo/Arch практичнее `pipx`.

## 💡 Кому полезно

- **Себе (хардненинг):** быстро проверить `sshd` на своих Gentoo/Debian/Arch и Dropbear на RT-AX56U, выпилить слабые алгоритмы по готовому гайду.
- **Пентест/аудит (recon):** энумерация SSH на авторизованных целях — версия, алгоритмы, потенциальные CVE.
- **CI/compliance:** JSON-вывод + policy-скан (`-P`) → гейт «конфиг SSH не деградировал» в пайплайне.
