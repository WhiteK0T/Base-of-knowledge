# 📡 Restreamer — свой стриминг-сервер (приём OBS, рестрим на площадки)

**Restreamer** ([github.com/datarhei/restreamer](https://github.com/datarhei/restreamer)) — зрелое **self-hosted решение для видеостриминга**: принимает поток из **OBS по RTMP/SRT**, раздаёт его на своём сайте (встроенный **VideoJS**-плеер + HLS) и **рестримит на YouTube/Twitch/Facebook/Vimeo/Wowza** и т.п. Есть удобный веб-UI, мастер настройки, REST API (Swagger), мониторинг зрителей/ресурсов, аппаратное ускорение. **Apache-2.0, ~5.1k★, живёт с 2015 года** — это не однодневка, а устоявшийся проект.

> [!note] Правка к посту: «Lang: HTML» — это не про суть
> GitHub помечает язык как **HTML** из-за веб-UI. По факту это **Go-ядро** ([datarhei/core](https://github.com/datarhei/core)) + **FFmpeg** для обработки видео + web-фронт. То есть «движок» — Go/FFmpeg, а не «HTML-программа».

> [!info] Что умеет (по README, подтверждено)
> - **Вход**: несколько аудио/видео-входов, RTMP/S, SRT, RTSP, локальные/USB-камеры, виртуальные устройства.
> - **Рестрим/выход**: на YouTube-Live, Twitch, Facebook, Vimeo, Wowza и любой RTMP/SRT-приёмник.
> - **Сервер раздачи**: HTTP/S (**HLS**), RTMP/S, SRT; встроенный **VideoJS**-плеер и настраиваемая публичная страница трансляции (можно без встраивания плеера).
> - **Автоматический HTTPS Let's Encrypt**, лимиты зрителей/полосы, мониторинг ресурсов (опц. **Prometheus-метрики**), логирование процессов.
> - **REST API (JSON), 100% Swagger** — всё скриптуется.
> - **HW-ускорение**: Raspberry Pi (MMAL/OMX), **Nvidia CUDA**, **Intel VAAPI** — отдельные Docker-образы (`rpi-latest`, `cuda-latest`, `vaapi-latest`).
> - Заявлен **GDPR-friendly**: без сторонних провайдеров, не собирает данные зрителей.

> [!caution] Подводные камни self-hosting стрима
> - **Транскодинг — тяжёлый.** *Рестрим без перекодирования* (copy) — лёгкий; но как только нужно **перекодировать** (сменить кодек/битрейт/разрешение) — это грузит CPU или требует **HW-ускорения** (VAAPI/CUDA/RPi). На слабом железе — только passthrough.
> - **Аплоад — главный лимит.** Рестрим на несколько площадок = ты **отдаёшь копию потока на каждую** (4 площадки ≈ 4× битрейта вверх). Домашний канал с узким upload это быстро упрёт. По-хорошему — VPS/сервер с широким каналом.
> - **Порты и проброс**: UI `8080`/`8181`, RTMP `1935`/`1936`, SRT `6000/udp`. Для доступа извне — **проброс портов** на роутере на внутренний IP.
> - **Безопасность**: демо-логин `admin/demo` — сразу **смени пароль**, закрой UI за HTTPS, не выставляй голым. `--privileged` в примерах нужен только для локальных USB-камер — без надобности не включай.
> - **Релизы**: свежий тег — **v2.12.0 (сен 2024)**, репозиторий при этом дорабатывается (последние правки — май 2026). Стабильный, но бурного потока релизов сейчас нет; 264 открытых issue (это нормально для крупного проекта).

## 🖥️ Применимость на системах владельца

Разворачивается **в Docker** (основной способ), образы под AMD64/ARMv7/ARM64:

| Система | Как |
| :--- | :--- |
| **Gentoo (основная) / Debian-Ubuntu / Arch** | ✅ через Docker (`datarhei/restreamer:latest`). Для перекодирования — задействуй **Intel VAAPI** (`:vaapi-latest`, проброс `/dev/dri`) или **Nvidia CUDA** (`:cuda-latest`, `--runtime=nvidia`), иначе ляжет на CPU |
| **VPS / облако** | ✅ **лучший вариант для рестрима**: широкий аплоад, публичный IP, порты открыты. UI за reverse-proxy c HTTPS |
| **Windows / macOS** | ✅ через Docker Desktop (для домашних тестов) |
| **Entware / RT-AX56U** | ➖ формально есть ARM-образы, но **Docker на роутере нет**, а FFmpeg-транскодинг на **armv7/512 МБ** нереален. Роутер годится максимум как точка **проброса портов** к серверу, но не как хост Restreamer |

> [!tip] Когда это тебе (self-host + Linux)
> Если хочешь **свою точку раздачи стрима** (камера/OBS → свой сайт + одновременный рестрим на площадки) без облачных сервисов — Restreamer закрывает это «из коробки» с UI и API. Практично: держи на **машине с VAAPI/CUDA** (перекодирование) или на **VPS с толстым каналом** (рестрим на несколько площадок), UI — за HTTPS, пароль сменить первым делом. Для разовой перекачки/конвертации файлов это не тот инструмент — это **живой стриминг**.
