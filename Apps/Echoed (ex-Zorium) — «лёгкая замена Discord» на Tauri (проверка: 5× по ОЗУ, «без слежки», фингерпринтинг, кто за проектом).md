# Echoed — «Discord в прошлом»?

**Что это.** Закрытый (проприетарный) мессенджер для сообществ: серверы, текстовые и голосовые каналы, видео, демонстрация экрана, роли, боты, канбан-доски и календарь. Десктопный клиент собран на **Tauri** — то есть оболочка на Rust вместо Electron, за счёт чего приложение действительно легче Discord. Веб, Windows, macOS, Linux, iOS, Android.

Идея живая: Discord тяжёлый, и в 2026 году к нему добавилась верификация возраста со сканом лица. Лёгкая альтернатива без этого — востребованная ниша. Но конкретно этот проект подан в посте так, что почти каждый пункт требует уточнения, а два заявления прямо противоречат тому, что лежит в его собственном коде.

> [!warning] Аудитория поста отреагировала скептически
> Под самим постом **👎 79 против ❤ 25** — редкий случай, когда реакции перевешивают в минус. Проверка объясняет, почему.

> [!info] Паспорт проекта (проверено 12 августа 2026)
> - **Сайт:** `echoed.gg`, приложение — `beta.echoed.gg` (всё ещё **бета**)
> - **Раньше назывался Zorium**: `zoriumapp.com` отдаёт редирект на `echoed.gg`
> - **Исходники закрыты**, публичного репозитория нет
> - **Версии:** десктоп **1.7.8** (9 августа 2026), iOS — **8.0.0**
> - **Юрлицо:** Echoed Labs LLC, Вайоминг, рег. № 2026-001939737
> - Голос и видео — на **LiveKit**, реалтайм — Socket.IO, API — `go.echoed.gg`

## 3. Про «в 5 раз меньше оперативы»

Разберём честно, потому что тут есть и правда, и передёргивание.

**Что правда.** Tauri действительно принципиально экономнее Electron. Electron тащит с собой целый Chromium и Node.js в каждом приложении; Tauri использует **системный вебвью** — WebView2 на Windows, WKWebView на macOS, WebKitGTK на Linux — и добавляет к нему тонкий слой на Rust. Разница в размере дистрибутива видна невооружённым глазом:

| Сборка Echoed 1.7.8 | Размер |
| :--- | ---: |
| Windows `.exe` | 30 МБ |
| Windows `.msi` | 33 МБ |
| macOS `.dmg` (universal) | 50 МБ |
| Linux `.deb` | 35 МБ |
| Linux `.rpm` | 35 МБ |
| **Linux `.AppImage`** | **121 МБ** |

Установщик Discord — заметно за сотню мегабайт, и это ожидаемо: там внутри свой браузер.

**Что передёргивание.**

1. **Арифметика.** 700 ÷ 150 = 4,7. «В 5 раз» — округление в свою пользу.
2. **Сравниваются разные нагрузки.** 700 МБ Discord набирает не на пустом месте: это аккаунт с десятками серверов, историей, активным голосом, оверлеем и аппаратным ускорением. Свежий клиент почти без серверов на этом фоне будет лёгким у кого угодно. Корректное сравнение — одинаковый профиль нагрузки, и такого замера проект не приводит.
3. **Память не исчезает, а переезжает.** Процесс приложения худеет за счёт того, что рендерингом занимается системный вебвью. На Windows это WebView2 (тот же Chromium, просто общий на всю систему), на Linux — WebKitGTK. В диспетчере задач вы увидите меньше у самого приложения, но не обязательно у системы в целом.
4. **На Linux «лёгкость» частично теряется.** AppImage весит 121 МБ против 35 МБ у `.deb` — ровно потому, что тащит зависимости с собой. А на главной странице сайта из всех линуксовых сборок ссылка стоит **только на AppImage**.

> [!note] Итог по весу
> Приложение объективно легче Discord — это следствие архитектуры Tauri, и тут спорить не с чем. Но «в 5 раз» — маркетинговая формулировка из неравного сравнения, а не измерение. Реальный выигрыш зависит от того, сколько у вас серверов и активна ли голосовая связь.

## 4. «Без слежки»: что говорит политика и что делает код

Это главная находка проверки, и её стоит изложить точно — с разделением на то, где претензия справедлива, а где нет.

### Что в приложении чисто

Веб-приложение `beta.echoed.gg` **не подгружает** ни Google Analytics, ни рекламные скрипты — единственный внешний хост в нём это Google Fonts. Никаких PostHog, Mixpanel, Amplitude в бандле нет. Это правда, и её надо признать.

### Что в приложении не чисто

В бандле есть модуль `deviceFingerprint`, который динамически подгружает **ThumbmarkJS** — известную открытую библиотеку **фингерпринтинга браузера** — и вызывает `getFingerprint()` с таймаутом 4 секунды:

```js
const $w = Fe("deviceFingerprint");
async function Gh() {
  if (cc !== null) return cc;
  const { getFingerprint: t } = await import("./thumbmark.esm-C0oKVfyv.js");
  const e = await Promise.race([t(), new Promise(n => setTimeout(() => n(""), 4000))]);
  return cc = typeof e === "string" ? e : "", cc;
}
```

Полученный отпечаток отправляется на сервер при **входе** и при **регистрации**:

```js
const h = await Gh();
const g = await $i(_e.AUTH_LOGIN,    { email: t, password: e, captchaToken: n, fingerprint: h });
...
const h = await $i(_e.AUTH_REGISTER, { name: n, username: r, email: t, password: e,
                                       captchaToken: s, fingerprint: m });
```

А вот дословная цитата из [Cookie Policy](https://echoed.gg/cookies.php) того же проекта:

> **Fingerprinting:** We don't use browser fingerprinting techniques.

> [!danger] Прямое противоречие
> Заявление «мы не используем фингерпринтинг браузера» ложно применительно к поставляемому коду. Отпечаток считается и уходит на сервер при каждом логине.
>
> **Справедливости ради:** использование выглядит защитным — привязка устройства, борьба с мультиаккаунтами и спамом. Это ровно та механика, которая позволяет обещать «антиспам без верификации по документам», и как инженерное решение она разумна. Претензия не к самому фингерпринту, а к тому, что политика его отрицает, вместо того чтобы честно описать: «считаем отпечаток устройства для защиты от злоупотреблений».

### Реклама на самом сайте

Сайт `echoed.gg` подгружает Google Tag Manager с идентификатором `AW-10928115957`. Префикс `AW-` — это **Google Ads**, отслеживание конверсий, а не аналитика. Более того, на просмотр страницы срабатывает событие конверсии с денежной ценностью:

```js
gtag('event', 'conversion', {
  'send_to': 'AW-10928115957/epzKCL7sz5YcEPWh99oo',
  'value': 1.0, 'currency': 'USD'
});
```

Этот тег стоит на всех страницах, **включая саму `cookies.php`** — ту, где написано:

> **Analytics Cookies:** We don't use Google Analytics or similar tracking services.
> **Third-Party Cookies:** We don't allow third parties to set cookies through our platform.

Комментарий в исходнике страницы гласит `<!-- Google tag (gtag.js) For search console -->` — но Search Console тут ни при чём, `AW-` это рекламный кабинет.

> [!important] Как это оценивать
> Лозунг «ZERO ADS. EVER. No tracking» относится к **приложению**, и в приложении рекламы действительно нет. Но маркетинговый сайт продвигается через Google Ads с отслеживанием конверсий, а страница, которая клянётся в отсутствии сторонних трекеров, сама этот трекер и загружает. Для проекта, который продаёт себя приватностью, это заметный удар по доверию к формулировкам.

### Чего нет вообще: сквозного шифрования

В политике перечислена только «Encryption of data in transit (HTTPS/TLS)», а сообщения — «Stored in our database». **E2EE нет.** Оператор технически видит всю переписку. У Discord ровно так же, так что регрессии нет, но подача «без слежки» создаёт впечатление приватности, которой в продукте не заложено. Также собираются «Usage Data: login times, feature usage».

### Мелочь, говорящая о зрелости документов

В Cookie Policy описаны куки `a_session_[project_id]` — это **соглашение об именовании из Appwrite**, готового BaaS-бэкенда. При этом там же написано «Echoed runs on its own native authentication». А в реальном коде токены хранятся иначе: `echoed_refresh_token` и `echoed_session_id` лежат в **localStorage**, плюс ставится маркерная кука `echoed_jwt=1`. То есть политика описывает не ту систему, которая сейчас работает, — судя по всему, осталась от прежней архитектуры.

> [!caution] Побочный вывод по безопасности
> Cookie Policy отдельно хвалит флаг `HttpOnly`, который «защищает от XSS, потому что кука недоступна из JavaScript». Но refresh-токен в текущей сборке лежит в `localStorage`, а он **полностью доступен JavaScript**. Любая XSS-уязвимость в мессенджере (а мессенджер — это пользовательский контент, ссылки, разметка, эмодзи) означает угон долгоживущего токена. Это не смертельно и встречается сплошь и рядом, но заявленной в документе модели защиты не соответствует.

## 5. Что под капотом на самом деле

| Компонент | Реализация |
| :--- | :--- |
| Оболочка десктопа | **Tauri** (Rust) поверх системного вебвью |
| Интерфейс | Веб-приложение, JS-бандл ~950 КБ (сборка Vite) |
| Голос, видео, шаринг экрана | **LiveKit** — открытый WebRTC SFU |
| Реалтайм-события | Socket.IO, хост `socket.echoed.gg` |
| Основной API | `go.echoed.gg` |
| Антибот | captcha + отпечаток устройства (ThumbmarkJS) |
| Аватары по умолчанию | DiceBear |
| Раздача сборок | LiteSpeed на `software.echoed.gg` |

Это нормальный современный стек, собранный из хороших готовых кирпичей. Но именно поэтому формулировка «написан на Rust — быстрый» вводит в заблуждение: сетевой стек, кодеки и качество звонков здесь определяются **LiveKit**, а не Rust. «Sub-20ms voice» и «4K@60fps» — это характеристики LiveKit, доступные любому, кто его возьмёт.

## 6. Установка на четырёх системах

### Gentoo (основная)

Ebuild отсутствует, официальной сборки под Portage нет. Варианты:

```bash
# Вариант 1: AppImage (проще всего, но 121 МБ и тянет своё окружение)
sudo emerge --ask sys-fs/fuse:0            # AppImage требует FUSE 2
wget https://software.echoed.gg/v1.7.8/Echoed_1.7.8_amd64.AppImage
chmod +x Echoed_1.7.8_amd64.AppImage
./Echoed_1.7.8_amd64.AppImage

# Вариант 2 (легче): распаковать .deb вручную — 35 МБ вместо 121 МБ
wget https://software.echoed.gg/v1.7.8/Echoed_1.7.8_amd64.deb
ar x Echoed_1.7.8_amd64.deb
tar -xf data.tar.gz -C ~/.local/echoed --strip-components=2 usr/
```

Для второго варианта нужен системный WebKitGTK — Tauri-приложения на Linux рисуются им:

```bash
sudo emerge --ask net-libs/webkit-gtk
```

> [!tip] Самый разумный путь на Gentoo
> Учитывая, что приложение — это веб-фронтенд в оболочке, **проще пользоваться веб-версией** `beta.echoed.gg` в обычном браузере. Вы не потеряете почти ничего (кроме отображения игровой активности), не будете ставить непроверенный бинарник без исходников и не станете держать 121-мегабайтный AppImage.

### Debian / Ubuntu

Здесь всё просто — есть родной пакет, хотя ссылки на него на главной странице нет:

```bash
wget https://software.echoed.gg/v1.7.8/Echoed_1.7.8_amd64.deb
sudo apt install ./Echoed_1.7.8_amd64.deb
```

Обновлений через apt не будет — репозитория проект не держит, придётся качать новую версию руками.

### Arch

В AUR есть пакет, но он отстаёт от актуальной версии:

```bash
yay -S echoed-appimage      # на 12.08.2026 там 1.7.6, а актуальна 1.7.8
```

Либо `.rpm`/`.deb` распаковать вручную, либо AppImage напрямую. Никакого официального сопровождения у AUR-пакета нет — это сборка энтузиаста поверх закрытого бинарника.

### Entware (ASUS RT-AX56U)

> [!caution] Неприменимо
> Echoed — десктопное GUI-приложение с голосом и видео. На роутере ему делать нечего: нет графической подсистемы, а 512 МБ ОЗУ и armv7 не для WebKitGTK. Серверную часть тоже не поднять — она закрытая и облачная, self-hosting проект не предлагает.

## 7. Разумные альтернативы

Если задача — уйти с Discord, а не попробовать конкретно этот проект:

| Вариант | Открытый код | Self-host | E2EE | Комментарий |
| :--- | :---: | :---: | :---: | :--- |
| **Revolt** | ✅ AGPL | ✅ | ❌ | Ближайший идейный аналог Discord, живёт давно, есть публичный код |
| **Matrix + Element** | ✅ Apache | ✅ | ✅ | Федерация и сквозное шифрование; голос слабее Discord |
| **Mumble** | ✅ BSD | ✅ | частично | Если нужен только голос — лучший по задержкам и весу |
| **TeamSpeak** | ❌ | ✅ | ❌ | Проприетарный, но проверенный годами |
| **Echoed** | ❌ | ❌ | ❌ | Легче Discord, но закрытый, в бете, у одного автора |

Ключевое отличие: у Revolt и Matrix код можно прочитать и проверить утверждения о приватности. У Echoed — нельзя, приходится верить политике, которая, как показано выше, расходится с собственным кодом как минимум в двух пунктах.

## 8. Итог

**Что действительно хорошо:**
- Приложение объективно легче Discord — это неизбежное следствие Tauri, и это не маркетинг.
- Регистрация без верификации по документам и без сканирования лица — на фоне Discord 2026 года это настоящая ценность.
- Набор функций для проекта такого масштаба удивительно широкий: роли, боты с REST API, канбан, календарь, OAuth-провайдер, аудит-лог, антирейд.
- Сборки под все платформы, включая `.deb` и `.rpm`, а не только AppImage.
- В самом приложении рекламных и аналитических трекеров нет.

**Что нужно держать в голове:**
- Это **не новинка**, а переименованный Zorium, существующий с апреля 2025.
- Приложение всё ещё живёт на домене `beta.` — это бета.
- «В 5 раз меньше памяти» — это 4,7× из неравного сравнения без методики.
- «Написан на Rust» — на Rust оболочка; голос и видео это LiveKit.
- **Политика проекта противоречит его коду**: заявленное отсутствие фингерпринтинга опровергается ThumbmarkJS в модуле авторизации, а страница с обещанием «никаких сторонних трекеров» сама грузит рекламный тег Google Ads.
- Сквозного шифрования нет — оператор видит переписку.
- Исходники закрыты, self-hosting не предусмотрен, проверить обещания независимо невозможно.
- Численность аудитории противоречива даже в собственных материалах; по данным магазинов речь идёт о тысяче загрузок и нуле отзывов.
- Три разных названия владельца на трёх площадках и массовый адрес регистрации в Вайоминге.

**Кому подойдёт:** тому, кто хочет лёгкий клиент для небольшой компании друзей и кого устраивает уровень приватности «как у Discord, но без скана лица». Пробовать разумно **через веб-версию** — она даёт почти всё то же самое и не требует ставить закрытый бинарник от малоизвестного разработчика.

**Кому не подойдёт:** тем, кому нужны проверяемая приватность, сквозное шифрование, свой сервер или гарантия, что проект не исчезнет. Для этих задач Revolt и Matrix объективно надёжнее.
