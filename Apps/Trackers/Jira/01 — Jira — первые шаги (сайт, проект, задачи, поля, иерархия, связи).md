# 🚀 Jira — первые шаги: сайт, проект, задачи

Часть серии — [карта серии и обзор](00%20%E2%80%94%20Jira%20%E2%80%94%20%D1%87%D1%82%D0%BE%20%D1%8D%D1%82%D0%BE%2C%20Cloud%20%D0%B8%D0%BB%D0%B8%20Data%20Center%2C%20%D0%BE%D1%81%D0%BD%D0%BE%D0%B2%D0%BD%D1%8B%D0%B5%20%D0%BF%D0%BE%D0%BD%D1%8F%D1%82%D0%B8%D1%8F%20%D0%B8%20%D0%BA%D0%B0%D1%80%D1%82%D0%B0%20%D1%81%D0%B5%D1%80%D0%B8%D0%B8.md).

## 1. Сайт

1. https://www.atlassian.com/software/jira/free → регистрация по почте или через Google/GitHub-аккаунт.
2. Имя сайта — `имя.atlassian.net` (поменять потом можно, но ссылки старых интеграций сломаются — выбирайте сразу нормальное).
3. Язык интерфейса — **Профиль → Personal settings → Language** (есть русский). В серии названия даю в английском варианте: в документации, JQL и интеграциях всё равно английские имена.

Мобильные приложения Jira Cloud есть для Android и iOS — удобно двигать карточки и отвечать на комментарии.

## 2. Проект: шаблон и тип управления

**Projects → Create project** → выбрать **шаблон** и **тип**.

### Шаблоны

| Шаблон | Для чего |
| :--- | :--- |
| **Kanban** | непрерывный поток задач без спринтов — **лучший старт для своих проектов** |
| **Scrum** | работа спринтами: бэклог, планирование, отчёты по скорости |
| **Bug tracking** | только список багов без доски |
| Top-level planning, Cross-team planning | планирование над несколькими командами (Premium) |

### Team-managed или company-managed

| | **Team-managed** (бывш. next-gen) | **Company-managed** (бывш. classic) |
| :--- | :--- | :--- |
| Кто настраивает | любой администратор проекта, прямо в проекте | администратор Jira, общие схемы |
| Настройки | свои для проекта: статусы, поля, типы — просто и быстро | общие схемы workflow, полей, прав — переиспользуются между проектами |
| Гибкость | ниже (одна доска, проще права) | выше: несколько досок, сложные workflow, JQL-доски |
| Совет | **для обучения и личных проектов** | когда проектов много и нужны единые правила |

Переделать team-managed в company-managed можно только переносом задач в новый проект — решите заранее. Для серии подойдёт **Kanban, company-managed**: так понятнее, как устроены workflow и схемы (заметка 02), и доступны все возможности CI-интеграций.

### Ключ проекта

Короткий идентификатор из латинских заглавных букв: `WEB`, `BOT`, `INFRA`, `KB`. Из него строятся ключи задач **`WEB-1`, `WEB-2`…** — именно их потом пишут в ветках и коммитах, чтобы Jira связала код с задачей. Делайте ключ коротким (2–5 букв): его будете печатать постоянно.

## 3. Типы задач и иерархия

```
Уровень 1   Epic          «Новый личный кабинет»
             │
Уровень 0   Story · Task · Bug     «Форма входа» · «Настроить CI» · «Падает на пустом пароле»
             │
Уровень −1  Subtask               «Вёрстка» · «API» · «Тесты»
```

| Тип | Когда использовать |
| :--- | :--- |
| **Epic** | крупная цель на недели или месяцы; объединяет задачи |
| **Story** (история) | функция с точки зрения пользователя: «Как пользователь, я хочу…» |
| **Task** | техническая работа: настроить, обновить, перенести |
| **Bug** | что-то работает не так |
| **Subtask** | часть задачи, которую удобно отслеживать отдельно |

На тарифе Premium можно добавить уровни **выше эпика** (например, «Инициатива»). Свои типы (Spike, Chore, Improvement) добавляются в настройках проекта.

## 4. Задача: создание и поля

Создать — кнопка **Create** или клавиша **`c`** в любом месте Jira.

| Поле | Что писать |
| :--- | :--- |
| **Summary** (заголовок) | коротко и конкретно: «Добавить проверку длины пароля», а не «Пароль» |
| **Description** | детали; редактор понимает Markdown-сокращения (`#`, `*`, `` ` ``, ```` ``` ````), таблицы, чек-листы, вставку скриншотов |
| **Assignee** | исполнитель (один) |
| **Reporter** | кто завёл |
| **Priority** | Highest … Lowest |
| **Labels** (метки) | свободные теги: `frontend`, `tech-debt`, `claude` |
| **Components** | часть системы (`api`, `web`, `ci`) — в company-managed проектах |
| **Fix versions** | в каком релизе будет готово |
| **Parent** | эпик (или задача для подзадачи) |
| **Sprint** | в каком спринте (Scrum) |
| **Story points** / **Original estimate** | оценка (заметка 02) |
| **Due date** | срок |

### Шаблон хорошего описания бага

```markdown
## Шаги
1. Открыть /login
2. Оставить пароль пустым, нажать «Войти»

## Ожидалось
Сообщение «Введите пароль»

## Фактически
500 Internal Server Error

## Окружение
Firefox 140, Gentoo, сборка #128 (main@a1b2c3d)

## Логи / скриншоты
(вложение)
```

### Шаблон задачи для разработки (и для ИИ-агента)

Чем точнее задача, тем лучше её выполнит и человек, и агент (заметка 06):

```markdown
## Цель
Зачем это нужно — одним-двумя предложениями.

## Критерии готовности
- [ ] …
- [ ] тесты на …
- [ ] документация обновлена

## Ограничения
Что трогать нельзя, какие зависимости не добавлять.

## Ссылки
Макет, связанная задача, обсуждение.
```

## 5. Работа с задачей

| Действие | Как |
| :--- | :--- |
| Сменить статус | кнопка статуса справа сверху или перетаскивание на доске |
| Комментарий, упоминание | вкладка Comments, **`@имя`** — человеку придёт уведомление |
| Наблюдать (watch) | значок глаза — уведомления об изменениях |
| Вложения | перетащить файл в задачу (лимит места на Free — 2 ГБ на весь сайт) |
| Подзадача | **Create subtask** в задаче |
| Клонировать | **⋯ → Clone** |
| Перенести в другой проект | **⋯ → Move** (ключ задачи сменится, старый будет перенаправлять) |
| Массовое изменение | в поиске задач **⋯ → Bulk change**: статус, исполнитель, метки сразу у многих |
| История изменений | вкладка **History** — кто что поменял |

### Связи между задачами

| Тип связи | Смысл |
| :--- | :--- |
| **blocks / is blocked by** | не сделать B, пока не сделано A |
| **relates to** | просто связаны |
| **duplicates / is duplicated by** | дубль |
| **clones / is cloned by** | создана клонированием |

Связи видны в задаче и доступны в JQL (`issue in linkedIssues("WEB-10")`, заметка 03). Ссылки на внешние ресурсы (PR, документ, Confluence) — **Link → Web link**.

### Учёт времени

**⋯ → Log work** или в поле Time tracking:

- формат: `1w 2d 3h 30m` (по умолчанию в дне **8 часов**, в неделе **5 дней** — настраивается администратором);
- **Original estimate** — план, **Time spent** — потрачено, **Remaining** — осталось;
- время можно логировать прямо из коммита — `#time 2h` в [smart commits](05%20%E2%80%94%20Jira%20%2B%20Git%20%D0%B8%20CI-CD%20%E2%80%94%20GitHub%20Actions%2C%20Bitbucket%20Pipelines%2C%20GitLab%20CI%20%28%D0%BA%D0%BB%D1%8E%D1%87%D0%B8%2C%20smart%20commits%2C%20%D1%81%D0%B1%D0%BE%D1%80%D0%BA%D0%B8%20%D0%B8%20%D0%B4%D0%B5%D0%BF%D0%BB%D0%BE%D0%B8%29.md).

### Уведомления

**Personal settings → Notifications**: письма о назначении, упоминаниях, изменениях наблюдаемых задач. Чтобы не утонуть в почте, оставьте упоминания и назначения, остальное смотрите в колокольчике.

## 6. Пользователи и доступ

- **Settings (шестерёнка) → User management → Invite** — пригласить по почте (на Free — до 10 человек, включая вас).
- На Free все участники видят все проекты; роли и тонкие права появляются с Standard.
- Для ботов и интеграций (CI, скрипты) используют **API-токены**: https://id.atlassian.com/manage-profile/security/api-tokens. Токен действует от имени пользователя и с его правами — для автоматизации лучше завести отдельного пользователя-бота. Токены теперь создаются с **ограниченным сроком действия** (до года) и, по желанию, с ограниченными правами (scopes).
